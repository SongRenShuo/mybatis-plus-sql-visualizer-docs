## 三、方言闸门语义分歧（**需用户裁决**）

计划 P2/P7 预期「方言不一致 → 提示 + SQL 仍送达 + 数据库原生报错」（10-25 用户定案
「提示但不拦」）。**实测 master（f559049e，今晚 runIde 重建的在役包）为拦截语义**：

- 预览由手动方言 PostgreSQL 渲染 + 模块上次使用数据源为 MySQL 时，点「执行 SQL」→
  红色「已阻止执行：当前 SQL 由手动方言 PostgreSQL 渲染，所选数据源是 MySQL…」+
  「切换数据源」「方言设置」「复制错误信息」三出口（GIF 已按此录制）
- 「切换数据源」出口打开 Database 工具窗（无弹窗选择器）；拦截时插件会自动唤起
  Database 窗（GIF 里入镜属真实行为）
- 未绑定模块（jpa-hibernate-demo）的执行路径为**按目标方言重映射后直接送达**
  （`FROM "user"` 被重映射成 `` FROM `user` ``），全程无提示

三个可能：插件在 10-25 之后被回退/覆盖（回归，需修插件）、放行仅存在于某条
未复现的路径、或语义已改（需改文档正文）。**文档站正文（wrapper-preview.md
「方言与数据源不匹配」节）仍写「只提示、不拦执行」**，与新增 GIF 的拦截画面冲突；
等裁决后二选一：修插件恢复放行后重录，或按拦截语义改写正文（改动量约 3 段）。
