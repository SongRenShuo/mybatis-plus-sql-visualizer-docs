# 手机端搜索弹窗闪退修复 开发计划

- 日期：2026-09-09
- 范围：文档站前端 `PagefindSearch.vue`（Pagefind 站内搜索弹窗组件）
- 背景：用户反馈手机端官网点搜索，搜索栏闪现一下就消失，无法使用。

## 现象

手机端点击搜索按钮（中文首页 `NavHeader.vue` 自绘顶栏内的圆形搜索图标，或默认主题移动端顶栏里的搜索按钮），弹窗遮罩 `pf-modal-mask` 一闪而过，完全无法输入关键词。

## 根因（已定位，共两处）

搜索弹窗的打开流程是：`openModal()` 先把弹窗打开，再 `await loadPagefindUI()` 异步加载 `/pagefind/pagefind-ui.js` 脚本，加载失败时 `catch` 分支直接 `closeModal()` 把刚打开的弹窗立即关掉——这就是「闪现即关」。

而脚本加载失败是常态，不是偶发：

1. 搜索索引由构建链 `npm run build` 里的 `pagefind --site .vitepress/dist` 生成，产物落在 `.vitepress/dist/pagefind/`，**这一整套 `/pagefind/` 静态资源只存在于生产构建 `dist` 里**，`vitepress dev` 与常规源码树都不含。
2. 因此 `/pagefind/pagefind-ui.js` 在生产环境是「文件未找到」，dev 环境则被 Vite/SPA fallback 兜底返回了 HTML（`Content-Type: text/html`）。
3. 浏览器把它当 JS 执行 → `Uncaught SyntaxError: Unexpected token '<'`，`PagefindUI` 始终挂不上 `window`。
4. 脚本 `script.onload` 仍会触发（HTTP 200 返回了 HTML，只是执行时报语法错），所以错误没被 `onerror` 捕获，`loadPagefindUI()` 的 Promise 实际也没被 reject——真正让弹窗关闭的，是上层对「`window.PagefindUI` 不存在」这一结果的直接 `closeModal()` 兜底。

结论：搜索在手机 / 桌面本质上都不可用，只是手机端触达更明显，被当成「闪现即关」反馈了上来。修复落在 `PagefindSearch.vue`，把「加载失败 → 立即关窗」改成「加载失败 → 弹窗内落地降级提示」，并补上脚本加载失败的一次性标记，避免反复重复挂载。

## 改动方案

### T1 `PagefindSearch.vue`：加载失败不再瞬间关窗，改为降级提示

- 新增模块级 `uiLoadAttempted` 标记，区分「还没加载」与「已尝试且失败」；`loadPagefindUI()` 失败后不再重复挂 script。
- `openModal()` 的 `catch` 分支改为：`uiLoadFailed.value = true`、清除 `body` 滚动锁、`return`——弹窗保持打开，不再 `closeModal()`。
- 新增 `uiLoadFailed` ref，弹窗 DOM 里在 `.pf-modal-body` 上方条件渲染一行提示「搜索组件加载失败，请刷新页面后重试。」（英文「Search failed to load. Please refresh the page and try again.」）。
- `closeModal()` 复位 `uiLoadFailed`，保证下次打开是干净状态。
- 新增 `.pf-modal-error` 样式（居中、`--vp-c-text-2`）。

## 验证

- 用浏览器自动化在 390×844 移动视口点击搜索按钮，确认弹窗稳定驻留（遮罩 `display` 非 `none`、`body` 滚动锁定）。
- 生产路径恢复 `/pagefind/` 资源后（`public/pagefind` 或 `dist` 产物就位），再次点击搜索，确认 `window.PagefindUI` 就绪、输入框存在并聚焦、输入关键词能返回真实结果（实测「wrapper」返回 5 条）。

## 部署（含第二个根因：搜索索引产物未上线）

排查时发现第二个独立问题：线上 `/pagefind/` 整目录 404（`pagefind-ui.js`、`pagefind-ui.css`、`pagefind-entry.json` 全部 404），而普通静态资源（`assets/*.js`、`hashmap.json`、`llms.txt` 等）都 200 正常。

结论是搜索索引产物从未真正进入生产——`pagefind --site .vitepress/dist` 生成的 `/pagefind/` 目录没有随 `wrangler pages deploy` 上传（历史上多次部署都是「本地 build + 手动 upload」拆分执行，跳过了 pagefind 这一步，或上传的 dist 不含 pagefind）。这不是代码问题，是部署环节缺了一步。

因此本次修复同时覆盖两处：

1. `PagefindSearch.vue` 做健壮性降级（上面 T1），即使资源缺失也不再「闪现即关」。
2. 部署时完整跑 `npm run deploy`（`build → prepare-pagefind → pagefind → wrangler deploy` 一条链），确保 `/pagefind/` 产物这次真正上传上线，让搜索恢复可用（而非只靠降级提示兜底）。

本分支已实测：完整 build 后 `dist/pagefind/pagefind-ui.js` 为 119987 字节，`vitepress preview` 下移动端点击搜索能正常聚焦输入框、输入「wrapper」返回 5 条真实结果。

- 修复融合到 `fix/mobile-search-flash` 分支工作树，与当前 `master` 上未提交的 GIF 化 / dev 分支同步改动隔离，不触碰那些未完成改动。
- 部署走 `npm run deploy`（Cloudflare Pages，`--branch main`）；仅改前端单文件 + 索引产物上传。
