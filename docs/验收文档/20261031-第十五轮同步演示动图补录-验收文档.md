## 三、机制取证（本轮最花时间的部分，留给下次直接抄）

1. **平台的 runner 枚举按 exec 文件方言过滤，无匹配源时回退「全部源」**：`.idea/sql-visualizer/exec/mpsql-exec.sql` 被按渲染方言（PostgreSQL）预映射后，日志 `[M36] runners=1` 只给 PG 源（远端 `MySQL`/`dbx_test`），于是「单 runner 直接执行」、永不弹选择器。把两个远端 PG 源临时移出 `.idea/dataSources.xml` 后变成 `[M36] runners=6`（全部 MySQL 源）+ `show popup with 6 runners`，选择器才出现。录制结束后两份 XML 已按原样还原。
2. **能装下 `FROM "user"` 且带全字段的库是 `mp_demo` 而不是 `mpj_demo`**：`mpj_demo.user` 只有 `id/name/age/sex/head_img` 五列（3 行），`mp_demo.user` 才是 `id/username/password/age/email/role_id/dept_id/status/remark/create_time/update_time/deleted/version`（10 行）。`mpj_demo` 那套是早期 execute-sql 演示用的另一张表。
3. **数据源 URL 必须带 `sessionVariables=sql_mode=ANSI_QUOTES`**：否则 `FROM "user"` 在 MySQL 里是字符串字面量、直接语法错。本轮新建的 `mp_demo@localhost` 源按此拼 URL（`create_database_connection` 的校验会拒带 `sessionVariables` 的 URL，故先用纯 URL 建源、再改 `dataSources.xml` 补参数）。
4. **放行态的提示行会被真实报错覆盖**：`onExecutionDialectGate` 对 `MANUAL_CONFLICT` 走 `resultPanel.showStatus()`（下一拍 EDT），真实错误随后覆盖同一 infoLabel。所以「提示行」要能停在画面里，执行必须**不报错**——这也是必须选 `mp_demo`（有全字段）而不是 `mpj_demo` 的原因。
5. **执行视图（Result 网格）在本沙盒会话没挂上**：日志止于 `[M36] runRunner invoked OK`，没有 `result/layout OK` / `results refreshed`，面板停在预览态（`未绑定数据源（在控制台执行一次查询即可绑定）`）。会话确实建在 `mp_demo/MySQL`（`session created … target=5bbcde8e/MySQL, execute=true`），SQL 已提交。这张片因此以「信息行」收尾而不是结果网格；结果网格形态由 `execute-sql.gif` 覆盖，不冲突。

## 四、N2：插件缺陷定案 → 修复 → 补录（已闭环）

首轮实测四条能力里三条复现失败，逐条归因（2026-10-31 当天完成分析）：

| 声称能力 | 归因 | 处置 |
|---|---|---|
| 输入 `#`/`$` 自动补 `{}` | **插件缺陷**：`ParamBraceTypedHandler.inStatementText` 只看一层 parent，且把「子标签体内正文」与「子标签标记区」混为一谈——`<where><if>`、`<choose><when>` 等真实 mapper 主流排版下全灭；语句标签自身属性区还会误插 | **已修**（T-XmlBraceNested，插件仓 `e69c6e5d`）：重写为「最近语句标签祖先（任意深度）+ 体内容孩子推导标记区」；`ParamBraceTypedHandlerTest` 新增 5 用例 + 原 6 用例 + `XmlGapEditingAssistTest` 11 用例，22/22 绿 |
| `#{…,` 结构属性键（jdbcType= 等） | **仍未出**：修复后实测 `#{status,` + Ctrl+Space 出的是 SQL 关键字/列名弹窗，无 `jdbcType=` 等键；伴随平台 `AsyncCompletion` SEVERE `MpSqlMapper:UserMapper.xml != MpSqlMapper:UserMapper.xml`（注入身份断言，日志两次实录） | **登记未录**：疑似插件 contributor 在完成期触碰宿主 PSI 触发注入重解析，或纯平台断言，需单独排查（建议从 `XmlSqlCompletionContributor` 宿主还原路径入手） |
| 标签属性值补全（refid→sql id） | 首轮探针落点错（Home 后连按 Left 落到上一行行尾），修复后未再复测 | 未入片 |
| 动态标签折叠 | 平台 `XmlFoldingBuilder` 既有行为，本插件 `SqlMapperFoldingBuilder` 只做「语句标签带 id 占位」；折叠箭头坐标不可靠 | 未入片 |

N2 成片（两拍，全部实证在镜）：`<where><if>` 体内行尾敲 `#` → 自动补出 `{}`（修复主镜头）；续敲 `status,` + Ctrl+Space → 补全弹窗（列名带中文注释）；Esc + 撤销还原，首尾同态（接缝 0.33）。

**注意**：站点 `features/xml-preview` 正文「`#{}` 占位符补 `jdbcType` / `javaType` / `typeHandler` 等结构属性」在当前 2026.2 实测不成立——该句是否需要加条件（如「依赖完成期注入身份稳定性」）或回落，待上面第二项排查后一并定夺。
