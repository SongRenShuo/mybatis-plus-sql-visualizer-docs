# ArtCraft 官网手法吸收-开发计划

> 日期：2026-11-02 11:10
> 状态：计划待实施（本轮只出计划，未改代码、未部署）
> 依据：`docs/调研报告/20261102-1110-ArtCraft官网首页手法调研-调研报告.md`
> 范围：官网首页 11 个区块中的样式层改动（必做）；产品决策类改动（需用户定夺后再实施）
> 关联：`docs/开发计划/20261010-1521-官网首页视觉与信息架构升级-开发计划.md`（上一轮同域改造）、`docs/开发计划/20261029-1129-首页CTA装饰图标去除与全站Emoji审查-开发计划.md`（去 AI 味取向）

## 一、背景与结论

用户提出分析 <https://getartcraft.com/> 并提取可吸收到当前官网的做法。调研已完成（见关联报告），结论是：

**目标页有 6 项手法值得吸收，其中 3 项是低成本高收益的样式层改动，3 项需要先做验证或用户决策；另有 7 项明确排除。**

核心判断：目标页是面向大众创意用户的产品展示页，当前官网是面向开发者评估与安装的工具页。目标页首屏纯文字零媒体（实测 8413 字节、`<img>`/`<video>`/`<canvas>` 计数均为 0），靠文字层级撑起首屏；当前官网首屏是一个代码对照块（Java Wrapper 链 ↔ 生成的 SQL），直接回答「我的 Wrapper 能不能预览」。**当前官网的首屏策略比目标页更适合本产品，不改。**

真正值得吸收的是目标页在**排版细节**上的四个手法：标题内的强调词、HUD 标签样式、发丝网格分隔、标题字重字距。它们的共同点是成本极低（多数只改一处 CSS）且与产品形态无关。

## 二、取舍原则

沿用上一轮的三条约束，并新增两条：

1. **只改样式层，不改信息架构**。本轮不动区块顺序、不动文案语义、不动 `homeContent.js` 的键结构。
2. **中文侧与英文侧分别定案**。目标页的斜体强调手法依赖拉丁字形，中文无斜体（浏览器合成倾斜观感差），中文侧必须换等价手法。
3. **不做无谓装饰**。目标页的 24 个 `.tick` 准星标记、15 色应用矩阵、社区影片墙一律排除（与 `20261029-1129` 的去 AI 味取向冲突）。
4. **改一处 CSS 能解决的不改组件结构**。优先用 CSS 变量 + 类覆盖，避免动 15 个 Vue 组件的结构。
5. **暗色模式必须同批验**。当前官网有完整的 `.dark` 变量集，任何颜色改动都要在两套模式下各验一次。

## 三、任务清单

### T1 标题强调词样式（P0，必做）

**对应调研 5.1**

在区块标题中选一个关键词，用主强调色 + 字重强调。目标页用 `<span class="font-serif italic">`，中文侧改为颜色 + 字重。

**候选位置**（需用户定夺，见第六节）：

| 区块 | 现标题 | 建议强调词 |
|------|--------|-----------|
| 核心能力 | 大幅提升您的 SQL 调试效率 | `SQL` |
| 更多特性 | 我们为您考虑周全 | `周全` |
| 数据事实 | 不靠形容词，靠可核验的数字 | `可核验` |
| CTA | 准备好告别繁琐的SQL 调试方式了吗？ | `告别` |

**改动落点**：

- `.vitepress/theme/data/homeContent.js` — 4 处标题字符串改为带 `<span>` 的 HTML，中英各 4 处（共 8 处）
- `.vitepress/theme/components/home/` 中渲染这 4 个标题的组件 — 确认用 `v-html` 或改为插槽；**注意不要引入 XSS 面，文案来自本地数据文件可接受**
- `.vitepress/theme/style.css` 或各组件 `<style>` — 新增 `.title-accent` 类（`color: var(--primary-color); font-weight: 600`）

**英文侧**：可以用衬线斜体（`font-family: Georgia, serif; font-style: italic; font-weight: 400`），与目标页手法一致，但**需先引入衬线字体栈**（系统 Georgia 即可，无需自托管）。

**验收**：

- 亮暗两模式下强调词与正文有明确视觉区分
- 强调词不换行断裂（中文长词需 `white-space: nowrap` 或按词切分）
- 移动端 390×844 下标题不溢出

### T2 HUD 标签样式统一（P1，必做）

**对应调研 5.3**

把 `section-eyebrow` 从普通小字改为目标页的 HUD 标签样式。

**目标样式**（取自目标页实测 class）：

```css
.section-eyebrow {
  font-size: 11px;
  font-weight: 700;
  letter-spacing: 0.12em;
  text-transform: uppercase;
  color: var(--primary-color);
  font-family: var(--vp-font-family-mono), ui-monospace, monospace;
}
```

**改动落点**：`.vitepress/theme/style.css` 中 `.section-eyebrow` 一处。

**中文侧适配**：`text-transform: uppercase` 对中文无效（无大小写），保留无害；字距 `0.12em` 对中文有效，是中文侧的主要变化。

**同时统一**：目标页把区块编号、页脚链接、列表项都压进同一个 HUD 层级。当前官网可一并处理的落点：

- `.section-eyebrow`（区块眉题，9 处）
- `.steps-num`（步骤编号）
- `.feature-card-tags`（功能卡标签行）
- `.welfare-*` / `.facts-*` / `.pricing-*` / `.updates-*` 中的 meta 行

**验收**：

- 9 个区块眉题在亮暗两模式下均清晰可辨
- 中文眉题在 `letter-spacing: 0.12em` 下不拥挤
- 移动端眉题不换行（`white-space: nowrap` + `overflow: hidden`）

### T3 发丝网格分隔（P1，必做）

**对应调研 5.4**

用 `gap-px + 父容器背景色 + 子项背景色` 得到 1px 均分网格，替换卡片边框。

**目标页做法**（实测 HTML）：

```html
<div class="grid gap-px border-t border-line bg-line md:grid-cols-2">
  <article class="bg-bg">…</article>
</div>
```

**改动落点**：

- `.vitepress/theme/components/home/FeaturesGrid.vue` — 8 张功能卡
- `.vitepress/theme/components/home/FeatureAlternate.vue` — 8 个能力块（**注意：该区块有配图，需逐卡验证**）

**新增 CSS 变量**（`style.css`）：

```css
--line-color: #e5e7eb;              /* 亮色，需按实测调整 */
.dark { --line-color: #374151; }    /* 暗色 */
```

**验收**：

- 网格线在亮暗两模式下均可见但不抢眼
- 8 张卡在 `md`（768px）换列时线条自动重排
- 390×844 单列时网格线正确
- `FeatureAlternate` 的配图不被网格裁切

### T4 标题字重与字距（P2，先验证再实施）

**对应调研 5.5**

**目标样式**（取自目标页实测 class）：

```css
.section-title {
  font-weight: 500;
  line-height: 1.1;
  letter-spacing: -0.02em;
}
```

**为什么标 P2**：调研第八节把「中文黑体 500 与 400 差异是否明显」列为待验证前提。中文系统黑体（微软雅黑 / PingFang / 思源黑体）的 500 字重可能回落到 400，导致改动无视觉效果；而紧字距对中文的作用也未经实测。

**先做的事**：在浏览器里对同一个中文标题分别渲染 `font-weight: 400 / 500 / 600 / 700` 与 `letter-spacing: 0 / -0.02em / -0.035em`，截图对比。**若有明显差异则实施，若无则放弃此项**。

**改动落点**：`.section-title`（11 个区块共用）。

**验收**：仅在验证有视觉效果时执行；执行后需全区块回归。

### T5 产品决策项（P2，需用户定夺）

**对应调研 5.6**

首屏信息分层调整。当前首屏有三级信息（CTA 组 / 亮点标签 / 统计数据），目标页有五级（主 CTA / 次 CTA / 跨产品引导 / 平台清单 / 信任标签）。

**不直接推荐的原因**：目标页首屏零媒体，靠文字层级就能撑起；当前首屏右侧是代码对照块，已承担「证明这东西能用」的职责，再加层级会挤压它。

**用户定夺后可做的方向**（三选一或都不做）：

1. 给现有三级信息加视觉层级（CTA 组放大、亮点标签改 HUD 样式、统计数据加分隔线）
2. 增加第四级「平台 / 环境清单」（如 `macOS · Windows · Linux` 的等价物 `IntelliJ IDEA 2024.3+`）
3. 保持现状

## 四、不做清单

以下为目标页中存在但**明确排除**的形态，理由是它们与本产品形态或既有取向冲突。

| 排除项 | 理由 |
|--------|------|
| 纯文字巨型首屏 | 丢掉代码对照块＝丢掉最强证据，详见调研报告 6.1 |
| 双产品线对比区块 | 单一产品无对比对象 |
| 社区影片墙 | 「数据事实」三条数字对开发者更有说服力 |
| 15 色应用矩阵 | 单一产品无承载对象 |
| 装饰性准星标记（24 个 `.tick`） | 纯装饰，与去 AI 味取向冲突 |
| 吸顶眉题条替换 SectionNav | 目标页眉题条不可点击，弱于现有 9 锚点导航 |
| 全站换字体（Archivo / Instrument Serif / Inter） | 不含中文字形，收益仅限英文；新增 3~5 个 woff2 拖慢首屏 |
| 跨产品引导（`Looking for ArtCraft Studio?`） | 单一产品无第二产品线 |
| 巨型逐字母字标 | 与「代码对照块」首屏策略冲突，且中文无逐字母排版基础 |

## 五、验收与部署

### 5.1 验收档位

按既有三档分层：

- **定向**：每个任务实施后由实施者自查（亮暗两模式 + 1440×900 / 390×844 两档视口）
- **统一全量门禁**：全部任务完成后单派一个只读收口代理跑一次权威全量（`npm run build`），主控同时写文档收尾，**并行不空等**
- **构建校验**：本轮改动涉及 `.vitepress/theme/` 样式与组件，属「大改动」判据中的「引入新平台 API 面或反射入口」之外，但动了 15 个组件中的 2 个结构，**建议跑一次 `npm run build` 门禁**

### 5.2 部署

- 部署命令：`npm run deploy`（Cloudflare Pages，见 `deployment-target` 记忆）
- 提交策略：测试通过即 commit（只 add 本次文件，不 push），部署按任务流程
- **禁止**在未做真机截图验收前部署

### 5.3 回归重点

| 改动 | 回归点 |
|------|--------|
| T1 标题强调词 | 4 个标题 × 2 语言 × 2 模式 = 16 种组合 |
| T2 HUD 标签 | 9 个区块眉题 × 2 模式 |
| T3 发丝网格 | `FeaturesGrid` 8 卡 + `FeatureAlternate` 8 块 × 2 模式 × 2 视口 |
| T4 标题字重 | 11 个区块标题 × 2 模式 |
