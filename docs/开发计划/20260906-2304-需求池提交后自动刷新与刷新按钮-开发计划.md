# 需求池提交后自动刷新与刷新按钮 开发计划

- 日期：2026-09-06 23:04
- 范围：仅文档站前端（`.vitepress/theme/components/feedback/`），后端无改动
- 背景：用户反馈两个问题——
  1. 在「新增反馈」弹窗提交成功后，弹窗自动关闭，但列表/看板/统计/右侧动态面板都还是旧数据，必须手动刷新浏览器才能看到新反馈；
  2. 需求池页没有任何刷新入口，想看最新数据只能整页刷新。

## 现状分析

- `FeedbackPool.vue` 提交弹窗 `<FeedbackForm ... @done="closeForm" />`：`done` 事件仅在提交成功路径发出（FeedbackForm.vue 全文只有一处 `emit('done')`），当前处理器只关弹窗，不调 `loadData()`。
- 列表与看板共用同一份 `posts/stats/statusStats` 状态，`loadData()` 是唯一加载入口（挂载时与搜索回车时调用）。
- `FeedbackActivity.vue`（右侧需求池动态）的加载逻辑内联在 `onMounted` 里，未抽取函数，外部无法触发重载。
- `FeedbackPage.vue` 里还有一条深链路径：`?category=xxx` 直开提交弹窗，成功后同样不刷新其身后的反馈池与动态面板。
- 工具栏 `.pool-toolbar` 目前左侧为「列表/看板」切换、右侧仅「＋ 新增反馈」一个按钮。

## 改动方案

### T1 FeedbackPool.vue：提交成功后自动刷新 + 暴露 reload

- 弹窗 `@done` 由 `closeForm` 改为 `onSubmitted`：先 `closeForm()`，再 `loadData()`，并向父级 `emit('submitted')`（新增 emit 声明）。
- `defineExpose({ reload: loadData })`，供父组件在深链提交成功后调用。
- 提交成功到刷新完成之间 `loading.value = true`，列表自然显示「加载中...」，无需额外状态。

### T2 FeedbackPool.vue：工具栏新增刷新按钮

- `.pool-toolbar` 右侧、「＋ 新增反馈」左边加「刷新」按钮：`↻` 图标 + i18n 文案，点击调 `loadData()`；`loading` 期间图标旋转（CSS 动画）并禁用，防止重复点击。
- 移动端（≤768px）`.pool-toolbar` 加 `flex-wrap: wrap`，三个控件放不下时自动换行。

### T3 FeedbackActivity.vue：抽取加载函数并暴露 reload

- `onMounted` 里的加载逻辑抽取为 `async function loadActivity()`，`onMounted(loadActivity)`。
- `defineExpose({ reload: loadActivity })`。

### T4 FeedbackPage.vue：深链提交成功后联动刷新

- 给 `<FeedbackPool>` 加 `ref="poolRef"`、监听新增的 `@submitted`；给 `<FeedbackActivity>` 加 `ref="activityRef"`。
- 池内弹窗提交成功（`submitted` 事件）→ 调 `activityRef.reload()` 刷新右侧动态。
- 深链弹窗 `@done` 由 `closeForm` 改为 `onDeepLinkSubmitted`：`closeForm()` + `poolRef.reload()` + `activityRef.reload()`。

### T5 i18n.ts：新增 refresh 文案

- zh：`refresh: '刷新'`；en：`refresh: 'Refresh'`。`MessageKey` 为 `keyof typeof messages.zh` 联合类型，两侧同步添加即可通过类型检查。
