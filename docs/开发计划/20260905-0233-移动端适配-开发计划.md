# 文档站移动端适配 - 开发计划

> 时间: 2026-09-05 02:33
> 仓库: mybatis-plus-sql-visualizer-docs（VitePress 1.6.3 + 自定义主题组件）
> 关联: sql-visualizer-admin 仓库同日「管理后台移动端适配」计划（两仓库并行实施）

## 一、背景

文档站和管理后台此前都只面向 PC 端浏览，移动端存在布局不协调、文字重叠、横向溢出等问题。本文档站已做全量代码盘点（34 个主题源文件逐一核对），问题集中在三类：反馈池系列组件完全没有断点、全局样式破坏了 VitePress 自带的表格滚动、自定义首页导航在移动端直接消失。

## 二、问题清单（均有代码证据）

### 严重

1. **全站文档页表格横向滚动失效**：`style.css:342-352` 把 VitePress 默认的 `display:block + overflow-x:auto` 表格覆盖回 `display: table` + `overflow: hidden`，宽表格直接撑破视口产生整页横滚；`style.css:361` 表头 `white-space: nowrap` 加剧溢出。影响所有含表格的文档页和 changelog 动态表格。
2. **首页移动端无导航入口**：`NavHeader.vue:130-140` 在 <768px 把 `.nav-links` 整个 `display:none`，且没有汉堡按钮/抽屉；首页是 `layout:false` 不渲染 VitePress 自带导航 → 移动端用户在首页无法进入任何页面。另外 `NavHeader.vue:106-157` logo 区 + 操作区在 320px 视口必然溢出换行。

### 高

3. **FeedbackPool.vue 全文件 0 个 @media**：移动端默认落在看板视图（`:170`）；搜索框固定 200px（`:437`）；筛选控件 0.8rem（iOS 聚焦触发自动放大）；弹窗 footer 的提示文字会把按钮挤出（`:634-666`）。
4. **RoadmapBoard.vue 无断点**：`grid-template-columns: repeat(auto-fill, minmax(210px,1fr))`（`:96-101`）在 375px 下 6 个状态列纵向堆叠成约 6 屏长列表，看板语义消失。

### 中

5. **FeedbackDetail.vue**：评论昵称输入框固定 220px（`:593-595`）、输入控件 0.875rem（`:580`）。
6. **FeedbackActivity.vue**：`.activity-label` 0.6875rem、`.activity-meta` 0.7rem（`:182,214`），11px 字号过小。
7. **HeroSection.vue**：装饰光斑 `.blur-circle` 宽高 20rem + `left:30%` 绝对定位（`:203-225`），无任何 overflow 裁剪 → 375px 下制造页面横向滚动。
8. **英文首页 VPHero 图片溢出**：`style.css:173-183` 对 `.VPHero .image` 做 `scale(2)`、≤768px 仍 `scale(1.5)`，320px 容器放大后超视口，image-container 无裁剪。
9. **FeedbackForm.vue**：已有 640px 断点处理两列/类型按钮（正面），但输入控件 0.875rem 仍有 iOS 缩放问题；附件删除按钮触控目标约 24px。
10. **VoteButton.vue**：触控高度约 34px（`:55-68`）。

### 确认无需处理（避免误改）

FeedbackPage.vue 已有 767/1024 断点且两列布局折单栏正确；CoolHome/FeaturesGrid/Testimonials/PricingSection/CtaSection/DocsShowcase/WelfareCard/SocialProof/CodeTabs 等首页组件均有断点或 max-width 收缩，无溢出风险；config.mts 文档页 nav 走 VPNavBar 自带移动端菜单；viewport meta 由 VitePress 默认注入，正常。`FeatureCards.vue` 是无样式死组件，不启用即不影响。

## 三、业界方案调研结论

- **VitePress 官方主题本身移动端完善**（960px 汉堡菜单、表格 block 滚动），问题全部出在自定义覆盖和自定义组件——修法是「恢复默认行为 + 补组件断点」，不引入任何适配库。
- **大厂通用断点约定**：Bootstrap/Ant Design/Element Plus 栅格均以 768px 作为 md/平板分界，本项目现有断点散布在 600~1280 共 8 种，本次统一以 **768px 为主断点**（新增断点一律 768，不重排存量断点，控制改动面）。
- **rem/vw 方案（postcss-px-to-viewport、amfe-flexible）适合 C 端营销页**，对以文档和组件为主的本站没有收益，不引入。
- **触控规范**：Apple HIG 建议 44×44pt 触控目标；iOS Safari 对 font-size<16px 的输入框聚焦会强制放大页面，表单控件统一提升到 16px。
- **装饰性绝对定位元素**：参照本项目 WelfareCard 的正确做法（`overflow:hidden` 裁剪），对首页 hero 加 `overflow-x: clip`。

|---|---|---|

| T5 | FeedbackPool：按视口初始化默认视图(<768 用 list)；搜索框移动端 flex:1；筛选/输入控件字号 ≥16px、触控高度提升；弹窗 footer 允许换行、hint 不挤按钮 | feedback/FeedbackPool.vue |

实现原则：只新增 @media 和必要的响应式属性，**不改桌面端现有视觉**；断点统一 max-width: 768px（NavHeader 沿用其已有的 767/min-768 体系）；不做浏览器自动化验证，用构建产物 grep + 桌面开发服务器抽查代替。

## 五、验证方案

1. `npm run build` 构建通过（--ignoreDeadLinks 脚本自带）。
2. dist 产物 grep 验证：新增断点样式进入产物（如 `.roadmap-board` 横滚类、NavHeader 汉堡类）。
3. 桌面端回归：PC 视口下首页/需求池/文档页样式与改前一致（改动全部在媒体查询内或为无视觉影响的防御性修复）。
4. 部署后线上抽查 pages.dev 部署 URL 的 CSS 产物。

## 六、风险

- style.css 表格修复影响全站文档页，需保留原有圆角/边框视觉（在 block 布局上验证观感）。
- NavHeader 汉堡菜单是新交互，注意与文档页 VPNavBar 的菜单视觉风格保持一致。
- RoadmapBoard 横滚看板需保证滚动条在移动端不占空间（touch 滚动原生支持）。
