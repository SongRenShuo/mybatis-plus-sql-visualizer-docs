## 一、背景与结论

用户反馈：首页导航栏「插件名称字体有点小」「右侧几个按钮布局太乱」。

实测后结论是：字号偏小属实但只是表层，右侧「乱」背后有三条硬缺陷，其中两条已经影响到功能：

1. **搜索按钮在 ≥960px 时被撑成 192×36 的空壳**，里面只有一个 18px 图标，空转面积 90.6%。这条规则本意是给文档页的「带文字搜索框」用的，却泄漏到了首页的图标变体上。
2. **768~1023px 整段顶栏从 64px 撑到 88px**：导航链接、语言标签、下载按钮全部折成两行，品牌名被裁成「SQL Visualize」。1024 下三组宽度和与内容宽完全相等（961/961），组间距为 0。
3. **顶栏变高把页内锚点顶到吸顶栏底下**：1024 下吸顶总高 132px（88+44），而 `--home-anchor-offset` 仍是 124px，跳转后区块标题压在章节条下方 8.3px。

所以这不是「调调字号间距」的活，需要先把盒模型和断点收拾干净，再谈品牌名的视觉层级。

## 三、问题清单

### P1 搜索按钮被撑成 192px 空壳（最影响观感，且是拥挤的元凶）

读数：≥960px 时 `.pf-trigger` 为 192×36，`children.length = 1`（只有 18×18 svg），图标中心距按钮左边 96px（正好居中），空转面积 90.6%。

成因：`PagefindSearch.vue:283-291` 的 `@media (min-width: 960px) { .pf-trigger { width: 192px } }` 与 `:263-272` 的 `.pf-trigger-icon { width: 2.25rem }` 同权重（各 1 个类选择器），媒体查询在源码中更靠后，因此胜出。而这条 192px 规则本来只服务非 compact 的文字搜索框（文档页 `index.ts:37` 用非 compact 变体），首页 `NavHeader.vue:147` 写死 `compact`，于是图标按钮也被撑开。

后果：960~1023px 区间这一项多占约 156px，直接把右侧组推到与导航链接贴死，进而触发 P2。

### P2 768~1023px 顶栏从 64px 涨到 88px，文字集体折行

读数：1024 下顶栏 88px、下载按钮 94.5×64（2 行）、三组宽和 961 = 内容宽 961（组间距 0）；768 下顶栏 88px、下载按钮 83.2×64、705 = 705。截图确认 1024 下「功能详解 / 使用指南 / 需求池 / 关于」「简体中文」「免费下载」全部折成两行，品牌名被裁成「SQL Visualize」（logo-area 实测 159.5px，小于自然宽 162.4px）。

成因：`.nav-links`、`.logo-area`、`.btn-primary` 均未声明 `flex-shrink: 0`，`.nav-link` 未声明 `white-space: nowrap`，三组在空间不足时被等比压缩。

后果：顶栏高度不再是常量，吸顶总高 132px 与 `--home-anchor-offset: 124px` 失配——1024 下跳转到 `#sec-tech` 后目标顶边在 123.7px，压在章节条（底边 132px）下方 8.3px。1280 下吸顶总高 108px，留白 16px，属正常。

### P3 右侧控件尺寸、形状、间距三套标准

读数（1280）：高度集合 `{20, 36, 40}`，宽度 `{106, 34, 20, 20, 192, 96}`，圆角集合 `{0, 8px, 9999px}`。

- 两个仓库图标是 20×20 的裸位图，可点区域 20×20，低于 WCAG 2.5.8 的 24×24 最小目标尺寸，且没有任何 hover / focus 视觉反馈（`NavHeader.vue` 全文无 `.nav-gitee:hover`）。
- 语言按钮与主题按钮同款（8px 圆角、36 高），搜索按钮却是全圆角、无边框的圆形，下载按钮是全圆角实心胶囊——四种形状并排。
- 间距 16/16/6/16/16：仓库图标对因 `margin-left: -0.625rem` 收成 6px，其余 16px，簇内簇外不分层。
- 仓库图标被夹在「主题切换」和「搜索」中间，把工具簇从中间切断，视觉上分成两团（1280 截图中 GitHub 图标与放大镜之间有明显空档，正是 P1 的 87px 内边距造成的）。

### P4 移动端品牌名消失、仓库图标重叠

读数：≤480px 时 `.logo-text` 为 `display: none`，`.logo-area` 宽 28px（只剩 logo）。390 下右侧组 298px 占视口 76.4%，logo 28 + 动作区 298 = 326，内容宽 327，余量 1px。两个仓库图标间距 −2px（`gap: 0.5rem` 与 `margin-left: -0.625rem` 相减），实测 Gitee 右边界 157、GitHub 左边界 155，重叠 2px，截图可见两图标相贴。

360 下下载按钮折成 2 行（71.2×60），顶栏涨到 84px。

### P5 品牌名同时「太小」和「太淡」

读数：18px/700，与正文同号（18px），为主标题的 37.5%；对比度浅色 3.72:1、暗色 2.36:1，均低于 4.5:1。窄屏 768 以下降到 16px，480 以下直接隐藏。

也就是说，用户说的「字体有点小」，实际是「字号落在正文层级 + 对比度不足」的叠加——单把字号调大会让偏淡的问题更明显（字越大越容易被看清明度不足），必须两条一起改。

### P6 语言标签是导航里最小的一级文字

读数：`.nav-lang-label` 13px，比导航链接（14px）还小 1px，而它承载的是「当前语言」这一状态信息，属于需要一眼读出的内容；下拉菜单项也是 13px（`NavHeader.vue:363`），与主菜单 14px 不成体系。

## 四、方案对比

### 方案 A：统一盒模型 + 修正宽度泄漏 + 移动端收纳（推荐）

三件事一起做：

1. 把搜索按钮的 192px 规则限定到非 compact 变体（`:not(.pf-trigger-icon)`），图标按钮回到 36×36。
2. 右侧动作区统一为「工具图标簇 + 主 CTA」两段式：语言、主题、Gitee、GitHub、搜索统一 36×36 / 8px 圆角 / hover 软底，簇内间距 4px，簇间 12px，CTA 前 16px；仓库位图保持 20×20 居中放进 36×36 容器（位图不缩，避免糊）。
3. 补齐 `flex-shrink: 0` 与 `white-space: nowrap`，让 768~1023 顶栏回到 64px；移动端把两个仓库入口收进全屏菜单，品牌名改为 ≥400px 显示 15px。

- 改动面：`PagefindSearch.vue` 一处媒体查询、`NavHeader.vue` 样式段（约 8 条规则）+ 模板两处（仓库链接搬进 `.mobile-menu`）。
- 预期读数（按现有盒子推算，非实测）：工具簇 5 项 = 语言 106 + 4 个 36px 方形 = 250，簇内 4 个 4px 间距共 16；簇与 CTA 间 12，CTA 96，合计约 378px。即 1280 下占 29.5%、1024 下占 36.9%；1024 下三组和约 159.5 + 273.1 + 378 ≈ 811 < 961，组间距恢复；顶栏 9 档全部为 64 / 60。
- 优点：一次性消掉 P1~P4 的根因；不引入新状态机；文档页搜索框行为不变。
- 缺点：视觉密度变化较大，需要重新过一遍三档截图。

### 方案 B：只做渐进收纳（不动搜索按钮）

保留 192px 搜索按钮，改为按优先级逐档收纳：≥1280 全展示；1024~1279 收起语言标签文字；768~1023 收起仓库图标进「更多」菜单；<768 走汉堡。

- 优点：不动 `PagefindSearch`，风险面小。
- 缺点：192px 空壳仍然存在（用户看到的那团空白还在），1024 档要靠额外状态补，断点维护成本高；仓库入口在中间档消失影响外链曝光。治标不治本。

### 方案 C：只调字号与间距

品牌名 18→22px，仓库图标 20→24px，gap 统一 12px，加 `nowrap`。

- 优点：改动最小。
- 缺点：解决不了 192px 空壳与 768~1023 的组间贴死（因为总宽仍超），也解决不了品牌名对比度。

### 结论

采用 **方案 A**。若实施中发现「仓库入口移入菜单」不可接受（见第七节待验证前提），则 A 的移动端部分退回为「<400px 隐藏品牌名」的现状，其余步骤照做——A 的前两步本身已经能消掉 P1/P2/P3。

## 七、风险与待验证前提

**待验证前提**

1. `.pf-trigger-icon` 的 36×36 只被 960 断点的 `width` 规则破坏（height 未受影响，实测 36）。已由 computed style 证实，但文档页非 compact 变体是否也吃到这条规则，需在 `/guide/getting-started` 实测一次后再改。
2. 把 Gitee / GitHub 移入全屏菜单会影响外链曝光。当前这两个链接没有埋点（只有下载按钮走 `trackDownload`），无法从数据侧评估损失；若产品上不接受，T5 的移动端部分退回为「<400 隐藏品牌名」。
3. 暗色品牌色改用 `--primary-light`（#4FC1FF）后与 logo 图形的蓝色是否协调，属主观项，实施后需截图确认一次。

**风险**

1. `--primary-color` 全站 80 处引用，任何「顺手改成实色」的做法都会波及全站链接与按钮配色。方案只新增导航专用变量，实施时需 grep 复核没有误改全局变量。
2. `NavHeader.vue` 的 `<style scoped>` 无法直接命中 `PagefindSearch` 内部节点。用 `:deep()` 可行但脆弱；给组件传 class 更干净，代价是改 `PagefindSearch.vue` 的 props（多一处生产文件改动）。
3. 顶栏从 88px 回到 64px 后，`--home-anchor-offset` 若被同步调小会反向多留空白。已核对 124 = 64 + 44 + 16，只需改注释，不动数值。
4. 视觉密度变化较大，可能引出新的窄屏临界值问题（例如 400~480 区间的品牌名宽度），T7 的 9 档读数就是为这个准备的。

**回滚**：T1 是单条选择器改动，T2~T5 集中在 `NavHeader.vue` 的样式段与两处模板，T6 是注释。全部可按步回滚，互不牵连。

## 八、横向参考（未实测，属行业惯例）

以下三条是开发者工具类站点导航的常见做法，**未对具体站点做实测**，仅用于说明方向，不照抄整站风格：

1. 左侧「logo + 品牌名」自成一组，品牌名通常 ≥20px 且为实色，不与导航链接混在同一字号档。
2. 右侧分成「工具图标簇 + 主 CTA」两段：图标按钮统一为 32~36px 方形、hover 软底；主 CTA 是唯一的实心胶囊，作为视觉终点。
3. 移动端顶栏只保留主题、搜索、CTA、菜单四个入口，语言与源码仓库这类低频入口收进全屏菜单。
