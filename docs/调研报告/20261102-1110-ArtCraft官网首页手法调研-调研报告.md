# ArtCraft 官网首页手法调研报告

> 调研对象：<https://getartcraft.com/>（ArtCraft，开源 Rust 桌面创作软件 + 生成式 AI 工作室）
> 调研目的：识别该页中可迁移到 SQL Visualizer 官网首页的视觉语言、信息架构与交互手法
> 调研时间：2026-11-02 11:10
> 取材方式：生产环境 HTML（176KB）与站点 CSS（68KB）下载后静态分析；当前官网生产 HTML（76KB）同法对照；两个仓库的源码（Vue 组件 / 数据文件）逐文件读取。下文所有读数均为当次实测，非文档转述。

## 一、调研范围与不涉及的边界

本报告只讨论页面在「视觉语言、信息架构、交互手法」三层的做法，以及这些做法对当前官网的适用性。不讨论 ArtCraft 的产品内容本身（应用矩阵、AI 模型清单、定价策略），也不建议引入与本产品无关的业务形态。

有一条判断贯穿全文：目标页是一张**面向大众创意用户**的产品展示页，当前官网是一张**面向开发者评估与安装**的工具页。前者可以用纯文字首屏、八个编号功能块和大量留白撑起节奏，因为它的用户不需要在首屏就判断「这东西在我的技术栈里能不能跑」；后者的用户恰恰相反，首屏必须在三秒内回答「我的 Wrapper 链 / XML / JPA 能不能预览」。因此本报告对目标页的做法逐项做了取舍，吸收结构性的、可复用的部分，明确排除与开发者决策无关的形态。取舍清单见第七节。

## 三、视觉语言

### 3.1 配色与主题

站点用两套 `theme-color` meta 跟随系统偏好：

```
<meta name="theme-color" content="#f2f1ee" media="(prefers-color-scheme: light)">
<meta name="theme-color" content="#0b0b0c" media="(prefers-color-scheme: dark)">
```

从 CSS 提取的语义色变量：

| 角色 | 亮色 | 暗色 | 用途 |
|------|------|------|------|
| 主背景 | `#faf9f7` | `#0b0b0c` 系 | 整页底 |
| 抬升面 | `#faf9f7` | `#101014` | 卡片 |
| 主强调 | `#2d81ff` | `#74aaff` | 链接、标记点、CTA |
| 应用强调 | 20+ 个 `--app` / `--app-ink` 字面量 | 同 | 15 个应用各一色 |
| 分隔线 | `--line` / `--line-strong` | 同 | 发丝网格 |

两点值得注意。

第一，它的强调色是**蓝**（`#2d81ff`），而当前官网强调色也是蓝（`#2e6ae0d6`）。两者不是竞品撞色，而是同一类工具产品的合理选择，这反过来说明当前官网的配色不需要改。

第二，它把「应用矩阵」的 15 个色值散在 CSS 里做成 `--app` / `--app-ink` 变量（实测提取到 20 余个不同字面量），这是**多产品页**的专属需求。SQL Visualizer 是单一产品，引入这套多色系统没有承载对象。

### 3.2 字体系统

这是目标页最值得吸收的部分。它用**三字体分层**：

```css
--font-archivo: "Archivo", "Archivo Fallback";      /* 展示：标题、巨型字标 */
--font-instrument: "Instrument Serif", ...;          /* 衬线：标题内的强调词 */
--font-inter: "Inter", "Inter Fallback";             /* 正文 */
--font-mono: var(--font-geist-mono), ui-monospace;   /* 代码、数字、标签 */
```

关键手法是**标题内的衬线斜体强调词**。实测源码：

```html
<h2 class="... font-display text-4xl font-medium leading-[1.02] tracking-[-0.035em] text-ink-strong sm:text-5xl md:text-6xl">
  The control that mere <span class="font-serif italic font-normal">words</span> cannot buy.
</h2>
```

同一个手法在四个标题上重复使用：

| 位置 | 标题 | 强调词 |
|------|------|--------|
| 03 功能 | The control that mere *words* cannot buy. | `words` |
| 04 所有权 | Stop *renting* from websites. | `renting` |
| 05 证明 | Made with *ArtCraft*. | `ArtCraft` |
| 结尾 | Start *crafting*. | `crafting` |

它的作用是把一个普通陈述句变成一个有节奏的口号——无衬线负责力量感，衬线斜体负责停顿和语调。成本极低（一个 `<span>` + 一条 CSS），收益是标题立刻不像模板。

字体是**自托管**的，实测 CSS 中有 6 条 `@font-face`，全部指向 `/_next/static/media/*.woff2`，并配了本地回退字体与度量覆盖：

```css
@font-face{font-family:Archivo Fallback;src:local(Arial);
  ascent-override:88.96%;descent-override:21.28%;line-gap-override:0.0%;size-adjust:98.7%}
```

`font-display: swap` + 首屏 `<link rel="preload">` 预载 5 个 woff2（实测单个文件 30~60KB 量级）。中文站点不能照搬 Archivo（不含中文字形），但**分层思路**可以：中文标题保持系统黑体，只在英文词、数字、版本号上用等宽或衬线强调。

### 3.3 排版密度

标题排版参数（从 class 直读）：

| 元素 | 字号 | 行高 | 字距 | 字重 |
|------|------|------|------|------|
| 区块标题 | `text-4xl` → `sm:text-5xl` → `md:text-6xl` | `1.02` | `-0.035em` | `font-medium` |
| 卡片标题 | `text-2xl` | — | `-0.02em` | `font-medium` |
| 正文 | `text-lg` | `leading-relaxed` | — | 常规 |
| HUD 标签 | `text-[11px]` | — | `0.12em` | `font-bold` + 全大写 |

值得注意的是**标题用 `font-medium`（500）而不是 bold**，配合 `-0.035em` 的紧字距和 `1.02` 的行高。这产生一种「大而不笨」的观感。当前官网标题走的是 `font-weight: bold` + `line-height: 1.2`，字距默认 0。

HUD 标签是另一个可吸收的样式：`text-[11px] + font-bold + uppercase + tracking-[0.12em]`，用于区块编号条、列表项、页脚链接。它把「辅助信息」统一压成一个可识别的视觉层级，和正文拉开距离。当前官网的 `section-eyebrow`（`Quick Start` / `Core Capabilities` 等）已经承担同样职责，但样式更接近普通小字。

### 3.4 分隔机制：发丝网格

目标页大量使用** 1px 发丝线**，实测 `border-line` 出现 78 次、`bg-line` 出现 24 次。核心手法是「用背景色画线」：

```html
<div class="grid gap-px border-t border-line bg-line md:grid-cols-2">
  <article class="bg-bg">…</article>
  <article class="bg-bg">…</article>
</div>
```

`gap-px` + 父容器 `bg-line` + 子项 `bg-bg`，就得到一张 1px 分隔的卡片网格。优点是分隔线随网格自动均分，永远不用手调边框，且天然响应式（`md:grid-cols-2` 换列时线条自动重排）。

另有 24 个 `.tick` 元素，是 11×11px 的十字准星标记，绝对定位在分隔线交点：

```css
.tick{pointer-events:none;width:11px;height:11px;position:absolute}
.tick:before,.tick:after{content:"";background:var(--line-strong);position:absolute}
.tick:before{width:1px;top:0;bottom:0;left:5px}
.tick:after{height:1px;top:5px;left:0;right:0}
```

这是纯装饰（`pointer-events:none` + `aria-hidden`），作用是给发丝网格的交点一个「工程图」的暗示。当前官网有 9 处 `border: 1px solid var(--border-color)` + 4 处 `border-top`，是常规做法，没有网格均分能力。

### 3.5 滚动与动效

目标页的动效规模实测：

| 机制 | 计数 | 说明 |
|------|------|------|
| `data-reveal` | 102 | 逐元素进入视口揭示 |
| `data-reveal-group` | 12 | 分组揭示 |
| `data-draw-rule` | 12 | 分隔线绘制动画 |
| `data-draw-tick` | 24 | 准星标记绘制 |
| `data-draw-eyebrow` | 10 | 吸顶眉题条 |
| `data-choreo` | 6 | 区块级编排 |
| `hover:` 类 | 220 | 悬停态 |
| `transition-*` 类 | 84 | 过渡 |
| `@keyframes` | 2 | 只有 `marquee-scroll` 和 `spin` |

这里有个反直觉的读数：**动效相关的数据属性有 176 处，但 keyframes 只有 2 个**。它没有卷轴视差、没有粒子、没有 3D 变换。102 个 `data-reveal` 做的都是同一件事——淡入 + 位移，靠 `transition` 而非 `animation` 实现。24 个 `data-draw-tick` 和 12 个 `data-draw-rule` 是「装饰线随滚动画出」，也是过渡。

两个关键细节：

**一是 `prefers-reduced-motion` 全站生效**，写在 CSS 里而非 JS 里：

```css
@media (prefers-reduced-motion:reduce){
  *,:before,:after{scroll-behavior:auto!important;
    transition-duration:.01ms!important;
    animation-duration:.01ms!important;
    animation-iteration-count:1!important}
}
```

一条规则覆盖全站，不依赖每个组件自己记得处理。

**二是吸顶眉题条**。10 个区块中 5 个带 `data-draw-eyebrow`，结构是 `sticky top-12 z-30 border-y border-line bg-bg/60 backdrop-blur-md`，内容为「编号 / 区块名」+ 右侧一句补充说明（如 `Real footage — captured in ArtCraft`）。滚动到该区块时标题条吸附在顶栏下方，随区块滚动进出。实测 SSR HTML 里就带 `sticky` class，说明吸顶是纯 CSS 行为，JS 只负责装饰线的绘制进度。

当前官网的 `SectionNav` 是一条**常驻横向章节导航**（9 个锚点，阈值线法高亮），形态不同但解决的问题相同。目标页的做法更轻——不需要常驻导航，滚动到哪里就显示哪里的名字。

### 3.6 媒体策略

目标页的 7 段功能演示视频全部是：

```html
<video src="/videos/features/WorldLabs_Demo_2.webm"
       class="absolute inset-0 h-full w-full object-cover"
       muted loop playsInline preload="none" aria-label="Image to Location demo"></video>
```

四个特征：**静音 + 循环 + `preload="none"` + `aria-label`**。`preload="none"` 意味着首屏完全不加载视频，7 段视频只在进入视口时才由浏览器自行拉取。配合 `muted` 自动播放（隐式），这是一套「看起来像自动播放的幻灯片，实际零首屏成本」的做法。

3 个社区影片没有内嵌播放器，用的是 YouTube 缩略图（`https://i.ytimg.com/vi/<id>/hqdefault.jpg`）+ 一个 `Play` 按钮。这是**延迟加载第三方iframe** 的标准做法——不用 YouTube 的 `iframe`，避免第三方脚本拖慢首屏。

当前官网的首屏零媒体（`HeroSection.vue` 中无 `img` / `video` / gif），这一点反而比目标页更保守。

### 3.7 可访问性

实测 25 个 `aria-label`，覆盖了图标按钮和装饰媒体：

```
aria-label="Switch to dark theme"
aria-label="Join the ArtCraft Discord"
aria-label="Play video: Made with ArtCraft #1"
aria-label="Image to Location demo"     ← 7 段视频各一条
aria-label="Community"
```

另有 `aria-hidden="true"` 大量用于装饰元素（准星、分隔线、巨型字标的逐字母 span）。当前官网也有类似处理，但在**视频/动图类媒体**上缺 `aria-label`——GIF 是纯装饰图，视频则需要注意。

### 3.8 信息架构

目标页的 7 个区块形成一条明确的叙事弧：

```
产品矩阵（我们有什么）
  → 旗舰产品（重点是什么）
  → 功能详解（为什么强）
  → 所有权（为什么免费且永久）
  → 社区证明（别人用了做出什么）
  → 双产品线对比（选哪个）
```

它把「免费开源」放在**倒数第三**位（04 所有权），而不是开头。这个顺序值得注意：先让用户相信产品强，再告诉他们不收费。当前官网的顺序是：

```
首屏 → 快速上手 → 技术栈 → 核心能力 → 预览能力 → 更多特性
     → 开源免费 → 数据事实 → 免费下载 → 最近更新 → CTA
```

「开源免费」在第 7 位，位置接近，但**「数据事实」放在「免费下载」之前**，这是当前官网的一个差异点——目标页把「社区证明」放在倒数第二，当前官网把它放在中间。

### 3.9 首屏信息密度

目标页首屏（8413 字节）包含：

- 一个纯文字的巨型字标（逐字母 `<span>`，用于排版控制）
- 两行标题 `Capable tools` / `for artists.`
- 一句副标题（27 词）
- 两个 CTA + 一个「其他架构下载」链接
- 一个「在找 ArtCraft Studio？」的跨产品引导
- GitHub 链接 + 平台清单 + `No subscription required`

**没有截图、没有演示、没有代码块、没有数据。** 它赌的是「文字足够有说服力」。

当前官网首屏是一个**代码对照块**（Java Wrapper 链 ↔ 实时生成的 SQL），加三个统计数据（版本 / IDEA 支持 / 开源协议）。这是完全相反的策略：目标页卖「理念」，当前官网卖「这东西真的能用」。

对开发者工具而言，当前官网的策略更合理——但目标页首屏的**信息分层**值得学：它把「主要 CTA / 次要 CTA / 跨产品引导 / 平台清单 / 信任标签」五级信息在一个首屏内排完，且每级视觉权重清晰。当前官网首屏的三级信息（CTA / 亮点标签 / 统计数据）相对扁平。

值得记下的两处既有优点：

1. **`prefers-reduced-motion` 已是全局 CSS 规则**（`style.css:945`），与目标页做法一致，不需要补。
2. **`SectionNav` 的阈值线法**比目标页的吸顶眉题条重得多，但解决的是同一问题。当前实现已经在源码里记录了「缓存偏移会失准，改为每帧读矩形」的教训，说明这条路已经踩过坑并收敛。

## 五、可吸收项（按价值排序）

### 5.1 标题内的强调词样式（P0，成本极低）

**做法**：在区块标题里选一个关键词，用衬线斜体或等宽字体 + 主强调色渲染，其余保持无衬线。

**为什么值得吸收**：当前官网 11 个区块标题全部是纯无衬线，且多数是「名词 + 形容词」结构（`大幅提升您的 SQL 调试效率`、`我们为您考虑周全`），读起来像一个模板。目标页用**同一个 `<span>` 手法**把四个标题变成了有节奏的口号，实测每处成本一行 HTML。

**适配注意**：中文没有斜体字形（浏览器会合成倾斜，观感差），所以中文侧应改用**颜色 + 字重**而非斜体。英文侧可以用衬线斜体（目标页手法原样）。

**候选位置**（当前文案，需用户定夺）：

| 区块 | 现标题 | 建议强调词 |
|------|--------|-----------|
| 核心能力 | 大幅提升您的 SQL 调试效率 | `SQL` 或 `效率` |
| 更多特性 | 我们为您考虑周全 | `周全` |
| 数据事实 | 不靠形容词，靠可核验的数字 | `可核验` |
| CTA | 准备好告别繁琐的SQL 调试方式了吗？ | `告别` |

### 5.2 HUD 标签样式统一（P1）

**做法**：把 `section-eyebrow`（`Quick Start` / `Core Capabilities` / `Live Preview` 等）从普通小字改为 `11px + 全大写 + 字距 0.12em + 主强调色`，与区块编号、页脚链接统一成一个视觉层级。

**为什么值得吸收**：目标页用这一套把「辅助信息」从正文里彻底分离出来，用户能一眼认出「这是标签不是内容」。当前官网的 `section-eyebrow` 已经承担同样职责，但视觉上与正文拉不开。

**成本**：改 `style.css` 中 `.section-eyebrow` 一处，全区块生效。

### 5.3 发丝网格分隔（P1）

**做法**：`gap-px + 父容器 bg-line + 子项 bg-bg` 得到 1px 均分网格。

**为什么值得吸收**：当前官网 8 张功能卡（`FeaturesGrid`）和 8 个能力块（`FeatureAlternate`）用的是卡片边框 + 间距，换列时需要手调。网格均分在响应式换列时自动重排，且能省掉卡片的 4 条边框。

**成本**：中。需要改 `FeaturesGrid.vue` / `FeatureAlternate.vue` 的容器与卡片样式，且要重新验证暗色模式下的 `--line` 色值。

### 5.4 标题字重与字距调整（P2）

**做法**：区块标题从 `bold` + `line-height: 1.2` 改为 `font-weight: 500~600` + `line-height: 1.1` + `letter-spacing: -0.02em`。

**为什么值得吸收**：目标页用 `font-medium` + `-0.035em` 做出「大而不笨」的观感。当前官网标题偏传统。

**成本**：低，但**风险高于收益**——中文黑体在紧字距下容易显得拥挤，且这会影响全站标题。建议只做英文侧或先做 A/B 对比。

### 5.5 视频/媒体懒加载策略（P2）

**做法**：`preload="none"` + `muted` + `loop` + `playsInline` + `aria-label`。

**为什么值得吸收**：当前官网首屏零媒体，暂时没有性能压力。但功能详解页有 9 张 GIF（每张 200KB~1MB 量级），若未来换成视频，这套策略可以直接用。

**成本**：低，但当前无承载对象，**建议只记录不实施**。

### 5.6 首屏信息分层（P2，需用户定夺）

**做法**：目标页首屏把信息分五级——主 CTA / 次 CTA / 跨产品引导 / 平台清单 / 信任标签，每级视觉权重清晰。

**为什么可能值得吸收**：当前官网首屏有三级信息（CTA 组 / 亮点标签 / 统计数据），相对扁平。

**为什么不直接推荐**：目标页首屏零媒体，靠文字层级就能撑起；当前官网首屏右侧是一个代码对照块，本身已经承担了「证明这东西能用」的职责。再往里加层级会挤压代码块。**这是一个产品决策，不是纯样式改动**，需用户判断。

## 六、明确排除项

以下内容在目标页中存在，但**不建议引入**当前官网。

### 6.1 纯文字巨型首屏

目标页首屏 8413 字节零媒体，靠一个逐字母排版的文字标和两行标题撑满一屏。这是**消费级创意产品**的策略——它的用户不需要在首屏验证技术可行性。

SQL Visualizer 的用户打开首页时，脑子里的问题是「我的 `LambdaQueryWrapper` 能不能预览」。当前官网首屏的代码对照块（Java 链 ↔ 生成的 SQL）直接回答了这个问题，这是**比目标页更强**的策略。改成纯文字会丢掉最有说服力的证据。

### 6.2 双产品线对比区块

目标页结尾 `start` 区块把 Crafting Apps 和 ArtCraft Studio 并排对比，因为它有两个形态不同的产品线。SQL Visualizer 是单一产品，没有对比对象。

### 6.3 社区影片墙

目标页 `made-with` 区块放 3 个社区影片（YouTube 缩略图 + 播放按钮），因为它有 UGC 内容。当前官网的对应位置是「数据事实」（690 次安装 / 18 个版本 / 14 种方言），这三条数字对开发者的说服力高于影片——**当前官网的做法更合适**。

### 6.4 15 色应用矩阵

目标页用 20+ 个 `--app` 色值给 15 个应用各配一色。单一产品没有承载对象。

### 6.5 装饰性准星标记

24 个 11×11px 的 `.tick` 十字标记（`pointer-events:none` + `aria-hidden`）是纯装饰。这与当前项目已有的「去 AI 味」「不做无谓装饰」的取向冲突（见 `20261029-1129-首页CTA装饰图标去除与全站Emoji审查-开发计划.md`），不纳入。

### 6.6 吸顶眉题条替换 SectionNav

目标页的 `sticky` 眉题条更轻，但当前官网的 `SectionNav` 已经实现且有 9 个锚点可点击跳转——**目标页的眉题条不可点击**（实测无 `href` / 无点击行为），只起提示作用。两者不是替代关系，且当前实现已在源码中记录了踩坑教训（缓存偏移失准）。**保持现状**。

### 6.7 全站换字体

目标页的 Archivo / Instrument Serif / Inter 都不含中文字形，中文站点引入会导致回退到系统字体，实际收益仅限英文词。且自定义字体需要新增 3~5 个 woff2 文件（实测单个 30~60KB），对首屏是负担。**只记录分层思路，不实施**。

## 八、待验证前提

本报告在下述判断上属于**推断**，实施前应先证伪：

1. **中文侧「颜色 + 字重」能否替代斜体**。判断依据是中文无斜体字形，但未实测「主强调色 + 加粗」在中文标题里的实际观感。实施时应在亮暗两种模式下各做一次真机对比。
2. **发丝网格在暗色模式下的 `--line` 色值**。目标页暗色底是 `#0b0b0c`，当前官网暗色底是 `#2b2d30`，线色需要重新取，不能照搬。
3. **标题字重 500 在中文黑体上的可读性**。目标页用 `font-medium` 是因为 Archivo 的字重分布，中文系统黑体（微软雅黑 / PingFang）的 500 与 400 差异可能不明显。
4. **`FeaturesGrid` / `FeatureAlternate` 改网格后是否破坏现有 GIF 布局**。这两个区块当前有配图，改容器结构需要逐卡验证。
