# 需求池：提交弹窗按钮同行 + 顶部栏恢复 + 详情页样式优化 开发计划

- 立项时间：2026-09-04 10:29
- 实施状态：待排期
- 涉及项目：mybatis-plus-sql-visualizer-docs（公开站点，反馈池前端）
- 目标：修复提交反馈弹窗的按钮布局与嵌套、恢复需求池页的站点顶部栏、统一需求详情页视觉风格。

---

## 一、背景

需求反馈池（含提交弹窗、看板、详情）上线后，用户反馈三处体验问题：

1. **提交弹窗动作按钮错乱**：表单里有一个通栏的「提交反馈」按钮，弹窗底部另有一个「取消」按钮，看起来按钮分了两层、且表单像是多套了一层盒子。
2. **需求池页顶部栏消失**：点顶部「需求池」tab 进入 `/about/feedback` 后，整个站点的顶部导航不见了，页面孤零零一屏幕。
3. **需求详情页样式不协调**：点击某条反馈进入详情后，头部、附件、状态时间线、评论等区块样式五花八门，与全站风格不统一。

本次针对这三个问题形成开发计划。

---

## 二、现状诊断

### 2.1 问题一：提交按钮与取消不在同一行、多余盒子

结构现状（前端 `FeedbackPool.vue` + `FeedbackForm.vue`）：

- `FeedbackForm.vue` 是一个完整的表单组件，内部自带一个通栏 `.submit-btn`（`提交反馈`，disabled 跟随 `isValid`/`submitting`），并用自己的 `.feedback-form` 容器（带背景、边框、圆角、内边距）。
- `FeedbackPool.vue` 用 `.modal-dialog` 弹窗承载 `FeedbackForm`，弹窗底部另有 `.modal-footer`，里面只有「取消」按钮。

结果：弹窗里先是一个「盒子中的盒子」（`.feedback-form` 的 box 嵌在弹窗里），末尾是通栏「提交反馈」，下面又是一行「取消」。主操作按钮与取消按钮被拆到两处，视觉上多套了一个层级，也不符合「主/次操作同一行、右对齐」的常规弹窗规范。

### 2.2 问题二：需求池页顶部栏消失

- 站点其它 tab 页（首页、功能详解、使用指南、关于）都走 VitePress 默认 doc 布局，顶部有全局导航栏。
- 只有 `about/feedback.md` 用了 `layout: false`，把它渲染成不带任何主题布局的自定义整页（为了跑 `FeedbackPage`），所以进入该页时 VitePress 顶部导航栏整体消失。
- 需要让它和其它 tab 页一致，保留站点顶部栏（里面含「需求池」tab 本身）。

### 2.3 问题三：详情页样式不协调

`FeedbackDetail.vue` 目前各区块各自为战：

- 头部（标题 + 状态徽章 + 元信息）是平铺文字，没有卡片层次。
- 附件列表、状态时间线、评论列表、评论表单的边框/圆角/间距比例不统一（有的用 `--vp-c-border` 1px 边框，有的带背景，有的裸文本）。
- 操作按钮（投票）、评论提交按钮与站点其它组件的按钮风格不一致。
- 整体缺乏统一的卡片分组与 8px 间距网格，移动端适配也不理想。

需要统一到与「看板、提交表单、RoadmapBoard」一致的卡片化风格。

---

## 三、方案设计

### 3.1 提交弹窗：主/次按钮同一行 + 去掉嵌套盒子

**交互目标**：弹窗底部只有一行操作，右侧右对齐放「取消 + 提交反馈」，表单区不再带自己的外框背景。

**实现（前端，docs 项目）**

- `FeedbackForm.vue`：
  - 从组件内部**移除通栏的 `.submit-btn`**（不再自带提交按钮）。
  - 向父级暴露提交能力：用 `defineExpose({ submit, canSubmit })`，其中 `canSubmit` 是响应式的 `isValid && !submitting`（`submitting`、`isValid` 本就有），`submit()` 是现有的 `handleSubmit()`。
  - 新增 `embedded?: boolean` prop：为 true 时把 `.feedback-form` 去盒（透明背景、去边框圆角、压缩内边距），适配弹窗内嵌场景。
- `FeedbackPool.vue` 弹窗：
  - 用 `ref` 拿到表单实例（`<FeedbackForm ref="formRef" ... embedded />`）。
  - `.modal-footer` 改为一行右对齐：「取消」+「提交反馈」；`提交反馈` 的 `disabled` 绑定 `!formRef?.canSubmit`，点击调用 `formRef.submit()`。
  - 保留 Esc / 遮罩 / × 关闭；提交成功仍走表单 `done` → 关闭。
- 效果：弹窗底部一排【取消 | 提交反馈】，表单区无多余盒子，与主流弹窗一致。

### 3.2 需求池页恢复站点顶部栏

**根因**：`about/feedback.md` 的 `layout: false` 去掉了整个主题布局（含顶部导航栏）。

**实现（前端，docs 项目，二选一）**

- **方案 A（推荐，与其它 tab 一致）**：去掉 `layout: false`，让 `about/feedback.md` 走 VitePress 默认 doc 布局；页面里仍渲染 `FeedbackPage`。顶部导航栏（含「需求池」tab）随之恢复。
  - 为让反馈池占满又不被文档侧边栏挤坏：页面 frontmatter 加 `sidebar: false`（隐藏「关于」侧边栏），内容区用 `layout` 默认排版即可。
  - 复核 `FeedbackPage` 在默认布局下内容宽度（VitePress 内容容器约 70rem）是否突兀，必要时给 `.feedback-page` 设 `max-width` 与默认内容一致或适度放宽。
- 方案 B（不引入默认布局）：保留 `layout: false`，但在该页自定义排版里复刻一个顶部栏（复用 `NavHeader` 或调 `useData` 注入 VitePress 导航）。工作量更大、且容易与默认导航不一致，不推荐。

选 A：一行改动即可把顶部栏找回来，且与其它 tab 导航完全一致。

### 3.3 需求详情页样式统一优化

**目标**：详情页与「看板 / 提交表单 / 列表」视觉一致——统一卡片、间距、按钮、状态色。

**实现（前端，docs 项目 `FeedbackDetail.vue`）**

- 采用统一的卡片化 sections：每个区块（详情、附件、状态时间线、评论）用同一套 `.card` 容器（`--vp-c-bg-soft` 背景 + `--vp-c-border` 边框 + 圆角 12px + 内边距），区块标题统一字号/字重。
- 头部：标题 + 状态徽章（`StatusBadge`）+ 类型/分类 + 时间，信息分组清晰；类型用与看板一致的标签样式。
- 附件：图片缩略图（4rem 圆角）+ 文件名 + 大小，与提交弹窗里的附件列表样式统一成一套.
- 状态时间线：沿用时间轴但统一配色（圆点按状态色取 `statusColor`，而不是一律品牌色），行高与卡片一致。
- 评论：评论区复用评论区卡片；输入框与提交表单 input/textarea 同一套边框/圆角/聚焦样式；「发表评论」用站点主色按钮。
- 8px 间距网格（4/8/16/24/32）统一各 section 间距，补齐移动端单列布局。
- 复用 `i18n.ts` 已有文案，不新增硬编码英文。

样式上对照 `FeedbackForm.vue` / `RoadmapBoard.vue`，抽出可复用的间距、卡片、按钮、标签 token，避免三处各写一套。

## 四、任务拆分

优先级：P0 本次必须做。

### T1 提交弹窗按钮同一行 + 去盒（P0）
- `FeedbackForm.vue`：移除内部 `.submit-btn`，`embedded` prop 去盒样式，`defineExpose({ submit, canSubmit })`。
- `FeedbackPool.vue`：`formRef` 拿到表单，`.modal-footer` 渲染「取消 + 提交反馈」一行，提交按钮 `disabled`/点击绑定表单能力。
- 验收：弹窗底部一行右对齐【取消 | 提交反馈】；表单区无多余盒子；提交/校验/成功闭环正常。

### T2 恢复需求池页顶部栏（P0）
- `about/feedback.md` 去掉 `layout: false`，加 `sidebar: false`；`FeedbackPage` 照常渲染。
- 视情调整 `.feedback-page` 宽度以适配默认布局。
- 验收：进入需求池页时站点顶部导航栏在，点「需求池」tab 高亮可达。

### T3 详情页样式统一优化（P0）
- `FeedbackDetail.vue` 重构为统一卡片 sections；头部、附件、时间线、评论样式对齐全站；状态色统一；移动端适配。
- 验收：详情页各区块卡片风格一致，视觉与看板/提交弹窗协调。

## 五、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 去掉 `layout:false` 后 FeedbackPage 与默认布局冲突（宽度/侧边栏） | 中 | 低-中 | 加 `sidebar:false` + 复核 `.feedback-page` 宽度，小步验证 |
| Submit 逻辑从表单移到 footer 时机/校验回归 | 中 | 中 | `canSubmit` 与 `submit()` 统一由表单暴露，seed 数据联调 |
| 详情页大改影响现有功能 | 低 | 低 | 仅样式，逻辑不动，逐区块验证 |
