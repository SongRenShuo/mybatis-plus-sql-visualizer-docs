# 文档页更新时间显示-开发计划

> 日期：2026-10-29 12:15
> 状态：计划待实施（本轮只出计划，未改配置、未构建、未部署）
> 范围：文档站所有使用默认文档布局（VPDoc）的页面；首页与 `layout: page` 页不在范围

## 一、需求与现状

用户希望每篇文档能显示自己的更新时间，位置在文档上方或下方都可以。

现状是"文案配了、开关没开"：

- `.vitepress/config.mts` 的 zh/en 两套 `themeConfig` 里都已经有 `lastUpdated: { text: '最后更新于' }` 与 `{ text: 'Last updated' }`（约 :211 / :283）。
- 但站点根配置**没有** `lastUpdated: true`。VitePress 只有在根级开启时才在构建期为每页取 git 时间。
- 产物印证：`.vitepress/dist/guide/getting-started.html` 里能 grep 到"最后更新于"，但那是序列化进页面的主题配置字符串，不是渲染节点，页面里没有 `<time>`、也没有 `.VPLastUpdated`；`sitemap.xml` 里同样没有 `<lastmod>`。

VitePress 1.6.4 源码事实（`node_modules/vitepress/dist/node/chunk-D3CUZ4fa.js`）：

- 只有 `includeLastUpdatedData && frontmatter.lastUpdated !== false` 成立时，才执行 `pageData.lastUpdated = getGitTimestamp(fileOrig)`；frontmatter 写 `lastUpdated: false` 可以单页关闭，写日期则直接用该日期。
- `getGitTimestamp` 的实现是 `git log -1 --pretty="%ai" <文件名>`，工作目录设为该文件所在目录，并按文件路径缓存。拿不到时返回 0 或 NaN，模板里按假值处理、不显示。
- 默认主题的 `VPDocFooter` 在 `page.lastUpdated` 为真时渲染 `VPDocFooterLastUpdated`，位置在 `.edit-info` 里，也就是**正文之下、上一篇/下一篇之上**。
- 该组件把可读文本放在 `onMounted` 里生成（SSR 只输出 `<time datetime="ISO 时间">`，文本为空），默认 `formatOptions` 是 `{ dateStyle: 'short', timeStyle: 'short' }`，支持 `forceLocale` 与任意 `Intl.DateTimeFormat` 选项（含 `timeZone`）。
- `generateSitemap` 在根级 `lastUpdated` 为真时**自动**给每个 URL 生成 `<lastmod>`，同样尊重 frontmatter 的关闭标记。

实测 git 时间可用：`guide/getting-started.md` 最后提交 2026-10-27 17:23:44 +0800，`features/wrapper-preview.md` 为 2026-10-27 07:28:48 +0800。

## 二、方案

### 方案 A（推荐）：开启内置能力，显示在正文下方

改动只有配置，不加组件：

1. `.vitepress/config.mts` 根级加 `lastUpdated: true`（放在 `cleanUrls` 附近即可）。
2. zh/en 两处的 `lastUpdated` 补格式选项：

```ts
// root（zh）
lastUpdated: {
  text: '最后更新于',
  formatOptions: {
    year: 'numeric',
    month: '2-digit',
    day: '2-digit',
    timeZone: 'Asia/Shanghai',
    forceLocale: true
  }
}
// en
lastUpdated: {
  text: 'Last updated',
  formatOptions: { year: 'numeric', month: '2-digit', day: '2-digit', timeZone: 'Asia/Shanghai', forceLocale: true }
}
```

选择理由：

- 位置就是用户说的"下方"，且在所有文档页一致；有 sidebar、有 outline 的页面用的是同一个页脚。
- 只到"天"：更新时间用于判断文档新旧，时分是噪音，还容易让访客困惑时区。
- `timeZone: 'Asia/Shanghai'` 固定按北京时间出日期，避免海外访客看到跨日。
- `forceLocale: true` 让中文页用中文格式（2026/10/27）、英文页用英文格式（10/27/2026），不随访客浏览器语言跳。
- 顺带把 sitemap 的 `<lastmod>` 补上，对搜索引擎是纯收益，不需要另写脚本。

已知观感问题：内置模板固定输出 `{{ text }}: <time>`，中文会呈现"最后更新于: 2026/10/27"，冒号是半角。要全角冒号或 `2026-10-27` 这种 ISO 写法，得走方案 B。

### 方案 B（备选）：标题上方自定义一行

只有用户明确要求"放上方"或"要全角冒号/ISO 日期"时才做：

1. 仍然开启根级 `lastUpdated: true`（页面数据与 sitemap 都依赖它）。
2. 新增 `.vitepress/theme/components/DocUpdated.vue`，读 `useData().page.lastUpdated`，用固定的 `Intl.DateTimeFormat('zh-CN', { timeZone: 'Asia/Shanghai', ... })` 在 SSR 阶段就算出文本，保证服务端与客户端一致、不产生 hydration 失配；无时间时返回空节点。
3. 在 `theme/index.ts` 的 `Layout` 里挂到 `doc-before` 槽。注意该槽位于 `<main>` 之前，视觉上在 H1 **之上**；若必须落在标题下方，需改用 markdown 插件在第一个 h1 后插节点，复杂度明显上升，不建议为一行日期引入。
4. 因为内置页脚仍会渲染同一份数据，需要同时用 CSS 隐藏 `.VPDocFooter .last-updated`，否则会出现两处。这是方案 B 的主要代价。

### 不做

- 不在每篇 md 里手写日期或 frontmatter `lastUpdated`，维护成本高且容易忘。
- 不给首页（`layout: false`）和需求池 / Bug 悬赏（`layout: page`）加时间，它们没有文档页脚。
- 不引入"预计阅读时间"等其他元信息，本次只解决更新时间。

## 三、边界与例外

- **首页**：`index.md` / `en/index.md` 是 `layout: false` 的自定义首页，没有文档页脚，不会显示。
- **`layout: page` 页面**：`about/feedback.md`、`about/bounty.md`、`en/about/feedback.md`、`en/about/bounty.md` 走自定义页面布局，不会显示。若以后要显示，需要各自加组件。
- **新文件**：尚未提交的 md 拿不到 git 时间，页面暂时不显示；首次提交后的下一次构建才出现。
- **时间语义**：取的是最后一次**提交**时间，不是工作区修改时间。改完不提交不会变。
- **重命名**：`git log` 未加 `--follow`，改名后的文件时间会变成改名那次提交的时间。
- **自动生成页**：`about/changelog.md` 由 `scripts/update-changelog.mjs` 生成，时间等于生成脚本那次提交。
- **内部文档**：`docs/**` 也会构建上线并显示时间。若认为内部计划文档不该露时间，可在 `transformPageData` 里对 `relativePath.startsWith('docs/')` 清空 `lastUpdated`；默认不做。
- **中英不同步**：中英文是两份独立文件，时间各自独立，可能出现英文页比中文页旧的情况，属正常。

## 四、实施步骤

1. 改 `.vitepress/config.mts`：根级加 `lastUpdated: true`；两处 `themeConfig.lastUpdated` 补 `formatOptions`。
2. `npm run build`，逐项核对产物：
   - `dist/guide/getting-started.html` 出现 `class="VPLastUpdated"` 与 `<time datetime="...">`，其 ISO 值换算成北京时间应与 `git log -1 --pretty="%ai" guide/getting-started.md` 一致；
   - `dist/sitemap.xml` 出现 `<lastmod>`，抽查两条与 git 时间一致；
   - `dist/en/guide/getting-started.html` 文案为 `Last updated`；
   - `dist/about/feedback.html` 与 `dist/index.html` 不含 `VPLastUpdated`；
   - `dist/docs/` 下任意一篇有该节点（按默认不排除）。
3. 记录构建耗时变化：开启后每页会多一次 `git log` 调用（按文件缓存，共约 161 次）。预估增加数秒，实测后回填本计划。
4. `npm run preview`，用浏览器看中文页与英文页各一篇：日期文本在 JS 挂载后出现，位置在正文末尾、上一篇/下一篇之上；刷新无闪烁错位。
5. 提交配置改动（只 add `config.mts` 与本计划），部署按任务流程另行确认。

## 五、验收边界

- 所有默认文档布局页面在正文下方显示"最后更新于 / Last updated + 日期"，日期与 `git log -1` 一致。
- 首页、需求池、Bug 悬赏、404 页面不出现该行。
- 中文页显示日期格式为 `2026/10/27` 一类，英文页为 `10/27/2026` 一类，不随访客系统语言漂移。
- 海外时区访问不出现日期跨日（按 `Asia/Shanghai` 固定）。
- 构建成功、无 hydration 报错；sitemap 每条 URL 带 `<lastmod>`。
- 不新增依赖，不引入客户端请求。

## 六、待验证前提

- **构建发生在本地**：当前部署链路是 `npm run deploy` = 本地 `vitepress build` + `wrangler pages deploy` 上传 dist，git 历史完整，时间可用。若哪天改成 Cloudflare Pages 从 Git 仓库自动构建，浅克隆会让所有页面拿到同一个提交时间，必须在上游补 `git fetch --unshallow`（或继续本地构建后上传）。实施前确认部署方式没有变。
- **中文路径可用**：`docs/开发计划/…` 等含中文的路径由 VitePress 以参数数组 spawn git（不经 shell），预期正常；实施时挑一篇中文名页面抽检。
- **构建耗时**：161 次 git 调用的实际开销未测，按每次几十毫秒估算在数秒量级；若实测明显变慢，再考虑批量取时间（一次 `git log --name-only` 解析后注入）替代。
- **页脚位置**：在有 sidebar 与无 sidebar 两种文档页上位置一致，按源码判断相同，仍需目视一次。
- **SSR 文本为空**：内置组件只在客户端填充可读日期，静态 HTML 里只有 `datetime` 属性。若要求 HTML 直接带可读日期（无 JS 环境、SEO 摘要），只能走方案 B 的自定义组件。
