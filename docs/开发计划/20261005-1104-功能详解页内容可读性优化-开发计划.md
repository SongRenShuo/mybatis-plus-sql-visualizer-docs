# 功能详解页内容可读性优化——开发计划

> 日期：2026-10-05
> 状态：已完成（已部署生产并验证）
> 输入：用户反馈「功能详解文字内容较多，用户理解和查看不太方便」，要求参考互联网大厂产品文档的做法对内容做优化。

## 一、背景与问题定性

功能详解（`/features/`）中英各 10 页，是文档站的核心内容面。历轮插件功能同步把 CHANGELOG 条目并入对应小节，页面持续增重，当前量化现状（2026-10-05 实测，正文字符数按去除空白计）：

| 页面 | 中文字符数 | 超 150 字长段 | 最长单段 |
|------|-----------|--------------|---------|
| sql-log | 8,172 | 7 | 332 字 |
| xml-preview | 5,187 | 9 | 497 字 |
| mcp | 3,736 | 4 | 312 字 |
| wrapper-preview | 3,427 | 1 | 228 字 |
| jpa-preview | 3,400 | 0 | 161 字 |
| 其余 5 页 | 各 ≤1,129 | 0 | ≤139 字 |

四个重页占总字数约 72%，英文页同步增重（sql-log 英文 24.6KB、xml-preview 13.9KB）。三个结构性病根：

1. **变更增量堆进正文。** 边界行为、版本兼容、内部机制全留在正文流：sql-log「自动展开工具窗口」整节讲防抖秒数与恢复条件，xml-preview「参数面板类型契约」整段讲输入容错。这些内容对首次阅读者是噪音，对老用户属于「用时再查」。
2. **段落超长，一段多义。** 单段最长 497 字，一段同时讲是什么、为什么、边界与历史，括号套括号，扫读不可及。
3. **页面骨架不统一。** annotation-preview 651 字极简清晰，sql-log 8,172 字巨重，同一导航下阅读体验割裂；VitePress 提示容器在 features 下零使用（guide 已有两处 `::: tip` 先例，主题支持）。

## 二、对标参考：大厂文档模式与本站落地

按用户要求取材三家可公开核验的大厂规范或范本，映射到本站：

| 来源 | 核心模式 | 本站落地 |
|------|---------|---------|
| [Google 开发者文档风格指南](https://developers.google.com/style)（段落结构章） | 一段一个意思；段落 3~5 句；关键信息前置（front-load），扫读只看首句就能抓住每节要点 | 单段上限 3 句或约 120 字；每节首句必须是结论或定义 |
| [Ant Design 组件文档骨架](https://ant.design/components/tree-cn)（何时使用 → 代码演示 → API → 注意 → FAQ） | 固定页面骨架，读者在任何组件页都能按同一路径找信息 | 十页统一骨架：一句话定位 → 触发方式 → 核心能力 → 分节详解 → 边界与细节（折叠）→ 反馈链接 |
| [阿里云帮助文档分层](https://help.aliyun.com)（概述 → 快速入门 → 开发指南 → 开发参考 → 常见问题） | 渐进披露：主路径短，细节下沉到独立层级 | 首屏快速上手不超过 3 步；兼容性、版本迁移、内部机制降级进 `::: details` 折叠块 |

Stripe、Vercel、微软写作风格指南的同类通例一并吸收：视觉锚点优先——能用表格不用段落，能用列表不用长句，风险提示用醒目容器而非埋在长段里。

**总原则：只重组，不删信息，不新写能力。**所有现存事实表述保留落点（正文、折叠块），改后不出现插件里不存在的功能（历轮同步红线不变）。

## 三、目标骨架（十页统一）

```markdown
# 标题
<GifPlayer src="..." alt="..." />
一句话定位（≤40 字，说清这个功能解决什么问题）

## 触发方式                  ← 表格化：入口 / 操作，新用户 10 秒上手
## 核心能力（可选，能力多于 4 项的页加总览表）
## 分节详解（每能力一节）
   每节：首句结论 → 短段 / 表格 / 列表 → 细节
::: details 边界与兼容性说明（可选，标题写明何时需要看这块）
   版本迁移、平台告警、内部机制、低频边界
:::
> 反馈池链接（保留现状）
```

改写规则（十页统一执行）：

1. 一段一个意思，单段不超过 3 句或约 120 字，超出拆段、转列表或转表格。
2. 每节首句为结论或定义，细节后置；扫读首句即可了解全节大意。
3. 操作类内容改步骤列表，对照类内容转表格，已有表格保留。
4. 兼容性与版本迁移（如历史目录改名、旧版文件兼容）、平台告警（如 JEP 451）、内部机制（如 `-- pd:` 注释格式）进 `::: details` 折叠，折叠标题写明「何时需要看」。
5. 风险提示（无界写、`${}` 注入面）用 `::: warning` 保持醒目，不占正文流。
6. 括号注水清理：括号内容超过 12 字的拆为独立句，纯版本与来源标注移入折叠块。
7. 每页首屏固定为 GifPlayer + 一句话定位 + 触发方式。
8. 英文页以中文改写后的结构为准同步翻译，不做逐句机械对应。

## 四、分批实施

批次 0 为试点，模板观感经用户确认后再铺开；每批次完成即提交（只 add 本次文件，不 push）。

**批次 0 试点：sql-log（中英 2 页）**

选最重的一页检验模板，也是用户最痛的一页。要点：

- 「两种捕获通道」改为总表加两小节；增强捕获七条 bullet 中纯边界类（注入失败回落、JEP 451 告警、冷却与重新授权）折叠
- 「自动展开工具窗口」「捕获诊断与授权」压缩：行为条件（防抖、焦点、恢复三条件、会话记忆）折叠，正文只留开箱行为一句话
- 「跳转到源码」332 字长段拆分，拦截器 Java 代码块保留，「框架帧过滤登记」细节折叠
- 「去重与过滤」「条目序号」「时间戳与时间来源」转表格
- 「SQL 历史」版本兼容段（目录改名、v2 格式、旧版兼容）折叠
- 「单击预览与双击弹窗」两级预览行为压为表格，IN 列表展开等渲染细节折叠

**批次 1：xml-preview + jpa-preview（中英 4 页）**

- xml：「回滚 SQL」497 字长段拆三小节（INSERT 自动回滚 / UPDATE·DELETE 粘贴生成 / 其余语句说明）；「参数面板类型契约」容错细节折叠，正文留一句「参数按签名识别类型，输入行给占位提示」；「执行防护」七条 bullet 转表格

**批次 2：mcp + wrapper-preview（中英 4 页）**

- mcp：「使用口径」「计划与建议类输出」转表格；「设置页门控」与平台开关关系的段落折叠；「只读与安全」三条防线收紧
- wrapper：「参数回填」按数据源校正列名的边界折叠；「JOIN 关系图」渲染细节折叠；「执行计划」方言表含验证程度列，保留

**批次 3：其余五页轻量对齐（中英 10 页）**

annotation-preview、batch-operation、code-completion、crud-sql、sql-to-java 各不超过 1,200 字，只做首屏定位与触发方式表格化，不强行折叠。

## 五、红线核对

- 不新增能力表述：改后每个名词与行为仍以插件仓 master 实际能力为准
- 信息零丢失：改前每条事实性表述在改后正文或折叠块可追溯，实施时逐页自查
- 既有元素不动：GifPlayer 与 poster、反馈池链接、页面交叉链接、底注三档口径、frontmatter
- 变更记录.md 追加一行（唯一权威总册，最新在上）
