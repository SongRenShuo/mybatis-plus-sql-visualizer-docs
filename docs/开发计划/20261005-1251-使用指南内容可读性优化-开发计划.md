## 二、configuration.md 病根与改法

**病根是形态错位而非长度**：配置参考页的「配置项 | 默认值 | 作用」三列表格本身正确，但历轮同步把整段行为说明塞进单元格——6 处单元格超 120 字（最长 254 字），升级语义、边界行为、校验规则全挤在表格单元格里；且与功能页折叠块**近乎原文重复**（空参数填充策略、自动展开窗口、拦截器注入等两处各讲一遍），形成「三处重复、改一处漏两处」的维护面。

**改法（对标阿里云参数表 / Stripe API Reference 惯例：参数表每格一句是什么 + 默认值，细节链接到详情页）**：

1. 6 处巨型单元格瘦身：每格只留「是什么 + 默认行为」一句主描述，升级语义 / 边界 / 校验细节移出表格——进单元格下方的 `::: details` 折叠块或链接到功能页对应锚点
2. 与功能页重复的描述改为链接（功能页为唯一权威）：空参数填充策略 → xml-preview#参数面板；自动展开 / 自动监听 → sql-log#触发方式与#自动展开工具窗口；拦截器注入与源码跳转 → sql-log#跳转到源码；方言智能推断 → wrapper-preview#11-种方言分页渲染；列名校正 → wrapper-preview#参数回填；数据目录版本迁移细节保留本页（配置页职责）
3. 瘦身后单元格上限 120 字；表格结构（配置项 | 默认值 | 作用三列）不变
4. 英文镜像同构重写

## 三、faq.md 改法

FAQ 天然 Q&A 形态健康（问答即「用时再查」，与功能页折叠块同角色），只做两处：

1. 「跳转到源码」段（258 字）拆两段：先答「为什么跳不准」，再给「怎么配拦截器」
2. 「最近执行记录」段（177 字）拆两段：先答「为什么是空的」，再给「怎么才有内容」

英文 faq 随 configuration 同轮由子代理按新版中文同构收敛（英文长段 17 处一并处理）。

## 四、红线

- 只重组不删信息：改前每条事实性表述在改后正文或折叠块可追溯；configuration 单元格瘦身的细节落点为折叠块或功能页链接，**链接目标必须是重构后功能页真实存在的锚点**（逐个核对锚点 slug）
- 不新增能力表述；GIF、反馈链接、交叉链接、frontmatter 不动
- offline / comparison / compatibility / getting-started / shortcuts 五页本轮不动（英文 offline 的长段属同源内容英文展开，随轮次自然收敛的原则本轮回置，不单独改写）
- 变更记录.md 追加一行；功能页同步口径更新：「功能页为唯一权威，配置页与 FAQ 只留短答案 + 链接」
