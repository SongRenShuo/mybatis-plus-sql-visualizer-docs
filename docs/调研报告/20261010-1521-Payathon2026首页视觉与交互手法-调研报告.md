# Payathon 2026 首页视觉与交互手法调研报告

> 调研对象：<https://aipay.alipay.com/community/events/payathon-2026>（支付宝 AI 付 · 年度黑客松活动页）
> 调研目的：识别该页中可迁移到 SQL Visualizer 官网首页的视觉语言、信息架构与交互手法
> 调研时间：2026-10-10 15:21
> 取材方式：1440×900 与 390×844 两档视口实测截图；页面 DOM 几何与计算样式读取；站点 CSS/JS 产物下载后静态分析。下文所有读数均为当次实测，非文档转述。

## 一、调研范围与不涉及的边界

本报告只讨论页面在「视觉语言、信息架构、交互手法」三层的做法，以及这些做法对当前官网的适用性。不讨论活动内容本身（赛制、奖金、报名规则），也不建议引入与本产品无关的业务形态。

有一条判断贯穿全文：目标页是一张**面向报名转化**的活动页，当前官网是一张**面向开发者评估与安装**的产品页。前者的信息目标更偏「制造参与冲动」，后者更偏「让人相信这东西真的有用」。因此本报告对目标页的做法逐项做了取舍，吸收结构性的、可复用的部分，明确排除炫技与无关形态。取舍清单见第六节。

## 三、视觉语言

### 3.1 配色

从 `payathon-2026.dp-aqLMh.css`（76KB）统计颜色字面量出现频次，得到的实际用色结构是：

| 角色 | 色值 | 出现次数 | 用途 |
|------|------|---------|------|
| 主背景 | `#10141b` | 11 | 整页深色底 |
| 更深底 | `#05080c` | 4 | 首屏黑洞区域 |
| 面板/卡片 | `#202834` | 2 | 卡片、下拉 |
| 描边 | `#3a4452` | 5 | 卡片边框、分隔 |
| 主强调 | `#86eaff` | 18 | 链接、图标、轨道描边、青色高亮 |
| 次强调 | `#ff8623` / `#ff997b` | 5 | 首屏 CTA、奖池数字 |
| 正文 | `#fff` / `#f3f4f6` / `#e5e8ed` | 32 | 标题与正文 |
| 次级正文 | `#a4adbc` / `#8e99a9` / `#77818f` | 13 | 说明文字、导航未选中项 |
| 赛道色 | `#b4a7ff` `#a9e6b6` `#82b5ff` `#ff997b` `#86eaff` | 各 2 | 五条赛道各一色 |

两点值得注意。

第一，主强调色是**青色 `#86eaff`**，橙色只是首屏与奖池的局部强调。整页 18 次青色对 5 次橙色，主次分明。

第二，赛道色不是写死的五个十六进制，而是通过 `--track-color` 变量注入，卡片描边与光晕用 `color-mix(in srgb, var(--track-color) 24%, transparent)` 派生。也就是说新增一条赛道只需给一个变量，派生色自动跟上。这套「语义色变量 + 派生」的写法是整页唯一具备系统性的配色机制。

### 3.2 ASCII 纹理系统

这是整页最具辨识度的部分。装饰元素全部由字符构成：位图式的 `1 0 0 1 1 0` 序列、点阵圆环、`# * = + - . :` 组成的网格。它的三个特点决定了它值得关注：

- 零图片成本。全部由 CSS 背景或脚本生成，没有一张装饰位图。
- 语义自洽。字符网格天然带「终端/开发者」意味，与面向开发者的产品定位一致，不是任意花纹。
- 可承担结构职能。第 7400px 与 13491px 两个 256px 高的字符网格带，实际作用是深色区与浅色区之间的过渡，把生硬的分界变成了一个视觉段落。

### 3.3 章节眉题

每一节在中文标题上方，先给一行超大、低对比的英文，字距拉宽：`WHY JOIN`、`REWARDS`、`CHOOSE YOUR TRACK`、`MARK YOUR CALENDAR`、`PARTNER BENEFITS`、`YOUR NEXT BUILD`。

它在长页面里的作用是**建立章节感**：用户滚动时先看到一行醒目的英文，立刻知道进入了新章节，再读中文标题获取具体信息。这是低成本的节奏工具——不改内容，只加一行文字，就能把「九个连续区块」变成「九个有边界的章节」。

### 3.4 明暗分区节奏

整页走的是 深 → 浅 → 深：首屏到评审标准是深色（0 至 7656），参赛权益与合作伙伴是白底（7656 至 13491），结尾号召与页脚回到深色。中间用两个 ASCII 过渡带衔接。

这个节奏解决的是长页面的疲劳问题。当前官网 10018px 全浅色，靠 `#f9fafb` 与 `#ffffff` 交替，对比度极低，滚到中段容易失去位置感。

### 3.5 字体

页面加载自定义数字字体 `AlipayNumber`（normal/medium/bold 三档，按需加载，实测状态为 unloaded）。中文走系统 sans-serif。数字字体只用在倒计时与奖池金额上。

这一点对当前官网没有直接可复用性：引入自定义字体意味着新增字体文件与授权问题，收益仅是数字更好看。**不建议吸收**。

## 四、信息架构与交互清单

### 4.1 左侧常驻锚点导航（`.event-contents`）

整页最有价值的一个组件。桌面端固定在视口左侧的内容栏外，实测样式为：

```
position: fixed;
top: calc(var(--event-header-height, 60px) + 16px);
left: max(20px, calc((100vw - 1440px) / 2 + 20px));
width: 190px;
```

也就是说它落在 1440px 内容列**外侧的留白区**，不与正文争空间；只在 `min-width: 1440px` 时显示。移动端降级为顶栏下方的固定条（344px 居中，带下拉）。

它同时叠了三个机制，逐一看实现：

**滚动联动（scroll-spy）**。脚本缓存六个目标区块的绝对 top，以 `scrollY + 60 + 100` 为阈值线判断当前区块；滚到底部时强制选中最后一项。导航在首屏底部进入视口后才显示（`data-visible` 属性控制）。

**高斯放大（dock 效果）**。当前项的缩放系数按与激活项的距离做高斯衰减：

```
scale = 1 + 0.18 * exp(-d² / 1.1)
```

当前项 1.18 倍，相邻项约 1.09，隔一项基本回到 1。这就是 macOS Dock 的放大手感。`prefers-reduced-motion: reduce` 时降级为「当前项 1.18、其余 1」的静态差异。

**跨明暗自动反色**。脚本克隆了一份导航文字与 logo，放进一个 `mix-blend-mode: difference` 的覆盖层（`.contents-blend-layer`），用 `clip-path: inset()` 对齐原导航位置。这样导航滚过深色区与浅色区时颜色自动反转，不需要按区块切换主题类。实测 `data-blend-ready`、`data-contents-invert` 属性即此机制的开关。

这三条里，滚动联动是刚需，反色是巧解，Dock 放大属于锦上添花。

### 4.2 数字滚动与倒计时

奖池 `¥200,000` 以滚动数字呈现，首屏有 `052 天 08:40:59` 倒计时与「报名中」徽章。

对活动页这是核心，对产品页没有等价物。可借鉴的是「让静态数字动起来」这个念头本身，但前提是有值得动的数字（见 6.A）。

### 4.3 编号步骤条

「从报名开始」一节用 `01 02 03 04` 四个编号 + 横向连线表达流程。这是最朴素也最有效的结构表达：把并列的卡片变成有顺序的路径。

### 4.4 赛道卡的贴纸形态

`Vibe Pay`、`Skill Pay`、`Machine Pay`、`Token Pay`、`Agent Pay` 五个赛道标签是**倾斜的矩形色块**，各自带赛道色与描边光晕，像贴在页面上的标签。配合 3.1 的 `--track-color` 变量体系，五个标签同构但不同色。

### 4.5 贡献热力图式活动日历

活动日历用 GitHub 贡献图那种方格矩阵表达九月至十二月的四个阶段，每阶段一色。把时间跨度压成一张可一眼扫完的图。

### 4.6 合作伙伴跑马灯

logo 横向无限滚动，两端用 `mask-image: linear-gradient(90deg, transparent, #000 10%, #000 90%, transparent)` 渐隐。这个渐隐写法比硬切边自然，是可直接复用的细节。

### 4.7 ASCII 区块过渡带

见 3.2。实现上是 `.ascii-stage` 容器 + 脚本生成字符网格。

### 4.8 入场与揭示动画

CSS 里共 22 个 `@keyframes`，包括：

- `entry-cursor` / `entry-brackets`：首屏标题的终端光标闪烁与方括号入场，用 `steps(1, end)` 做阶梯式跳变，刻意保留「终端刷新」的粗糙感。
- `overview-ink` + `clip-path: var(--ink-clip)`：标题的墨迹揭示，从裁剪到 `inset(0)` 展开。
- `race-logo-glitch`：合作伙伴 logo 的故障抖动。
- `payathon-arrow-marquee`、`tide` 系列等。

动画驱动方式是统一的 `data-*` 属性开关：`data-running`、`data-error`、`data-motion-running`、`data-text-entered`、`data-overview-reveal`。脚本只负责切属性，动画全部写在 CSS 里。这个模式的好处是可维护、可测试、Vue 里能直接用属性绑定实现，值得学。

### 4.9 评审节的 SVG 骨骼生物

「什么样的产品更有竞争力」一节的插图是四只由 `0`/`1` 字符构成的动物（海豚、豹、龟），用 SVG 分组 + `transform-origin` + `flipper`/`stride`/`turtle-glide` 等关键帧做出游动与行走。

这是整页最重的资产，也是**最不该学**的一项：实现成本高，需要为每种形态单独调骨骼，且与 SQL Visualizer 的产品语境毫无关系。

### 4.10 终端代码块首屏

首屏放了一段真实的代码字面量：

```js
const payathon = {
  slogan: "Build & Bill",
  mode:   "real_money",
};
```

对开发者产品而言，「像代码」比「像广告」更可信。这是首屏可以用极低成本建立技术气质的手法。

### 4.11 报名表单向导（不适用）

页面内嵌了一整套报名 → 产品开通 → 技术集成 → 沙盒验证 → 服务注册的多步向导。与本产品无关，列出仅为说明目标页的信息密度构成。

## 五、当前官网首页对照诊断

实测数据（2026-10-10，生产环境 <https://sql-visualizer.jvtools.cn/>，1440×900）：

| 指标 | 当前官网 | Payathon 2026 |
|------|---------|---------------|
| 整页高度 | 10018px | 15013px |
| 区块数 | 9 | 12 + 2 过渡带 |
| 页内导航 | 无 | 左侧常驻锚点导航（滚动联动 + 放大 + 反色） |
| 首屏底色 | 浅色（`#ffffff`） | 深色（`#10141b`） |
| 主强调色 | 蓝 `#2e6ae0d6` | 青 `#86eaff` + 橙 `#ff8623` |
| 装饰系统 | 两团模糊光斑 | ASCII 字符网格 |
| 明暗节奏 | 浅色为主，`#f9fafb` / `#ffffff` 交替 | 深 → 浅 → 深 |
| 章节标识 | pill 徽章（「更多特性」「Testimonials」） | 巨型英文眉题 + 中文标题 |
| 滚动揭示动画 | 无 | 逐节入场 |

首页区块实测（top / 高度）：hero 0/900、social-proof 900/248、features 1148/4302、docs-showcase 5450/659、more-features 6110/990、welfare 7099/560、testimonials 7659/762、pricing 8421/933、cta 9354/575。

诊断出六条问题，其中前两条是缺陷级：

**1. 首页没有任何页内导航。** 九个区块、10018px 的滚动长度，用户从首屏一路滚到底部定价区，中途无法跳转，也无法知道自己走到了哪一节。`NavHeader.vue` 只有「功能详解 / 使用指南 / 需求池 / 关于」四个站点级路由，全首页组件里 grep 不到一个 `href="#..."`。这是当前首页最大的可用性缺口。

**2. 首屏光斑配色与品牌色不符。** `HeroSection.vue:273` 与 `:280` 的两团模糊光斑写死为 `#f96a48c4`（橙）与 `#ec4899`（粉），而全站品牌色是蓝 `#2e6ae0d6`（`style.css:49`、`:101`）。这两组色值是 CoolRequest 模板的遗留，视觉上表现为首屏 logo 后面一团粉红暖光，与蓝色标识和蓝色 CTA 相互打架。生产截图可复现。

**3. 全站没有滚动揭示动画。** 除 `NavHeader.vue` 的 `scrollY > 50` 吸顶判断外，首页所有组件都没有 `IntersectionObserver` 或滚动监听。区块是硬切出现的，长页面显得平淡。

**4. 明暗节奏弱。** 浅色打底，`#f9fafb` 与 `#ffffff` 交替，两档明度差极小（`style.css:17`、`:53`），区块边界几乎看不出来。

**5. 章节感缺失。** 每节只有一个小 pill 徽章，信息量弱，无法在滚动时提供「进入新章节」的信号。

**6. 功能卡同质化。** `FeaturesGrid` 的六张卡（多框架支持 / 极致性能 / 智能识别 / 广泛集成 / 安全防护 / 历史记录）是清一色白卡 + 同色图标块，没有区分度，也没有语义色体系。

另外记录一条范围事实：中文首页与英文首页是两套独立实现。中文首页是 `index.md`（`layout: false`）+ `CoolHome.vue` 九组件树；英文首页是 `en/index.md`（`layout: home`）+ VitePress 默认 hero + `EnHomeFeatures` + `EnFeatureMatrix`。任何首页改版都要单独决定英文侧跟不跟，不能假定自动同步。

## 六、可吸收清单

### A. 直接吸收

| 项 | 做法 | 对当前官网的落点 |
|----|------|-----------------|
| 页内锚点导航 | 左侧常驻 rail，滚动联动高亮当前区块 | 首页新增组件，挂在 `CoolHome.vue` |
| 章节眉题 | 每节一行低对比大字距英文眉题 | 九个区块组件各加一行 |
| 跑马灯两端渐隐 | `mask-image: linear-gradient(90deg, transparent, #000 10%, #000 90%, transparent)` | 替换现有技术栈跑马灯的硬切边 |
| `data-*` 驱动动画 | 脚本只切属性，动画全在 CSS | 作为后续所有动画的统一约定 |
| `prefers-reduced-motion` 降级 | 动画均可关停 | 新增动效时必须带 |

### B. 改造后吸收

| 项 | 目标页做法 | 改造方向 |
|----|-----------|---------|
| 首屏深色化 | 整页深色打底 | 插件截图本身就是深色 IDE 界面，浅色首屏与截图割裂。可只把首屏改深色，其余保持浅色，形成深→浅节奏 |
| 终端代码块 | 装饰性伪代码 | 换成真实素材：左侧三行 `LambdaQueryWrapper` 链，右侧生成的 SQL，即本产品的核心承诺 |
| 语义色体系 | `--track-color` + `color-mix` 派生 | 给六张功能卡分配语义色（预览/日志/生成/多框架/AI/安全），纯色描边，不做渐变 |
| 明暗分区 | 深 → 浅 → 深 | 把收尾的文档展示、定价、CTA 三段做深色，与深色首屏呼应 |
| 编号步骤条 | 01–04 流程 | 用「写代码 → 看 SQL → 跑起来 → 查日志」表达真实使用路径 |
| 滚动揭示 | 逐节入场 | 统一一个 `useReveal` 组合式函数，IntersectionObserver 加类名，CSS 负责过渡 |

### C. 不吸收

| 项 | 理由 |
|----|------|
| ASCII 骨骼生物动画 | 成本极高，且与 SQL 调试的产品语境无关 |
| 报名/登录多步表单向导 | 本产品无对应业务 |
| 自定义数字字体 `AlipayNumber` | 新增字体文件与授权问题，收益仅是数字观感 |
| Dock 高斯放大 | 用户对「无谓动效」敏感，放大效果在导航项只有九个时收益有限，高亮已足够 |
| 全站 ASCII 纹理铺底 | 会压过产品截图这个真正的主角；只建议在过渡带等极小面积使用 |
| 倒计时 | 无对应业务 |

## 七、待验证前提

以下四条是本报告在推断时依赖的假设，实施前需先证伪或确认：

1. **「左侧 rail 落在 1440 内容列外侧」在当前官网是否成立。** 当前官网的容器宽度、`CoolHome` 的 `overflow-x: clip`（`CoolHome.vue:43`）与 VitePress 全局 `.container` 内边距叠加情况需要实测。已知踩坑记录：首页内层 `div.container` 会撞 VitePress 全局 `.container` 的 24px 内边距，375px 视口下卡片内容只剩 279px。若留白区不足 190px，rail 需改为悬浮抽屉或收窄。
2. **深色首屏与现有暗色模式是否冲突。** 站点已支持暗色模式（`style.css:69` 起）。首屏若写死深色，暗色模式下需确认不会出现「深色首屏 + 深色导航」糊成一片。同时 `NavHeader` 的 `transparent` 状态在深色首屏上需重新验证文字对比度。
3. **功能卡语义色的分配是否有产品依据。** 六张卡目前是并列关系，分色需要先确认它们确实分属不同能力域，否则颜色只是噪音。
4. **英文首页是否本轮跟进。** 中英首页两套实现（见第五节末），需用户明确本轮范围。

## 八、结论

目标页真正值得学的不是它的深色皮肤或 ASCII 花纹，而是三件结构性的事：**长页面要有页内导航**、**要有章节节奏**、**要有明暗分区**。这三件在当前官网都是空缺，且都不依赖任何重型技术。

交互手法上，`data-*` 属性驱动 CSS 动画、`mask-image` 渐隐、`color-mix` 派生语义色这三条是可以直接沿用的工程约定；`mix-blend-mode` 反色层与 Dock 放大属于可选的巧劲，不建议在首轮引入。

视觉上有一条现成的缺陷值得顺手修掉：首屏光斑的橙粉色值是模板遗留，与品牌蓝不符。

不建议吸收的部分同样明确：骨骼动画生物、表单向导、自定义字体，以及大面积纹理铺底。当前官网的主角是产品截图，视觉手法应当为截图服务，而不是与截图争夺注意力。
