## 二、根因分析（比单张重录更重要）

### 2.1 跳行弹窗：修法改错了地方

`Go to Line:Column` 弹窗在 6 张里命中。查录制脚本后定案：

- 跳行由 `lib/nav.py` 的 `goto()` / `goto_col()` / `goto_token()` 与 `gifkit.goto_line()` 实现，
  两者都是 **Ctrl+G → Ctrl+A 清空 → 输入行号 → Enter**；
- 从 Ctrl+G 到 Enter 之间约 **1.5~2.0 秒**，弹窗在这段时间一直可见——15fps 下就是 **20~30 帧**；
- 上一轮（`20261024-1026` 计划）的修法是「`goto_col` 末尾无条件按 Esc」，但 **Esc 在 Enter 之后**，
  弹窗早已入镜，**该修法对「弹窗入镜」无效**；实测 `lib/nav.py:116-129` 的 `goto_col` 末尾也没有 Esc。

**修法（四选一，按场景挑；④为本轮 T-DocsGifRecord1025 实测新增，最彻底）**：

1. **把跳行移出录制窗口**——在 `Recorder.start()` 之前完成跳行（首选，改动最小）；
2. 改用不弹窗的定位：gutter 点击（已有 `find_gutter_icons` 像素定位）、`Ctrl+F` 搜索；
3. 走 IDE 内置 MCP `open_file_in_editor` 按路径精确打开（主仓 `record/mcpnav.py` 已有，**录制环境缺失，见附录 A 同步清单**；本轮 mcp-agent 录制用过）；
4. **`Ctrl+Home` 钉首行 + `post_wheel` 滚动到目标行**（每滚一档 = 3 行），**零弹窗、零文档副作用**。
   本轮 a15 / r10 两条最难的视频都用它。⚠️ 别再用 `goto*` 系列做录制内定位——2026-10-25/26 实测
   Ctrl+G 路线还会**往文档里塞杂散空行**（`UserServiceImpl.java`、`schema.sql` 双双中招，文档比磁盘多
   1~3 行 → 固定行号全部错位），且脏文档若在关页签时被 IDE 自动保存会写回磁盘。脏文档恢复顺序必须是
   **关页签 → `git checkout` → `Ctrl+Alt+Y` → 重开**，顺序反了脏内容会再写回一次。

> 补充事实（2026-10-26 核对）：主仓 `record/lib/nav.py` 在 10-25 已加过「Enter 重试 + Esc 兜底」护栏
> （`_goto_dialog_open()`，按弹窗输入框的蓝色 focus 边框判据），**录制环境的旧拷贝没有这段**——同步
> `lib/nav.py` 后，`goto*` 路线的「弹窗留在画面上」问题会显著缓解；但护栏只处理 Enter 之后，
> 「Ctrl+G 到 Enter 之间 1.5~2.0s 弹窗可见」仍在，所以首选还是修法 1 / ④。

### 2.2 拍错功能：入口/同名文件混淆

`wrapper-preview.gif` 拍成了 `UserMapper.xml` 的 `<select>` 预览。工程里 `UserMapper.xml` /
`UserMapper.java` / `UserRepository.java` 都有同名或近名文件，上一轮已因此踩过 3 次。

**修法**：开录前用 MCP `open_file_in_editor` 按**绝对路径**打开目标文件；开录后**加一条画面断言**——
预览面板元信息行必须含预期类型（Wrapper 链应为 `LAMBDA_QUERY` / `MPJ LAMBDA`，
XML 应为 `XML select: …`），断言不过即中止本次 take。

### 2.3 分镜没走完 / 场景不成立

- `diagnostic-report`：只演示了菜单选择与保存框，报告本体没展示 → 重录时把 Markdown 出口的产物
  **贴回编辑器或剪贴板预览**，HTML 出口**用浏览器打开**；
- `dialect-gate`：原计划要的是「PG 渲染 → MySQL 目标源」的冲突场景，实际录成了「PG 渲染 → PG 源」
  → 重录前先把目标数据源切到 MySQL（`mpj_demo@localhost`），并确认结果行出现「方言不一致」说明与
  「切换数据源 / 方言设置」两个出口；
- `wrapper-params`：alt 与画面方向相反 + 演示值自带引号 → 重录时**从已勾选状态开始、取消勾选**，
  参数值一律**不带引号**（`tom` 而不是 `'tom'`）。

### 2.4 演示值带引号

`wrapper-params` 里输入 `'tom'` 后 SQL 渲染成 `WHERE username = '''tom'''`，看着像引号 bug。
**约定**：演示参数值一律不带引号，引号由插件按字段类型决定。

### 3.2 插件方言把录制分成两批（2026-10-26 补，影响批次顺序）

插件「渲染方言」决定预览 SQL 的方言与快捷模板行为，**两张图对它的要求相反**：

| 图 | 需要的插件方言 | 原因 |
|---|---|---|
| 批 1~3 其余全部（含 #1~#8、#10） | **MySQL**（当前沙盒即此状态） | 渲染 MySQL 语法、`LIMIT`/反引号形态与旧片一致 |
| #9 `dialect-gate` | **PostgreSQL（手动指定）** | 预览头要显示「方言: PostgreSQL（手动指定）」才构成与 MySQL 目标源的冲突 |

⚠️ **切换的三个坑（2026-10-26 实测）**：

1. 设置页「数据库方言」下拉改成 PostgreSQL 后，**运行时是否立即生效未验证**；稳妥路径＝
   改沙盒 `config/options/mp-sql-visualizer.xml`（`dialect=PostgreSQL` + `dialectAuto=false`）→ **重启沙盒**。
   10-25 实测过：改了 XML 但没重启，快捷模板仍按旧方言生成。
2. 方言为「手动指定 PostgreSQL」时，**快捷模板（EXPLAIN / COUNT / 抽样 10 行）会被方言闸门
   fail-closed 拦截**（对 MySQL 目标源）——所以 `sql-snippets` 这类模板演示**必须排在 MySQL 批**。
3. 切方言生效判据：预览面板头部显示「方言: PostgreSQL（手动指定）」；或对同一 SQL 重渲后看
   `LIMIT` / 引号形态。

**批次顺序建议**：MySQL 批（批 0~2 + 批 3 的 #8/#10 + 批 4/5）先录 → 最后切 PostgreSQL + 重启 →
录 `dialect-gate` → （可选）改回 MySQL。避免中途反复重启。

## 八、风险

1. **沙盒许可**：沙盒偶发弹许可框（`JBAClientHelper connect timed out`），按既有处置停手交用户手工激活，不代录激活码；
2. **同名文件**：工程里 `UserMapper.xml` / `UserMapper.java` / `UserRepository.java` 同名或近名，一律走 MCP 按绝对路径打开；
3. **录制独占键鼠**：录制期间不能并行跑构建；发现被抢前台立刻停手说明；
4. **首页引用回归**：`wrapper-preview` 重录后要检查首页卡片与快速开始页的显示（同一文件，6 处引用）；
5. **文案回滚**：`jpa-write-path` / `xml-ognl` 两处 alt 本轮按画面删掉了未拍到的动作，重录补齐后**要恢复**对应句子；
6. **AI 面板 / Services 面板干扰**：`Ctrl+Shift+F12` 全藏会把 AI 面板和结果网格一起藏掉——
   `sql-snippets` 的结果网格在 Services 里，只能逐个关残留页签；paste 提示词时若输入框坐标
   点偏会**把文字打进编辑器污染源文件**（本轮实测），开录前截图核对输入框位置；
7. **粘性行复活**：给 SQL 文件绑定数据源后编辑器顶部会出现粘性行，右键会落在粘性行上被吃掉
   （菜单弹不出来）——`Ctrl+Shift+A` 搜「Sticky Lines」→ Disable for SQL，关掉后锚点 y 会变需重测；
8. **快捷模板被方言闸门拦**：插件方言手动指定 PostgreSQL 时 EXPLAIN/COUNT/抽样对 MySQL 目标源
   fail-closed（中文文案「已阻止执行」）——见 §3.2，改方言要重启；
9. **Recent chats 时间标签**：AI 面板首末帧的「18m / 0m」标签是天然差异，接缝判据应容忍它，
   别为了首尾一致去等时间跳变。
