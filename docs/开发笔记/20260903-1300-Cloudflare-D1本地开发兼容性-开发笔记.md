# Cloudflare D1 本地开发兼容性问题

- 记录时间：2026-09-03 13:00
- 项目：sql-visualizer-admin（Cloudflare Workers + D1 方案）

## 问题描述

在 Windows 环境下使用 Wrangler 的本地 D1 数据库时，出现访问冲突错误：

```
npx wrangler d1 execute sql-visualizer-admin --local --file=./migrations/0001_init.sql

*** Received structured exception #0xc0000005: access violation
The Workers runtime failed to start.
```

## 根本原因

Cloudflare Workers 运行时（workerd）在 Windows 平台存在兼容性问题，导致本地 D1 数据库无法正常启动。

这是 Wrangler 3.x/4.x 在 Windows 上的已知问题，与 workerd 的二进制兼容性有关。

## 解决方案

### 方案1：使用远程 D1 数据库（推荐）

直接操作远程 D1 数据库，绕过本地运行时：

```bash
# 创建数据库（只需一次）
npx wrangler d1 create sql-visualizer-admin

# 应用迁移到远程数据库
npx wrangler d1 execute sql-visualizer-admin --remote --file=./migrations/0001_init.sql

# 执行查询
npx wrangler d1 execute sql-visualizer-admin --remote --command="SELECT * FROM fb_posts"
```

### 方案2：使用 JSON 文件本地开发

创建本地 JSON 文件数据库用于开发测试：

```javascript
// local-dev.mjs
import { readFileSync, writeFileSync, mkdirSync } from 'fs';

let db = { posts: [], votes: [], comments: [], /* ... */ };
const DB_PATH = './.local/feedback.db.json';

function loadDB() {
  try { db = JSON.parse(readFileSync(DB_PATH, 'utf-8')); } catch { saveDB(); }
}

function saveDB() {
  writeFileSync(DB_PATH, JSON.stringify(db, null, 2), 'utf-8');
}

// 提供与 D1 类似的 API
export function prepare(sql) {
  return {
    bind: (...args) => ({ all: async () => mockQuery(sql, args) }),
    run: async () => ({ changes: 1, lastInsertRowid: db.posts.length }),
    first: async () => mockQuery(sql)[0] || null,
  };
}
```

### 方案3：使用 SQLite 替代

使用 `better-sqlite3` 或 Node.js 22+ 的 `node:sqlite` 模块：

```javascript
// 使用 better-sqlite3
import Database from 'better-sqlite3';
const db = new Database('./.local/feedback.db');
db.exec(`CREATE TABLE IF NOT EXISTS posts (...)`);

// 使用 node:sqlite (Node.js 22+)
import { DatabaseSync } from 'node:sqlite';
const db = new DatabaseSync('./.local/feedback.db');
```

**注意**：`node:sqlite` 在 Node.js 22.5.0+ 可用，但可能需要实验性标志。

## 项目中的实践

本项目采用以下策略：

1. **生产环境**：使用 Cloudflare D1（远程）
2. **开发环境**：使用 JSON 文件存储（`local-dev.mjs`）
3. **部署**：`npx wrangler pages deploy` + `npx wrangler deploy`

```bash
# 本地开发
node local-dev.mjs

# 部署 Worker
npx wrangler deploy

# 部署 Pages
npx wrangler pages deploy admin-spa --project-name sql-visualizer-admin

# 初始化远程数据库
npx wrangler d1 execute sql-visualizer-admin --remote --file=./migrations/0001_init.sql
```

## 验证方法

```bash
# 验证远程 D1 是否可用
npx wrangler d1 execute sql-visualizer-admin --remote --command="SELECT COUNT(*) FROM fb_posts"

# 验证本地开发服务器
curl http://localhost:8787/api/health
```

## 经验总结

1. **Windows 上不要依赖本地 D1**，直接使用 `--remote` 操作远程数据库
2. **开发时可以使用 JSON 文件或 SQLite** 作为本地替代方案
3. **升级 Wrangler 可能修复兼容性问题**，但不要依赖于此
4. **CI/CD 环境（Linux）通常没有这个问题**，可以正常使用本地 D1
