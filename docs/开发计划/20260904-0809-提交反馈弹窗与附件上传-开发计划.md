# 需求池：提交反馈弹窗 + 标题居中 + 附件上传 开发计划

- 立项时间：2026-09-04 08:09
- 实施状态：待排期
- 涉及项目：mybatis-plus-sql-visualizer-docs（公开站点，反馈池前端）+ sql-visualizer-admin（Cloudflare Workers + D1 + Hono + R2，反馈池后端）
- 目标：把「提交反馈」改为弹窗交互；让需求池页头标题真正居中；支持提交时上传附件并限制大小。前后端一起实现。

---

## 一、需求拆解

本次共三个相对独立的需求，前两个纯前端，第三个前后端都要动：

1. **提交反馈改为弹窗**：现在表单是点「＋ 新增反馈」后在页面内展开一整个表单块，占版面；改成弹出层（dialog / overlay），交互更聚焦。
2. **标题居中**：需求池页头的「需求反馈池 / 提交您的需求、Bug 或建议，社区投票决定优先级」当前因为右侧有「中/EN」语言切换按钮，用了 flex 两端对齐，导致标题整体偏左，需要真正居中。
3. **附件上传（限制大小）**：提交反馈时新增上传附件的能力，服务端必须限制最大大小（防滥用），并规范文件类型。需要一个可持久化的存储与一套上传/回读接口，且要在详情页、管理后台能看到附件。

---

## 二、现状诊断

### 2.1 前端现状（docs 站点）

- `FeedbackForm.vue`：是一个内联表单组件，包含类型选择、标题、描述、功能分类、昵称/邮箱、提交按钮、成功提示。结构性上是 `<div class="feedback-form">` 段落，没有弹层壳。
- `FeedbackPool.vue`：`submit-block` 里用一个「＋ 新增反馈」虚线按钮 + `showForm` 开关控制表单是「收起 / 展开」，表单以内联块渲染在页面流中；`done` 事件在提交成功后把表单收回去。
- 页头：`<div class="pool-header">` 内有一行 `<div class="header-row">`（flex，`justify-content: space-between`），左侧是标题块、右侧是「中/EN」lang-toggle。CSS 里 `.pool-header` 虽设置了 `text-align: center`，但被 `header-row` 的左右分栏覆盖，标题实际靠左。
- 现有 `FeedbackDetail.vue` 负责详情展示，尚无附件渲染逻辑。

### 2.2 后端现状（sql-visualizer-admin）

- 存储现状：`wrangler.toml` 里 **R2 存储桶绑定是注释掉的**（`# [[r2_buckets]] ...`），当前只有 D1（SQLite）和 KV（也是注释的）。要存附件字节必须启用 R2（或改用 D1 存 base64——不建议，D1 有单行/单库体积限制且读写低效）。
- `fb_posts` 表已有一列 `extra_data TEXT`，可以存附件元数据 JSON，但更规范的是单独建一张 `fb_attachments` 表（post_id 关联）。
- 提交接口 `POST /api/v1/feedback/posts` 目前是 JSON body（title/description/type/category/name/email）；Hono `c.req.parseBody()` 支持 multipart 但当前未用。
- 依赖里没有现成的上传/存储封装，R2 的 Get/Put 走 Workers 原生 `BUCKET.put(key, value)`。
- 公开上传有滥用风险（磁盘/流量/垃圾文件），必须做大小限制、类型白名单、限流。

## 三、方案设计

### 3.1 需求一：提交反馈改为弹窗

**交互设计**：页面里保留「＋ 新增反馈」触发点；点击后弹出居中的模态框，内容即现有表单；弹窗支持三种关闭方式：右上角 ×、按 Esc、点遮罩；提交成功自动关闭并清空。

**实现（前端，docs 项目）**

- `FeedbackPool.vue`：
  - 保留 `showForm` 状态和「＋ 新增反馈」按钮。
  - `showForm = true` 时渲染一个遮罩 + 对话框容器（可 `Teleport` 到 body，避免被页面样式影响），把 `FeedbackForm` 放进对话框 body。
  - 新增关闭逻辑：`closeForm()`（`showForm=false`）；监听 `keydown` Esc 关闭；点击遮罩（判定目标是遮罩本身而非内容区）关闭。
  - 提交成功沿用现有 `@done="showForm = false"`，同时清空表单。
  - 弹窗内「收起/关闭」按钮更新为「取消 / 关闭」。

- `FeedbackForm.vue`：本身结构基本不动，只做两处：
  - 顶部对齐弹窗标题，去掉原来那句会在弹窗里重复的说明（或保留到弹窗头部）。
  - 成功提交的 `done` 事件已存在，沿用。

- `i18n.ts`：补充弹窗相关文案（如 `dialogTitle` 直接用 `submitTitle`、`cancel`/`close`、附件文案，见需求三）。

**为什么不直接塞 Element Plus / 原生 message**
本站是 VitePress 定制组件，`FeedbackForm` 用手写 CSS。做弹窗用轻量自实现遮罩层即可（三态关闭 + 焦点），不必引入重型 UI 库；也可考虑原生 `<dialog>` 更省事但样式需自己控制，两者任选，方案按自实现 overlay 写。

### 3.2 需求二：页头标题居中

目标：`需求反馈池` 主标题与副标题在页头带状区域居中，同时保留右侧「中/EN」切换。

**实现（前端，docs 项目，`FeedbackPool.vue` 样式）**
当前 `.header-row` 是 `display:flex; justify-content:space-between`，把标题顶到左侧。改法：

- 方案 A（推荐）：`.header-row` 改 `display:grid; grid-template-columns: 1fr auto 1fr`，三列：
  - 左列占位空（`1fr`），
  - 中列放标题块、`text-align:center`，
  - 右列放 lang-toggle（`auto`）。
  这样标题严格居中，语言按钮固定在右侧，且在不同屏宽下居中稳定。

- 方案 B：去掉 flex 分栏，标题块居中，lang-toggle 用 `position:absolute; right` 放到页头右上角。实现简单，但页头需要 `position:relative`，小屏下可能与标题重叠，需额外响应式处理。

若原本就要求标题 + 副标题整体居中和语言的独立排布，方案 A 更稳。

### 3.3 需求三：附件上传（限制大小）

**数据与存储设计（后端，sql-visualizer-admin）**

启用 R2：在 `wrangler.toml` 取消注释并补上
```toml
[[r2_buckets]]
binding = "BUCKET"
bucket_name = "sql-visualizer-attachments"
```
对应创建存储桶（`wrangler r2 bucket create sql-visualizer-attachments`）。

新增表 `fb_attachments`（新增迁移 `0003_attachments.sql`）：
```sql
CREATE TABLE IF NOT EXISTS fb_attachments (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id   INTEGER NOT NULL REFERENCES fb_posts(id),
    object_key TEXT   NOT NULL,          -- R2 中的键，如 "feed/2026-09-04/uuid.png"
    file_name TEXT   NOT NULL,           -- 原始文件名（仅展示，脱敏）
    mime_type TEXT   NOT NULL,
    file_size INTEGER NOT NULL,          -- 字节
    created_at TEXT   NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_fb_attachments_post ON fb_attachments(post_id);
```
（也可用 `fb_posts.extra_data` 存 JSON 数组，省一张表；但独立表更适合查询、排序、后续扩展，方案按独立表写，plan 内注明二选一。）

**接口设计**

- `POST /api/v1/feedback/upload`（multipart）
  - 入参：`file` 字段。
  - 校验（服务端强制，前端先拦截）：
    - 大小上限：默认 **5MB**（可配），超限返回 `413`。
    - 类型白名单：图片 `png/jpg/gif/webp`，文档 `pdf`，文本 `txt/md`；其余 `415`。不做 `svg`（XSS 风险，除非额外消毒）。
    - 文件名清洗：截断长度、去掉路径/危险字符，最终文件名用服务端生成的安全名。
  - 处理：`const obj = await c.env.BUCKET.put(key, file, { httpMetadata: { contentType } })`；`key = feed/YYYY-MM-DD/<uuid>.<ext>`。
  - 返回：`{ code:0, data:{ key, fileName, mimeType, fileSize, url } }`。`url` 指向回读路由（见下），或 R2 公网域名（若开启 public bucket，plan 里按 Worker 回读路由写，更可控）。
  - 限流/防滥用：同一 IP/指纹短时间上传次数限制（可用现有 `sys_user_activity` 或新增简单计数），防止刷存储。

- `GET /api/v1/feedback/attachments/:key`（或 `/files/:key`）
  - 从 `BUCKET.get(key)` 读取，`Response(blob, { headers: { 'Content-Type': mime, 'Content-Disposition': ... } })` 回流给浏览器。
  - 该路由负责正确的缓存与 Content-Type，前端用它作为预览/下载地址。

- `POST /api/v1/feedback/posts` 变更
  - body 增加可选 `attachments?: Array<{ key, fileName, mimeType, fileSize }>`。
  - 提交成功后把每条写入 `fb_attachments` 关联新 post；可顺带把 `submitterEmail` 已有字段复用做通知。

- 读链路：`GET /posts/:postNo` 详情返回时 join 出 `attachments` 数组；列表 `/posts` 可只带 `attachmentCount`（或暂不带，按需）。

**前端实现（docs 项目 `FeedbackForm.vue` + `FeedbackDetail.vue`）**

- `FeedbackForm.vue` 新增附件区：
  - `<input type="file" multiple>`（或拖拽），选择后先做**前端预校验**：逐文件判断大小 ≤ 5MB、类型在白名单，超限即时提示并剔除，避免白传。
  - 逐个调 `upload` 接口拿 key，展示「上传中 / 成功 / 失败重试」列表；失败不阻塞标题/描述填写。
  - 随 JSON 提交把附件 `key` 列表带给 `/posts`。
  - `i18n.ts` 补文案：`attachment`/`addAttachment`/`maxSize`/`uploading`/`fileTooLarge`/`fileTypeError`/`removeFile` 等。

- `FeedbackDetail.vue`：
  - 详情展示附件：图片类型渲染缩略图（点击放大或新开），其它类型渲染为可下载链接（文件名 + 大小）。
  - 补 `category` 已有，无需新文案之外的改动。

- 管理后台 SPA（`admin/`）：`Posts.vue` 详情/表格可展示附件图标与数量；如需预览复用 Worker 路由即可。（可选，plan 里列为低优先。）

**大小限制的具体数值与理由**
- 默认 `MAX_UPLOAD_BYTES = 5 * 1024 * 1024`（5MB）：图片场景足够，兼顾存储与请求体成本。
- 类型白名单集中一处常量（`src/modules/feedback/constants.ts` 加 `ALLOWED_ATTACHMENT_TYPES`）。
- 前端与服务端都做限制，但**以服务端为准**（前端只是体验优化，可被绕过）。

**安全与风控**
- 上传公开但受大小/类型/限流约束；R2 桶默认私有，不回随便开公网读，统一走 Worker 回读路由并设缓存。
- 文件名不信任客户端，服务端自生成安全键。
- 容量治理：超过阈值可针对单文件/Post 数量上限（如单个反馈最多 3 个附件）加约束。

## 五、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 公开上传被刷存储/流量 | 中 | 高 | 大小 + 类型白名单 + 限流 + 附件数上限；桶私有统一走 Worker 回读 |
| R2 首次启用配置/权限出错 | 中 | 中 | 先本地 `wrangler dev --local` 联调，再部署 |
| 弹窗关闭逻辑（Esc/遮罩/焦点）体验坑 | 中 | 低 | 自实现 overlay 时统一事件处理，组件级测试 |
| 标题居中在不同屏宽下偏移 | 低 | 低 | 三列 grid 方案 + 移动端验证 |
| D1 弃用 base64 存文件导致的体积问题 | 低 | 中 | 明确只用 R2 存字节，D1 只存元数据 |
