## 2. 技术方案

### 2.1 核心策略：覆盖 VitePress 默认首页

VitePress 的 `layout: home` 通过 `VPHero` / `VPFeatures` 等内置组件渲染。要完全复刻 Cool Request，需要：

1. **创建自定义首页组件** `CoolHome.vue` — 包含所有目标区块
2. **在 `index.md` 中禁用默认布局区块** — 通过 frontmatter 控制
3. **在 `index.md` 中嵌入 Vue 组件** — 使用 `<CoolHome />` 替代默认渲染
4. **在 `index.ts` 中注册组件** — `app.component('CoolHome', CoolHome)`

### 2.2 实现路径

由于 VitePress 的 `layout: home` 不支持完全禁用内置区块，采用以下方案：

```
方案：CSS 隐藏默认区块 + 在 markdown 中嵌入完整自定义组件
```

具体：
- `index.md` 的 frontmatter 保留 `layout: home` 但 hero/features 置空
- 在 markdown body 中直接渲染 `<CoolHome />` 组件
- 通过 CSS 隐藏残留的 `.VPHero` / `.VPFeatures`（如需要）

或者更干净的方案：

```
方案：使用 `layout: false` + 完全自定义 Layout
```

- `index.md` 设置 `layout: false`
- 在 `index.ts` 的 `Layout` 函数中检测首页路由，渲染自定义 `CoolHomeLayout`
- 其他页面继续使用 `DefaultTheme.Layout`

**推荐方案二**：`layout: false` + 条件渲染，避免 CSS 隐藏带来的维护负担。

## 8. 风险与注意事项

| 风险 | 应对 |
|------|------|
| VitePress `layout: false` 丢失导航/页脚 | 在 `CoolHomeLayout` 中手动引入 `VPNav` / `VPFooter` 组件 |
| 视频资源过大 | 使用 IntersectionObserver 按需加载，或 GIF 替代 |
| 3D 倾斜在移动端体验差 | 移动端禁用 3D 效果，仅保留静态卡片 |
| 暗色模式视频切换 | 使用 `<video>` + CSS `display` 切换，或统一使用中性背景 |
| 内容数据（下载量等）无法实时获取 | 使用静态数字 + 定期手动更新，或 BadgeBar 组件复用 |
| 定价区无实际付费方案 | 简化为单卡片"完全免费"展示，或移除该区块 |
