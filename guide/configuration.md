# 配置详解

所有配置位于 `Settings > Tools > SQL Visualizer`。设置对话框左上角的搜索框能直接搜到这些条目——插件的每个设置项都登记进了 IDE 设置搜索的索引；插件自己的落地页里另有一个页内搜索，两者索引同一份数据，命中结果一致。

![SQL Visualizer 设置主页面（Tools > SQL Visualizer）](/demo/settings.png)

设置顶层「SQL Visualizer」页底部是**能力矩阵**——四行讲清这个插件做什么：运行期捕获真实参数与耗时、不启库的写前静态还原、MCP 十一工具给 AI agent 用、以及兼容矩阵与文档入口。

![设置落地页底部的能力矩阵（增强捕获 / 免库预览 / MCP 十一工具 / 兼容矩阵与文档）](/demo/settings-landing.png)

设置变更无需重启 IDE：重新触发预览即按新配置生效。

## SQL 预览

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| 数据库方言 | 智能推断 | 分页 / upsert 子句按方言渲染，默认「智能推断」、可手动固定，项目级留空 = 跟随全局。详见 [Wrapper → SQL 预览 · 方言分页](../features/wrapper-preview.md#_14-种方言分页渲染) |
| 替换 ? 占位符 | 开 | 关闭后变量也渲染为 `?` |
| 格式化输出 | 开 | 多行缩进（关 = 单行） |
| 竖向排列值行列名标注 | 开 | 预览竖排展示时 INSERT 每个值行尾显示 `-- 列名` 配对注释（竖排按钮 tooltip 同步提示可在此关闭） |
| 零占位符字面量参数恢复 | 开 | 日志 SQL 无 `?` 占位符时，把字符串字面量识别为可编辑参数；数值常量仅在比较 / IN / BETWEEN / VALUES 语境识别，`LIMIT` 与投影列常量不会误认成分页参数 |
| SQL 预览字段较多时自动折叠 | 关 | 开启后预览编辑器把超长字段列表（SELECT / INSERT 列清单、VALUES 组、UPDATE SET）收起为「… N 列」占位符，点折叠标记还原；主预览、单击预览、历史预览、Log → SQL 结果区与原生控制台一并生效 |
| 自动折叠字段数阈值 | 10 | 字段列表元素数达到该值且跨多行才折叠；仅勾选自动折叠后可编辑 |
| 逻辑删除注入 | 开 | `@TableLogic` 时自动追加 `AND deleted = 值` |
| 逻辑删除值 | 0 | 逻辑删除条件的值 |
| 嵌入列命名 | 自动 | `@Embeddable` 字段展平成列时是否加组件路径前缀（如 `qty_base_qty` 而非 `base_qty`）；「自动」会识别工程里的 `ImplicitNamingStrategy`，判不出按无前缀处理 |
| 多租户注入 | 关 | 实体查询 / 更新 / 删除自动追加 `AND tenant_id = ?`（预览模拟，对齐 MP 多租户拦截器语义） |
| 租户列名 | `tenant_id` | 注入的租户列列名，可按业务调整（如 `org_id` / `shop_id`） |
| 租户列默认值 | 1 | UPDATE SET / INSERT 追加租户列时的字面量默认值 |
| INSERT 时追加租户列 | 开 | 子开关：开启后 INSERT 列清单追加租户列（对齐 MP `TenantLineInnerInterceptor` INSERT 语义）；仅 INSERT 生效，需同时开启多租户注入，UPDATE / DELETE 不受影响 |
| 模拟分页拦截器（COUNT 查询预览） | 开 | mapper 方法 / XML / 注解语句带 `Page` / `IPage` 参数时，预览**尾追分页子句**并**并列产出** COUNT 包裹（`SELECT COUNT(*) FROM (...) TOTAL`），对齐 MyBatis-Plus `PaginationInnerInterceptor` 运行时行为（`searchCount=false` 时跳过）。详见 [Wrapper → SQL 预览 · 分页模拟](../features/wrapper-preview.md#_14-种方言分页渲染) |
| 附分页 COUNT 查询预览 | 开 | 分页模拟的子开关：关闭后只追加 `LIMIT`、不再生成 COUNT 语句；总开关关闭时本项不生效（父开关优先） |
| 启用 JdbcTemplate SQL 字符串预览 | 开 | 为 `queryForList` / `update` 等方法的字符串 SQL 实参显示预览图标并支持 `Alt+Shift+Q`；命名参数（`NamedParameterJdbcTemplate` 的 `:name` 占位符）可回填 |
| 显示 DataPermissionInterceptor 运行时差异提示 | 关 | 开启后 SELECT / UPDATE / DELETE 预览的警告区提示「运行时该拦截器会动态追加条件」 |
| 数据权限模拟条件 | 空 | 手动填写的 WHERE 片段（如 `dept_id IN (1,2,3)`），追加到 SELECT / UPDATE / DELETE 语句末尾，用于预览数据权限生效后的形态 |
| 预览面板内结构化渲染 EXPLAIN | 关（实验特性） | 默认走原生数据库控制台；开启后 MySQL 家族（表格行）与 PostgreSQL 家族（FORMAT JSON 树）的计划在预览面板内结构化渲染并附索引建议，其余方言与任何失败路径自动回退原生控制台（双通道并存） |
| 跨会话保留原始 EXPLAIN 计划 | 关 | 关闭时计划只在当前会话内可比；开启后按「项目 + 数据源 UUID + 方言 + 格式 + SQL 指纹」保存快照供下次对比，每条最多 5 份、单份上限 256 KiB。**默认关闭**：原始计划未脱敏，谓词可能含业务值与凭据；清除预览历史会一并删除已保留的计划。详见 [Wrapper → SQL 预览 · 跨次对比与计划历史](../features/wrapper-preview.md#跨次对比与计划历史) |
| 执行超时 | 30 秒 | 执行 / EXPLAIN 链的超时护栏（0 = 不限）：挂死的查询不再永远停在加载态，超时先请求取消再报错；多语句脚本的预算随语句数放大（封顶 8 倍） |
| 按数据源校正列名 | 开 | 实体字段名与库真实列名不一致时，用数据源真实列集合纠正预览 SQL 的列名；全局与项目级各有开关。详见 [Wrapper → SQL 预览 · 参数回填](../features/wrapper-preview.md#参数回填) |
| 空参数填充策略 | 占位符 `?` | 带签名信息的参数输入行留空时的填充方式，占位符 `?`（默认）/ NULL 字面量 / 空字符串三选一。详见 [XML / HQL 动态 SQL 预览 · 参数面板](../features/xml-preview.md#参数面板) |

::: details 方言智能推断的完整规则（何时看：需要固定方言或排查方言不符时）
推断只认 SQL 数据源——Redis 一类非 SQL 数据源不会被当成候选拉低共识。配置证据按来源模块收窄（多模块各自连不同库时不再互相挤成「无共识」），扫描排除测试资源目录（主库 PostgreSQL + 测试 H2 不再互斥），并优先采用激活 profile（`spring.profiles.active` / `include`，`${ENV:default}` 取默认值）；模块内无结论才回落项目级。日志与历史条目双击预览携带本次执行的方言，不再一律按 MySQL 渲染。兜底不再硬编码 MySQL：拿不到 IDE 数据源时按「配置里的 JDBC URL → 驱动坐标 → SQL 方言特征」取唯一共识，再退一级到项目 / 全局设置，状态行显示当前推断结果与来源。方言下拉首项即「智能推断」；升级语义：此前从未改过方言设置的老用户自动进入推断模式（原默认 MySQL），手动值原样保留。各方言的保留字均已按官方文档 / 引擎实测校准，H2 的 upsert 输出为原生 `MERGE INTO ... KEY` 形态。
:::

::: details 填充策略的选择依据（何时看：执行报错或疑似有参数没填时）
默认保留 `?` 待填提示，避免 NULL 静默过滤行（如 `amount >= NULL` 恒不匹配，不易察觉有参数没填）；需要可直接执行的 SQL 时切 NULL / 空字符串档。已持久化过 NULL / 空字符串的老用户保持原档。
:::

### 数据目录

历史 SQL 与执行临时文件保存在项目 `.idea/sql-visualizer/` 目录下（历史文件在其 `sql-history/` 子目录）。v2026.9.2 起该目录由旧名 `mybatis-plus-sql-visualizer` 更名而来，旧目录数据不再读取——升级后历史 SQL 从新目录起算。

「自动保存」组下方另有三个清理入口，边界各自独立：

| 入口 | 作用范围 |
|------|---------|
| 打开捕获历史目录 | 只在文件管理器中打开捕获历史目录，**不删除任何文件** |
| 清除预览 SQL 历史… | 清除预览历史（含收藏、标签与条目内参数快照），不动参数历史与命名方案 |
| 清除参数历史 / 预设… | 清除参数历史与命名方案；已打开面板的旧缓存与迟到写回一并失效 |

三者互不连带：清预览历史不会删参数快照，清参数历史也不碰历史文件。

## 禁用 API

「禁用 API」子页把团队那条「这几行代码不许写」的硬规则从评审时的 grep 搬进编辑器。规则跨项目共享（存 `mp-sql-visualizer-banned-api.xml`），改动即时生效，没有 OK / 应用按钮。

| 配置项 | 说明 |
|--------|------|
| 类 | 精确模式填全限定名（`com.acme.LegacyDao`）；正则模式按整串匹配（`com\.acme\..*`） |
| 匹配模式 | 精确 / 正则，决定「类」这一栏怎么读 |
| 方法名正则（可空） | 整串匹配；留空表示该类任意方法都算命中 |
| 级别 | 错误（标红）/ 警告（标黄） |
| 说明（必填） | 为什么禁用、应该改用什么——编辑器里的提示与扫描报告都直接引用这段文字 |

- 命中的方法调用在编辑器里标红或标黄，悬停显示你写的说明；单点认为没问题时用 `@SuppressWarnings("BannedApi")` 抑制
- **规则列表为空时零行为**：检查器不参与 daemon，不会因为装了插件就多出一堆提示
- 匹配按方法的**声明类**判定：覆写场景下规则要写子类；目前只覆盖 Java 调用点
- Tools 菜单「统计禁用 API 存量」对全项目 Java 文件做一次只读扫描，按规则汇总命中数并列出明细（上限 500 条），报告在编辑器打开；索引构建期间会提示稍后再试

## 外部 SQL 模板

给「SQL 不在 MyBatis 里」的项目用的兜底通道：像根节点 `<sqls>`、语句 `<sql id="…">`、`:命名参数` 这类自研模板，插件不认它的语法——你不必教插件，只要配一条自己的渲染命令，把它当函数用。默认关闭，关闭时 `sqlv_render_sql` 行为完全不变、不会启动任何进程。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 用外部命令渲染自研模板语句 | 关 | 总开关；关着时这条链一次都不走 |
| 语句标签名 | `sql` | 逗号分隔的 XML 标签名（如 `sql,query`），匹配不区分大小写；光标落在这些标签上时改走外部渲染 |
| 渲染命令 | 空 | 按参数列表启动（**不经 shell**），每个参数一个 token；含引号的参数用 `"…"` / `'…'` 括起来 |
| 超时（秒） | 10 | 限定 1 ~ 120，超时即强杀进程 |
| 工作目录 | 空 | 留空用项目根；填了不存在的目录也回落项目根 |

命令里可用的占位符：`{template}` 模板文件路径、`{sqlId}` 语句 id、`{paramsJson}` `sqlv_render_sql` 传入的参数 JSON（未传时为空串）。例如 `node scripts/render.js {template} {sqlId} {paramsJson}`。

几条边界要说清：命令在**你自己的机器上、以你的身份**执行，插件不校验内容、不做沙箱，等价于你手敲一条命令；只替换上面三个占位符，其余字符不经 shell 解释（所以通配符、管道、变量展开都不会生效）。命令失败、超时或输出为空时返回 `EXTERNAL_RENDER_FAILED`，不会静默回落到 mapper 逻辑给出一个看似正常的错答案。参数 JSON 原样交给命令，不写进任何日志或错误文本。

目前这条通道只作用于 MCP 的 `sqlv_render_sql`；编辑器里的 gutter 预览与面板预览仍按插件原生识别规则工作，不认自研模板。

## 项目级设置

`Settings > Tools > SQL Visualizer（当前项目）`在总开关之下提供 10 项覆盖：数据库方言、参数替换、SQL 格式化、逻辑删除注入、逻辑删除值、表前缀 / 表后缀、表名推断策略、忽略字段、按数据源校正列名（其中 4 项是勾选）。增强捕获属于全局设置，不在项目级覆盖范围内。

![SQL Visualizer 项目级设置页（Tools > SQL Visualizer（当前项目））：总开关未开启时下列各项置灰并显示全局生效值](/demo/settings-project.png)

- 总开关「使用项目设置」关闭时，10 项覆盖全部置灰并显示全局生效值——页面所见即运行时所用；「重置为跟随全局」一键清空本项目覆盖
