## 一、结论先行

站点的工程底子是扎实的：124 条内链全部可达、90 个演示资源零缺失、hreflang / canonical / JSON-LD / sitemap / Pagefind 搜索 / llms.txt 一应俱全，演示资产覆盖密度在同类插件站点里属于第一梯队。真正的问题不在「做得不够多」，而集中在三条线上：

1. **转化路径断在文档页**。48 个文档页没有任何安装入口——顶栏给了「需求池」「Bug 悬赏」位置，偏偏没有「安装」；功能页正文里 Marketplace 链接数为 0。搜索流量主要落在功能页，读者读完想装，只能自己想办法回去。
2. **可信度有几处硬伤**。「超过 1000 名开发者」没有任何出处且高于 Marketplace 实际下载量（687 次）；三条首页评价查无来源、Marketplace 评论区为 0，源码注释还写明星级 5/5/4 是刻意编排的；兼容性页声称支持 PyCharm / WebStorm / GoLand，而插件硬依赖 Java 模块，Marketplace 兼容列表里根本没有这几个 IDE。
3. **对外口径失真**。方言数一处一个说法（14 / 11 / 9 并存），版本号 SSR 与客户端各说各话（2026.10.31 vs 2026.10.30 会当着访客的面跳变）；线上 robots.txt 是 Cloudflare 托管版，把百度等中文爬虫全挡在门外——中文主站的中文搜索入口基本没了，而这一条在仓库里看不到。

围绕这三条线，本报告给出五路调研的全部证据，开发计划按「信任与口径治理 → 转化路径铺设 → 渠道与增长 → 体验打磨」四条主线排任务。

## 二、站内盘点（调研 A）

### 2.1 现状概览

- VitePress 1.6.4，`cleanUrls` + `lastUpdated` 开启，`srcExclude: ['docs/**']`（`.vitepress/config.mts:54-66`）；Pagefind 搜索索引 1.2MB；`vitepress-plugin-llms` 产出 llms.txt / llms-full.txt（423KB）。
- Cloudflare Pages 配套 Functions：`/api/changelog` 代理 Marketplace、`/feed.xml` 输出 RSS、`/api/v1/*` 转发反馈后台、`_middleware.js` 把两个旧域名 301 到新域名。
- 中英双语：zh 根目录 + `/en/` 镜像，文件清单一一对应（`scripts/check-en-parity.mjs` 只比对文件名，不比内容）。
- 插件版本单一来源 `.vitepress/data/plugin-version.json`（当前 `2026.10.31`），由 `scripts/sync-plugin-version.mjs` 写入，**取值优先读插件仓 gradle.properties**——这是口径失真的根因之一。

### 2.3 P0：影响转化或误导用户

**P0-1 文档页没有任何安装入口。**
顶栏导航只有 6 个站内链接（`config.mts:192-199`、`:276-283`），dist 抽查 features/mcp、sql-log、wrapper-preview、guide/faq、en/features/jpa-preview 五页，Marketplace 链接数都是 0；全站 markdown 里 Marketplace 链接只出现在 about/index、guide/compatibility、guide/getting-started 三页。

**P0-2 兼容性页的 IDE 范围断言与事实相反。**
`guide/compatibility.md:6` 写「同时兼容 IntelliJ 平台的其他 IDE（PyCharm、WebStorm、GoLand 等 2024.3+）」，英文页更写死「install fine」。而插件仓 `plugin.xml:85` 是硬依赖 `<depends>com.intellij.java</depends>`，Marketplace 兼容列表也没有这三个 IDE。用户按文档去装装不上，然后认定文档不靠谱。

**P0-3 「超过 1000 名开发者」无出处，且高于实际下载量。**
`homeContent.js:324`（中）、`:707`（英）。Marketplace 总下载 687 次，下载次数还不等于人数。开发者对数字敏感，去 Marketplace 一对，整页可信度连坐。

**P0-4 三条首页评价无法核验，星级是刻意编排的。**
`homeContent.js:226-232` 的源码注释原话：「星级不统一成五颗——三张全五星的整齐感本身像刷的；这里是 5 / 5 / 4」；副标题自称「三句来自实际使用的话」。评价只有昵称和首字头像，没有可点进去的出处；Marketplace 0 评论 0 评分。**此项需站长确认评价来源：属实则补出处，补不出则撤下——被识破的代价远大于它带来的转化。**

**P0-5 线上 robots.txt 屏蔽百度等中文爬虫，且无 Sitemap 行。**
2026-11-01 实测生产 robots.txt 是 Cloudflare 托管的 Content-Signal 版本：`Baiduspider / PetalBot / Bytespider / KimiBot / GPTBot / ClaudeBot / Google-Extended / CCBot` 全部 Disallow，无 `Sitemap:` 行。站点默认语言中文、专门做了 llms.txt 面向 AI 检索，robots 却把百度和多数 AI 爬虫挡在门外，方向自相矛盾。开关在 Cloudflare 控制台（托管 robots / AI 爬虫控制），仓库 `public/` 下没有 robots.txt。

### 2.5 P2：打磨项（摘要）

两处断锚（configuration → wrapper-preview 的「跨次对比」锚点中英都断）；compatibility「见关于页」指向不存在的内容；sql-to-java「四种形态」vs roadmap「五形态」；about 区 prev/next 与侧栏顺序不符；404 页只有中文；DocsShowcase 两个 alt 写死中文、与 FeatureAlternate 共用同一张 GIF；Wrapper 卡能力点误写 XML 动态标签；PricingSection 下载按钮漏挂 `trackDownload`；BadgeBar 与 SiteNotice 两个组件是死代码（前者挂的插槽在 `layout:false` 首页根本不渲染，徽章还是旧插件名）；61 张 PNG 海报（约 21MB）零引用（GifPlayer 已去海报层）、`cli-manager-logo.png` 820×820 只显示 40px；`/features/`、`/guide/` 分区首页 404；RSS 有 feed 无入口（head 里没有 `rel="alternate"`）；sql-log 中英标题层级漂移；英文首页离线包按钮指向 Gitee 而 GitHub 镜像有同版本 release；静态 roadmap 与需求池 RoadmapBoard 两套路线图并存；about/index 技术栈表写内部构建版本号（易过期）。

### 2.6 资产与完整性

- `public/demo` 共 151 个文件 83MB：69 个 GIF 共 56MB、80 个 PNG 共 26MB。体积 Top10 全是 GIF（jpa-derived-query 2.25MB 起步）。
- 124 条内链全部可达；38 条带锚点链接中 36 条有效；90 个 `/demo/` 引用零缺失零孤儿。
- 61 张未被引用的 PNG 全是 GIF 同名海报（P2 资产冗余项）。

### 2.7 空白缺失（同类站常见、本站没有的）

文档页常驻安装按钮；可核验的社会证明；可被收录的静态版本页（按版本分条 + 锚点）+ 首页「最近更新」模块；新版本公告条（SiteNotice 组件已有但未启用）；功能总览页（`/features/` 落地页）；站点隐私说明（站内埋点 + 收集反馈/悬赏邮箱，Marketplace 的 privacyPolicyUrl 也是空的）；MP4/WebM 视频格式演示；RSS 入口与周报订阅曝光；面向英文用户的社区渠道（只有微信二维码）；分人群上手路径（快速开始只讲 Wrapper，XML/JPA/只想看运行日志的用户没有第一步）。

### 2.8 未覆盖范围（如实登记）

移动端与真实浏览器渲染实测、插件能否真免重启安装、百度实际收录现状、GitHub star 数（API 限流）、Gitee Releases 下载次数（API 不提供）、首页评价真实来源（只能站长确认）。本地 dist 是 10-31 构建，README 页与 robots.txt 两项已在线上复核。

**排名公式**（官方文档明文）：搜索得分 = 相关性（ID/名称/描述/tags/vendor 名加权）× Staff-pick × `log10(1+5×下载)` × `sqrt(评分)`。代入：我们 log10(1+5×687)≈3.54、评分空缺；MyBatisX 7.44×sqrt(4.72)≈2.17，仅这两项就是我们的约 4.6 倍。**相关性与评分是唯二能主动改变的乘法项**；评分用贝叶斯平均（全站先验 4.06，要做量不凑单条五星）。

### 5.4 增长打法与渠道（E）

**案例共性**：MyBatisCodeHelperPro——长期、按大版本在同一社区反复露面（V2EX 送码帖 412 回复；同一篇不送码的版本帖 34 回复；转掘金 6014 阅读 2 赞），GitHub 仓库当公开问题追踪器；Rainbow Brackets——固定「月报」栏目比每版发公告省力，**反面教训：改变免费承诺会被评分记很久（44 条一星），长期免费就把「永久免费」写明当卖点**；Kasama/Show HN——105 分两年只换 841 下载，HN/PH 对本插件性价比极低；Clicknow 复盘——垂直社区远胜泛社区，付费导航站只值一条外链。**掘金规律：解决具体痛点的教程（5k~15k 阅读）远胜发布公告（6k 阅读 2 赞），收藏数高于点赞数（读者当工具书存）。**

**渠道优先级**（成本/预期均有实测依据，详见底稿 06 §四）：P0 = Marketplace listing 本身（相关度是唯一可快速改变的变量）+ 掘金痛点教程；P1 = CSDN/博客园同步、知乎老问题、awesome-mybatis-plus 提 PR（582 star，无 IDE 插件分区，提「新增分类」PR 且连带列 MyBatisX 等）、JetBrains Java Annotated Monthly 投稿（每月 20 日截稿，需英文文章）；P2 = V2EX（回复中位数 0，有预期）、B 站 30 秒短视频（64 张动图可直接剪）、公众号投稿、Gitee 推荐；不做 = Product Hunt、HN 首发、付费导航站、送东西换评分（官方审核规则明确禁止）。

**SEO 现状与机会**：这类词的 SERP 前排是 CSDN 教程和 Marketplace 插件页，**没有一个插件官网在承接**——官网做「问题页」是空位。18 个关键词（「mybatis 打印完整 sql」「mybatis log 插件 免费替代」「idea mybatis sql 预览」「mybatis plus wrapper 生成的sql 怎么看」「jpa 查看生成的sql」「sql 转 querywrapper」「不用 p6spy 打印 sql」等）与页面承接映射已列全（底稿 06 §三），重点：`features/sql-log` 标题改用户语言（如「MyBatis 日志转完整 SQL（问号自动替换参数）」）、`guide/comparison` 承接选型词（与 MyBatisX / MyBatis Log Free / p6spy 的可验证事实对比）、新增 2~3 篇问题页。

**评分冷启动（合规）**：自然评分要约几千下载才出一条（实测：CHP 约 7300 下载/条、MyBatisX 4.5 万/条），必须主动请——时机放在用户已得到价值之后（第 N 次成功预览后一次性气泡，带「不再提示」）；每期 change-notes 末行固定一句评分邀请（每次更新都触达的免费位）；官网 changelog / 反馈页底部放入口。红线：不附带任何奖励，负面反馈引导到需求池而不是拦着不让评；已解决评论不计分，认真回复差评是合规止损。
