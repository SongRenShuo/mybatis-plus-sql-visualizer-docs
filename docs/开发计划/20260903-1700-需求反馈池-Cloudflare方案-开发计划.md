## 一、项目定位

### 1.1 总体定位

`sql-visualizer-admin` 是 SQL Visualizer 插件的**云端管理后台**，采用 Cloudflare 边缘计算 + Serverless 数据库架构，以**需求反馈池**为切入点，逐步拓展为插件的完整运营支撑平台。

### 1.3 设计原则

- **模块化**：每个功能模块独立路由、独立表前缀、独立服务层，互不耦合
- **渐进式**：MVP 只上反馈池，架构预留模块注册机制，新功能即插即用
- **零运维**：Cloudflare 全托管，无服务器需维护
- **零成本优先**：免费额度内完成核心功能
- **边缘优先**：API 在全球边缘节点响应，延迟 < 50ms
- **类型安全**：TypeScript 端到端类型推导

```

    │
    ├── 静态资源 (VitePress HTML/CSS/JS) → Cloudflare Pages CDN 缓存
    │
    └── API 请求 (/api/v1/*) → 最近的边缘 Worker 节点
                                  │
                                  ├── 公开 API (feedback) → 直接查 D1 → 返回 JSON
                                  │
                                  └── 管理 API (admin/*) → JWT 验证 → 查 D1 → 返回 JSON
```

### 3.3 模块注册机制

```typescript
// src/modules/registry.ts
// 新模块只需实现 Module 接口并注册即可

interface Module {
  name: string;                    // 模块名: 'feedback' | 'analytics' | ...
  prefix: string;                  // 路由前缀: '/api/v1/feedback'
  router: Hono;                    // 模块路由实例
  init?: (db: D1Database) => Promise<void>;  // 初始化钩子（建表、种子数据）
}

const modules: Module[] = [
  feedbackModule,    // 需求反馈池
  // analyticsModule,  // Phase 2: 数据统计
  // contentModule,    // Phase 3: 内容管理
];

// 自动注册所有模块路由
modules.forEach(m => app.route(m.prefix, m.router));
```

## 四、数据库设计（D1 / SQLite）

### 4.1 设计规范

> **关于注释**：D1 基于 SQLite，不支持 MySQL 的 `COMMENT` 子句。使用标准 SQL 注释（`--` 单行 / `/* */` 块注释）在迁移文件中保留语义说明，随迁移文件版本化管理。

**表命名规范**：
- 表名统一小写下划线：`fb_posts`, `fb_votes`, `sys_admins`
- 模块前缀：`fb_` = feedback（反馈池），`sys_` = system（系统通用），未来 `an_` = analytics, `cm_` = content management
- 索引命名：`idx_表名_字段名`

### 4.2 建表语句

```sql
-- ========================================
-- 模块: feedback（需求反馈池）
-- ========================================

-- ----------------------------------------
-- 表: fb_posts
-- 描述: 反馈帖子主表，存储用户提交的需求、Bug、改进建议和使用问题
-- ----------------------------------------
CREATE TABLE fb_posts (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,    -- 自增主键
    post_no         TEXT    NOT NULL UNIQUE,              -- 展示编号，如 FR-0001，对外暴露
    title           TEXT    NOT NULL,                     -- 反馈标题，5-200 字符
    description     TEXT    NOT NULL DEFAULT '',          -- 详细描述，支持 Markdown 格式
    type            INTEGER NOT NULL DEFAULT 1,           -- 类型: 1=Feature 2=Bug 3=Improvement 4=Question
    status          INTEGER NOT NULL DEFAULT 1,           -- 状态: 见状态枚举
    category        TEXT,                                 -- 功能分类: wrapper/xml/annotation/sql-log/batch/completion/other
    vote_count      INTEGER NOT NULL DEFAULT 0,           -- 冗余计数字段，避免实时 COUNT
    comment_count   INTEGER NOT NULL DEFAULT 0,           -- 冗余计数字段，避免实时 COUNT
    submitter_name  TEXT,                                 -- 提交者昵称，非必填，展示用
    submitter_email TEXT,                                 -- 提交者邮箱，非必填，用于状态变更通知
    is_anonymous    INTEGER NOT NULL DEFAULT 1,           -- 是否匿名: 0=实名 1=匿名
    is_pinned       INTEGER NOT NULL DEFAULT 0,           -- 是否置顶: 0=否 1=是
    is_deleted      INTEGER NOT NULL DEFAULT 0,           -- 软删除标记: 0=正常 1=已删除
    source          TEXT    NOT NULL DEFAULT 'web',       -- 来源: web=网页 ide=IDE插件 import=导入
    ide_version     TEXT,                                 -- IDE 版本（In-IDE 提交时自动填充）
    plugin_version  TEXT,                                 -- 插件版本（In-IDE 提交时自动填充）
    extra_data      TEXT,                                 -- JSON 扩展字段，供未来模块复用
    created_at      TEXT    NOT NULL DEFAULT (datetime('now')),  -- 创建时间
    updated_at      TEXT    NOT NULL DEFAULT (datetime('now'))   -- 最后更新时间
);

CREATE INDEX idx_fb_posts_status_type ON fb_posts(status, type);
CREATE INDEX idx_fb_posts_category ON fb_posts(category);
CREATE INDEX idx_fb_posts_vote_count ON fb_posts(vote_count DESC);
CREATE INDEX idx_fb_posts_created_at ON fb_posts(created_at DESC);

-- ----------------------------------------
-- 表: fb_votes
-- 描述: 投票记录表，通过 post_id + fingerprint 联合唯一约束防重复投票
-- ----------------------------------------
CREATE TABLE fb_votes (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,        -- 自增主键
    post_id     INTEGER NOT NULL,                         -- 关联帖子 ID
    fingerprint TEXT    NOT NULL,                         -- 投票者指纹（IP+UA 的 SHA-256 前 16 位）
    created_at  TEXT    NOT NULL DEFAULT (datetime('now')),  -- 投票时间
    FOREIGN KEY (post_id) REFERENCES fb_posts(id),
    UNIQUE(post_id, fingerprint)                          -- 联合唯一：每人每帖一票
);

CREATE INDEX idx_fb_votes_post_id ON fb_votes(post_id);

-- ----------------------------------------
-- 表: fb_comments
-- 描述: 评论表，支持楼中楼回复（parent_id 指向父评论）
-- ----------------------------------------
CREATE TABLE fb_comments (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,        -- 自增主键
    post_id     INTEGER NOT NULL,                         -- 关联帖子 ID
    parent_id   INTEGER,                                  -- 父评论 ID，NULL 表示顶级评论
    content     TEXT    NOT NULL,                         -- 评论内容，支持纯文本或 Markdown
    author_name TEXT    NOT NULL,                         -- 评论者昵称
    author_role INTEGER NOT NULL DEFAULT 0,               -- 角色: 0=普通用户 1=管理员
    is_official INTEGER NOT NULL DEFAULT 0,               -- 是否官方回复: 0=否 1=是
    is_deleted  INTEGER NOT NULL DEFAULT 0,               -- 软删除: 0=正常 1=已删除
    created_at  TEXT    NOT NULL DEFAULT (datetime('now')),  -- 评论时间
    updated_at  TEXT    NOT NULL DEFAULT (datetime('now')),  -- 最后编辑时间
    FOREIGN KEY (post_id) REFERENCES fb_posts(id)
);

CREATE INDEX idx_fb_comments_post_id ON fb_comments(post_id, created_at);

-- ----------------------------------------
-- 表: fb_tags
-- 描述: 标签表，用于对反馈进行自由分类
-- ----------------------------------------
CREATE TABLE fb_tags (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,        -- 自增主键
    name        TEXT NOT NULL UNIQUE,                     -- 标签名称，唯一
    color       TEXT DEFAULT '#3b82f6',                   -- 标签颜色（十六进制）
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))   -- 创建时间
);

-- ----------------------------------------
-- 表: fb_post_tags
-- 描述: 帖子与标签的多对多关联表
-- ----------------------------------------
CREATE TABLE fb_post_tags (
    post_id INTEGER NOT NULL,                             -- 帖子 ID
    tag_id  INTEGER NOT NULL,                             -- 标签 ID
    PRIMARY KEY (post_id, tag_id),
    FOREIGN KEY (post_id) REFERENCES fb_posts(id),
    FOREIGN KEY (tag_id) REFERENCES fb_tags(id)
);

CREATE INDEX idx_fb_post_tags_tag_id ON fb_post_tags(tag_id);

-- ----------------------------------------
-- 表: fb_status_logs
-- 描述: 状态变更日志，记录每次状态流转的前后状态、原因和操作员
-- ----------------------------------------
CREATE TABLE fb_status_logs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,        -- 自增主键
    post_id     INTEGER NOT NULL,                         -- 关联帖子 ID
    from_status INTEGER NOT NULL,                         -- 变更前状态
    to_status   INTEGER NOT NULL,                         -- 变更后状态
    reason      TEXT,                                     -- 变更原因（尤其 Declined 时必须填写）
    operator    TEXT NOT NULL,                            -- 操作者（管理员用户名）
    created_at  TEXT    NOT NULL DEFAULT (datetime('now')),  -- 变更时间
    FOREIGN KEY (post_id) REFERENCES fb_posts(id)
);

CREATE INDEX idx_fb_status_logs_post_id ON fb_status_logs(post_id);

-- ----------------------------------------
-- 表: fb_notifications
-- 描述: 通知发送日志，记录每次推送的接收方、渠道、内容和状态
-- ----------------------------------------
CREATE TABLE fb_notifications (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,        -- 自增主键
    post_id     INTEGER,                                  -- 关联帖子 ID（可为空，如系统通知）
    type        TEXT    NOT NULL,                         -- 通知类型: new_feedback / status_update / official_reply
    channel     TEXT    NOT NULL,                         -- 推送渠道: pushplus_wechat / pushplus_mail / pushplus_webhook
    recipient   TEXT    NOT NULL,                         -- 接收方（邮箱地址或 pushplus topic）
    title       TEXT    NOT NULL,                         -- 通知标题
    content     TEXT    NOT NULL,                         -- 通知内容摘要
    status      INTEGER NOT NULL DEFAULT 0,               -- 发送状态: 0=待发送 1=成功 2=失败
    error_msg   TEXT,                                     -- 失败原因
    created_at  TEXT    NOT NULL DEFAULT (datetime('now'))  -- 创建时间
);

CREATE INDEX idx_fb_notif_post_id ON fb_notifications(post_id);
CREATE INDEX idx_fb_notif_type ON fb_notifications(type);

-- ========================================
-- 模块: system（系统通用）
-- ========================================

-- ----------------------------------------
-- 表: sys_admins
-- 描述: 管理员表，用于管理后台登录认证
-- ----------------------------------------
CREATE TABLE sys_admins (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,       -- 自增主键
    username     TEXT NOT NULL UNIQUE,                    -- 登录用户名，唯一
    password     TEXT NOT NULL,                           -- 密码（BCrypt 哈希，非明文）
    display_name TEXT,                                    -- 显示名称
    role         INTEGER NOT NULL DEFAULT 1,              -- 角色: 1=管理员 2=超级管理员
    is_active    INTEGER NOT NULL DEFAULT 1,              -- 是否启用: 0=禁用 1=启用
    created_at   TEXT NOT NULL DEFAULT (datetime('now')), -- 创建时间
    last_login   TEXT                                     -- 最后登录时间
);

-- ----------------------------------------
-- 表: sys_settings
-- 描述: 系统配置键值表，存储全局配置（如功能开关、API 密钥占位等）
-- ----------------------------------------
CREATE TABLE sys_settings (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,        -- 自增主键
    key         TEXT NOT NULL UNIQUE,                     -- 配置键，如 'feedback.enabled'
    value       TEXT,                                     -- 配置值（JSON 字符串）
    description TEXT,                                     -- 配置说明
    updated_at  TEXT    NOT NULL DEFAULT (datetime('now')),  -- 最后更新时间
    updated_by  TEXT                                      -- 最后更新者
);

-- ----------------------------------------
-- 表: sys_audit_logs
-- 描述: 操作审计日志，记录管理员的关键操作（状态变更、删除、配置修改等）
-- ----------------------------------------
CREATE TABLE sys_audit_logs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,        -- 自增主键
    module      TEXT    NOT NULL,                         -- 操作模块: feedback / system / ...
    action      TEXT    NOT NULL,                         -- 操作类型: status_change / delete / config_update
    target_id   TEXT,                                     -- 操作目标 ID（如帖子 post_no）
    operator    TEXT NOT NULL,                            -- 操作者（管理员用户名）
    detail      TEXT,                                     -- 操作详情（JSON）
    ip_address  TEXT,                                     -- 操作者 IP
    created_at  TEXT    NOT NULL DEFAULT (datetime('now'))  -- 操作时间
);

CREATE INDEX idx_sys_audit_module ON sys_audit_logs(module, created_at DESC);
CREATE INDEX idx_sys_audit_operator ON sys_audit_logs(operator);
```

## 五、推送通知设计（pushplus 集成）

### 5.1 pushplus 概述

- **API URL**: `http://www.pushplus.plus/send`
- **请求方式**: POST（推荐）
- **免费额度**: 大部分渠道免费，短信/语音收费
- **支持模板**: html（默认）、txt、markdown、json 等

### 5.2 推送场景与渠道

| 场景 | 目标 | 渠道 | 说明 |
|------|------|------|------|
| 管理员收到新反馈 | 管理员个人 | `channel=wechat` 或 `channel=webhook` | 微信模板消息或钉钉/飞书机器人 |
| 用户状态变更通知 | 用户邮箱 | `channel=mail` | 用户提交反馈时填写的邮箱 |
| 用户官方回复通知 | 用户邮箱 | `channel=mail` | 同上 |

### 5.3 推送接口封装

```typescript
// src/services/pushplus.ts

const PUSHPLUS_URL = 'http://www.pushplus.plus/send';

interface PushPlusPayload {
  token: string;       // 用户 token（从 pushplus 官网获取）
  title: string;       // 消息标题
  content: string;     // 消息内容（支持模板格式）
  topic?: string;      // 群组编码（一对多发送时填写）
  template?: string;   // 模板类型：html / txt / markdown
  channel?: string;    // 渠道：wechat / mail / webhook / qq / cp
  callbackUrl?: string; // 回调地址
}

/**
 * 调用 pushplus 发送消息
 */
export async function sendPushPlus(payload: PushPlusPayload): Promise<{ code: number; data: string }> {
  const res = await fetch(PUSHPLUS_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      template: 'markdown',  // 默认使用 markdown 模板
      channel: 'wechat',     // 默认微信渠道
      ...payload,
    }),
  });
  return res.json();
}

/**
 * 通知管理员：有新反馈提交
 */
export async function notifyAdminNewPost(token: string, post: {
  postNo: string;
  title: string;
  type: string;
  category: string;
  submitterName?: string;
}) {
  return sendPushPlus({
    token,
    title: `📬 新反馈提交 - ${post.postNo}`,
    content: [
      `**${post.title}**`,
      `- 编号: ${post.postNo}`,
      `- 类型: ${post.type}`,
      `- 分类: ${post.category}`,
      `- 提交者: ${post.submitterName || '匿名'}`,
      `- 链接: https://sql-visualizer.jvtools.cn/about/feedback/${post.postNo}`,
    ].join('\n'),
  });
}

/**
 * 通知用户：反馈状态变更
 */
export async function notifyUserStatusChange(token: string, email: string, post: {
  postNo: string;
  title: string;
  newStatus: string;
  reason?: string;
}) {
  return sendPushPlus({
    token,
    title: `SQL Visualizer 反馈状态更新 - ${post.postNo}`,
    content: [
      `您好！您提交的反馈有了新进展：`,
      ``,
      `**${post.title}**`,
      ``,
      `状态已更新为：**${post.newStatus}**`,
      post.reason ? `\n原因：${post.reason}` : '',
      `\n[查看详情](https://sql-visualizer.jvtools.cn/about/feedback/${post.postNo})`,
    ].join('\n'),
    channel: 'mail',  // 邮件渠道
  });
}
```

### 5.4 通知发送时机

```
用户提交反馈
    │
    ├── 写入 fb_posts 表
    ├── 写入 fb_notifications（status=0 待发送）
    │
    └── 异步推送（不阻塞响应）:
        ├── notifyAdminNewPost() → pushplus 微信/webhook → 管理员
        └── 不通知用户（刚提交无需通知）

管理员修改状态
    │
    ├── 更新 fb_posts.status
    ├── 写入 fb_status_logs
    ├── 写入 fb_notifications
    ├── 写入 sys_audit_logs
    │
    └── 异步推送:
        ├── 如果用户填了邮箱 → notifyUserStatusChange() → pushplus mail → 用户邮箱
        └── 不通知管理员（自己改的）

管理员添加官方回复
    │
    ├── 写入 fb_comments（is_official=1）
    ├── 更新 fb_posts.comment_count
    │
    └── 异步推送:
        └── 如果用户填了邮箱 → notifyUserOfficialReply() → pushplus mail → 用户邮箱
```

### 5.5 通知防重复与容错

| 策略 | 实现 |
|------|------|
| 幂等性 | 同一 post_id + type + recipient 在 5 分钟内不重复发送 |
| 失败重试 | fb_notifications 记录 status=2 失败，管理后台可手动重发 |
| 静默失败 | pushplus 调用失败不影响主流程，仅记录日志 |
| 频率限制 | 同一用户邮箱 24h 内最多 5 条通知 |

#### 反馈列表查询 (src/modules/feedback/routes.ts 核心逻辑)

```typescript
import { Hono } from 'hono';

const router = new Hono<{ Bindings: Env }>();

router.get('/posts', async (c) => {
  const db = c.env.DB;
  const { page = '1', size = '20', type, status, category, sort = 'votes', keyword, tag } = c.req.query();

  const conditions: string[] = ['is_deleted = 0'];
  const params: (string | number)[] = [];

  if (type) { conditions.push('type = ?'); params.push(Number(type)); }
  if (status) {
    const statuses = status.split(',').map(Number);
    conditions.push(`status IN (${statuses.map(() => '?').join(',')})`);
    params.push(...statuses);
  }
  if (category) { conditions.push('category = ?'); params.push(category); }
  if (keyword) { conditions.push('(title LIKE ? OR description LIKE ?)'); params.push(`%${keyword}%`, `%${keyword}%`); }

  const sortMap: Record<string, string> = {
    votes: 'vote_count DESC, created_at DESC',
    newest: 'created_at DESC',
    trending: 'vote_count DESC, created_at DESC',
  };
  const orderBy = sortMap[sort] || sortMap.votes;
  const offset = (Number(page) - 1) * Number(size);

  const { results } = await db.prepare(
    `SELECT post_no, title, type, status, category, vote_count, comment_count,
            submitter_name, created_at
     FROM fb_posts
     WHERE ${conditions.join(' AND ')}
     ORDER BY is_pinned DESC, ${orderBy}
     LIMIT ? OFFSET ?`
  ).bind(...params, Number(size), offset).all();

  const postsWithTags = await Promise.all(
    (results as PostRow[]).map(async (post) => {
      const { results: tags } = await db.prepare(
        `SELECT t.name, t.color FROM fb_tags t
         JOIN fb_post_tags pt ON pt.tag_id = t.id
         WHERE pt.post_id = (SELECT id FROM fb_posts WHERE post_no = ?)`
      ).bind(post.post_no).all();
      return { ...post, tags, hasVoted: false };
    })
  );

  return c.json({ code: 0, data: { items: postsWithTags, page: Number(page), size: Number(size) } });
});
```

#### 投票逻辑（防重复）

```typescript
router.post('/posts/:postNo/vote', async (c) => {
  const db = c.env.DB;
  const { postNo } = c.req.param();

  const ip = c.req.header('cf-connecting-ip') || 'unknown';
  const ua = c.req.header('user-agent') || 'unknown';
  const fingerprint = await hashFingerprint(`${ip}:${ua}`);

  const post = await db.prepare('SELECT id FROM fb_posts WHERE post_no = ? AND is_deleted = 0')
    .bind(postNo).first<{ id: number }>();
  if (!post) return c.json({ code: 404, message: '帖子不存在' }, 404);

  const existing = await db.prepare('SELECT id FROM fb_votes WHERE post_id = ? AND fingerprint = ?')
    .bind(post.id, fingerprint).first();
  if (existing) return c.json({ code: 400, message: '已投票' }, 400);

  await db.batch([
    db.prepare('INSERT INTO fb_votes (post_id, fingerprint) VALUES (?, ?)').bind(post.id, fingerprint),
    db.prepare('UPDATE fb_posts SET vote_count = vote_count + 1 WHERE id = ?').bind(post.id),
  ]);

  return c.json({ code: 0, message: '投票成功' });
});
```

// src/middleware/rate-limit.ts
export async function rateLimit(c: Context, next: Next) {
  const kv = c.env.KV;
  const ip = c.req.header('cf-connecting-ip') || 'unknown';
  const key = `rate:${ip}:${c.req.path}`;

  const count = await kv.get(key).then(v => Number(v || 0));
  if (count > 50) return c.json({ code: 429, message: '请求过于频繁' }, 429);

  await kv.put(key, String(count + 1), { expirationTtl: 3600 });
  await next();
}

## 九、安全设计

| 威胁 | 防护措施 | 实现方式 |
|------|---------|---------|
| 刷票 | 指纹去重 + 限流 | IP+UA hash，KV 计数 50 次/小时 |
| 恶意提交 | 频率限制 + Turnstile | 5 次/小时/IP，Cloudflare Turnstile |
| XSS | 输入转义 + 输出净化 | DOMPurify 渲染 Markdown |
| 管理爆破 | JWT + 登录限流 | BCrypt 哈希，登录 5 次/小时/IP |
| 数据泄露 | API 字段白名单 | 列表/详情接口排除 submitter_email |
| 通知轰炸 | 频率限制 + 去重 | 同一邮箱 24h 最多 5 条 |
| Token 泄露 | Secret 注入 | pushplus token 通过 wrangler secret put |
| DDoS | Cloudflare 原生防护 | 自动，无需配置 |
| CSRF | CORS 白名单 | 仅允许 jvtools.cn 来源 |
| 审计追踪 | 操作日志 | sys_audit_logs 记录所有管理操作 |

### JWT 认证流程

```
管理员登录
    → POST /api/v1/admin/login { username, password }
    → 后端 BCrypt 验证
    → 签发 JWT (HS256, 2h 过期)
    → 前端存 sessionStorage
    → 后续请求 Header: Authorization: Bearer <token>
    → 中间件验证签名 + 过期时间
```

## 十三、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| D1 与 MySQL 语法差异 | 中 | 需调整 SQL | 避免高级特性，用标准 SQL |
| 免费额度超限 | 低 | 服务中断 | 设置告警；付费 $5/月起 |
| TypeScript 学习曲线 | 中 | 开发速度 | Hono 极简，1 天上手 |
| pushplus 不可用 | 低 | 通知失败 | 日志记录，可手动重发 |
| 邮件进垃圾箱 | 中 | 用户收不到 | 使用 pushplus 官方邮件渠道 |
| Vendor Lock-in | 中 | 迁移成本 | SQL 标准，迁移只需改连接层 |
| 模块间耦合 | 低 | 维护困难 | 严格模块前缀 + 独立表 + 独立路由 |

## 十四、核心设计原则

- **模块化架构**：每个功能模块独立路由、独立表前缀、独立服务层
- **渐进式演进**：MVP 只上反馈池，新功能即插即用
- **零成本优先**：免费额度内完成所有功能
- **零运维**：无服务器需管理，D1 自动备份
- **边缘优先**：API 在全球边缘节点响应
- **类型安全**：TypeScript 端到端类型推导
- **最小依赖**：Hono + 标准 Web API，无重型框架
- **安全默认**：限流、JWT、审计日志、字段白名单
