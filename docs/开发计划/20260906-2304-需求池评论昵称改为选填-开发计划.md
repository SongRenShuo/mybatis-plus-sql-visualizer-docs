# 需求池评论昵称改为选填 开发计划

- 日期：2026-09-06 23:04
- 范围：文档站前端 `FeedbackDetail.vue` + 后端 `sql-visualizer-admin` 评论接口
- 背景：用户要求需求池的需求评论，昵称不要强制填写。当前前后端都强制昵称，不填无法评论。

## 现状分析

- 前端 `FeedbackDetail.vue` 评论表单：
  - 提交按钮 `:disabled="!commentName || !commentContent.trim()"`——昵称为空直接禁用；
  - `submitComment()` 守卫 `if (!commentName.value || ...) return`；
  - 昵称输入框 placeholder 硬编码「昵称」。
- 后端 `sql-visualizer-admin/src/modules/feedback/routes.ts` `POST /posts/:postNo/comments`：
  - `if (!body.authorName || body.authorName.trim().length < 1) return 400 '请填写昵称'`；
  - 管理员推送 `notifyAdminNewComment` 与 `logNotification` 直接使用 `body.authorName.trim()`。
- D1 表 `fb_comments.author_name` 为 `TEXT NOT NULL`（migrations/0001_init.sql），空昵称不能落 NULL。
- 站点已有「匿名」显示约定：匿名发帖在详情接口返回 `'匿名'`，详情页作者展示 `post.submitterName || '匿名'`。

## 改动方案

### T1 后端 routes.ts：昵称改为选填，空值落「匿名」

- 删除 400「请填写昵称」校验；昵称解析为 `const authorName = (body.authorName || '').trim() || '匿名';`。
- INSERT 与管理员推送/通知日志统一使用 `authorName`（不再直接引用 `body.authorName`）。
- 无数据库迁移：`NOT NULL` 列写入 `'匿名'` 合法，历史数据不受影响。

### T2 前端 FeedbackDetail.vue：解除昵称强制

- 提交按钮禁用条件改为 `!commentContent.trim()`；`submitComment()` 守卫同步放开。
- `authorName` 传 `commentName.value.trim() || undefined`（空则不传字段）。
- 昵称输入框 placeholder 改用 i18n 既有键 `formName`（「昵称（选填）」/「Name (optional)」），复用 `t()`，组件已引入，无 i18n.ts 改动。
- 评论作者展示兜底 `c.author_name || '匿名'`，防御历史或异常空值。

## 接口契约（前后端对齐）

`POST {apiBase}/feedback/posts/:postNo/comments`

- 请求：`{ content: string, authorName?: string }`——`authorName` 变为可选；评论内容校验不变（trim 后 ≥2 字符）。
- 响应：成功 `{ code: 0, message: '评论成功' }`；昵称缺失不再 400，后端以 `'匿名'` 落库。
