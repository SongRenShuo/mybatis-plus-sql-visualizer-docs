# 功能详解页演示图手机端过小修复 — 开发计划

- 来源：用户 2026-09-20「手机端也确认下」→ 复核生产域发现功能详解页未被上一次首页修复覆盖
- 前置：`docs/开发计划/20260920-1230-首页功能卡手机端演示图过小修复-开发计划.md`（首页已修好并验证）
- 涉及仓库：文档站（分支 `t-home-mcp-feature`）
- 性质：**移动端排版缺陷**，与首页同源（水平内边距叠加），非动图资产问题

## 一、现象（生产域实测，390×844 视口）

`/features/mcp` 三张图宽度：

| 图 | 宽度 | 左偏移 |
| --- | --- | --- |
| `mcp-overview.svg`（开篇） | 279 | 48 |
| `mcp-agent.gif`（典型工作流） | 277 | 49 |
| `mcp.gif`（设置页门控） | 277 | 49 |

375px 视口里内容区只有 **279px**（`div.content-container` 链实测）。1280×920 的 IDE 截图压到约 22%，
文字不可读、动图动作看不出来。

**上一次修复未覆盖这里**：那条规则的选择器是 `.feature-video-wrapper`（首页组件 `FeatureAlternate.vue` 私有类），
功能详解页走的是 `<GifPlayer>`（全局类 `.mp-gif-player`），两者不相干。

## 二、根因

与首页同源，只是内边距来源不同：功能页的内缩来自 **VitePress 主题自身的 `.VPDoc` / `.container` 水平内边距**
（实测两侧各 48px，合计 96px），`.mp-gif-player` 又带 `width: 100%`，于是图片只能拿到 279px。

## 三、修复方案

窄屏让演示图整行出血，**同时必须加宽盒子**——组件根元素带行内 `width: 100%`（`:style="{ width: width || '100%' }"`），
只给负边距会把盒子整体左移、右侧溢出：

1. **`GifPlayer.vue`**：行内宽度只在调用方显式传 `width` 时才写
   （`:style="width ? { width } : undefined"`），默认宽度交回 CSS——28 处调用均未传 `width`，行为不变；
2. **`style.css`**：`.mp-gif-player` 补 `width: 100%`，并加窄屏媒体查询：

```css
@media (max-width: 767px) {
  /* 手机端演示图整行出血：抵消 VitePress 主题两侧各 48px 的水平内边距（实测内容区仅 279px）。
     width 用 calc 同步加宽——只给负边距会把盒子左移并右侧溢出。 */
  .mp-gif-player {
    width: calc(100% + 96px);
    margin-left: -48px;
    margin-right: -48px;
  }
}
```

选 `calc(100% + 96px)` 而不是 `100vw`：`100vw` 含滚动条宽度，会引入横向溢出。

## 四、验收标准

1. 390px 视口下 `/features/mcp` 三张图宽度 ≥ 370px（整行出血）；
2. 360px / 320px 下 `documentElement.scrollWidth` 等于视口（无横向溢出）；
3. 桌面端（1280px）三张图宽度与修复前一致（279/277/277 → 桌面为 688 内宽下的原值）；
4. `npm run build` 通过，产物 CSS 含新规则；
5. 生产域部署后逐项复测，并补手机端截图供验收。

## 五、风险

| # | 风险 | 应对 |
| --- | --- | --- |
| R1 | 去掉行内默认宽度影响其它页面布局 | 28 处调用均未传 `width`，默认值由 `100%` 行内改为 CSS `100%`，等价；构建后抽查若干功能页图片宽度 |
| R2 | 负边距 + calc 在极窄屏溢出 | 出血量等于实测内边距和（96px），父级为满宽容器；部署后实测 360/320px |
| R3 | 影响首页卡片（同名类？） | 首页用 `.feature-video-wrapper`，与 `.mp-gif-player` 无交集；部署后复测首页七张卡宽度仍为 375px |
| R4 | `!important` 若改用会掩盖层叠问题 | 本方案不引入 `!important`（改为收窄行内样式），层叠保持可读 |

## 六、实施状态

**2026-09-20 已实施、已测试、已部署、已验证。**

- **改动**（分支 `t-home-mcp-feature`）：
  1. `GifPlayer.vue`：行内宽度改为仅在调用方显式传 `width` 时写（`:style="width ? { width } : undefined"`），
     默认宽度交回 CSS；
  2. `style.css`：`.mp-gif-player` 补 `width: 100%` + 窄屏出血媒体查询；
  3. **追加**（首轮部署后复验发现）：开篇示意 SVG 是 md 里 `![]()` 写的、不走 GifPlayer，渲染成 `p > img`，
     上一条覆盖不到（实测仍 279px）→ 补 `.vp-doc p > img[src^="/demo/"]` 同款规则，
     并同时 `max-width: none`（VitePress 默认 `img{max-width:100%}` 会把宽度钳在父级）。
- **测试**：`npm run build` 通过；产物 CSS 实证含
  `.mp-gif-player{width:calc(100% + 96px);margin-left:-48px;margin-right:-48px}` 与
  `.vp-doc p>img[src^="/demo/"]{max-width:none;width:calc(100% + 96px);...}`（均在 `max-width:767px` 块内）。
- **部署**：两次 `npm run deploy`（先 GifPlayer、后 SVG 补丁），生产域 `sql-visualizer-docs.pages.dev`。
- **验证（生产域实测）**：

| 视口 | 示意 SVG | `mcp-agent.gif` | `mcp.gif` | `scrollWidth` | 横向溢出 |
| --- | --- | --- | --- | --- | --- |
| 390 | **375** | **373** | **373** | 375（= body） | 无 |
| 320 | **320** | **318** | **318** | 320（= 视口） | 无 |
| 1280（桌面） | 576 | 574 | 574 | 1265 | 无 |

  修复前 390 视口三张分别为 279 / 277 / 277。
- **回归复核**：首页七张卡仍为 375px、`scrollWidth` 375（新规则限定 `.vp-doc`，首页自定义布局不匹配）；
  桌面端三张图宽度为居中自然宽（576/574/574），与修复前一致（媒体查询只在 `max-width:767px` 生效）。
- **验收标准对照**：① 390px 下三张 ≥370 ✅；② 320px 无溢出 ✅；③ 桌面端一致 ✅；④ 构建含新规则 ✅；
  ⑤ 生产实测 + 手机端截图已出 ✅。
