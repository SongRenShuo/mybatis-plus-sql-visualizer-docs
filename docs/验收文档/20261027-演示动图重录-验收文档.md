## 三、方言闸门语义分歧（**需用户裁决**）

计划 P2/P7 预期「方言不一致 → 提示 + SQL 仍送达 + 数据库原生报错」（10-25 用户定案
「提示但不拦」）。**实测 master（f559049e，今晚 runIde 重建的在役包）为拦截语义**：

- 预览由手动方言 PostgreSQL 渲染 + 模块上次使用数据源为 MySQL 时，点「执行 SQL」→
  红色「已阻止执行：当前 SQL 由手动方言 PostgreSQL 渲染，所选数据源是 MySQL…」+
  「切换数据源」「方言设置」「复制错误信息」三出口（GIF 已按此录制）
- 「切换数据源」出口打开 Database 工具窗（无弹窗选择器）；拦截时插件会自动唤起
  Database 窗（GIF 里入镜属真实行为）
- 未绑定模块（jpa-hibernate-demo）的执行路径为**按目标方言重映射后直接送达**
  （`FROM "user"` 被重映射成 `` FROM `user` ``），全程无提示

三个可能：插件在 10-25 之后被回退/覆盖（回归，需修插件）、放行仅存在于某条
未复现的路径、或语义已改（需改文档正文）。**文档站正文（wrapper-preview.md
「方言与数据源不匹配」节）仍写「只提示、不拦执行」**，与新增 GIF 的拦截画面冲突；
等裁决后二选一：修插件恢复放行后重录，或按拦截语义改写正文（改动量约 3 段）。

### 3.1 溯源结论（2026-10-27 补，先于裁决）

**没有被覆盖**。10-25 的放行修复（8619a3af，改 `DataSourceSelector.allowDialectGate`：
MANUAL_CONFLICT 提示后 `return true`）完整在役，之后仅 e7a27700 动过同目录。

真相是**两套闸门并存、语义不一致**：

| 路径 | 代码位置 | 手动方言 + 目标源冲突时 |
|---|---|---|
| 选择器手选数据源 | `DataSourceSelector.allowDialectGate`（8619a3af） | **放行**（提示后 `return true`） |
| 预览面板「执行 SQL」入口 | `SqlPreviewPanelExecution.onExecutionDialectGate`（T-DialectGateUx，后加） | **阻断** + 就地出口 |

从预览直接点「执行 SQL」走到的是后者 → GIF 按实际拦截录制。另：提示文案本身仍以
「已阻止执行：…」开头（bundle `execute.dialectGate.manualConflict`），在放行路径上
这句文案与实际行为不符。

### 8.3 本轮新增的两条可复用结论

1. **原生保存框会开在 IDE 后面**（任务栏可见、屏幕不可见）：按屏幕坐标点「保存(S)」

2. **录制区整段变白 = 前台被抢**，不是画面元素问题：保存框/文件对话框关闭的空档
   Chrome 会夺走前台，屏幕录制抓到的就是浏览器。判定法＝按亮度扫帧
   （灰度均值 >110 且连续多帧）；处置＝保存后立刻 `ensure_foreground` 并**校验前台句柄**，
   不要用不校验的 `SetForegroundWindow`。
