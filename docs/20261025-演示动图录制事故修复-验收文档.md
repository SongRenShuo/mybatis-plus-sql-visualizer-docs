## 一、验收判据

每张图给三个硬读数 + 一句画面判词：

| 读数 | 阈值 | 怎么取 |
|---|---|---|
| 宽 | 1280 | `Image.open(gif).size[0]` |
| 时长 | 6~15s | `duration × n_frames` |
| 体积 | ≤2MB | 文件大小 |
| 四边无白边 | 四边各 4px 带均值 <120 | 裁一张 `shot(REGION)` 算边缘亮度 |
| 首尾同态 | 视觉一致 | 抽首帧与尾帧目视比对 |

## 三、本轮修掉的系统性根因

| # | 根因 | 影响的图 | 修法 |
|---|---|---|---|
| 1 | **IME 未切英文**：`typewrite` 在中文态被转成候选框，汉字进了演示数据 | code-completion / annotation-preview | `nav.force_en_us()`（`LoadKeyboardLayoutW('00000409')` + `PostMessage(WM_INPUTLANGCHANGEREQUEST)`）；只调 `ActivateKeyboardLayout` 无效 |
| 2 | **Ctrl+G 输入框留在画面里**：`goto` 的 Enter 被 IME/时序吞掉，当时的像素护栏判不准（弹窗本体是深灰，与编辑器只差 3~5 个灰度级，实测恒判 False） | batch-operation / jpa-write-path / jpa-embedded | `goto_col` 末尾**无条件按 Esc**——跳转已生效，Esc 只关输入框 |
| 3 | **预览弹窗渲染中间态**：等 1.2~2.6s 不够，弹窗要 ~3s 才画完，中途开录会录到半透明错位 | jpa-write-path / jpa-criteria | 预览等待统一提到 3.4~3.6s |
| 4 | **构图错位与白边**：窗口外框与 REGION 没对齐（顶部切 20px）；照外框录进了 8px 圆角阴影 | 全部 | 外框对齐 `(277,25,1370,984)` + 录制区内缩 8px → `(285,26,1354,974)` |
| 5 | **凝视段被当静止裁掉**：裸屏捕获不含光标，纯 `moveTo` 零像素变化，assemble 裁完只剩 3.1s | jpa-criteria | 改成真实交互（粘贴参数值让 SQL 实时变化），兼顾演示效果 |
| 6 | **开错同名文件**：demo 工程里 `UserMapper.xml` / `UserMapper.java` / `UserRepository.java` 都有重名 | 本轮踩了 3 次 | 新增 `record/mcpnav.py`，走 IDE 内置 MCP `open_file_in_editor` 按路径精确打开 |
