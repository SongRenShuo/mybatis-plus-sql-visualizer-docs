# 需求池：首页入口 + 看板默认与中文标签优化 开发计划

- 立项时间：2026-09-04 01:15
- 实施状态：待排期
- 涉及项目：mybatis-plus-sql-visualizer-docs（公开站点，反馈池前端）+ sql-visualizer-admin（Cloudflare Workers + D1 + Hono，反馈池后端）
- 目标：把需求池入口提到官网首页顶部导航，进入后默认展示看板而非列表；优化看板的信息密度与可读性；前后端所有文字标签默认显示中文。

---

## 一、背景

需求反馈池自部署上线后，入口藏在「关于 > 需求反馈池」侧边栏里，普通访客几乎发现不了，社区投票的初衷没能实现。同时默认打开是列表视图，看板内容单薄，状态列还是英文，与全站中文基调不符。

本次要解决的三个体验问题：

1. 入口层级太深，需要把需求池提到首页顶部导航。
2. 默认视图是列表，不利于快速浏览「规划中 / 进行中 / 已完成」的整体进展，应改为默认看板。
3. 看板信息量不足、可读性差；且类型、状态、表单选项等一大批文字标签在中文环境下仍显示英文。

因为标签枚举（类型、状态）的英文映射同时存在于后端常量表和多个前端组件里，做中文默认必须前后端一起梳理，这正是本计划要一并评估的部分。

---

## 二、现状诊断

### 2.1 前端（docs 站点）现状

需求池由 `about/feedback.md` 挂载 `FeedbackPage.vue` 承载，内部再拆成 `FeedbackPool.vue`（列表/看板切换、筛选、统计）、`FeedbackForm.vue`（提交表单）、`FeedbackDetail.vue`（详情）、`RoadmapBoard.vue`（看板）、`StatusBadge.vue`（状态徽章）、`VoteButton.vue`（投票）、`i18n.ts`（文案表）。

**问题一：入口太深**
官网首页使用自定义 `CoolHome.vue` + `NavHeader.vue`，顶部导航只有「功能详解 / 使用指南 / 关于」三项，没有需求池入口。VitePress 全局导航（`config.mts` 的 `themeConfig.nav`）同样只有四项。需求池只能从「关于」侧边栏的「需求反馈池」进入，等于整个功能对首页访客不可见。

**问题二：默认是列表**
`FeedbackPool.vue` 中 `const view = ref<'list' | 'board'>('list')`，默认列表视图，用户需要手动切到看板。

**问题三：看板信息单薄、主题不统一**
`RoadmapBoard.vue` 的现状问题：

- 只展示状态 2~5 四列（Under Review / Planned / In Progress / Completed），把「待提交(1)、已拒绝(6)、重复(7)」全部丢弃，属于信息残缺。
- 每张卡片只有 点赞数 + 标题 + 类型图标 + 编号，没有状态标签、置顶标识、分类、类型文字，信息密度很低。
- 列的三色是写死的 `#f59e0b / #3b82f6 / #8b5cf6 / #10b981`，与全站 CSS 变量（`--vp-c-*`）没有打通，暗色模式下出不来。
- 没有置顶（`is_pinned`）标识，后端列表已经按置顶排序但前端没展示。
- 4 列固定栅格在小屏下才降级，中屏（平板）可读性差。

**问题四：中文默认缺失（多组件硬编码英文）**
中文环境下一大批标签仍是英文，且来源分散：

| 位置 | 硬编码英文 | 说明 |
|------|-----------|------|
| `FeedbackPool.vue` | `statusOptions` / `typeOptions` 的 `label` | 状态、类型下拉直接写英文 |
| `StatusBadge.vue` | `statusMap` 的 `label` | 状态徽章显示英文 |
| `FeedbackDetail.vue` | `statusLabels` | 状态时间线显示英文 |
| `FeedbackForm.vue` | `types` 数组 `label`、`categories` 数组 | 类型选项英文；分类显示 slug（wrapper/xml…） |
| `RoadmapBoard.vue` | `columns` 的 `label` | 看板列名英文 |
| `i18n.ts` zh 区 | `'type.*'`、`'status.*'` | 中文文案表里类型/状态本来就是英文 |
| 后端 API | `typeLabel` / `statusLabel` | 返回体里带的是英文标签 |

更深一层：后端 `/feedback/posts` 返回的 `typeLabel` / `statusLabel` 字段是英文，部分组件（`FeedbackDetail`）直接信任后端标签，前端 `i18n.ts` 根本管不到它。所以「默认中文」必须前端统一映射 + 后端标签一起处理，否则总会漏一块。

### 2.2 后端（sql-visualizer-admin）现状

- `src/modules/feedback/constants.ts`：`PostTypeLabels`、`PostStatusLabels` 全部英文；`PostStatusColors` 是十六进制色值。这些标签随 `/posts`、`/posts/:postNo` 返回给前端。
- `src/modules/feedback/routes.ts`：
  - `/posts` 返回 `typeLabel`、`statusLabel`，并 `ORDER BY is_pinned DESC`（排序逻辑已存在）但没有把 `isPinned` 一并返回给前端，置顶无法展示。
  - `/stats` 已返回 `statusStats`（按状态计数）+ `typeStats` + `totalPosts` + `totalVotes`，看板顶部完全可以直接消费。
  - `/analytics` 已提供 `categoryStats / sourceStats / dailyStats / versionStats`，可用于给看板 / 统计做增强，但当前前端没用上。
- 管理后台 SPA（`admin/`）：`api/index.ts` 的 `STATUS_MAP`、`TYPE_MAP` 同样英文；`Dashboard.vue` 统计卡（总反馈/总投票/评估中/已完成）已是中文，但「状态分布」表里状态名走英文 `STATUS_MAP`，与四周中文混排。

一句话总结后端：数据能力（统计、置顶、分类、趋势）其实都齐了，缺的是把标签默认成中文、以及把 `isPinned` 这些字段透出。

---

## 三、目标与范围

### 3.1 必须实现

1. 需求池入口出现在官网首页顶部导航（自定义首页 `NavHeader` + VitePress 全局导航均需加）。
2. 进入需求池默认展示「看板」视图，而不是列表。
3. 看板信息密度与可读性显著提升：列覆盖全部 7 种状态、卡片补状态/置顶/类型文字/分类、列色接入主题变量。
4. 需求池所有文字标签默认显示中文（类型、状态、分类、表单占位、列名、统计文案等），英文仅作为可切换的第二语言保留。

### 3.2 一并评估（结合后台自动化比）

- 后端抽一组前端可复用的中文标签映射，前端不再各自硬编码英文。
- 后端把 `isPinned` 返回给前端，支持看板置顶展示。
- 管理后台自身的中文标签修正（`STATUS_MAP` / `TYPE_MAP`），保持前后台口径一致。

### 3.3 不做

- 不改后端数据模型与表结构，不动 D1 迁移。
- 不为看板新增后端接口；置顶、统计、分类等用现有接口补齐字段即可。
- 不做真正的拖拽排序、实时协作等高成本交互。

## 四、方案设计

### 4.1 首页顶部导航加入口

两条导航来源都要改，保持文案一致「需求池」：

- **自定义首页 `NavHeader.vue`**：在 `class="nav-links"` 里加一项 `<a href="/about/feedback" class="nav-link">需求池</a>`，排在「关于」之前。
- **VitePress 全局导航 `config.mts`**：在 root 和 en 两个 `nav` 数组里都加 `{ text: '需求池' / 'Feedback', link: '/about/feedback' }`，保证从任何文档页也能点到。

可选项（建议做）：给需求池这个词配一个主题色高亮？不需要，普通链接即可；但可给该链接加一个小「投票」角标徽章提示有社区投票功能，避免和「关于」混在一起。

### 4.2 默认看板视图

`FeedbackPool.vue` 把 `view` 初值改为 `'board'`：

```ts
const view = ref<'list' | 'board'>('board')
```

同时把「列表 / 看板」切换按钮的顺序与默认选中态跟随初值即可（现状按钮高亮由 `:class={ active: view === 'board' }` 自动适配，无需额外改）。这样首页点进来第一眼就是看板。

### 4.3 看板优化（RoadmapBoard.vue 重构）

目标：一眼看懂「每条反馈现在处于什么阶段、有多少人支持、哪里置顶了」。

**列覆盖全部状态**
不再写死 4 列，改为 5 列（保留「提交待审 UNDER_REVIEW=2」合并进看板主语）或 7 列（全状态）？建议中间态：默认展示 2~5 + 1 待审合并，把 6、7（已拒绝/重复）叠成一个「已关闭」列，这样既不丢信息又不占太多横向空间。列定义：

| 状态 | 列名（默认中文） | 主题色变量 |
|------|-----------------|-----------|
| 1 待审 | 待审 | 中性 `--vp-c-text-2` |
| 2 评估中 | 评估中 | 橙 `#f59e0b` |
| 3 已规划 | 已规划 | 蓝 `#3b82f6` |
| 4 进行中 | 进行中 | 紫 `#8b5cf6` |
| 5 已完成 | 已完成 | 绿 `#10b981` |
| 6/7 已关闭 | 已关闭 | 灰 `--vp-c-text-3` |

实现上把「状态 → 列分组」从写死的 `columns` 改为一套映射 + 一个分组函数，中文标签走 `i18n.ts` 的 `status.*`，颜色接入主题变量（浅色用固定色值，暗色用 `--vp-c-*` 或透明度）。

**卡片信息补齐**
每张卡片按此结构展示（从多到少）：

- 置顶标识：`isPinned` 为真时，卡片左上角加一个小「📌 置顶」或图标。
- 标题（保留两行截断）。
- 副行：点赞数 + 类型文字（不再是裸图标）+ 分类（中文，若存在）+ 编号。
- 评论数（可选，有数据时显示）。

**数据获取**
看板从 `FeedbackPool` 传入的 `postsForBoard` 已带 `postNo/title/type/status/voteCount`，需补 `isPinned / commentCount / category / typeLabel`，`postsForBoard` computed 补映射即可。状态分组 + 置顶排序建议在 `FeedbackPool` 里统一算好传给 `RoadmapBoard`，按「置顶 > 投票数」排列。

### 4.4 中文标签统一（前后端一起）

这是这次最散、也最容易漏的部分，核心思路是 **「一份中文映射，前端不再各自硬编码」**。

**后端先行**（sql-visualizer-admin，保证 API 与后台口径一致）：

- `constants.ts`：新增默认中文映射（可按需拆 `zh` / `en` 两组，或默认中文、`?lang=en` 再出英文）：

  | 类型值 | 中文 | 状态值 | 中文 |
  |-------|------|-------|------|
  | 1 功能需求 | 功能需求 | 1 | 待审 |
  | 2 Bug | Bug | 2 | 评估中 |
  | 3 体验优化 | 体验优化 | 3 | 已规划 |
  | 4 疑问咨询 | 疑问咨询 | 4 | 进行中 |
  | | | 5 | 已完成 |
  | | | 6 | 已拒绝 |
  | | | 7 | 重复 |

  注：`type`/`status` 数值保持不动，只改标签文案；前端不能依赖 `typeLabel`/`statusLabel` 做逻辑。
- `routes.ts`：`/posts` 与 `/posts/:postNo` 的查询 SELECT 补齐 `is_pinned`，返回体加 `isPinned: !!post.is_pinned`（`/posts` 列表每条也要带）。
- `admin/src/api/index.ts` 的 `STATUS_MAP` / `TYPE_MAP`：`label` 改成对应的中文，`Dashboard.vue` 状态分布表即恢复全中文。

**前端统一**（docs 站点，`i18n.ts` 成为唯一文案源）：

- `i18n.ts` zh 区：把 `'type.feature'…`、`'status.1'…'status.7'` 都改成中文文案；en 区保持英文。
- `FeedbackPool.vue`：删除 `statusOptions / typeOptions` 里的英文 label，改为引用 `t('status.n')` / `t('type.x')`，筛选下拉全中文。
- `StatusBadge.vue`：接收 `locale`（或复用 i18n），`statusMap` 保留颜色，label 走 `t('status.n')`。组件由 `FeedbackPool/FeedbackDetail` 传入当前 locale。
- `FeedbackForm.vue`：`types` 数组 label 走 `t('type.x')`；`categories` 改为中文显示（类别 slug → 中文文案，如 wrapper→Wrapper 预览、xml→XML 预览…），提交时仍发送原始 slug。
- `FeedbackDetail.vue`：`statusLabels` 改用 `t('status.n')`；新增类别中文映射；评论/状态时间线的其他文案已是中文，保留。
- `RoadmapBoard.vue`：列名走 `t('status.n')`，卡片附加信息做中文映射。

**locale 怎么定**
现状组件有个 `zh/en` 切换按钮，但站点本身就是 `zh-CN` 为主。建议：默认 `locale = 'zh'`（已满足），中英切换保留但跟随站点语言（可从 `useData().lang` 或 URL `/en` 推断），避免进英文站还硬显示中文。

## 五、任务拆分

优先级：P0 必须本次做完；P1 随看板一起做；P2 收尾。

### T1 首页导航加入口（P0）
- `NavHeader.vue` 加「需求池」链接；`config.mts` 的 root/en `nav` 数组加对应 nav 项。
- 验收：首页顶部和文档页顶部都能点到需求池。

### T2 默认看板视图（P0）
- `FeedbackPool.vue` `view` 初值改 `'board'`。
- 验收：进需求池首屏即看板。

### T3 后端中文标签 + 透出 isPinned（P0）
- `constants.ts` 加中文标签；`routes.ts` 补 `is_pinned` 查询与返回；`admin` SPA 的 `STATUS_MAP`/`TYPE_MAP` 中文化。
- 验收：`/posts`、`/posts/:postNo` 返回中文 `typeLabel/statusLabel` 且带 `isPinned`；管理后台状态表全中文。

### T4 看板列覆盖与分组重构（P0）
- `RoadmapBoard.vue` 改为 5 列（待审/评估中/已规划/进行中/已完成/已关闭，默认取 2~5 + 1 待审 + 6/7 已关闭），列名走 i18n，颜色接主题变量。
- 验收：所有状态都能在某个列看到，不再丢 1/6/7。

### T5 看板卡片信息补齐（P1）
- `FeedbackPool.postsForBoard` 补 `isPinned / commentCount / category / typeLabel`；卡片支持置顶标识、类型文字、分类、评论数；排序按置顶 + 投票。
- 验收：看板卡片信息完整、置顶靠前。

### T6 前端文案统一走 i18n（P1）
- `FeedbackPool / StatusBadge / FeedbackForm / FeedbackDetail / RoadmapBoard` 全部改为引用 `t()`，删除组件内英文硬编码。
- 验收：中文环境所有可见标签为中文；切换到 en 正常。

### T7 看板统计条与无障碍收尾（P2）
- 看板顶部可复用 `/stats` 的 `statusStats` 显示「X 条 / 已规划 3 / 已完成 5」之类的轻量统计（前台已有 stats-bar，看板模式补一栏）。
- 验收：看板顶部有状态分布概览。

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 后端标签改中文后，英文站/老数据出现中英混排 | 中 | 低-中 | 数值 key 不变，仅文案；英文站前端按 `t()` 二次映射不信任后端 label |
| 组件 i18n 改动量大、易漏 | 中 | 中 | 收敛到 `i18n.ts` 单一文案源，按组件逐项验收 |
| 看板从 4 列改 5 列横屏空间 | 中 | 低 | 保留响应式降级（平板 2 列、手机 1 列），列多时正文用小字 |
| `isPinned` 后端字段缺 | 低 | 低 | `/posts` 与详情两处一起确认；缺则回退「置顶不显示」不阻塞 |
