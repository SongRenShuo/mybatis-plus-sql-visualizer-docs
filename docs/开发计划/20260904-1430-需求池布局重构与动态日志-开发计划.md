# 需求池整体优化：布局重构 + 动态日志 + 管理后台 开发计划

- 立项时间：2026-09-04 14:30（含管理后台优化更新）
- 实施状态：待排期
- 涉及项目：mybatis-plus-sql-visualizer-docs（公开站点，反馈池前端）+ sql-visualizer-admin（Cloudflare Workers + D1 后端 + Vue/Element Plus 管理后台）
- 目标：
  1. 解决需求池页顶部留白与右侧空白导致不居中的问题，右侧改为「需求池动态日志」。
  2. 管理后台：状态/类型统一中文、修系统设置路由、设置改开关、反馈管理支持查看详情 + 昵称/邮箱模糊查询、总览重构为图形化。

## 第一部分：文档站需求池布局重构（右侧动态日志 + 顶部留白）

### 1.1 布局根因（前端）

当前 `about/feedback.md` 走 VitePress **默认文档布局**，DOM 为 `VPDoc.has-aside`：内容在左列，右侧固定挂一个「页面导航」大纲栏 `.aside`。反馈池页没有任何 `<h2>` 大纲条目，这栏就是**空白占位**，导致反馈池偏左、整体不居中；同时文档布局的 `.VPDoc` 自带 `padding-top`（48px）造成顶部留白。之前用 `:has()` + `!important` 覆盖不稳定，治标不治本。

### 1.2 后端数据（动态日志可行性：可行）

`sql-visualizer-admin` 已有数据：
- `fb_status_logs`（状态变更日志，已建索引）：join `fb_posts` 得「某反馈 X→Y 状态，操作人，时间」——最合适的日志来源。
- `fb_posts`（`created_at/post_no/title/status`）：可取「最新新增」。
- `sys_user_activity`（`action=vote/comment/submit`）：可选补充。

**缺一个公开接口**：现有 `/admin/changelog`、`/admin/user-activity` 都要 `getAdminUser` 鉴权，不能给公开页用。需新增公开 `GET /api/v1/feedback/activity`（最近状态变更 + 新增反馈，倒序限量）。数据现成，**结论：可行**。

### 1.3 方案设计

- `about/feedback.md` 恢复 `layout: false`（从根上去掉右侧空大纲 + 文档顶部留白）。
- 顶部渲染 VitePress `VPNavBar`（与其它 tab 一致的顶部栏，含全局中英文切换）。
- 主体居中两列：左＝现有 `FeedbackPool`；右＝新增 `FeedbackActivity`「需求池动态」面板（消费 `/feedback/activity`）。
- 响应式：宽屏两列，窄屏右列隐藏/折到下方。
- 后端新增 `GET /api/v1/feedback/activity?limit=20`：汇总 `fb_status_logs` + 新增 `fb_posts`，统一结构，`is_deleted=0`，复用 `PostStatusLabels`，限量。

## 第二部分：管理后台优化（sql-visualizer-admin/admin + 后端）

### 2.1 现状诊断（逐项）

- **状态/类型中文（A1）**：`admin/src/api/index.ts` 的 `STATUS_MAP`/`TYPE_MAP` **已是中文**；`StatusTag.vue`、`Dashboard.vue`、`Posts.vue` 均用中文 map 或后端中文 `typeLabel/statusLabel`。**源码层面基本已中文化**。用户看到英文，最可能是**线上管理后台 SPA 是旧构建**（源码中文化后未重新构建部署）。
- **系统设置路由（A2）**：路由 `/settings` 存在、菜单 `index="/settings"`（`AdminLayout.vue`）源码正确；疑似旧构建或视图加载问题。
- **系统设置开关（A3）**：`Settings.vue` 源码**已用 `el-switch`** 渲染布尔值（`isBooleanValue` → `el-switch`，非布尔用 `el-input`），且兼容 `true/false` 与 `1/0`。**用户看到 true/false 文本＝线上是旧构建**（未部署带 switch 的版本）。
- **反馈管理详情（A4）**：`Posts.vue` 列表只有「改状态 / 删除」，**无详情查看**。
- **昵称/邮箱查询（A5）**：`Posts.vue` 用公开 `GET /feedback/posts`，仅支持 `keyword`（标题/描述 LIKE）+ `status`；公开接口**不返回 `submitter_email`**，也不支持昵称/邮箱查询。后端**无管理端列表接口**。
- **总览图形化（A6）**：`Dashboard.vue` 只有统计卡 + 状态分布表格，**无图形**。后端已有 `/stats`（statusStats/typeStats）与 `/analytics`（categoryStats/sourceStats/dailyStats/versionStats），数据齐全；`admin` 依赖里**没有图表库**。

> 小结：A1/A2/A3 主要靠「重新构建部署管理后台 SPA」让已写好的源码生效 + 核对残留英文；A4/A5/A6 是真正的新功能（前端 + 部分后端接口）。

### 2.2 各需求方案

**A1 状态/类型中文化 + 部署**
- 全量核对管理后台各视图（总览/反馈管理/通知日志/数据统计/系统设置）无英文残留（含通知 `channel`、类型 tag、时间戳等），统一走中文 map / 后端中文 label。
- **重新构建并部署管理后台 SPA**（`admin/` → `wrangler pages deploy`），让已中文化源码生效（这是 A1/A2/A3 的关键）。

**A2 系统设置路由修复**
- 核对 Settings 视图可正常加载（源码可用）。
- 若确认是旧构建：重新构建部署后即修复；保险起见核对 `el-menu router` 模式 `/settings` 跳转与 `activeMenu`。

**A3 系统设置改开关**
- 源码已用 `el-switch`，重新构建部署后生效；核对布尔识别（true/false、1/0）与保存时转字符串（`toBackendValue`）；核对后端 `sys_settings` 布尔项值格式。

**A4 反馈管理查看详情**
- `Posts.vue` 操作列加「查看」，点开 `el-drawer` 展示详情：标题/类型/状态/分类/昵称/邮箱、描述（markdown 渲染）、附件（图片预览 / 下载）、评论列表、状态历史时间线。
- 数据用现有 `GET /api/v1/feedback/posts/:postNo`（已返回 description/comments/statusLogs/attachments）；管理端如需显示邮箱，补 `submitter_email`（管理端可见，公开端保持隐藏）。

**A5 昵称/邮箱模糊查询（需后端接口）**
- 后端新增**管理端** `GET /api/v1/admin/posts`：支持 `submitterName`（昵称 LIKE）、`submitterEmail`（邮箱 LIKE）、`status`、`type`、`keyword` + 分页，返回含 `submitterName`/`submitterEmail` 的列表 + 正确 `total`。
- 前端 `Posts.vue` 工具栏加「昵称」「邮箱」输入框，接入新接口，用接口 `total`（替代当前「本页是否满」估算）。

**A6 总览图形化（需图表库）**
- 引入 **ECharts + vue-echarts**（Element Plus 后台标准）；或轻量自绘（CSS/SVG 柱/折线）。
- 总览加图表：状态分布（饼/环）、类型分布（柱）、近 30 天新增趋势（折线，来自 `/analytics` dailyStats）、来源/分类占比（柱）。统计卡保留，数据复用现有 `/stats`、`/analytics`，尽量不新增后端。

## 第四部分：风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 管理后台线上是旧构建，误判为代码 bug | 高 | 中 | A1/A2/A3 先重建部署，再核对；避免重复改已正确源码 |
| 整页 `layout:false` + `VPNavBar` 样式/暗色一致性 | 中 | 中 | 参照首页自定义页做法，沿用 VitePress 主题 |
| 动态/查询接口被刷 | 低 | 低 | 只读 + 限量；管理端接口走 `getAdminUser` 鉴权 |
| ECharts 体积 | 中 | 低 | 按需引入 / 懒加载；或轻量自绘替代 |
| 邮箱敏感信息 | 中 | 中 | 邮箱仅管理端接口返回，公开端不返回 |
| 多智能体并行改 admin 同文件冲突 | 中 | 中 | 按文件划分职责：后端 routes/admin 一个，前端各视图分开 |
