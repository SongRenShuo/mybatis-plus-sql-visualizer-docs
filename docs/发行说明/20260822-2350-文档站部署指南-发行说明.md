# 文档站部署指南

> 适用项目：基于 VitePress 构建，部署到 Cloudflare Pages
> 最后更新：2026-09-02（域名更名迁移后全面修订）

---

## 1. 前置条件

| 工具 | 用途 | 安装 |
|------|------|------|
| Node.js | 构建 VitePress | ≥ 18 |
| wrangler CLI | 部署到 Cloudflare Pages | `npm install -g wrangler` |
| Cloudflare 账号 | 托管服务 | 免费计划即可 |

## 2. 首次部署

### 2.1 安装依赖

```bash
npm install
```

### 2.2 构建

```bash
npm run build
```

构建产物输出到 `.vitepress/dist`。

### 2.3 配置部署令牌（一次性）

本仓库根目录的 `.cf-token`（gitignored，与 admin 仓库同源各存一份）是一个自定义 API Token
（`cfut_` 开头），权限为：账户 `Workers Scripts` 编辑、`D1` 编辑、`Workers R2 存储` 编辑、
`Cloudflare Pages` 编辑、区域 `DNS` 编辑。

所有 `wrangler` 命令通过环境变量注入该令牌，不再走 `wrangler login` 的 OAuth 登录：

```bash
export CLOUDFLARE_API_TOKEN=$(cat .cf-token)
```

> 注意：这个 token 对 DNS zone 只有 `jvtools.cn` 一个区域的编辑权，**没有 `All Zones` 权限**。
> 部署 Worker 时 wrangler 会回退到 zone 级路由更新，日志里会出现一条
> `Authentication error [code: 10000]`——这是无害的，表示「无权限 zone 的既有路由不会被删除」，
> 自定义域名 `api.sql-visualizer.jvtools.cn` 的路由保持原样不受影响。

### 2.4 部署

日常部署直接用封装好的脚本（构建 + 上传一步完成，项目名已写死为 `sql-visualizer-docs`）：

```bash
npm run deploy
```

等价于：

```bash
wrangler pages deploy .vitepress/dist --project-name sql-visualizer-docs --branch main --commit-dirty=true
```

参数说明：
- `--project-name`：Cloudflare Pages 项目名称（首次部署自动创建）
- `--branch main`：指定生产分支
- `--commit-dirty=true`：允许有未提交的更改时部署

部署成功后会输出类似：
```
✨ Deployment complete! Take a peek over at https://xxxxxx.<项目名>.pages.dev
```

## 4. 自定义域名配置

### 4.1 添加域名到 Pages 项目

wrangler 没有 domain 子命令，走 Cloudflare API（`.cf-token` 自带 `pages:write`，可直接调）：

```bash
curl -X POST "https://api.cloudflare.com/client/v4/accounts/<账户ID>/pages/projects/sql-visualizer-docs/domains" \
  -H "Authorization: Bearer <API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name": "子域名.jvtools.cn"}'
```

API Token 的位置：仓库根 `.cf-token`（`cfut_` 开头，与 admin 仓库同源），同一 token 可直接当 Bearer 用。

### 4.2 添加 DNS CNAME 记录

CNAME 必须指向**域名所属的那个项目**的 pages.dev 地址，指错项目时域名验证会一直 pending，API 查询会报 `CNAME record not set`。

在 Cloudflare Dashboard 中：
1. 进入域名 → **DNS** → **记录**
2. 点击 **添加记录**
3. 填写：
   - 类型：**CNAME**
   - 名称：**子域名前缀**（如 `sql-visualizer`）
   - 目标：**`sql-visualizer-docs.pages.dev`**
   - 代理状态：**已代理**
   - TTL：**自动**
4. 保存

DNS 生效后（几分钟内）证书自动签发（Google CA，HTTP 验证），随后自定义域名即可访问。

### 4.3 查询域名验证状态

```bash
curl -s "https://api.cloudflare.com/client/v4/accounts/<账户ID>/pages/projects/sql-visualizer-docs/domains" \
  -H "Authorization: Bearer <API_TOKEN>" | python -m json.tool
```

关注三处：`status`（active 才算就绪）、`verification_data.status`（DNS 记录是否就位，带 error_message）、`validation_data.status`（证书签发进度）。

### 4.4 DNS 编辑权限（已并入主 token）

`.cf-token` 已包含「区域 `DNS` → 编辑 → 特定区域 `jvtools.cn`」权限，DNS 记录增删改直接用它即可，无需再单独建 token：

1. 用 `.cf-token` 当 Bearer 调 Cloudflare API（权限含 `Zone → DNS → Edit → jvtools.cn`）

```bash
# 查记录（Edit 权限含读）
curl -s "https://api.cloudflare.com/client/v4/zones/<zoneID>/dns_records?name=sql-visualizer.jvtools.cn" \
  -H "Authorization: Bearer <DNS_TOKEN>"

# 改记录指向（迁移项目时用）
curl -X PUT "https://api.cloudflare.com/client/v4/zones/<zoneID>/dns_records/<记录ID>" \
  -H "Authorization: Bearer <DNS_TOKEN>" -H "Content-Type: application/json" \
  -d '{"type":"CNAME","name":"sql-visualizer.jvtools.cn","content":"sql-visualizer-docs.pages.dev","proxied":true}'
```

注意：本机代理（127.0.0.1:7890）会干扰 DoH 查询，验证 DNS 解析建议直接用 `nslookup`。

## 5. 域名更换与项目迁移

2026-09-02 从 `mybatis-plus-sql-visualizer.jvtools.cn` 更名为 `sql-visualizer.jvtools.cn` 时趟出来的完整流程，后续再改域名照此办理。

背景约束：
- **Cloudflare Pages 项目名不可重命名**，换名只能新建项目
- 部署走 wrangler 直传，与 Git 仓库解耦，新建项目零迁移成本
- 同一自定义域名同一时间只能挂在一个项目上，迁移需先删后加（有秒级 522 窗口）

流程：

1. **仓库改动**：`.vitepress/config.mts` 里 ld+json `url` 和 sitemap `hostname` 两处换域名；`package.json` deploy 脚本换 `--project-name`
2. **新建项目**：`wrangler pages project create <新项目名> --production-branch main`，然后 `npm run deploy`
3. **挂域名**：按 4.1 用 API 把新域名挂到新项目；如果旧域名也要保留跳转，先从旧项目 `DELETE .../domains/<域名>` 再 POST 到新项目
4. **改 DNS**：按 4.2/4.4 给新子域加 CNAME 指向新项目，旧域名的 CNAME 也改指向新项目（不改则验证 pending、旧域名 522）
5. **旧域名 301**：用 `functions/_middleware.js`（Pages 根级中间件）按 Host 判断跳转，详见该文件注释。**不要用 zone 级 Redirect Rule**——wrangler token 没有 zone 写权限，而且 zone 规则覆盖不了 pages.dev 主机；中间件方案两者都能管
6. **验证**：新域名 200、旧域名任意路径 301 且路径查询串无损、`/sitemap.xml` 内全部为新域名、页面源码 ld+json 为新域名
7. **收尾**：搜索引擎提交新 sitemap；旧项目保留 1–2 周观察期后 `wrangler pages project delete <旧项目名>`，并清理 DNS 旧记录

回滚：deploy 脚本的 `--project-name` 改回旧项目重新部署即恢复原状。

## 6. 项目配置要点

### 5.1 主题设置

`.vitepress/config.mts` 中：

```typescript
export default defineConfig({
  // 'light' 亮色 / 'dark' 暗色
  appearance: 'light',
})
```

### 5.2 忽略死链接

开发文档中可能包含 localhost 链接，构建时会报错。在配置中忽略：

```typescript
export default defineConfig({
  ignoreDeadLinks: true,
})
```

### 5.3 站点域名

更新 sitemap 和 JSON-LD 中的域名：

```typescript
head: [
  ['script', { type: 'application/ld+json' }, JSON.stringify({
    'url': 'https://你的域名',
  })]
],
sitemap: {
  hostname: 'https://你的域名'
}
```

## 8. 常见问题

**Q: 构建时报死链接错误？**
A: 确保 `.vitepress/config.mts` 中设置了 `ignoreDeadLinks: true`

**Q: wrangler 未认证？**
A: 确认 `.cf-token` 存在且已 `export CLOUDFLARE_API_TOKEN=$(cat .cf-token)`；token 失效则去 Dashboard 重建/补权限（见 2.3）

**Q: 自定义域名无法访问？**
A: 按顺序排查：`nslookup` 看解析是否生效 → 4.3 的 API 看 `verification_data` 是否报 `CNAME record not set`（CNAME 指向了别的项目）→ 看 `validation_data` 证书是否签发完

**Q: 旧域名突然 522？**
A: 域名刚从别的项目迁过来、CNAME 还指向旧项目时会出现。把 CNAME 目标改成当前所属项目的 pages.dev 地址即恢复

**Q: zone 级配置（Redirect Rule、DNS 记录）API 报 Authentication error？**
A: `.cf-token` 只有 `jvtools.cn` 区域的 DNS 编辑权（无 `All Zones`），跨区域操作会报 10000；同一区域直接用 `.cf-token`（见 4.4）

**Q: 部署后页面不更新？**
A: 浏览器可能有缓存，尝试强制刷新（Ctrl+Shift+R）
