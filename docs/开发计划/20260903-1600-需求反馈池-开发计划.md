## 一、调研总结：主流产品方案设计对比

### 1.1 调研范围

| 产品 / 方案 | 定位 | 核心设计 |
|------------|------|---------|
| **GitHub Discussions** | 开源社区论坛 | 分类（Ideas / Q&A / Polls）、点赞投票、标签状态、Issue 双向转换 |
| **JetBrains YouTrack** | 开发者工具工单 | 18 状态工作流、匿名投票、Subsystem 分类、In-IDE 提交、REST API |
| **Canny.io** | SaaS 反馈平台 | Board 组织、Changelog 联动、AI 去重、状态通知邮件、内嵌组件 |
| **Fider** | 开源反馈系统 | Go + PG 自托管、极简投票、状态管理、Docker 一键部署 |
| **Linear** | 项目管理 | Customer Requests 关联工作项、客户维度排序、CSV 导出 |
| **Discord / Slack** | 社区即时反馈 | Emoji 反应投票、Bot 同步、Forum Channel 线程式讨论 |

### 1.2 各方案核心优劣

**GitHub Discussions** — 零成本、零搭建，投票仅限 GitHub 账号；缺乏路线图可视化，无法在官网直接展示。

**JetBrains YouTrack** — 状态机最完善（Shelved / Declined / Works As Intended），匿名投票防社交压力，In-IDE 提交降低摩擦；但面向超大项目，对小插件偏重。

**Canny.io** — 开箱即用，Changelog 联动 + 反馈闭环最佳；免费版仅 25 tracked users，付费 $79/mo，数据托管外部。

**Fider** — 自托管免费，Go + Docker 简单；功能精简，无 Changelog、无 AI 去重，维护靠自己。

**Discord/Slack** — 即时讨论好，但反馈碎片化、不可搜索、不能当主反馈渠道。

### 1.3 我们需要的核心设计要素

综合调研，提炼出适合「独立开发者 + IntelliJ 插件 + MySQL 自托管」场景的设计要素：

| 要素 | 来源 | 采用方式 |
|------|------|---------|
| 简单点赞投票（无反对票） | GitHub / YouTrack | 每人每帖一票，票数公开、投票者不公开 |
| 5~7 状态工作流 + 礼貌拒绝 | YouTrack | Submitted → Under Review → Planned / In Progress → Completed / Declined / Duplicate |
| 分类 + 自由标签 | YouTrack / GitHub | 结构化分类（Feature / Bug / Improvement）+ 自由标签 |
| 公开路线图视图 | Canny / GitHub | 按状态分栏展示：Under Review / Planned / In Progress / Completed |
| 关闭反馈循环 | Canny | 状态变更时通知提交者（可选邮件），Changelog 关联 |
| In-IDE 提交 | YouTrack | 插件内 Action 收集 IDE 版本等信息 + 跳转反馈页 |
| 表单模板 | GitHub Discussions YAML | 结构化提交引导（问题描述 / 期望方案 / 使用场景） |
| SEO 友好 + 可搜索 | Canny | 公开页面、可被搜索引擎收录、站内搜索 |
| 管理后台 | Canny / YouTrack | 合并重复、改状态、置顶、官方回复 |
| REST API | YouTrack | 前后端分离，VitePress 前端 + 后端 API 服务 |

### 2.2 技术选型

| 层 | 技术 | 理由 |
|----|------|------|
| 前端 | VitePress + Vue 3 组件 | 与文档站同源，无需额外框架 |
| 后端 | Spring Boot 3 + MyBatis-Java 生态，与插件同源 | Java 生态，MyBatis-Plus 与插件一致 |
| 数据库 | MySQL 8.x | 用户指定，成熟稳定 |
| 部署 | Cloudflare Workers（API 代理）+ 自建后端 / Railway | 低成本，弹性扩展 |
| 邮件通知 | Mailgun / Resend（免费额度） | 关闭反馈循环 |

### 2.3 部署策略

**Phase 1（MVP）**：单机 Spring Boot + MySQL，直接暴露 REST API，VitePress 构建时 SSG 预渲染静态列表页 + 客户端 JS 动态加载交互数据。

**Phase 2（优化）**：API 前加 Cloudflare Workers 做缓存 + 限流，管理后台加 JWT 认证。

### 3.2 表结构

```sql
-- ========================================
-- 反馈帖子主表
-- ========================================
CREATE TABLE `posts` (
    `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `post_no`       VARCHAR(16)     NOT NULL COMMENT '展示编号，如 FR-0001',
    `title`         VARCHAR(200)    NOT NULL COMMENT '标题',
    `description`   TEXT            NOT NULL COMMENT '详细描述（Markdown）',
    `type`          TINYINT         NOT NULL DEFAULT 1 COMMENT '1=Feature 2=Bug 3=Improvement 4=Question',
    `status`        TINYINT         NOT NULL DEFAULT 1 COMMENT '见状态枚举',
    `category`      VARCHAR(50)     DEFAULT NULL COMMENT '功能分类：wrapper / xml / annotation / sql-log / batch / completion / other',
    `vote_count`    INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '冗余计数字段',
    `comment_count` INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '冗余计数字段',
    `submitter_name` VARCHAR(64)    DEFAULT NULL COMMENT '提交者昵称（可选）',
    `submitter_email` VARCHAR(128)  DEFAULT NULL COMMENT '邮箱（用于通知，可选）',
    `is_anonymous`  TINYINT         NOT NULL DEFAULT 1 COMMENT '是否匿名提交',
    `is_pinned`     TINYINT         NOT NULL DEFAULT 0 COMMENT '是否置顶',
    `is_deleted`    TINYINT         NOT NULL DEFAULT 0 COMMENT '软删除',
    `source`        VARCHAR(32)     DEFAULT 'web' COMMENT '来源：web / ide / import',
    `ide_version`   VARCHAR(32)     DEFAULT NULL COMMENT 'IDE 版本（In-IDE 提交时）',
    `plugin_version` VARCHAR(32)    DEFAULT NULL COMMENT '插件版本（In-IDE 提交时）',
    `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_post_no` (`post_no`),
    KEY `idx_status_type` (`status`, `type`),
    KEY `idx_category` (`category`),
    KEY `idx_vote_count` (`vote_count` DESC),
    KEY `idx_created_at` (`created_at` DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='反馈帖子';

-- ========================================
-- 投票表（防重复投票核心）
-- ========================================
CREATE TABLE `votes` (
    `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `post_id`     BIGINT UNSIGNED NOT NULL,
    `fingerprint` VARCHAR(64)     NOT NULL COMMENT '投票者指纹：登录用户=userId，匿名=IP+UA hash',
    `created_at`  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_post_fingerprint` (`post_id`, `fingerprint`),
    KEY `idx_post_id` (`post_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='投票记录';

-- ========================================
-- 评论表
-- ========================================
CREATE TABLE `comments` (
    `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `post_id`       BIGINT UNSIGNED NOT NULL,
    `parent_id`     BIGINT UNSIGNED DEFAULT NULL COMMENT '楼中楼回复',
    `content`       TEXT            NOT NULL COMMENT '评论内容（纯文本或 Markdown）',
    `author_name`   VARCHAR(64)     NOT NULL COMMENT '评论者昵称',
    `author_role`   TINYINT         NOT NULL DEFAULT 0 COMMENT '0=user 1=admin',
    `is_official`   TINYINT         NOT NULL DEFAULT 0 COMMENT '是否为官方回复',
    `is_deleted`    TINYINT         NOT NULL DEFAULT 0,
    `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_post_id` (`post_id`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='评论';

-- ========================================
-- 标签表
-- ========================================
CREATE TABLE `tags` (
    `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `name`       VARCHAR(40)  NOT NULL,
    `color`      VARCHAR(8)   DEFAULT '#3b82f6' COMMENT '标签颜色',
    `created_at` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='标签';

-- ========================================
-- 帖子 - 标签关联表
-- ========================================
CREATE TABLE `post_tags` (
    `post_id` BIGINT UNSIGNED NOT NULL,
    `tag_id`  INT UNSIGNED NOT NULL,
    PRIMARY KEY (`post_id`, `tag_id`),
    KEY `idx_tag_id` (`tag_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='帖子标签关联';

-- ========================================
-- 状态变更日志（审计 + 时间线展示）
-- ========================================
CREATE TABLE `post_status_logs` (
    `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `post_id`     BIGINT UNSIGNED NOT NULL,
    `from_status` TINYINT         NOT NULL,
    `to_status`   TINYINT         NOT NULL,
    `reason`      VARCHAR(500)    DEFAULT NULL COMMENT '变更原因（尤其 Declined 时说明理由）',
    `operator`    VARCHAR(64)     NOT NULL COMMENT '操作者',
    `created_at`  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_post_id` (`post_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='状态变更日志';

-- ========================================
-- 管理员表（管理后台登录）
-- ========================================
CREATE TABLE `admin_users` (
    `id`           INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `username`     VARCHAR(40)  NOT NULL,
    `password`     VARCHAR(128) NOT NULL COMMENT 'BCrypt hash',
    `display_name` VARCHAR(64)  DEFAULT NULL,
    `is_active`    TINYINT      NOT NULL DEFAULT 1,
    `created_at`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `last_login`   DATETIME     DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='管理员';
```

## 四、API 设计

### 4.1 REST API 端点

#### 公开 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/posts` | 列表查询（分页、筛选、排序） |
| GET | `/api/posts/{postNo}` | 帖子详情（含评论列表） |
| POST | `/api/posts` | 提交新反馈 |
| POST | `/api/posts/{postNo}/vote` | 投票（防重复） |
| DELETE | `/api/posts/{postNo}/vote` | 取消投票 |
| POST | `/api/posts/{postNo}/comments` | 提交评论 |
| GET | `/api/tags` | 标签列表 |
| GET | `/api/stats` | 统计摘要（各状态计数、总票数等） |

#### 管理 API（需 JWT）

| 方法 | 路径 | 说明 |
|------|------|------|
| PATCH | `/api/admin/posts/{postNo}/status` | 修改状态 |
| PATCH | `/api/admin/posts/{postNo}/pin` | 置顶 / 取消置顶 |
| PATCH | `/api/admin/posts/{postNo}/merge` | 合并到另一帖 |
| DELETE | `/api/admin/posts/{postNo}` | 软删除 |
| POST | `/api/admin/tags` | 创建标签 |
| DELETE | `/api/admin/tags/{id}` | 删除标签 |
| GET | `/api/admin/comments` | 评论管理（待审等） |
| DELETE | `/api/admin/comments/{id}` | 删除评论 |

### 4.2 列表查询参数

```
GET /api/posts?page=1&size=20&type=1&status=3&category=wrapper&sort=votes&tag=enhancement
```

| 参数 | 类型 | 说明 |
|------|------|------|
| page | int | 页码，默认 1 |
| size | int | 每页条数，默认 20，最大 50 |
| type | int | 类型筛选 |
| status | int | 状态筛选（支持多值 `1,2,3`） |
| category | string | 功能分类 |
| sort | string | 排序：`votes`(默认) / `newest` / `trending` |
| tag | string | 标签筛选 |
| keyword | string | 标题 / 内容搜索 |

### 5.3 交互流程

#### 用户提交流程

```
点击「提交反馈」
    → 选择类型（Feature / Bug / Improvement / Question）
    → 填写标题 + 描述（Markdown，带模板引导）
    → 选择功能分类 + 可选标签
```

#### 用户投票流程

```
浏览列表 / 详情
    → 点击 👍 按钮
    → 前端乐观更新（+1 + 高亮）
    → POST /api/posts/{postNo}/vote
    → 已投票状态写入 localStorage（指纹辅助后端去重）
    → 再次点击取消投票
```

#### 管理员审核流程

```
登录管理后台
    → 查看 Submitted 列表
    → 点击帖子 → 查看详情 + 评论
    → 操作：
        - 改状态（附原因）
        - 合并到已有帖（自动合并票数）
        - 添加标签
        - 标记官方回复
        - 置顶
    → 保存 → 写 status_log → 若用户填了邮箱则发通知
```

## 六、防刷与安全设计

| 威胁 | 防护措施 |
|------|---------|
| 刷票 | 后端指纹去重（IP + User-Agent hash），频率限制（同 IP 每小时最多 50 票） |
| 恶意提交 | 表单频率限制（同 IP 每小时最多 5 条），可选邮箱验证 |
| XSS | 前端渲染转义，后端入参过滤，Markdown 渲染使用 DOMPurify |
| SQL 注入 | MyBatis-Plus 参数化查询，禁止拼接 SQL |
| CSRF | 管理 API 使用 JWT + Authorization Header，不使用 Cookie |
| 管理后台爆破 | BCrypt 加密，登录频率限制，JWT 过期时间 2h |

### 7.2 静态生成 + 客户端水合

由于反馈数据是动态的，采用「构建时预渲染骨架 + 客户端 JS 动态加载」模式：

1. `about/feedback.md` 包含一个 `<div id="feedback-pool"></div>` 挂载点
2. 构建时 SSG 生成静态 HTML 骨架（标题、描述、提交按钮）
3. 客户端 JS 在 mounted 后 fetch API 渲染列表
4. 对 SEO 友好的 meta 信息写在 frontmatter 中

### 7.3 开发代理

在现有 `vite.server.proxy` 基础上新增反馈 API 代理：

```ts
proxy: {
  '/api/posts': {
    target: 'http://localhost:8080',  // 本地后端
    changeOrigin: true
  },
  '/api/admin': {
    target: 'http://localhost:8080',
    changeOrigin: true
  }
}
```

## 十一、核心设计原则（自检清单）

- **低摩擦提交**：标题 + 描述即可提交，其他全部可选
- **无反对票**：只有点赞，避免负面对立（借鉴 GitHub / YouTrack）
- **状态透明**：每个反馈都有明确状态，拒绝时说明原因（借鉴 YouTrack Shelved / Declined）
- **反馈闭环**：状态变更时通知提交者，Changelog 标记已完成项（借鉴 Canny）
- **公开可搜索**：所有非删除帖子对搜索引擎可见，增加 SEO 入口
- **管理员友好**：合并重复、批量改状态、一键回复模板
- **数据自托管**：MySQL 自有，不依赖第三方 SaaS
