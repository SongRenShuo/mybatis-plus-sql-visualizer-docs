# 首页返回顶部悬浮按钮-开发计划

> 日期：2026-10-15
> 状态：本地实施与浏览器验收完成，未部署。用户追加要求：章节导航与回顶都用平滑滚动，且按钮覆盖文档站每个页面。
> 范围：中英首页及所有采用 VitePress 默认布局的文档页；首页章节导航也改为平滑跳转。

## 一、现状与需求

首页由 `CoolHome.vue` 组合长页面各区块，`NavHeader.vue` 与 `SectionNav.vue` 已处理吸顶导航和章节定位，但页面中段、页尾缺少直接返回页首的入口。用户希望滚动后在右下角出现悬浮按钮，点击回到顶部；样式与本站蓝白、低装饰的视觉一致。

待验证前提：`.cool-home` 使用 `overflow-x: clip`，新增的 fixed 元素必须实测没有被裁切；内嵌浏览器里原生平滑滚动和 rAF 驱动动画曾有落点/执行异常，不能假设“动画顺滑”就等于“确实回顶”；移动端全屏菜单和搜索弹层层级分别较高，需要确认悬浮按钮不会盖住它们。

## 二、交互与视觉方案

- 顶部不显示；滚动超过 400px 后显示，回顶后隐藏，不长期占据屏幕。监听使用 passive scroll，挂载时立即同步一次状态，卸载时移除监听。400px 取自 Ant Design `FloatButton.BackTop` 的默认显示阈值；MUI 示例用 100px，本页很长，取较晚的 400px 避免首屏稍动就盖住内容。
- 用户追加偏好：正常情况下点击采用浏览器原生平滑滚动回到 `top: 0`；系统启用 `prefers-reduced-motion: reduce` 时直接瞬时回顶。目标是绝对顶点，不沿用章节锚点的偏移计算；须在浏览器实测能最终到 0，若宿主不可靠则优先保证回顶成功。按钮是原生 `button`，有中英可访问名称和可见的键盘焦点；显示之前不进入 Tab 顺序。
- 图形采用简洁上箭头，不加文字标签、渐变和夸张动效。约 48×48px 圆形浅色卡片、细描边和轻阴影，图标用现有品牌蓝；悬停背景轻微变化，按下有反馈。暗色模式沿用站点 CSS 变量而非另建独立配色。
- 固定于视口右下，桌面端与边缘保持约 24px，手机端约 16px 加安全区 inset；层级低于吸顶导航、移动菜单和搜索弹层；不推挤正文、不造成横向溢出。按钮显隐不做 Vue 入离场过渡：内嵌浏览器 rAF 不执行时，离场元素可能永久留在页面并继续可点；平滑效果只用于实际回顶与章节跳转。
- 自定义首页经 `CoolHome.vue` 挂载；其余页面通过默认布局的 `layout-bottom` 插槽挂载同一组件。VitePress 当前版本只有无障碍跳过链接，没有现成的右下悬浮回顶按钮，因此不会重复。中英文按钮标签统一取 `.vitepress/theme/data/homeContent.js`。页面中的搜索弹窗、移动菜单和需求池模态层应覆盖悬浮按钮。
- 首页 `SectionNav.vue` 八个章节链接都改为原生平滑滚动，沿用现有绝对位置减吸顶避让高度的落点算法；减少动态效果时瞬时滚动。保持锚点 URL 更新，导航高亮和末节选中逻辑不变；改 hash 可能延迟触发浏览器片段滚动，需延后检查并按精确目标收口。

参考：Ant Design 的 [FloatButton.BackTop](https://ant.design/components/float-button/) 提供按滚动距离显隐的返回入口；MUI 的 [App Bar / Back to top](https://mui.com/material-ui/react-app-bar/#back-to-top) 用右下角悬浮按钮、淡入以及可访问名称。只借交互规律，不直接移植它们的蓝色实心 FAB、额外依赖或固定动画时长。

## 三、实施步骤

1. 新建 `.vitepress/theme/components/home/BackToTop.vue`，封装滚动判定、点击行为、视觉与可访问性；分别在 `CoolHome.vue` 与默认布局的 `layout-bottom` 插槽接入，避免单页双按钮。
2. 为 `homeContent.js` 的 zh/en 增加 `backToTop.label`；修改 `SectionNav.vue` 八个入口的滚动行为，不改首页其他区块的文案或布局。
3. 运行 `npm run build`，核对中英首页及一篇功能页的客户端组件；在实际浏览器中检查初始隐藏、滚过阈值后出现、点击平滑回到顶端并隐藏。章节导航至少覆盖近邻和跨多节两种距离，落点不被吸顶栏遮挡。
4. 验收桌面与手机宽度、亮色与暗色、键盘焦点、移动菜单和搜索弹层覆盖、窄屏无水平溢出；把实测结果回填本计划。

## 四、验收边界

- 中英首页及长文档页：初始停在顶部时按钮不可见、不可聚焦；滚过阈值后右下角可见且可点；单击平滑回到 `scrollY ≈ 0` 后消失。短页不必出现。
- 375px 窄屏按钮不越界、不挡导航按钮，也不造成横向滚动；中英文均显示相同交互。
- 不额外加载图标库、滚动库或第三方依赖；章节锚点 URL 与避让位置仍正确。
- 本任务只交付代码和本地验证；若无明确发布要求，不自动部署。

## 五、实施记录（2026-10-15）

改动落点：新增 `.vitepress/theme/components/home/BackToTop.vue`；`CoolHome.vue` 与 `.vitepress/theme/index.ts` 的 `layout-bottom` 各挂一次（默认布局页与自定义首页因此都覆盖，且 VitePress 1.6 本身没有右下回顶按钮，不会重复）；`homeContent.js` 增 zh/en `backToTop.label`；`SectionNav.vue` 八个入口改平滑滚动。共三次 `npm run build` 全部成功。

实测读数（Chromium，1280×720 与 375×812，经本地 `npm run preview`）：

| 场景 | 结果 |
|---|---|
| 首页顶部 | 无按钮、不可聚焦；`scrollY=0` |
| 首页 `#sec-capability` / `#sec-start` | 按钮出现；`#sec-start` 落点 `target.top≈134px`（与吸顶避让一致） |
| 首页点回顶 | 平滑滚动后 `scrollY=0`，按钮消失，`location.hash` 已清空 |
| 功能页 `#功能特性`（默认布局） | 按钮出现；点回顶后 `scrollY=0`、按钮消失、锚点清空、未被片段滚动拉回 |
| 英文首页 `#sec-capability` | `aria-label="Back to top"`，按钮出现 |
| 375×812 | `documentElement.scrollWidth=360 < 375`，无横向溢出；按钮贴右下 16px |
| 章节导航近邻（核心能力→预览能力） | 落点 `target.top≈124px`，高亮切到「预览能力」 |
| 章节导航跨多节（预览能力→技术栈） | 落点 `target.top≈124px`，高亮切到「技术栈」 |
| 暗色 / 亮色 | 暗色图标 `rgb(79,193,255)`、底色 `rgb(38,40,44)`；亮色图标品牌蓝、底色 `#fff` |

验收过程中发现并修掉三个真实缺陷，都不是「看起来没问题」就能带过的：

1. **入离场过渡把按钮永久留在页首**。按钮原用 `<Transition>` 淡入淡出，回顶到 0 后 `scrollY` 已归零但按钮仍可见可点——该宿主 rAF 不执行，离场回调不完成。改为 `v-if` 直接显隐，平滑只保留给实际滚动。
2. **带锚点回顶后被片段滚动拉回**。文档页从 `#功能特性` 回顶，浏览器自己的「滚动到片段」在回顶之后又把页面拉回 2541px，而按钮已隐藏，状态卡死。修法：回顶前用 `history.replaceState` 清掉地址栏片段标识。
3. **迟到滚动不派发 scroll 事件导致按钮不出现**。带 `#锚点` 进入文档页时 `scrollY` 已是 2541 但按钮没出现，此后也没有 scroll 事件。修法：挂载与换页后各做 4 次有限重查（0/250/700/1400ms），不常驻轮询。

未覆盖与残留不确定性：`prefers-reduced-motion: reduce` 分支只做了代码路径审阅，未在浏览器中实际模拟该媒体特性；移动端全屏菜单与搜索弹层的层级按 z-index（按钮 40 < 导航 50 < 搜索弹层 200 < 需求池模态 1000）推定未遮挡，未逐一开层实测；最终构建的画面截图未取到——会话内嵌浏览器的截图通道在收尾阶段持续超时/报 guest 未附着，按钮样式（48×48、圆角、描边、阴影、图标色）自截图成功后未再改动，故以 DOM 尺寸与颜色读数为准。
