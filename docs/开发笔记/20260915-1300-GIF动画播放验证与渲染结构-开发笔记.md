# GIF 动画播放验证与渲染结构（2026-09-15 文档站实证）

- 记录时间：2026-09-15 13:00（2026-09-15 修订一：纠正「IAB 不推进 GIF 帧」误判——canvas 采样方法缺陷所致，IAB 实际正常播放）
- 项目：mybatis-plus-sql-visualizer-docs（文档站，VitePress）
- 关联任务：docs/开发计划/20260915-1200-GifPlayer首屏懒加载竞态修复-开发计划.md（含修订一：取消 poster 兜底改 GIF 直出）

## 一句话结论

**「GIF 已就绪」不等于「GIF 在播」**：DOM 层验证（img 挂载、complete、opacity 1）全部通过，视觉上完全可能是静态帧。但**动画是否在播，不能靠 canvas 像素采样判定**——`canvas.drawImage` 对动画 GIF 只绘制首帧（Chromium 行为），像素指纹恒定会产生「静止」假象。动画判定只能以**真实可见渲染**为准（用户目视 / 真实浏览器）。

## 一、验证方法的能力边界（本次实证）

| 验证手段 | 能否判定动画在播 | 实测证据 |
|------|--------------|---------|
| 真实可见渲染（用户目视 / 真实浏览器前台） | ✅ 可靠 | 用户实测首页动画正常；直出结构修复后详解页正常；**ZCode 内嵌浏览器（IAB）同样正常播放 GIF**（用户实测，2026-09-15 修订一纠正） |
| canvas `drawImage` 像素采样 | ❌ **不可靠** | 无论动画是否在播，`drawImage` 对动画 GIF 只画首帧，多次采样指纹恒定——曾被误判为「IAB 不播 GIF」（2026-09-15 修订一推翻） |
| 单帧截图对比 | ❌ 不可靠 | 单帧快照无法反映帧推进，且 IAB 截图对未聚焦标签偶发超时 |
| DOM 结构断言（img 挂载 / complete / ready class / opacity 1） | ⚠️ 仅证明就绪 | 就绪 ≠ 在播；曾出现「DOM 全绿但视觉静止」的动态插入停帧（见第二节） |

推论：**动画播放验收只能委托真实可见渲染（用户目视）**，自动验收只能做结构断言 + 资产多帧核对（ffprobe 帧数 > 1 且 15fps）+ 断图回落 + 亮暗色 + 列宽锐利度，不得宣称「动画播放通过」。

## 二、渲染结构差异导致「同站有的动有的不动」（真实浏览器实证）

用户真实浏览器实测：官网首页动画正常、功能详解页静止。两者代码结构对比后定位——**差异不在 poster 兜底、不在 loading="lazy"**（两边都有），而在 GIF `<img>` 的存在方式：

| 位置 | GIF img 渲染方式 | 用户实测 |
|------|-----------------|---------|
| 首页 FeatureAlternate / DocsShowcase | 随页面**初始 HTML（SSR）直出**，poster 撑布局 + GIF 叠层淡入 | 动画正常 |
| 功能详解页 GifPlayer（旧） | **hydration 后由 JS 动态插入**（v-if 懒加载门控 + absolute 叠层） | 静止 |

修复：GifPlayer 重写为与首页同构——GIF img 随 SSR 直出，拆掉 v-if 懒加载门 / IntersectionObserver / poster 叠层 / opacity 淡入全套（commit 0040c09），20 处 md 调用同步删 poster 属性。修复后用户真实浏览器复验动画正常。

启示（经验级结论，未定位到 Chromium issue）：**动画 GIF 以「hydration 后动态插入 + absolute 叠层」方式渲染时，在部分环境存在解码停帧**；初始 HTML 直出的文档流 `<img>` 是最稳的路径。新页面接 GIF 优先直出，避免叠层/门控设计。

## 三、同族问题：IntersectionObserver 对「注册时已相交」元素不回调

本次同一组件里还叠了另一个坑：`onMounted` 创建 IntersectionObserver 并 `observe(container)`，对**注册观察时已处于视口内**（首屏）的元素，SPA hydration 时序下可能不派发回调（没有「从不相交到相交」的变化事件），`loaded` 门永不打开，首屏 GIF 恒停 poster。修复=挂载后同步 `getBoundingClientRect()` 判定，命中直接放行（不注册观察器）。与「GIF 缓存命中时 @load 监听器就位前已 complete」的 hydration 竞态（efda401 修过）同属一族的时序缺陷。

## 四、验收口径（已同步到《演示GIF录制指南》与 ide-demo-gif skill）

- **动画播放验收**：以真实可见渲染（用户目视 / 真实浏览器）为准；IAB 可正常播放 GIF；canvas 像素采样与单帧截图**不能**作为动画判据（drawImage 只画首帧）；自动验证只做结构断言 + 资产多帧 + 断图回落；
- **首屏零滚动验收**：加载后不做任何滚动输入，≤3s 内首屏 GIF 必须进入播放态——旧口径含滚动动作会撞开观察器门，掩盖「首屏不播」缺陷；
- **部署后 stale 场景**：唯一真实来源是「部署前已打开的 tab 未刷新」（SPA 内存态）；HTML 是协商缓存、JS chunk 文件名随内容换 hash，部署架构本身无缓存缺陷。
