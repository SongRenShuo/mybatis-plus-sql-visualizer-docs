# 文档页正文宽度对齐动图宽度 — 开发计划

> 日期：2026-11-13　|　站点：mybatis-plus-sql-visualizer-docs　|　范围：全部默认布局文档页（中英）
> 背景：正文 measure 只有 688px，演示动图按出血规则占到 800px（≥1440px 视口），用户要求**按动图宽度反向放宽文字区域**，而不是让图往两侧出血。

## 一、现状事实（已核实，非推断）

### 1.1 正文 688px 的真源

VitePress **1.6.4** `node_modules/vitepress/dist/client/theme-default/components/VPDoc.vue:190-192`：

```css
.VPDoc.has-aside .content-container {
  max-width: 688px;
}
```

- **硬编码字面量，不是 CSS 变量**——本版本不存在 `--vp-content-max-width`，别去找变量改，直接用更高优先级的选择器覆盖。
- `.has-aside` 由 `useSidebar()` 的 `hasAside` 决定（frontmatter `aside` 或有侧栏即真），**与视口无关**：768–1279px 档大纲元素隐藏但 class 仍在，688px 上限照样生效——这正是现有出血规则能生效的前提。

### 1.2 动图当前实际宽度（style.css:686-748 出血规则）

| 视口档 | 出血（两侧各） | 动图实际宽 |
| --- | --- | --- |
| ≥1440px | 56px | 688 + 112 = **800px** |
| 1280–1439px | 24px | 688 + 48 = **736px** |
| 1024–1279px | 56px | 688 + 112 = **800px** |
| 768–1023px | 24px | 688 + 48 = **736px** |
| <768px | 整行出血（抵消 .VPDoc 48px 内边距） | 视口宽 |

出血档位是当年按「与左栏/大纲安全间距 ≥24px 实测校准」定的（1600 视口实测 800px 刚好不压两栏），**这些档位本身就是各视口下不压侧栏/大纲的最大可用宽度**——所以文字宽度直接照抄这张表，不会引入压栏风险。

### 1.3 受影响面

- **在范围内**：`guide/*`（9 页）、`features/*`（12 页）、`about/*`（8 页）及 `en/` 对应镜像——全部默认布局、有侧栏、`has-aside` 成立，中英共用同一份 `style.css`，一处改全站生效。
- **不在范围内**：
  - 首页 `index.md` / `en/index.md`（layout: false，不走 VPDoc）；
  - `about/bounty.md`、`about/feedback.md`（layout: page 自定义页，无 688 约束）；
  - 正文里非 `/demo/` 前缀的普通图片（本来就受 `img{max-width:100%}` 钳制，随容器走）。

## 二、目标与方案

**目标**：≥768px 各档视口下，正文文字列宽度 = 该档动图宽度（800/736/800/736），动图不再出血、与文字同宽对齐。<768px 移动端保持现状（文字不可能比视口宽，动图整行出血照旧）。

### 方案：覆盖 max-width + 撤销桌面端出血规则

改动全部集中在 `.vitepress/theme/style.css`：

**① 新增覆盖规则**（选择器用 5 个 class 拼链——见「待验证前提 1」说明优先级问题）：

```css
/* 正文宽度对齐演示动图宽度（用户 2026-11-13 定案：文字列放宽到与动图同宽，
   不再让动图向两侧出血）。VitePress 1.6.4 VPDoc.vue 里
   .VPDoc.has-aside .content-container{max-width:688px} 是 scoped 硬编码
   （带 data-v 属性选择器，特异性 0-4-0），故须 5 class 链（0-5-0）压过它。
   档位照抄原出血规则实测校准值：各视口不压侧栏/大纲的最大可用宽度。
   max-width 是上限不是强制宽，窄档空间不足时自动收缩，无溢出风险。 */
.VPDoc.has-aside .container .content .content-container {
  max-width: 736px; /* 768–1023 与 1280–1439 档 */
}
@media (min-width: 1024px) {
  .VPDoc.has-aside .container .content .content-container {
    max-width: 800px; /* 1024–1279 与 ≥1440 档 */
  }
}
@media (min-width: 1280px) and (max-width: 1439px) {
  .VPDoc.has-aside .container .content .content-container {
    max-width: 736px; /* 1280–1439 容器余量最小，宁小勿挤（原 24px 出血档） */
  }
}
```

（768 以下同样被 736 上限覆盖，但视口不足时收缩为实际可用宽，与现状一致，无需单独规则。）

**② 删除桌面端四段出血规则**：`style.css:686-726`（≥1440 / 1280–1439 / 1024–1279 / 768–1023 四个 media 块），`.mp-gif-player` 与 `/demo/` 图恢复 `width:100%`，正好填满放宽后的容器——动图视觉宽度与改前逐像素一致，只有文字变宽。

**③ 保留 <768px 整行出血块**（`style.css:728-748`）原样不动。

**④ 同步修订相邻注释**：`style.css:657-660`「正文 measure 保持不动」的说明已过时，改写为新口径（文字 measure 跟随动图宽度）；新规则注释里写明出处（VPDoc.vue:190 与本计划编号）。

### 连带影响（预期内，验收时逐条看）

- 长表格（guide/comparison.md）、长代码块获得更宽可用空间——顺带收益。
- 行宽 800px ≈ 110+ 字符/行，可读性下降换一致性——用户明确要求，不做折中。
- `.vp-doc h1 + h2` 收窄规则（style.css:391）、h2 营销样式等与宽度无关，不动。
- GifPlayer 组件根元素 `width:100%`（GifPlayer.vue），随容器自动变宽；徽标定位 `right:14px` 跟随右缘，正常。

## 四、待验证前提（实施者先证伪再动手）

1. **特异性推断**：scoped 编译后 VitePress 规则带 `data-v` 属性（0-4-0），5 class 链（0-5-0）能压过。**证伪法**：DevTools 里直接看两条规则的 Applied By 状态；若 5 class 链仍输，退路是加 `!important`（只在覆盖这一处用，可接受）。
2. **档位空间推断**：1280–1439 档 736px 容器 + 大纲 256px + 侧栏在最小视口（1280px）下恰好放得下——依据是原出血档已实测不压栏，但「文字容器」与「出血图」占位方式不同（容器参与布局流，图是负 margin 出血），**须在该档实测大纲左缘与正文右缘间距 ≥24px**。
3. **has-aside 全页成立推断**：guide/features/about 全部页面 `hasAside` 为真。若有页面被 frontmatter 关了 aside（未逐页翻查），该页会脱离 688 约束、文字本来就全宽——只需在核对时确认没有意外页面变宽。

## 五、验收标准

1. **对齐**：≥1440 档（1600 视口）文字列与动图左右缘对齐（差 0px）；1280–1439 档两者同为 736px。
2. **不压栏**：1280/1366/1440/1600 四档视口，正文与右大纲间距 ≥24px，无横向滚动条。
3. **无回归**：comparison.md 宽表格、features 页代码块、GifPlayer 徽标位置、移动端 375px 出血动图均与改前一致。
4. **中英一致**：en/guide、en/features 抽查一页读数与中文侧相同。
5. 暗色主题抽查一页无异常。
6. 部署后生产环境截图交用户验收（final-screenshot-acceptance 约定）。

### 方案修正（实施期实测推翻「待验证前提 2」的纯 max-width 路线）

纯 max-width 覆盖在各档视口下「文字变不宽」：多数视口可用空间不足 736/800px（实测 1366 视口可用仅 652px、1100 仅 642px、1024 仅 566px），容器只会缩到可用宽——结果是**图缩水迁就文字**而非「文字长到动图宽度」。最终改为**对 content-container 本身施加与原动图完全相同的出血**（负 margin + width calc + 上限兜底），容器足迹＝原动图足迹逐像素一致：

| 档位 | 出血 | 上限 | 实测容器宽（=旧动图宽） |
| --- | --- | --- | --- |
| 768–1023 | ±24px | 736 | 768→694、900→736、960→550 ✓ |
| 1024–1279 | ±56px | 800 | 1024→678、1100→754、1200→800 ✓ |
| 1280–1439 | ±24px | 736 | 1280→624、1366→700、1400→734 ✓ |
| ≥1440 | ±56px | 800 | 1440→800、1600→800 ✓ |
| <768 | 不生效（容器不出血） | — | 375→文字 269（原样），动图整行出血 365 ✓ |

特异性前提 1 成立：5 class 链（0-5-0）压过 scoped 规则，DevTools/实测均生效（容器 computed maxWidth 736/800 随档切换）。
