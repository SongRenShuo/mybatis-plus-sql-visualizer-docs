# EdgeOne 海外加速接入全流程踩坑

> 2026-11-22 · 涉及仓:jvtools-home(主站)/ sql-visualizer-docs(文档站)/ Cloudflare DNS · 涉及产品:腾讯云 EdgeOne(免费版)、Cloudflare Pages、Cloudflare DNS

## 背景

国内用户访问 jvtools.cn 走 CF anycast,实测 TTFB 0.8~2s(跨海 RTT 税)。域名无 ICP 备案,EdgeOne 大陆加速区被强校验挡死,可用的是「全球可用区(不含中国大陆)」——即 EdgeOne 海外边缘(香港为主)接管流量、未命中回源 CF Pages 的过渡方案。本篇记录接入全程的坑与解法;方案终态(备案后迁大陆区)另见记忆档案,此处不展开。

## 核心坑:CF Pages 自定义域回环 423

接入完成后全站 423 Locked 持续 20 分钟以上,控制台却显示域名「已生效」+证书「已部署」,极易误判为部署未收敛而白等。

定位靠看回源响应头:

```
HTTP/1.1 423 Locked
cdn-loop: TencentEdgeOne; loops=16
Server: cloudflare
CF-RAY: a5e765fd6f9029c4-AMS
eo-cache-status: MISS
```

链路本身是通的(EdgeOne 边缘 → CF 边缘,TLS 与路由正常),423 是 CF 返回的:CF Pages 的自定义域要求 DNS 持续指向 CF,记录改灰云指向 EdgeOne 后,Pages 判定该域名未指向 CF,触发回环保护锁定该 Host 的全部请求。控制台的一切「已生效」都只是 EdgeOne 侧的状态,CF 侧的锁它不显示。

解法:回源 HOST 头从「使用加速域名」改成「自定义」,填 Pages 项目域名——主站与 www 填 `jvtools-home.pages.dev`,文档站填 `sql-visualizer-docs.pages.dev`;源站 IP(104.21.68.29)不变。CF 对 Host=pages.dev 的请求走项目默认域服务,与自定义域绑定状态无关,423 立即消失(实测改完一轮部署后 https 直接 200)。

推论:凡「CF Pages + 外层 CDN 回源到 CF」的架构,回源 Host 必须用 pages.dev 域名,不能用自定义域。

## 次级坑:pages.dev 的 SNI 被 GFW 阻断

排查期间发现 `curl --resolve jvtools-home.pages.dev:443:104.21.68.29` 与直接访问 pages.dev 都以 curl exit 35(TLS 握手被重置)失败——GFW 对 pages.dev 的 SNI 是阻断不是污染,`--resolve` 绕过 DNS 也绕不过 SNI 检测。

这带来一个假的两难:回源 Host 用自定义域撞回环 423,用 pages.dev 撞 SNI 阻断。实际不冲突:EdgeOne「不含中国大陆」加速区的回源请求从香港等境外节点发出,不经过 GFW,不会被掐;被掐的只是从大陆发起的直连(排查时的本机测试)。所以 pages.dev 在本方案里可用,但如果将来加速区域换成含大陆(备案后),大陆节点回源 pages.dev 会被 SNI 阻断——彼时架构应改为 EdgeOne Pages 大陆区托管,不再回源 CF,这个问题自然消失。

## EdgeOne 控制台流程坑

- 无备案域名添加站点时「中国大陆可用区」直接置灰,套餐无关,纯备案校验。
- 归属权验证要加 TXT 记录(主机记录 `edgeonereclaim`),CF API 加一条即可秒过验证;不走验证点「暂不验证」也行,代价是后续逐子域验证。
- 加速域名框留空无效,裸域(根域)的输入方式是在框内填 `@`,HOST 预览会变成裸域即为正确。
- 每次配置变更(加域名、改回源、动证书)都触发一次全球重新部署,实测 2~8 分钟;部署期间该域名所有请求 423,编辑与 HTTPS 配置入口同时锁死。切换 DNS 前应先配好证书,把 423 窗口压到一次。
- 免费证书走「申请免费证书 + 自动验证」,域名 CNAME 切到 EdgeOne 后自动验证即刻通过;证书申请提交≠可用,要等「证书申请中→已部署」。
- 免费版套餐 1 个站点配额,添加站点时从已购套餐绑定,无费用。

## 浏览器代操作坑(EdgeOne 控制台是重灾区)

- 弹窗用 tea-overlay 体系渲染,挂在 `#tea-overlay-root-clone` 容器下,Playwright 标准 `[role=dialog]`/`[class*=dialog]` 全部抓不到——判定「弹窗没开」前先查这个容器。
- 单选、分段选择都是自定义组件,原生 input 被 0 尺寸隐藏,`getByRole("radio")` 点击报 actionability/无 click point;要点容器类 `.app-edgeone-radio-wrap`、`.app-edgeone-segment` 内的按钮项。
- 顶栏搜索等无 placeholder 的输入框,`fill` 后按钮不激活(框架不认),逐字 `type` 才触发;域名添加主表单反而可以用 native setter + input/change 事件批量填。
- evaluate 系列脚本里跨引用变量不共享(每次 evaluate 独立),合并读取结果要在 JS 层拼接,别在第二个 evaluate 的字符串里引第一个的变量。
- 点击「下一步」类按钮经常「点了没反应」,多数是组件响应有 1~3 秒延迟——读状态前先等,不要立刻重试或换定位器。

## 工具边界

- CloudBase Skills 插件授权后(auth READY)能调 callCloudApi,但其 service 白名单只有 tcb/scf/sts/cam/lowcode/cdn/vpc,没有 teo——EdgeOne 的管控操作它一条都做不了,浏览器自动化是唯一代操作路线。
- CF API token(仓根 `.cf-token`)实测有 zone 读取 + DNS 记录写权限,归属权 TXT、灰云切换全用它完成,无需换 token。

## 实测效果与遗留

国内直连实测(2026-11-22,单机):三域 https 200、内容正确;HTML 未命中回源 TTFB 0.61~0.76s(基线 0.81~1.97s);静态资源边缘 HIT 0.58s。改善幅度 30~60%,资源命中后的大头收益要靠多次访问摊开,运营商视角差异待更多样本。

遗留三件:① `npm run deploy` 后 EdgeOne 边缘会留旧 HTML 缓存,需要在部署脚本尾部接 EdgeOne 清缓存 API 或给 HTML 配短 TTL;② 备案下来后迁大陆区(终态为 EdgeOne Pages 大陆区托管,不再回源 CF);③ admin 与 mybatis-plus-sql-visualizer 两个子域有意未接,维持 CF 直连。
