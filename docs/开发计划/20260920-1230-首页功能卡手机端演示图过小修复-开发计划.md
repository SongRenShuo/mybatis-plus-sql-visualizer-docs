# 首页功能卡手机端演示图过小修复 — 开发计划

- 来源：用户 2026-09-20 反馈「官网首页的 mcp 怎么没有动图」→ 澄清「是手机端没有正常显示」
- 涉及仓库：文档站（组件在分支 `t-home-mcp-feature`）
- 性质：**首页移动端排版缺陷**，非动图资产问题

## 一、现象与实测

**桌面端正常**：生产首页第七卡（MCP）渲染的是 GIF 内容且**在播**——间隔 1.6 秒两张截图不同（第一张十个工具全勾、第二张第一个已取消勾选）。六张新资产生产域全部 200，`Content-Type: image/gif`。

**手机端（390px 视口实测）**：演示图只渲染 **279×200**，占视口 74%。

| 元素 | offsetLeft | offsetWidth | padding |
| --- | --- | --- | --- |
| `section.features-section` | 0 | 375 | 24 / 24 |
| **`div.container`（组件内层）** | 24 | 327 | **24 / 24** |
| `div.features-list` | 48 | **279** | 0 |
| 图片（poster 与 GIF 同尺寸） | — | **279 × 200** | — |

## 二、根因

**两层水平内边距叠加**：组件内部写了一个 `<div class="container">` 包裹卡片列表，而 `container` 是 VitePress 主题的全局类名（`max-width: 1152px; margin: 0 auto; padding: 0 24px`）——组件自己的 `.features-section` 已有 24px 内边距，两处叠加后，375px 视口只剩 `375 − 24×2 − 24×2 = 279px`。

桌面端无害（视口宽，`max-width: 1152px` 居中后仍有富余），**手机端致命**：1280×920 的 IDE 截图被压到 279px（约 22%），界面文字只剩几个像素，动图那点动作自然也看不出来，读起来就是一张静止图。

**七张卡都受影响**，不是 MCP 卡独有——只是 MCP 卡是本次新换的图，用户从它注意到。

## 三、修复方案

窄屏让**演示图突破两层内边距、整行出血到视口宽**，文字保持原内缩（移动端常见的「图出血、文内缩」排版）：

```css
@media (max-width: 767px) {
  /* 手机端演示图整行出血：抵消 section 与内层 .container 各 24px 的水平内边距，
     图片由 279px 提到接近视口宽（375px，+34%）。只影响窄屏，桌面端不变。 */
  .feature-video-wrapper {
    margin-left: -48px;
    margin-right: -48px;
  }
}
```

选这个而不是「只去掉内层 container 的 padding」的理由：后者只能到 327px（+17%），仍不足；出血方案一次到位且不改动全局 `.container` 语义（避免影响首页其它用到该类的区块）。

**顺带**：内层 `div.container` 的类名与 VitePress 全局类冲突本身是个隐患，建议后续改名为组件私有类（如 `feature-inner`），本次不动以免扩大改动面。

## 四、验收标准

1. 手机视口（390×844）下演示图宽度 ≥ 370px（整行出血），七张卡一致；
2. 桌面端（≥768px）布局与修复前逐项一致（图片宽度、卡片栅格不变）；
3. `npm run build` 通过，产物 CSS 含新规则；
4. 生产域部署后，手机视口实测图片宽度与本地一致；
5. 补一张手机端生产截图供用户验收。

## 五、风险

| # | 风险 | 应对 |
| --- | --- | --- |
| R1 | 出血后图片贴屏幕边，圆角与阴影观感变化 | 出血量正好抵消内边距（48px），图片仍带 1rem 圆角；若观感不佳可退回 327px 方案 |
| R2 | 负边距在极端窄屏（<320px）溢出 | 出血量等于父级内边距之和，父级为满宽 section，不产生横向滚动；部署后实测 360px 与 320px |
| R3 | 桌面端被误改 | 规则写在 `max-width: 767px` 内，且与现有桌面媒体查询（`min-width: 768px`）互补不重叠 |
