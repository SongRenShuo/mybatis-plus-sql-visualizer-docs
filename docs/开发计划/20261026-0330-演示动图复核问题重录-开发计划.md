## 一、为什么要重录

本轮复核（逐张目视 + 反向自证）在 64 张里查出 10 张 SERIOUS。它们不是「画质不够好」，
而是**画面承诺与画面内容对不上**，挂在页面上会直接误导用户：

- 3 张**拍错功能**或**场景不成立**：`wrapper-preview`（拍成 XML 预览）、`dialect-gate`（无方言冲突）、
  `wrapper-params`（方向与 alt 相反）；
- 2 张**分镜没走完**：`diagnostic-report`（报告本体全程不可见）、`jpa-write-path`（缺「取消勾选」动作）；
- 6 张**跳行弹窗入镜**：`annotation-preview` / `batch-operation` / `xml-preview` / `jpa-embedded` /
  `jpa-write-path` / `jpa-derived-query`。

其中 `wrapper-preview` 是功能页 hero 且被**首页卡片、快速开始、DocsShowcase 共 6 处引用**，
影响面最大。

## 二、根因分析（比单张重录更重要）

### 2.1 跳行弹窗：修法改错了地方

`Go to Line:Column` 弹窗在 6 张里命中。查录制脚本后定案：

- 跳行由 `lib/nav.py` 的 `goto()` / `goto_col()` / `goto_token()` 与 `gifkit.goto_line()` 实现，
  两者都是 **Ctrl+G → Ctrl+A 清空 → 输入行号 → Enter**；
- 从 Ctrl+G 到 Enter 之间约 **1.5~2.0 秒**，弹窗在这段时间一直可见——15fps 下就是 **20~30 帧**；
- 上一轮（`20261024-1026` 计划）的修法是「`goto_col` 末尾无条件按 Esc」，但 **Esc 在 Enter 之后**，
  弹窗早已入镜，**该修法对「弹窗入镜」无效**；实测 `lib/nav.py:116-129` 的 `goto_col` 末尾也没有 Esc。

**修法（三选一，按场景挑）**：

1. **把跳行移出录制窗口**——在 `Recorder.start()` 之前完成跳行（首选，改动最小）；
2. 改用不弹窗的定位：gutter 点击（已有 `find_gutter_icons` 像素定位）、`Ctrl+F` 搜索；
3. 走 IDE 内置 MCP `open_file_in_editor` 按路径精确打开（`record/mcpnav.py` 已有，本轮 mcp-agent 录制用过）。

### 2.2 拍错功能：入口/同名文件混淆

`wrapper-preview.gif` 拍成了 `UserMapper.xml` 的 `<select>` 预览。工程里 `UserMapper.xml` /
`UserMapper.java` / `UserRepository.java` 都有同名或近名文件，上一轮已因此踩过 3 次。

**修法**：开录前用 MCP `open_file_in_editor` 按**绝对路径**打开目标文件；开录后**加一条画面断言**——
预览面板元信息行必须含预期类型（Wrapper 链应为 `LAMBDA_QUERY` / `MPJ LAMBDA`，
XML 应为 `XML select: …`），断言不过即中止本次 take。

### 2.3 分镜没走完 / 场景不成立

- `diagnostic-report`：只演示了菜单选择与保存框，报告本体没展示 → 重录时把 Markdown 出口的产物
  **贴回编辑器或剪贴板预览**，HTML 出口**用浏览器打开**；
- `dialect-gate`：原计划要的是「PG 渲染 → MySQL 目标源」的冲突场景，实际录成了「PG 渲染 → PG 源」
  → 重录前先把目标数据源切到 MySQL（`mpj_demo@localhost`），并确认结果行出现「方言不一致」说明与
  「切换数据源 / 方言设置」两个出口；
- `wrapper-params`：alt 与画面方向相反 + 演示值自带引号 → 重录时**从已勾选状态开始、取消勾选**，
  参数值一律**不带引号**（`tom` 而不是 `'tom'`）。

### 2.4 演示值带引号

`wrapper-params` 里输入 `'tom'` 后 SQL 渲染成 `WHERE username = '''tom'''`，看着像引号 bug。
**约定**：演示参数值一律不带引号，引号由插件按字段类型决定。

## 五、录制前置与新增闸门

### 5.1 环境（沿用既有管线，不新造）

- 构图：窗口 1370×984 @ 屏幕 (277,25)，录制区=窗口外框，IDE 缩放 120%、编辑器 13pt、Islands Dark，
  导出宽 1280（`wrapper-preview` 保持 1440），15fps，单张 ≤2MB、时长 6~15s
- 启动沙盒统一用 `./gradlew runIde -PgifRecord=true --args=<demo 工程绝对路径>`
  （它重建安装插件**并**合并沙盒 `config/idea64.exe.vmoptions`）
- 开录前七项自检：`config/idea64.exe.vmoptions` 含 qwdn 行 → 进程 `HAS qwdn` → 标题栏无
  `Start Free Trial` → 无许可弹窗 → Database 工具窗可用 → robot-server 8580 可达 → **无任何残留弹窗**
- 数据源：`mp_demo@localhost`（`user` 表全列）；`mpj_demo@localhost` 供 mpjdemo 模块；
  `dialect-gate` 另需 PG 源 `dbx_test@114.66.55.245`（首次连需装 `postgresql-42.7.13` 驱动并填凭据）

### 5.2 新增三道闸门（本轮事故的直接对策）

1. **跳行闸门**：录制脚本里禁止在 `Recorder.start()` 之后调用 `goto*`。加一条源码守卫——
   扫描 `scene_*.py`，若 `start()` 之后出现 `goto_line(` / `goto_col(` / `goto_token(` / `goto(` 即报错。
2. **画面断言闸门**：每段开录后先抓一帧，断言预览面板元信息行含预期类型
   （`LAMBDA_QUERY` / `MPJ LAMBDA` / `XML select: …` / `JPA`），不符即中止本次 take。
3. **收尾自检**：每段录完扫一遍该段帧，检出「跳行弹窗 / 加载占位（正在加载… / 正在处理… / 正在准备预览…）
   / 通知气球 / 红色报错计数 / 明文敏感值」即判该 take 不通过。

### 5.3 验收口径（沿用并强化）

1. **对着仓库里已提交的那份文件**逐帧看——本轮已证实「对着现场/中间产物验收」会得出与提交文件相反的结论（§二 与复核文档 §4.2）；
2. 每张写「首帧 / 关键动作帧 / 尾帧各看到了什么功能动作」，写不出即不通过；
3. alt 里每个名词（按钮名、面板名、弹窗名）都必须能在画面里找到；
4. 反向自证：这张图挂了，用户能从这个画面学到 alt 承诺的事吗。

## 八、风险

1. **沙盒许可**：沙盒偶发弹许可框（`JBAClientHelper connect timed out`），按既有处置停手交用户手工激活，不代录激活码；
2. **同名文件**：工程里 `UserMapper.xml` / `UserMapper.java` / `UserRepository.java` 同名或近名，一律走 MCP 按绝对路径打开；
3. **录制独占键鼠**：录制期间不能并行跑构建；发现被抢前台立刻停手说明；
4. **首页引用回归**：`wrapper-preview` 重录后要检查首页卡片与快速开始页的显示（同一文件，6 处引用）；
5. **文案回滚**：`jpa-write-path` / `xml-ognl` 两处 alt 本轮按画面删掉了未拍到的动作，重录补齐后**要恢复**对应句子。
