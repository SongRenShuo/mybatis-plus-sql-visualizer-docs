# 需求池 / Bug 悬赏页顶部导航透明重叠-开发计划

> 日期：2026-11-03 15:16
> 状态：已实施并部署（.VPNav 改常驻不透明，style.css 注释留痕，commit 7b02213；2026-11-11 盘点核实）
> 范围：`.vitepress/theme/index.ts` 的导航滚动逻辑 + `.vitepress/theme/style.css` 的 `.VPNav` 背景规则
> 关联：`docs/开发计划/20260904-1430-需求池布局重构与动态日志-开发计划.md`（这两页的布局来源）

## 一、问题

用户反馈：需求池、Bug 悬赏两个页面下滑时顶部导航是透明的，内容从导航底下穿过，看起来重叠。

实测复现（生产 https://sql-visualizer.jvtools.cn ，视口 1280×720，Chrome）：

| 页面 | `window.scrollY` | `.VPNav` class | 计算背景色 | 备注 |
| --- | --- | --- | --- | --- |
| `/about/feedback` | 0 | `VPNav transparent` | `rgba(0, 0, 0, 0)` | `.VPPage` 首元素 top = 64px |
| `/about/feedback` | 40 | `VPNav transparent` | `rgba(0, 0, 0, 0)` | 「需求反馈池」标题已压到导航上（截图确认） |
| `/about/feedback` | 948 | `VPNav scrolled` | `rgb(255, 255, 255)` | 超过阈值后恢复正常 |
| `/about/bounty` | 200 | `VPNav scrolled` | `rgb(255, 255, 255)` | 结构同款，同样存在 0~50px 窗口期 |
| `/`（首页） | 任意 | 无 `.VPNav` 元素 | — | 首页用自建 `NavHeader`，不走这套逻辑 |

## 二、根因

三层叠加：

1. **`.VPNav` 默认透明**：`style.css:127` 写死 `background-color: transparent !important`，只有 `.VPNav.scrolled`（`style.css:133`）才给底色。
2. **阈值 50px**：`index.ts:84-96` 的滚动处理在 `window.scrollY > 50` 时才加 `scrolled`，0~50px 区间保持 `transparent`。
3. **这两页内容紧贴导航下沿**：`layout: page` 的 `.VPPage` 首元素 top = 64px，与导航高度（实测 64~65px）齐平。于是滚动 0~50px 时，标题直接从**完全透明**的导航条底下滑过。

为什么只有这两页出问题：

- **文档页**：有侧栏，`.VPNavBar.has-sidebar` 规则（`style.css:134`）让导航常驻不透明，透明态永远不会被看到。
- **首页**：`layout: false`，导航是自建的 `NavHeader.vue`（第 60 行自带 `scrolled` / `transparent` 切换），与 `.VPNav` 无关。
- **全站只有这 4 个页面**（`about/feedback.md`、`about/bounty.md` 及 en 同名页）设了 `sidebar: false`——正好是用户点名的两页（中英各一）。

**触发时机**：本轮把周报订阅卡从页首移到页尾（`753241a`），「需求反馈池」标题上移到页面最顶部，原本被订阅卡挡住的重叠因此暴露出来。

## 三、方案对比

### 方案 A：取消 `.VPNav` 的透明态（推荐）

既然文档页靠 `has-sidebar` 常驻不透明、首页根本不用 `.VPNav`，那么**透明态目前没有任何页面受益**，是纯遗留设计。直接把默认背景改成不透明即可，一处 CSS + 一处 JS 分支。

- 改动：`style.css` 的 `.VPNav` 背景改 `var(--bg-primary)`；`index.ts` 里不再添加 `transparent` 类（`scrolled` 保留，只负责阴影/描边的抬升感）。
- 优点：改动最小、一次性覆盖 4 个页面、不引入新状态；与文档页观感统一。
- 风险：若将来有页面真需要「顶部透明导航」，需重新引入该态（目前无此需求）。

### 方案 B：给自定义页加常驻不透明类

保留透明态，在 `index.ts` 里判断当前页是否 `layout: page`（`document.querySelector('.VPPage')` 存在），是则给 `.VPNav` 加 `vp-page` 类，CSS 里与 `.scrolled` 同款底色。

- 优点：保留「首页顶部透明」的设计语义（虽然当前没页面用到）。
- 缺点：多一份 JS 状态与路由同步逻辑，多一个类，收益与 A 相同。

### 方案 C：把阈值从 50px 降到 4px

- 只改一个数字，但 0~4px 窗口仍在，且不解决「这两页与文档页观感不一致」的根因。不单独采用。

**结论：采用 A。** 若实施时发现 A 有不可接受的副作用，退回 B。

## 四、实施任务

### T1 去掉 `.VPNav` 的透明背景

文件：`.vitepress/theme/style.css:121-138`

- `.VPNav` 的 `background-color: transparent !important` 改为 `var(--bg-primary) !important`。
- `.VPNav.scrolled` 保留现有阴影与描边（此时它只承担「滚动后抬升」的视觉，不再负责「从不透明变不透明」）。
- 暗色模式无需另写：`--bg-primary` 在 `.dark` 下已有 `#2b2d30`（`style.css:105`）。

### T2 去掉滚动逻辑里的 `transparent` 分支

文件：`.vitepress/theme/index.ts:84-96`

- `scrollHandler` 只保留 `scrolled` 的加减，删除 `classList.add('transparent')` / `remove('transparent')` 两行。
- 同步删除首屏 `scrollHandler()` 调用里对 `transparent` 的依赖（保留一次调用以初始化 `scrolled` 状态）。

### T3 回归验证（不改代码，只读数）

对下列 6 个位置读 `document.querySelector('.VPNav')` 的 class 与 `getComputedStyle().backgroundColor`：

1. `/about/feedback` scrollY = 0 / 40 / 600
2. `/about/bounty` scrollY = 0 / 40 / 600
3. `/en/about/feedback`、`/en/about/bounty` 各取 scrollY = 40
4. 任一文档页（如 `/guide/getting-started`）scrollY = 0 / 600：导航应始终不透明，无变化
5. 首页 `/`：`NavHeader` 的透明/滚动行为不变（`NavHeader.vue` 未改动）
6. 暗色模式下取 1~2 个读数：背景应为 `rgb(43, 45, 48)`

## 五、验收标准

- 上述 4 个自定义页面在 scrollY = 0、40、600 三个位置，`.VPNav` 计算背景均不为 `rgba(0, 0, 0, 0)`；滚动 0~50px 区间不再出现标题穿过导航。
- 文档页顶部观感与改动前一致（本就不透明）；首页导航行为无变化。
- 中英文两侧、浅色/暗色两种模式各验一次。
- 构建通过（`npm run build`），页面无控制台报错。

## 六、风险与待验证前提

- **待验证前提**：文档页的常驻不透明来自 `.VPNavBar.has-sidebar`，而非 `.VPNav.scrolled`。已用生产页 CSS 规则表确认该规则存在（`style.css:134`），但实施后仍需按 T3 第 4 条实测一次，避免「去掉透明态后文档页顶部反而变白、与 hero 区不协调」——文档页当前顶部本就不透明，预期无变化。
- **待验证前提**：`.VPNav` 与 `.VPPage` 的 64px 对齐是否在所有断点成立。移动端（<768px）导航高度可能变化，实施后需在窄屏再量一次首元素 top 与导航高度，确认不会出现新的贴边。
- **风险**：`transition: all 0.3s` 会让背景变化有 0.3s 过渡；去掉透明态后不再有背景过渡，只剩阴影过渡，观感上更干脆，属预期变化。
- **回滚**：本次改动是两处小编辑（CSS 一行、JS 两行），回滚即恢复 `transparent` 分支与透明背景。

## 七、实施记录（2026-11-03）

1. `.vitepress/theme/style.css:127`：`.VPNav` 的 `background-color` 由 `transparent` 改为 `var(--bg-primary)`。
2. `.vitepress/theme/index.ts:87-96`：`scrollHandler` 删除 `transparent` 的加减，只保留 `scrolled`。
