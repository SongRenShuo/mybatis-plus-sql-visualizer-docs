# 开发计划：首页「大幅提升您的 SQL 调试效率」区块追加核心功能展示

> 日期：2026-09-15 08:18
> 仓库：mybatis-plus-sql-visualizer-docs（文档站 / 官网，Cloudflare Pages）
> 涉及组件：`.vitepress/theme/components/home/FeatureAlternate.vue`

## 一、需求分析与现状

首页「大幅提升您的 SQL 调试效率」区块（FeatureAlternate.vue）目前只展示 4 个功能，图文交替布局，每条配一张功能动图：

| # | 条目 | 动图 |
| --- | --- | --- |
| 1 | Wrapper → SQL 实时预览 | wrapper-preview.gif |
| 2 | 控制台日志一键还原 | sql-log.gif |
| 3 | SQL → Java 反向转换 | sql-to-java.gif |
| 4 | XML / 注解 / MPJ 全覆盖 | xml-preview.gif |

而 `public/demo/` 动图库现有 9 张功能动图（第 9 张 crud-sql.gif 已于 0915 上线功能页首屏），其中 5 张未进入首页区块：**crud-sql、jpa-preview、batch-operation、code-completion、annotation-preview**。

功能页（features/*.md）9 个全部配齐 GIF，首页展示已落后于功能页覆盖。首页是转化入口，最新旗舰功能（CRUD SQL 生成，v2026.9.14-beta）在该区块零露出；JPA / Hibernate 预览是受众面最大的一次扩展（超出 MyBatis 生态），同样未露出。结论：**值得加，且素材现成，纯前端条目追加，一次改动一个文件。**

## 二、入选分析与取舍

对 5 张未展示动图逐张评估：

| 候选 | GIF 体积 | 结论 | 理由 |
| --- | --- | --- | --- |
| crud-sql.gif | 928K | ✅ 追加 | 最新旗舰功能（右键一键生成 CRUD SQL），区块内零露出，动图信息量大、演示性强 |
| jpa-preview.gif | 2.6MB | ✅ 追加 | 受众最大扩展——覆盖 Spring Data JPA / Hibernate 用户，是「不止 MyBatis」的差异化卖点 |
| batch-operation.gif | 987K | ❌ 本轮不加 | 批量参数面板是预览弹窗的子能力，单独成条叙事偏弱；其卖点后续可并入 Wrapper 条目的要点清单 |
| code-completion.gif | 336K | ❌ 本轮不加 | 辅助性编辑增强，动图观感（弹窗列表）弱于面板/预览类；体量小，后续随需要再加不冲突 |
| annotation-preview.gif | 913K | ❌ 不加 | 第 4 条「多框架支持」的文案与要点已覆盖注解 SQL（@Select/@Update/OGNL），重复展示 |

追加规模两案：

- **方案 A（推荐，本计划按此实施）：追加 2 条 → 共 6 条**。叙事完整（预览 / 还原 / 转换 / 生成 / 多框架 / 跨生态六连），GIF 增量约 3.6MB（懒加载下滚动到位才拉取）。
- 方案 B（备选）：除 annotation 外全加 → 共 8 条。覆盖最全，但区块过长、条目稀释，批量操作与补全两条单独成项的必要性不足。

## 三、改动方案

### 3.1 条目与排序

现有 4 条位置不动，两处插入，全程保持图文左右交替（reverse 节奏：2、4、6）：

| # | 条目 | reverse | 状态 |
| --- | --- | --- | --- |
| 1 | Wrapper → SQL 实时预览 | — | 既有 |
| 2 | 控制台日志一键还原 | ✓ | 既有 |
| 3 | SQL → Java 反向转换 | — | 既有 |
| 4 | CRUD SQL 一键生成 | ✓ | **新增**（紧随反向转换，「SQL→代码 / 代码→SQL」互为镜像，叙事连贯） |
| 5 | XML / 注解 / MPJ 全覆盖 | — | 既有 |
| 6 | JPA / Hibernate SQL 预览 | ✓ | **新增**（与第 5 条组成「多框架 → 跨生态」收尾） |

### 3.2 新条目文案口径（以功能页已核实内容为准）

**CRUD SQL 一键生成**（badge：智能生成）

- 描述：实体类 / 数据库表右键即出 SELECT / INSERT / UPDATE / DELETE 候选，选定进预览直接编辑、复制
- 要点三条：
  - 三入口覆盖——实体类文件、项目视图节点、Database 表节点（Ultimate）
  - 候选浮层秒选——打字即过滤，Enter / 双击选定，ESC 关闭
  - 语义对齐 MP 运行时——乐观锁进 WHERE、自增主键默认不勾、逻辑删除出专用 DELETE 变体

**JPA / Hibernate SQL 预览**（badge：跨生态）

- 描述：Repository 派生方法、JPQL / HQL、Criteria 链静态解析出 SQL，不启动 Spring 容器、不连数据库
- 要点三条：
  - 派生方法解析——findByXxx 命名规则全支持，gutter 图标点击即出
  - @Query 全兼容——JPQL / 原生 SQL / @Modifying DML 直接预览
  - Criteria 链与 .hbm.xml——静态解析，不依赖容器与数据库

最终措辞实施时对照 `features/crud-sql.md`、`features/jpa-preview.md` 打磨，不引入功能页之外的新口径。

### 3.3 技术要点

1. **只改 `FeatureAlternate.vue` 的 `features` 数组**：追加两个条目对象（badge / title / description / features 三要点 / imageSrc / poster / reverse），模板与样式零改动——交替布局、懒加载、poster 常驻兜底、GIF 淡入叠层、加载失败摘除机制全部复用。
2. **aspect-ratio 无需调整**：区块 CSS 固定 `aspect-ratio: 1440 / 1034`（≈1.3926），新素材 1280×920（≈1.3913），比值差约 0.09%，object-fit: cover 下裁切不可见。布局由底层 poster 撑起，GIF 为绝对定位叠层，天然一致。
3. **clip-path 裁边沿用**：新素材与旧素材同出 MPSV-GifFresh 录制管线，窗框样式一致，沿用 `inset(0.15% 0.6% 0.85% 0.6%)`；目检若新素材边框宽度有异再分组微调（预期不用）。
4. **体积可控**：新增 GIF 合计约 3.6MB，但全部 `loading="lazy"` 且滚动进视口才发起请求，首屏实际增量只有 poster（各 207~246K）。jpa-preview.gif 2.6MB 偏大，本轮先观察滚动加载体验，压缩另列不阻塞。

## 五、验证与部署

1. `npm run build` 全站构建通过；
2. `npm run preview` 本地目检：6 条图文交替布局正常、新条目 GIF 正常播放、断网或改错路径时 poster 兜底不塌布局、窄屏（<768px）单列无裁切、暗色模式窗框裁边干净；
3. DevTools Network 确认新 GIF 懒加载生效（滚动到位才请求）；
4. `npm run deploy`（wrangler pages deploy --branch main）上线后 curl 生产域首页复核新条目渲染；
5. 测试通过即 commit（只 add 本次文件，不 push）。

- 不加批量操作 / 代码补全 / 注解预览条目（取舍理由见第二节，后续需要再评估）；
- 不动首页 FeaturesGrid 卡片区（CRUD SQL 已在「广泛集成」卡描述中提及，0914 轮已补）；
- 不动 GifPlayer 组件与任何功能页；
- 本轮不做 GIF 二次压缩（jpa-preview 2.6MB 先观察，需要时用 gifsicle 降帧另立任务）。
