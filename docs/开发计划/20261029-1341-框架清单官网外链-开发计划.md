## 一、需求理解

三句话拆开：

1. `guide/compatibility.md` 的「框架支持范围」表里，框架名现在是纯文本。用户希望点得出去，按「官网 > 官方 GitHub 仓库 > 官方文档站」的优先级取目标。
2. 「其他类似的地方也一起优化掉」——全站还有哪些地方是「把第三方框架当主体列出来」，一并处理。
3. 产出是计划文件，先不做实施。

### 1.1 链接投放口径

文档站的正文里，同一个框架会反复出现（仅 `MyBatis-Plus` 一个名字就出现在 12 个中文站点页里）。如果每处都上链，一页能挂十几个外链图标，读起来比现在更差。所以定两条编辑规则：

- **只链「清单位置」与「页面开篇的主体指名」**：支持范围表、同类写法表、页面首段点名的技术栈、FAQ 里「依赖怎么引」的那一处。正文里当定语用的提及（「JPA 的 findAllById 没有预览」「Hibernate 日志合并」这类）不链。
- **同一页面同一框架最多出现一次链接**。jpa 预览页开篇已经点了 Spring Data JPA 与 Hibernate，后面正文不再重复。

这样全站新增 56 个外链（中英各 28 个），覆盖 10 个文件，不改变任何既有链接。

### 1.2 与现有站点约定对齐

- 站点已开 `themeConfig.externalLinkIcon: true`（`.vitepress/config.mts`），外链会自动带一个右上箭头伪元素，不需要手工加图标；VitePress 1.6 默认给正文外链加 `target="_blank" rel="noreferrer"`（实测站内既有的 Marketplace / Gitee Releases 链接同样带），也不需要手写这两个属性。
- 中英必须 1:1 同构，两边的表格行数、链接数量、URL 集合完全一致。
- 本仓库 Gitee 为主仓、GitHub 为镜像，内容改动两边同时生效，不需要同步脚本。

### 1.3 本次不做

- 不做链接点击统计、不加跳转中转页。
- 不做数据库方言外链（理由见第七节）。
- 不动插件仓库与工具站。

## 八、待验证前提与风险

1. **Querydsl 官网证书不可用（已实测，不是本机网络问题）**：`querydsl.com` 解析到 GitHub Pages 的 185.199.x.x，`openssl s_client` 拿到的是 `CN=*.github.io` 证书，SAN 里没有 querydsl.com；curl 直连与本地代理都报 `SEC_E_WRONG_PRINCIPAL`，浏览器同样会拦。已改用官方仓库 `https://github.com/querydsl/querydsl`（代理下 200）。若项目日后为自定义域名补上证书，可换回官网。
2. **外链箭头在表格里的观感**：`externalLinkIcon` 是 CSS 伪元素（`.vp-doc a[href*='://']::after`），会出现在每个表格外链后。桌面宽度大概率没问题，375px 下需要目视确认不会把 `MyBatis Dynamic SQL` 这类长名称挤成孤立单词。
3. **拆表后的小标题**：新增 `### 其他 ORM（MVP）` 会让右侧「页面导航」多一项（outline 配置为 2-3 级）。若用户不希望目录变长，可退回「一张表 + 行内多链接」的形态，但那样一格最多 6 个箭头，可读性更差。
4. **JdbcTemplate 归属调整**：把 JdbcTemplate 从 MyBatis 行拆出来属于口径校正，依据是 `features/wrapper-preview.md:30` 与 `guide/faq.md:144`。实施前再确认插件侧确实把 JdbcTemplate 当作独立支持面（不是 MyBatis 的附属）。若插件实际按 MyBatis 归类，保留原行、只加链接。
5. **构建绿不等于链接有效**：`npm run build` 带 `--ignoreDeadLinks`，只校验站内链接，外链拼错照样构建成功。验收必须同时看巡检读数与双向核对，不能拿 build 通过当外链无误。
6. **英文页与中文页的链接集合必须一致**：两页各 13/5/2/2/6 个，URL 集合完全相同。任何一侧漏改都会导致中英信息不对等，用 `diff` 两页的 `grep -o 'https\?://[^)]*' | sort -u` 结果收口。
7. **设置项名称内嵌链接的观感**：FAQ 的 JdbcTemplate 那条把链接放在「启用 … SQL 字符串预览」这个设置项名称中间，读者可能误以为是界面上的可点元素。实施时先按此做，若目视显得别扭，改为在答案末尾补一句「JdbcTemplate 属 Spring Framework，官方文档见 …」。
8. **MCP 客户端两条链接的语义偏差**：JetBrains AI Assistant 的 `/ai-assistant/` 现在 301 到 `/ai-ides/`（页面名「AI in JetBrains IDEs」），链接文字与落地页标题不完全一致，属于产品页合并，可接受；Codex 用官方仓库而非官网，因为官网对 curl 直连和本地代理都返回 403，如果后续浏览器验证官网可达，可换回 `https://openai.com/codex/`。
