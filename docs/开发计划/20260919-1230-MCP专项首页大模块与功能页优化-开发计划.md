## 三、功能页 features/mcp.md 优化（中英）

现页 64 行骨架偏「清单」，按开发者视角重组为「上手 → 工具速查（含输入）→ 工作流 → 安全」：

1. 新增「快速上手」节：前提（IDEA 2025.2+ 内置 MCP Server）→ 在 agent 里添加当前 IDE 的 MCP Server 连接（如 Claude Code `use_idea_mcp`）→ 直接调用 `mpsv_*` 工具。三步走。
2. 工具表增加「输入」列，字段全部对照源码签名：
   - `mpsv_render_sql(filePath, line, xmlSnippet, sourceType)`：文件+行号，或直接贴 mapper XML 片段
   - `mpsv_render_logs(logText, sqlPrefix?, paramPrefix?, hibernateSqlPrefix?, hibernateParamPrefix?, mixedPrefixMatching?)`：整段日志原文，前缀可定制
   - `mpsv_schema_context(tables, dataSource?, maxTables?)`：表名清单
   - `mpsv_explain(selectSql, dataSource?, dialect?)`：单条 SELECT
   - `mpsv_check_sql(sql)`、`mpsv_perf_advice(sql)`、`mpsv_reverse_sql(sql)`：一条 SQL
   - `mpsv_rollback_plan(sql, primaryKeyColumns?)`：INSERT/UPDATE/DELETE 语句
   - `mpsv_crud_sql(filePath?, className?)`：实体类文件路径或类名
   - `mpsv_mapper_check(xmlSnippet?, filePath?, simulate?)`：mapper XML，simulate 可选
3. 分组按 agent 工作流重排：拿 SQL（render_sql / render_logs / crud_sql / reverse_sql）→ 看库（schema_context / explain）→ 执行前把关（check_sql / mapper_check / rollback_plan / perf_advice）。
4. 新增「典型工作流」节：改一条慢 SQL 的 agent 调用顺序示例（render_sql 拿真实 SQL → explain 看计划 → perf_advice 拿建议 → 回代码修改），只描述调用顺序与工具能力，不虚构返回报文格式。
5. 既有「使用口径 / 使用前提 / 设置页门控 / 只读与安全 / 计划与建议类输出」内容保留，随新结构归位。
6. `en/features/mcp.md` 同构重写。

## 四、MCP 演示 GIF 录制计划（本次只立项，不录制）

目标产物：`public/demo/mcp.gif` + 同名 poster（基准 1280×920，wrapper 1440×1034，沿用现行 demo 规格）。录制沿用 ide-demo-gif 技能管线（脚本重放 + 帧稳定采样 + PixPin 录制沙盒），后续单独会话执行。

演示场景候选（择一或两条剪拼）：

- **场景 A（推荐）MCP 调试工具直调**：IDEA 2026.2 沙盒装 MCP Server 插件 + 启用插件 MCP；用 MCP Inspector / 兼容客户端连接 IDE MCP Server，依次调用 `mpsv_render_sql`（贴 mapper 片段 → 返回真实可执行 SQL）、`mpsv_schema_context`（表名 → 表列注释上下文）、`mpsv_explain`（SELECT → 执行计划）。画面主体是工具调用的请求/响应与 IDE 内 SQL 预览面板同框。
- **场景 B agent 对话式**：Claude Code（或 Cursor）连 IDE 后以自然语言「把 UserMapper.getUserById 渲染成可执行 SQL 看看」→ agent 调 `mpsv_render_sql` 返回 SQL → 追问执行计划（`mpsv_explain`）。更贴近真实用法，但依赖外部 agent 画面，录制窗口内元素多、稳定性弱于 A。

录制要点：

1. 前置检查：沙盒 IDE ≥2025.2（现行 GIF 沙盒 2026.2.1 满足）；设置页「MCP 工具」总开关开启；演示项目含 UserMapper/UserDO 与可用数据源（explain 需要真连库，可复用现有 testdb 容器或本地 MySQL）。
2. 脚本先行：把每一步的输入文本写成脚本文件重放（贴片段、点调用），避免手敲抖动；调用间隔留足响应渲染时间。
3. 采样与规格对齐既有管线：1280×920 采样区、帧稳定双扫描判落位、产物 ≤8MB（超限降帧率/时长）。
4. 交付物替换链：`public/demo/mcp.gif` + `public/demo/mcp.png`（真截图 poster）→ `FeatureAlternate.vue` MCP 卡 `imageSrc` 改 `/demo/mcp.gif`、`poster` 改 `/demo/mcp.png` → 发行说明登记。
5. 红线提醒：录制画面里不得出现与插件无关的内部信息（沙盒路径、并行会话痕迹）；返回报文如实录制不摆拍修改。
