## 二、场景脚本要点

### R1 dialect-gate（照抄 745fd58 的场景骨架，行为换新）

1. 设置页方言手动指定 PostgreSQL（沿用上次录法的入口路径）
2. 打开 Wrapper 链预览（SQL 呈 `FROM "user"` 双引号形态）——上次已验证该场景可行，脚本路径在录制仓 `sql-visualizer-recording` 找 dialect-gate 对应 scene
3. 点「执行 SQL」→ 数据源选 MySQL（mpj_demo@localhost）
4. **验收锚点**：结果区出现「方言不一致：…」信息提示（非红字阻断）、执行继续提交、出口「切换数据源 / 方言设置 / 复制错误信息」在；**不得出现**「已阻止执行」字样
5. poster 重出；zh/en 共用，alt 已是新口径无需改文案

### N1 mapper-nav-jump

1. 前置：在 demo 工程确认一对现成的「mapper XML 语句 ↔ 接口方法」（namespace + id 匹配才出图标，锚点要提前踩点，见 §四前提 2）
2. 分镜：XML `<select id=…>` 行 gutter 图标点击 → 编辑器落到接口方法行；再点接口方法行的图标 → 跳回 XML 语句行
3. 验收锚点：两枚图标 tooltip 分别为「跳转到 Mapper 接口方法」「跳转到 Mapper XML 语句」（bundle `gutter.mapperStatement.tooltip` / `gutter.mapperMethod.tooltip` 亲证）；跳转落行正确、往返各一次

### N2 xml-editing-support

1. 分镜（两镜）：①焦点放进 `<if>` 内 SQL 文本——`#` 输入自动补 `{}`、`#{` 后触发补全选 `jdbcType`；②点动态标签折叠三角收起 `<if>`
2. 引用导航（跳转 include 定义）作为可选第三镜，画面挤不下就裁
3. 验收锚点：补全弹窗在场、折叠生效；**须等索引就绪**（dumb 态补全降级为只补关键字，见 §四前提 4）

### N3~N5（可裁项）

按用户点名后补细化分镜；N3 需先在 demo 控制台跑出 CREATE / DROP 类 DDL 日志条目；N5 需先改 demo 工程（走插件仓正常流程，改动单独提交）。
