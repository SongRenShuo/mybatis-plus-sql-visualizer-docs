# 需求池推送分类中文化 开发计划

- 日期：2026-09-07 01:03
- 范围：后端 `sql-visualizer-admin`（constants.ts + feedback/routes.ts），无前端改动
- 背景：在需求池创建新需求时，推送给管理员的推送plus 消息里分类显示为英文 slug（`分类: other`），应为中文标签（`分类: 其他`）。

## 现状分析

- 前端 `FeedbackForm.vue` 提交的是分类 slug（`wrapper`/`xml`/…/`other`），中文标签只存在于前端 `i18n.ts` 的 `cat.*` 键（`cat.other: '其他'` 等），不随请求上传。
- 后端 `src/modules/feedback/constants.ts` 只有 `Categories` slug 数组（校验/筛选用），没有 slug → 中文标签映射；对比之下反馈类型已有 `PostTypeLabels`，状态已有 `PostStatusLabels`，唯独分类缺标签表。
- 创建反馈接口 `src/modules/feedback/routes.ts`（`POST /posts`）通知管理员处：
  - `notifyAdminNewPost(cfg, { ..., category: body.category || 'other', ... })` 原样传 slug；
  - `pushplus.ts` `notifyAdminNewPost` 模板直接输出 `- 分类: ${post.category}` → 推送内容显示 `分类: other`；
  - 同处 `logNotification` 落库内容 `${body.category || 'other'}` 也是 slug，管理后台「通知记录」同样显示英文。
- 评论通知 `notifyAdminNewComment`、状态变更/合并/回复等用户邮件通知均不涉及分类，无需改动；管理后台 SPA 不展示分类字段，无需改动。
- `body.category` 无合法性校验（原样落库），转换时需兜底：未知 slug 显示原值而非 undefined。

## 改动方案

### T1 constants.ts：新增 CategoryLabels

- `src/modules/feedback/constants.ts` 在 `Categories` 旁新增：

  ```ts
  export const CategoryLabels: Record<string, string> = {
    wrapper: 'Wrapper 预览',
    xml: 'XML 预览',
    annotation: '注解预览',
    'sql-to-java': 'SQL 转 Java',
    'sql-log': 'SQL 日志',
    batch: '批量操作',
    completion: '代码补全',
    other: '其他',
  };
  ```

- 中文文案与前端 `i18n.ts` zh 的 `cat.*` 逐一对应，后续前端改文案需两处同步（已属既有模式：`PostTypeLabels` 同样前后端各一份）。

### T2 routes.ts：通知内容用中文标签

- import 增加 `CategoryLabels`。
- `POST /posts` 通知块顶部解析一次：`const categoryLabel = CategoryLabels[body.category || 'other'] || body.category || '其他';`
- `notifyAdminNewPost` 的 `category` 传 `categoryLabel`；`logNotification` 的 `content` 同步使用 `categoryLabel`。
- 数据库 `fb_posts.category` 仍存 slug（筛选、看板统计、深链都依赖 slug），只转换推送展示层。

## 验证

- `npx tsc --noEmit` 通过；`vitest run` 全量测试通过。
- `wrangler deploy` 后线上创建一条分类为「其他」的测试需求，推送内容应显示 `分类: 其他`；通知记录落库同步为中文。
- 验证后删除测试数据。
