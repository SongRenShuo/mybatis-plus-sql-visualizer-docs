## 四、录制期纪律

**插件功能问题一律停录回修，不在录制现场处理**（用户指令，2026-09-19）。

录制过程中一旦发现插件功能问题——界面异常、数据错误、崩溃、行为与文档描述不符、工具返回不符合预期——**立即停止录制**，不在现场改代码、不打临时补丁、不绕过问题继续录。带着问题往下录只会产出与真实行为不符的演示，事后还得重录。

处置流程：

1. 停录，记录现场证据（截图 / `idea.log` 片段 / 复现步骤），写进本计划实施状态；
2. 回插件项目（`F:\code\Java\Gitee\SongRenShuo\mybatis-plus-sql-visualizer`）按正常流程处理：定位根因 → 修复 → 补或跑测试 → 按插件仓库自身规范提交；
3. 修复验证通过后**重新开始录制该张**，不是续录——停录时的现场状态已不可信；
4. 若该问题同时影响文档描述（行为已变、能力受限、入口变了），同步订正对应文档页，不能只改代码。

录制现场改代码之所以禁止：`-PgifRecord=true` 是 262 录制态构建，改源码会触发重构建、污染沙盒状态与已标定的坐标，且录出来的画面与用户实际拿到的发行版不一致。修复必须走插件仓库的正常流程，产物以发行版为准。

本纪律适用于所有轮次录制，不只本轮——同步写进《演示GIF录制指南-说明文档》（见 T5）。

## 五、分镜设计

### M1 · MCP：门控、注册面与调用留痕

MCP 的演示对象是「插件注册进平台内置 MCP Server 的十个只读工具」，画面元素全部落在 IDE 内，不需要外挂 agent 窗口——这使它可以沿用既有单窗口构图基线，不必破例做双窗口合成。三段：

**M1-a 门控（必录，零依赖）**
`Settings → Tools → SQL Visualizer → MCP 工具` 子页（`McpConfigurable`）：总开关 + 十个工具逐项复选框 + 全选/全不选 按钮（按钮文本随全选状态切换）+ 「打开 MCP Server 设置」按钮与说明行。演示点「全不选」→ 十个复选框全灰 → 点「全选」→ 恢复 → 单独关掉一个工具（如 `sqlv_explain`）体现门控粒度。门控即时生效（`McpToolsetSupport.isEnabled()` 每次由平台 `getEnabledToolsets` 读取），无重启。

**M1-b 注册面（必录，依赖 T0 判定）**
点「打开 MCP Server 设置」→ 跳转平台 `Settings | Tools | MCP Server` 页（`com.intellij.mcpserver.settings.McpServerSettingsConfigurable`），`Exposed Tools` 列表里能看到插件注册的 `sqlv_*` 工具与逐项启用开关——这是「十个工具真的注册进平台内置 server 了」的现场证据。若 T0 判定该页不列插件工具（平台版本或页面形态差异），本段取消，动图缩为 M1-a + M1-c。

**M1-c 调用留痕（可选，依赖 T0 判定）**
打开 `idea.log`，可见 `[MCP-AUDIT] tool=… status=… elapsedMs=… args=…` 行（`McpAuditLog.call` 按 INFO 落盘，每次调用一行）。**该段只在 T0 证实 agent 侧可实际驱动后录制**——审计行的价值在于它由真实调用产生，无调用时不得用历史日志或伪造行充数。若 agent 不可驱动，本段取消并在动图说明中如实反映（动图只覆盖门控与注册面）。

agent 侧的驱动方式（**2026-09-19 定案：走 ACP**，用户选定）：

1. **首选——AI Assistant 的 ACP agent**：AI Assistant 经 Agent Client Protocol 在 IDE 内启动 Claude Agent，由它调用 IDE 内置 MCP Server 的 `sqlv_*` 工具，对话与工具调用结果都呈现在 AI 面板内。画面全程留在同一个 IDE 窗口，既不破构图基线，也与用户日常用法一致。已装并启用过的 ACP agent：Claude Agent（最近使用 2026-09-11）、Codex、Cline、GitHub Copilot、OpenCode、Junie。
2. 备选——IDE 内置 Terminal 跑 Claude Code CLI（已实测可通，结论见下）。
3. 末选——外挂 agent 独立窗口（引入第二窗口，须先申请构图豁免）。

**为什么选 ACP（本机实证，2026-09-19）**：

- **MCP 是白送的**：日志实证 `AcpIdeaMcpProviderImpl - Running private IJ MCP session for agent acp.registry.claude-acp over Stdio`——IDE 给 ACP 的 Claude Agent 自动开**私有 stdio MCP 会话**，不用端口、不用鉴权 token、不用手工接入。终端路线则要处理端口漂移与 token，见下。
- **认证可外部托管，直接用方舟配置**：沙盒缺 `config/options/acpAgents.xml` 时面板退化为「选择身份验证方式：JetBrains / Anthropic Console」；补上 `agent_auth = MANAGED_EXTERNALLY` 后变为「由智能体管理」，模型选择器直接显示 `deepseek-v4-1-flash-260910`，即 claude-acp 读用户 `~/.claude/settings.json` 的方舟端点。**重启沙盒后已实测生效**。
- **不需要 JetBrains AI 订阅**：日志 `AiaActivationState: jbai=null, byok=null, acp=AcpAuthContext(agentCount=5)`——ACP 侧 5 个 agent 可用，与 JetBrains AI 授权无关。
- **agent 侧机器级共享**：注册表在 `%APPDATA%\JetBrains\acp-agents\installed.json`（不在产品配置目录）、凭据在 `~/.claude`、`~/.codex`，沙盒直接可见，不需重装或重登。

**沙盒侧前置（已落到分支 `t-gif-rec-mcp`）**：

1. `ml-llm` 声明式安装（`build.gradle.kts` 的 `plugin("com.intellij.ml.llm", "262.9437.276")`）——AI Assistant 不在 distro 内置插件里，且 `prepareSandbox` 每次重建沙盒 `plugins/` 目录，手工拷贝会被清掉。
