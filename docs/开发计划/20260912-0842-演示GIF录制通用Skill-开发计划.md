# 演示 GIF 录制通用 Skill 开发计划

- 立项时间：2026-09-12 08:42
- 背景：修订九轮（2026-09-12）7/8 张演示 GIF 重录验收通过，录制方法论已沉淀在三处——插件仓库 `docs/经验总结/20260910-0100`（原理与平台坑）、文档站 `docs/演示GIF录制指南-说明文档.md`（操作手册）、插件仓库 `record/`（可执行工具 gifkit/assemble/shot + 场景脚本 scene_t1~t8）。但三者都是文档与项目内脚本，换一个项目、换一台机器就要从头翻文档拼流程。目标是把这套方法论做成 ZCode **通用 skill**：自然语言说「给 XX 功能录一张演示 GIF」即可触发，skill 自带工具脚本与操作手册，跨项目可复用。
- 目标：新建用户级 skill `~/.zcode/skills/ide-demo-gif/`，自包含工具脚本 + 精炼操作手册；在文档站与插件仓库的经验文档中互链，形成「skill 管执行、文档管背景」的分工。

## 一、现状盘点

| 资产 | 位置 | 通用化程度 |
|------|------|-----------|
| gifkit.py（贝塞尔轨迹/点击/快捷键/wait_stable 帧稳定采样/Recorder 录屏） | 插件仓库 record/ | 部分——find_gutter_icons 硬编码 region 偏移 (277,25)，open_file 首行坐标硬编码 |
| assemble.py（空白压缩+光标回绘+GIF 转制+poster） | 插件仓库 record/ | 通用，无项目耦合 |
| shot.py（单步标定：shot/click/move/pos/key） | 插件仓库 record/ | 通用 |
| scene_t1~t8（分镜脚本） | 插件仓库 record/ | 项目专属（坐标+业务），不进 skill，只提炼模板 |
| 经验文档两份 | 插件仓库 + 文档站 docs/ | 纯文档，不可执行 |
| ZCode skill 机制 | `~/.zcode/skills/<name>/SKILL.md`，frontmatter 仅认 name/description/when_to_use/license/metadata；description 超 1024 字符拒载，触发看 description 前 ~250 字符；目录内可带任意辅助文件 | —— |

## 二、Skill 设计

### 2.1 名称与位置

- 名称：`ide-demo-gif`
- 位置：用户级 `C:\Users\USER\.zcode\skills\ide-demo-gif\`（discovery 顺序第 2 级，全项目可用；不放工作区级，避免仓库耦合）
- 声明 main-agent-only：录制靠桌面自动化（pyautogui 直控 + 必要时 computer-use），子代理不应接手

### 2.2 目录结构

```
~/.zcode/skills/ide-demo-gif/
├── SKILL.md              # 触发描述 + 全流程手册（规格/环境/标定/录制/转制/验收/坑表）
└── scripts/
    ├── gifkit.py         # 通用化改造版（见 T2）
    ├── assemble.py       # 插件仓库现版直接拷入（含残留帧修复）
    ├── shot.py           # 插件仓库现版直接拷入
    └── scene_template.py # 新场景脚手架（本轮从 scene_t4/t3 提炼的通用骨架）
```

### 2.3 frontmatter 草案

- `name: ide-demo-gif`
- `description`（前 250 字符决定触发，须前置「何时用」）：录制 IntelliJ/JetBrains IDE 功能演示 GIF：脚本重放 + 帧稳定采样 + 无损中间产物转制。当用户要求录制/补拍/重录 IDE 插件功能演示动图、把操作过程做成循环 GIF、给文档站或 README 配演示图时使用。Windows + pyautogui 桌面自动化，主智能体亲自执行。
- 可选 `when_to_use`：与 description 同义收敛，补充「不适用于网页/移动端录屏」

### 2.4 SKILL.md 内容大纲（精炼手册，目标 ≤180 行）

1. 前置条件：Windows、Python（mss/PIL/pyautogui/numpy）、ffmpeg、目标 IDE 可启动；并行任务登记（如项目有该机制）
2. 成品默认规格表：1370×984@(277,25)、缩放 120%、编辑器 13pt、树关、Islands Dark、15fps、宽 1280（首页共用位 1440）、4~6MB 预算、同名 png poster——标注「为文档站验证过的基线，其他项目可按投放宽度等比调」
3. 环境就位清单：runIde 启动（runIde 开关/沙盒按目标项目实际）、主题缩放字体、窗口 MoveWindow 定位（等 IDE 空闲，AWT 钳制）、关目录树、IME 英文态
4. 工作流：标定（shot 抓帧→写 scene 常量）→ take（Recorder + wait_stable，自包含就位）→ 转制（核对 decoded==Recorder.frames）→ 抽帧验收（动作/定格/poster 三处）→ 投放位实测
5. 坑表（七条定论，每条现象→原因→处置一句话）：assemble 残留帧、监听类工具「先有控制台再武装」、IME 英文态、打字场景全键盘化、强前台与可视区点击、两套坐标系、Zoom 运行时钳制
6. 环境还原清单

## 三、任务清单

### T1 skill 目录与 SKILL.md 初稿

建 `~/.zcode/skills/ide-demo-gif/`，按 2.3/2.4 写 SKILL.md。素材取自：文档站《演示GIF录制指南》（操作顺序）+ 插件仓库经验总结 §四~§七（坑表）。写完自检：description ≤1024 字符、触发词前置、无项目专名（SQL Visualizer/demo 工程名不进 SKILL.md，只留在示例注释）。

### T2 工具脚本通用化

1. gifkit.py：`find_gutter_icons` 的 region 偏移 (277,25) 与 `open_file` 的 first_row (930,342) 参数化（带默认值=文档站基线，注释说明「换构图必重标」）；模块头加用法示例
2. assemble.py、shot.py：现版拷入，文件头注明来源仓库与同步规则
3. 新写 scene_template.py：常量区（REGION/控件坐标）+ locate 助手 + main 骨架（就位→start→动作→定格→清理→stop）+ 注释标注「动手前先戳一遍验证分镜动作真实存在」
4. **权威源约定**：通用化后以 skill 内 scripts 为权威；插件仓库 record/ 保留 scene_tN（项目场景），其 import 的 gifkit 仍是仓库内副本——两份 gifkit 的同步规则写进 SKILL.md 与插件仓库经验总结：**通用能力改动改 skill 并反向同步，场景坐标改动只动项目 scene**

### T3 安装与发现验证

1. skill 落盘后新开会话验证：`/` 菜单 Skills 组出现 ide-demo-gif；Settings → Skills 可见
2. 触发测试：用「帮我给 XX 录一张演示 GIF」「重录某个 demo 动图」等自然语言验证自动触发；不触发则按 description 前 250 字符重写

### T4 实战验证（skill 的毕业考）

用 skill 流程完整走一个轻量真实场景（推荐：等 T6 sql-to-java 输入编辑器回归修复后的补录 scene_t6，一举两得；修复前可先用 t2 batch 或 shot 标定流程干跑）。验收产出物规格全部达标（帧数一致、接缝、poster 一致、投放位实测）才算过。

### T5 文档收尾

1. 文档站《演示GIF录制指南》头部加一行「已固化为 skill ide-demo-gif（~/.zcode/skills/），本文保留作背景与规格依据」
2. 插件仓库经验总结加同样的互链
3. 两仓库各自本地 commit（不 push）

## 四、验收标准

1. `~/.zcode/skills/ide-demo-gif/` 目录自包含：仅依赖 Windows + Python 三方库 + ffmpeg，换机器装好依赖即可用
2. 新会话自然语言触发成功，skill 加载无 frontmatter 告警
3. 按 SKILL.md 从零走完标定→录制→转制→验收，产出物符合成品规格表（T4 实证）
4. gifkit 通用化后，插件仓库现有 scene_tN 不改一行仍可跑（向后兼容）
5. 两处经验文档互链到位，同步规则成文

## 五、风险与备注

- **skill 膨胀**：SKILL.md 控制在手册粒度，原理性内容留在两份经验文档；scene 模板只给骨架不给业务
- **双拷贝漂移**：gifkit 在 skill 与插件仓库各一份，靠 T2.4 的权威源约定 + 文档互链约束；若后续频繁双向同步，再考虑改为 skill 内 PYTHONPATH 直指插件仓库（牺牲自包含换单一来源，本轮不做）
- **桌面控制权限**：pyautogui 直控不需要 MCP，但抢前台/强前台场景可能要 computer-use 辅助——SKILL.md 写明主智能体执行与降级路径
- **触发面过宽**：description 明确「IDE 桌面 GIF」边界，避免与 browser-use（网页自动化）抢触发
- skill 属用户级资产，不入任何项目仓库；本项目仓库只保留本计划与文档互链
