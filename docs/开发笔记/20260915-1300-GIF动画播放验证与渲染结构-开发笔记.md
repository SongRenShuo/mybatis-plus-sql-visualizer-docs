# GIF 动画播放验证与渲染结构（2026-09-15 文档站实证）

- 记录时间：2026-09-15 13:00
- 项目：mybatis-plus-sql-visualizer-docs（文档站，VitePress）
- 关联任务：docs/开发计划/20260915-1200-GifPlayer首屏懒加载竞态修复-开发计划.md（含修订一：取消 poster 兜底改 GIF 直出）

## 一句话结论

**「GIF 已就绪」不等于「GIF 在播」**：DOM 层验证（img 挂载、complete、opacity 1）全部通过，视觉上完全可能是静态帧。动画是否真的在播，只能靠**真实浏览器**（或能推进图像动画帧的渲染环境）确认；嵌入式 webview（ZCode 内嵌浏览器）与 headless（puppeteer）**不推进任何 GIF 动画帧**，canvas 像素采样指纹恒定，会给出「静止」的假象。

## 一、验证环境的能力边界（本次实证）

| 环境 | GIF 动画帧推进 | 实测证据 |
|------|--------------|---------|
| 真实浏览器（Chrome/Edge 前台） | ✅ 正常 | 用户实测首页动画正常；直出结构修复后详解页也正常 |
| ZCode 内嵌浏览器（IAB webview） | ❌ 不推进 | canvas 像素采样 5 次指纹恒定；**外部已知动画 GIF（维基百科旋转地球）同样静止**——非站点问题，是 webview 图像动画暂停策略 |
| headless（puppeteer） | ❌ 不推进 | 与 IAB 同源问题（录制指南落地清单原写「puppeteer 抽查动画播放」已修正，见下） |

判定方法：`canvas.drawImage(gif) + getImageData` 取同一区域像素指纹，间隔 0.9s 采样多次，`new Set(samples).size > 1` 才说明帧在动。DOM 类（挂载/ready/opacity）不作为动画判据。

推论：**动画类验收必须委托用户真实浏览器**，自动验收只能做结构断言 + 资产多帧核对（GIF 文件本身帧数 > 1 且 15fps），不能宣称「动画播放通过」。

## 二、渲染结构差异导致「同站有的动有的不动」（本次根因）

用户实测：官网首页动画正常、功能详解页静止。两者代码结构对比后定位——**差异不在 poster 兜底、不在 loading="lazy"**（两边都有），而在 GIF `<img>` 的存在方式：

| 位置 | GIF img 渲染方式 | 用户实测 |
|------|-----------------|---------|
| 首页 FeatureAlternate / DocsShowcase | 随页面**初始 HTML（SSR）直出**，poster 撑布局 + GIF 叠层淡入 | 动画正常 |
| 功能详解页 GifPlayer | **hydration 后由 JS 动态插入**（v-if 懒加载门控 + absolute 叠层） | 静止 |

修复：GifPlayer 重写为与首页同构——GIF img 随 SSR 直出，拆掉 v-if 懒加载门 / IntersectionObserver / poster 叠层 / opacity 淡入全套（commit 0040c09），20 处 md 调用同步删 poster 属性。修复后用户真实浏览器复验动画正常。

启示（未在 Chromium issue 层面定位，属经验级结论）：**动画 GIF 以「hydration 后动态插入 + absolute 叠层」方式渲染时，在部分 Chromium 环境存在解码停帧**；初始 HTML 直出的文档流 `<img>` 是最稳的路径。新页面接 GIF 优先直出，避免叠层/门控设计。

## 三、同族问题：IntersectionObserver 对「注册时已相交」元素不回调

本次同一组件里还叠了另一个坑：`onMounted` 创建 IntersectionObserver 并 `observe(container)`，对**注册观察时已处于视口内**（首屏）的元素，SPA hydration 时序下可能不派发回调（没有「从不相交到相交」的变化事件），`loaded` 门永不打开，首屏 GIF 恒停 poster。修复=挂载后同步 `getBoundingClientRect()` 判定，命中直接放行（不注册观察器）。与「GIF 缓存命中时 @load 监听器就位前已 complete」的 hydration 竞态（efda401 修过）同属一族的时序缺陷。

## 四、验收口径修正（已同步到《演示GIF录制指南》）

- **动画播放验收**：真实浏览器为准；IAB/headless 只能查结构（img 存在、complete、多帧资产），不得宣称动画通过；
- **首屏零滚动验收**：加载后不做任何滚动输入，≤3s 内首屏 GIF 必须进入播放态——旧口径含滚动动作会撞开观察器门，掩盖「首屏不播」缺陷；
- **部署后 stale 场景**：唯一真实来源是「部署前已打开的 tab 未刷新」（SPA 内存态）；HTML 是协商缓存、JS chunk 文件名随内容换 hash，部署架构本身无缓存缺陷。
