## 二、分镜（scene_t9_crudsql.py，约 10 秒）

单主线走**实体侧编辑器右键**入口（Community 也可用的主路径，与文档页「触发方式」第一落点一致）。Database 表节点入口不做第二分镜——官方风格一支视频只演示一个功能点，表节点入口在文档页已有文字承载。

1. 打开 `User.java`，光标平滑移至类名行，右键呼出编辑器上下文菜单，停 0.5 秒（菜单内「生成 CRUD SQL」可见）
2. 点击「生成 CRUD SQL」→ 候选浮层弹出（SELECT 全表 / SELECT 按主键 / INSERT / UPDATE / DELETE / DELETE（逻辑删除）六项双行渲染），停 1 秒
3. 键入过滤字符收窄候选 → Enter 选定 INSERT，停 1 秒
4. 预览窗口出现 INSERT SQL 与批量列勾选面板（自增主键 `id` 默认不勾），停 2 秒
5. 取消勾选一列 → SQL 对应列实时收缩，停 1 秒
6. 收尾构图与首帧一致，循环不跳

poster 取分镜 4 帧（INSERT 与列勾选面板同屏，即「关键内容帧」）。

节奏与操作纪律（沿用总计划 §2.4 + 录制指南 §四）：录制前手动戳一遍每个动作确认真实生效；动静反差、关键结果停 1~2 秒；单段直出不拼接；IME 英文态；PixPin 热键冲突规避（开 Settings 走工具栏齿轮菜单）。

## 五、风险与备注

- **右键菜单项位置**：action 注册在 EditorPopupMenu 末位（anchor=last），上下文菜单过长时需确认「生成 CRUD SQL」在可视范围内；若被 IDE 分组折叠或溢出，改用 Project 视图实体节点右键入口（同一 action，分镜第 1 步平移，其余不变）
- **候选浮层为 JBPopup 轻量浮层**：定位跟随光标，编辑器滚动会漂移——脚本标定坐标前先把视图滚动到位再固定；键入过滤的响应速度以沙盒实测为准，过滤字符现场标定（「in」命中 INSERT 是否唯一待实测，不合适就换词或省略过滤直接方向键 + Enter）
- **逻辑删除变体取舍**：User 实体 `@TableLogic` 使浮层多出「DELETE（逻辑删除）」项——属真实能力，默认按全量六项录；若嫌浮层过高构图局促，换无逻辑删除注解的实体（Order / Role）变五项，二选一以画面观感定，须在实施记录里注明用了哪个
- GifPlayer hydration 补位（T12）已双保险，新页接入即受益，无前端改造量
- **一份录制两处投放**：文档站 GIF 与插件 README demo-09 为同一成片的两份拷贝（README 无 poster 机制，仅拷 GIF）；若后续成片因站点侧原因重转制，两份须同步替换，防口径漂移。4~6MB 单文件入插件仓库与既有 8 张同量级，Gitee 仓库体积无增量风险
- 录制完现场还原：杀 demo 应用与沙盒进程、注销并行任务；中间产物不进仓库（record/perf 已 gitignore）
- 部署可与下次站点更新合批；本计划单独 deploy 亦可，按当日批次定
