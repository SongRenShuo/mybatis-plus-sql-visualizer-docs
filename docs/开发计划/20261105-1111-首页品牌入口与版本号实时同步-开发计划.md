## 一、背景与结论

用户报两件事：

1. 首页左上角「SQL Visualizer」点了没反应，进不去官网首页；文档页的同一个位置是好的。
2. 首页首屏「最新版本」还停在 `v2026.11.3`，而最新版已经是 `v2026.11.4`；同一页底部的「最近更新」显示是对的。

两件事成因完全不同，但都不是「哪里写错了一个字符」，而是两条设计缺口：

- **品牌区从来就不是链接。** 首页是 `layout: false` + 自绘 `NavHeader.vue`，品牌块是 `<div class="logo-area">`（`NavHeader.vue:75-78`），没有 `<a>`、没有 `href`、没有 `cursor: pointer`。文档页走 VitePress 默认 `VPNavBarTitle`，它渲染的是 `<a class="title" href="…">`，所以那边一直正常。这条缺口从首页复刻 Cool Request 布局那一版（`519a029`）就在，中间几轮品牌图改造（`6e5edc6` / `fee8614` / `d573140`）都没碰过「可点」这件事。
- **首屏版本号是构建期快照，且没有实时通道。** `usePluginVersion` 直接读 `.vitepress/data/plugin-version.json` 的静态值（`usePluginVersion.js:2-14`），这个文件只在 `npm run build` / `npm run deploy` 时由 `scripts/sync-plugin-version.mjs` 重写。站点 2026-11-03 部署之后没有再构建，快照就停在 2026.11.3；而「最近更新」（`RecentUpdates.vue`）和更新日志页（`ChangelogList.vue`）都在挂载后拉 `/api/changelog` 实时补齐，所以它们显示 2026.11.4。同一页两个版本号来自两条数据链，这就是「上面旧、下面新」的全部原因。

结论：要修的是三件事——品牌区补链接（含中英 locale 前缀）、首屏版本号接 Marketplace 实时通道（构建期只做兜底）、明暗切换换成整页级的圆形揭示（取法 cool-request-web，现在的切换是「谁有 transition 谁自己动」，长页面上参差）。外加一次构建 + 部署把静态快照刷新到 2026.11.4。

## 二、现状核查（实测读数）

### 2.1 生产页面的品牌区结构

```
$ curl -s --compressed https://sql-visualizer.jvtools.cn/
… <div class="nav-content" data-v-52b2961d><div class="logo-area" data-v-52b2961d><img src="/logo.svg" alt="Logo" class="nav-logo" …><span class="logo-text" …>SQL Visualizer</span></div> …

$ curl -s --compressed https://sql-visualizer.jvtools.cn/guide/getting-started
… <a class="title" href="/" data-v-9f43907a> …
```

首页那一侧没有任何 `<a>` 包住品牌区；文档页那一侧是链接，`href="/"`。英文首页 `/en/` 同样只有 `<div class="logo-area">`。

### 2.2 文档页为什么正常（源码依据）

VitePress 1.6.4 的 `node_modules/vitepress/dist/client/theme-default/components/VPNavBarTitle.vue`：

```vue
<a class="title" :href="link ?? normalizeLink(currentLang.link)" :rel="rel" :target="target">
```

`currentLang.link` 在根 locale 是 `/`、在 `en` locale 是 `/en/`，所以文档页的品牌链接天然带语言前缀。首页自绘顶栏不经过这个组件，这一层能力就丢了。

另外 VitePress 的路由拦截（`dist/client/app/router.js:20-31`）只对 `<a>` 生效：`go(href)` → 同路径时不压栈、直接 `loadPage` + `scrollTo(0, 0)`。也就是说，品牌区一旦变成 `<a href="/">`，同页点击的表现是「回到顶部」，跨页点击是正常 SPA 跳转，与文档页行为一致。

### 2.3 版本号的三条数据链

| 展示位置 | 数据来源 | 是否实时 | 当前值 |
| --- | --- | --- | --- |
| 首屏 `hero-stat-value`（标签「最新版本」） | 构建期 `plugin-version.json` 兜底 + 挂载后 `/api/changelog` 实时覆盖（`usePluginVersion.js`） | 是（本轮补上） | `v2026.11.4`（实时）/ `v2026.11.3`（当前 SSR 快照） |
| JSON-LD `softwareVersion`（`config.mts`） | 同一个 JSON，构建期读入 | 否（SEO 面，只能靠重新构建） | `2026.11.3` |
| 页面底部「最近更新」3 条 | 构建期 `latest-updates.json` + 挂载后 `/api/changelog` 合并（`RecentUpdates.vue:31-58`） | 是 | `2026.11.4` |
| 更新日志页 | 构建期 `changelog.json` + 挂载后 `/api/changelog` 合并（`ChangelogList.vue:52-63`） | 是 | `2026.11.4` |

`plugin-version.json` 现值：

```json
{ "version": "2026.11.3", "source": "env:PLUGIN_VERSION", "syncedAt": "2026-11-03T15:53:44.359Z" }
```

`scripts/sync-plugin-version.mjs:9-15` 的取值优先级是 `env:PLUGIN_VERSION` → 同级插件仓 `gradle.properties` → Marketplace API → 保留现值。所以：

- 2026-11-03 那次部署显式钉了 `PLUGIN_VERSION=2026.11.3`，快照就此定格；
- 之后再没构建过，Marketplace 出了 2026.11.4 也进不来；
- 同级插件仓 `gradle.properties` 现在写的是 `version=2026.11.4`，Marketplace API 最新一条也是 `2026.11.4`（`cdate=1793803279000`，即 2026-11-04），两个来源口径一致——现在只要跑一次构建，静态值就会自己升到 11.4。

      1 2026.11.2

三处分别是 JSON-LD `softwareVersion`、首屏 `hero-stat-value`、`RecentUpdates` 的 SSR 快照。其中只有中间那处在客户端没有任何补齐路径，所以用户看到的就是「上面 11.3、下面 11.4」。

### 2.5 关于那次「版本号跳变」

`usePluginVersion.js` 的旧注释留了前科：曾经在客户端拉 `/api/changelog` 后无条件覆盖显示值，结果构建期版本比 Marketplace 公开版新时（开发版已升、公开版还没审过），页面先渲染 `v2026.10.31` 再跳变回 `v2026.10.30`，于是整段逻辑被删掉、退回纯静态。

用户这次定的口径是「构建期兜底、实时从 Marketplace 取」——也就是公开版就是「最新版本」的定义，实时值应当覆盖静态值。跳变的根子不在「实时覆盖」本身，而在**静态值可能来自开发版**（`sync-plugin-version.mjs` 的第二优先级是同级插件仓 `gradle.properties`，本机开发时会拿到未发布号）。所以本轮的做法是：实时值拿到即用，同时把「部署必须钉 `PLUGIN_VERSION` 为已发布版本」写进部署步骤——生产上静态值与实时值本来就相等，不会出现可见跳变；本地开发时若静态值是未发布号，挂载后会纠正成公开版，这个纠正方向是对的。

## 三、根因

| 现象 | 根因 | 位置 |
| --- | --- | --- |
| 首页点品牌名无反应 | 品牌区是 `<div>`，不是链接；自绘顶栏没有 VitePress 的 `VPNavBarTitle` | `NavHeader.vue:75-78` |
| 英文首页同理 | 同上；且 `NavHeader` 未使用 `useHomeContent().localePath` 生成 locale 前缀 | `NavHeader.vue:10`、`useHomeContent.js:22-26` |
| 首屏版本号滞后 | 版本号只有构建期快照一条链，发版后不重新部署就永不更新 | `usePluginVersion.js:2-14` |
| 同页底部却正确 | 「最近更新」挂载后拉 `/api/changelog` 合并 | `RecentUpdates.vue:39-58` |

## 四、方案

### 4.1 品牌区改成真链接

把 `NavHeader.vue` 的品牌块整体包成 `<a>`，`href` 走 `localePath('/')`（中文 `/`、英文 `/en/`），保留现有 `.logo-area` 类名与内部 `img + span` 结构，不改任何尺寸：

```vue
<a class="logo-area" :href="localePath('/')" aria-label="SQL Visualizer">
  <img src="/logo.svg" alt="" class="nav-logo" aria-hidden="true" />
  <span class="logo-text">SQL Visualizer</span>
</a>
```

要点：

- **`localePath` 必须用**。写死 `href="/"` 会让英文首页的品牌把用户丢回中文站；`useHomeContent` 已经导出了这个函数（`useHomeContent.js:22-26`），`NavHeader` 现在只解构了 `c`，补一个即可。
- **`aria-label` 必须有**。`≤479px` 时 `.logo-text` 是 `display: none`（`NavHeader.vue:366-370`），屏幕上只剩图标；若不给链接名字，读屏与键盘用户会拿到一个无名链接。同时把 `img` 的 `alt="Logo"` 改成空 + `aria-hidden`，避免念成「Logo SQL Visualizer」。
- **样式只加三行**：`.logo-area { text-decoration: none; color: inherit; }`，外加 `:focus-visible` 描边，沿用站内已有配方（`BackToTop.vue:116-119` / `SectionNav.vue:217-221`：`outline: 2px solid var(--primary-color); outline-offset: 3px;`）。不加 hover 变色——品牌区不需要 hover 反馈，加了反而与旁边纯文字链接抢注意力。
- **同页点击的表现**交给 VitePress 路由（回顶部、不压栈），不写 `@click.prevent`。理由：与文档页行为完全一致，且保留中键新开、右键「在新标签页打开」这些原生能力。

### 4.2 首屏版本号：构建期兜底，Marketplace 实时为准

口径（用户 2026-11-05 定）：**构建期快照只负责首帧与失败兜底，显示值以 Marketplace 实时数据为准。**

在 `usePluginVersion.js` 里：

1. 首帧仍用静态快照（SSR 与 hydration 必须一致，`RecentUpdates` 已是这个模式）；
2. 挂载后拉 `/api/changelog`，用 `scripts/changelog-core.mjs` 的 `collectUpdates(raw)[0].version` 取 Marketplace 最新一条——**不用 `buildEntries()`**，因为后者会把累计日志里出现过的版本号也补成条目（更新日志页需要这个行为，首屏「最新版本」不需要，避免把日志里提到的版本当成已发布版本）；
3. 拿到就替换，不做「只进不退」比较——公开版就是「最新版本」的定义；拉取失败/超时/返回非数组则保留静态值，静默不报错。

关于跳变（见 §2.5）：生产上不会出现，因为部署步骤钉住 `PLUGIN_VERSION` 为已发布版本，静态值与实时值相等；本地开发时若静态值取自 `gradle.properties` 的未发布号，挂载后会被纠正成公开版，这个纠正方向本身是对的。

顺带把 `RecentUpdates` 里的 fetch 抽成共享函数（新文件 `.vitepress/theme/composables/liveUpdates.js`，导出带模块级 Promise 缓存的 `getLiveUpdates()`），两处共用一个请求：否则首页每次加载会对同一个 `/api/changelog` 打两次。CF Function 侧虽有 `Cache-Control: max-age=3600`（`functions/api/changelog.js`），但两处都在 `onMounted` 并发发出，第一次是穿透的。

明确不改的部分：

- **JSON-LD `softwareVersion`** 仍是构建期值。爬虫读的是 SSR HTML，客户端改它没有意义；靠 T4 构建刷新。
- **不做定时构建/部署**（CF Pages Deploy Hook + 外部 cron 可做，但引入一个外部调度器换 24 小时的版本号时效，成本不划算）。实时补齐已经把时效压到「打开页面即最新」，静态快照只影响首帧与 SEO 面。

### 4.3 否决的备选

| 方案 | 否决理由 |
| --- | --- |
| 只重新部署，不改代码 | 今天能好，下次发版又滞后。用户报的是第二次出现（10.31 那轮同款），根因还在 |
| 首屏版本号直接删掉静态值、只留客户端渲染 | 首帧空白或闪位，且 SSR HTML 里没有版本号，搜索引擎与分享卡片都拿不到 |
| 首屏版本号改成无条件取实时值 | 就是 2.5 那次事故的原样复现（构建期版本更新时会倒退跳变） |
| 品牌区用 `router-link`/`@click` 手写跳转 | 自绘顶栏里没有 VitePress 的 router 实例注入；`<a href>` 原生能力更全，路由拦截由 VitePress 全局代理 |

### 4.4 明暗切换：整页级圆形揭示（取法 cool-request-web）

**现状为什么不丝滑。** 现在没有任何整页过渡，只有零散组件各自带 `transition`：`.VPNav` 是 `transition: all 0.3s`（`style.css:140`），按钮类是 `all 0.25s`（`style.css:230/293/309`），首页 `.cool-home` 带 `background-color 0.3s`；而 `.vp-doc` 正文、侧栏、表格、代码块一律没有过渡。结果是一次切换里，导航在慢慢褪色、正文瞬间反色，长页面上就是「一块一块到位」的参差感。

**cool-request-web 的做法（`F:\code\Java\Github\other\houxinlin\cool-request-web`）。** 用 View Transitions API 做圆形揭示，而不是靠 CSS 过渡：

`src/app/components/TopNav/top-nav.tsx:109-148`

```tsx
const isToLight = isDarkMode;
const x = isToLight ? 0 : event.clientX;
const y = isToLight ? window.innerHeight : event.clientY;
const endRadius = Math.hypot(Math.max(x, innerWidth - x), Math.max(y, innerHeight - y));
document.documentElement.style.setProperty("--x", `${x}px`);
document.documentElement.style.setProperty("--y", `${y}px`);
document.documentElement.style.setProperty("--end-radius", `${endRadius}px`);
document.startViewTransition(() => { /* 切主题 */ });
```

`src/app/common/common.less:60-79`

```less
::view-transition-old(root), ::view-transition-new(root) { animation: none; mix-blend-mode: normal; }
::view-transition-old(root) { z-index: 1; }
::view-transition-new(root) { z-index: 9999; animation: circle-expand 0.6s ease-in-out; }
@keyframes circle-expand {
  from { clip-path: circle(0px at var(--x) var(--y)); }
  to   { clip-path: circle(var(--end-radius) at var(--x) var(--y)); }
}
```

精华就三条：**旧图垫底不动、新图用 `clip-path` 圆从点击点揭开、半径取「点击点到最远角」的距离**（保证圆一定能盖满视口）。它把整页当作一张快照做转场，所以页面里有多少个组件、各自有没有 `transition` 都不影响观感。

**本项目落地。** 新增 `.vitepress/theme/composables/useThemeTransition.ts`，对外只暴露 `toggle(event, el)`：

1. 不支持 `startViewTransition` 或用户开了「减少动态效果」时，直接落值（等价于今天的行为）；
2. 支持时写入 `--theme-switch-x/y/radius` 并 `startViewTransition`；
3. 回调里**同步**写 `html.dark`——VitePress 的 `isDark` 是 `@vueuse/core` 的 `useDark`，落类名靠 `watchEffect`（微任务），而 View Transition 在回调返回后立刻拍「新」快照，等不到那次微任务；
4. 回调里 `await nextTick()`——太阳/月亮图标、`aria-checked` 这些要等 Vue 渲染完才进快照，否则动画结束后图标会「晚一拍」跳变；
5. 切换期间给 `<html>` 挂 `.theme-switching`，全局 `transition: none`——否则快照会拍到颜色过渡的中间态，等于把同一段过渡演两遍；
6. 键盘触发的 click 事件 `clientX/clientY` 都是 0，这时退回按钮几何中心，拿不到按钮再退回右上角。

**两个入口都要接上**：

- 首页自绘顶栏 `NavHeader.vue` 的按钮，`@click` 直接换成 `toggleTheme($event, $event.currentTarget)`；
- 文档页 / 移动端菜单里的开关是 VitePress 默认 `VPSwitchAppearance`（`node_modules/vitepress/dist/client/theme-default/components/VPSwitchAppearance.vue`，点它走 `isDark.value = !isDark.value`）。在 `theme/index.ts` 的 `setup()` 里用**捕获阶段**的 document click 监听拦下 `.VPSwitchAppearance`，`stopPropagation` 掉 VitePress 自己的处理再走同一个 toggle。拦截失效的后果可控：类名一变就拦不住，开关照旧能用，只是没有动画。

**不采用的做法**：给 `*` 加全局 `transition: background-color/color`。属性过渡是全页重绘，长页面上明显掉帧，而且 SVG、图片、阴影这些还会出现「一半新一半旧」；View Transition 是拍两张图做一次合成，代价低得多。

### T3 明暗切换改 View Transitions 圆形揭示

- 文件：新增 `.vitepress/theme/composables/useThemeTransition.ts`、`.vitepress/theme/style.css`（尾部新增一段）、`.vitepress/theme/components/home/NavHeader.vue`（按钮 click）、`.vitepress/theme/index.ts`（捕获阶段拦截 `VPSwitchAppearance`）
- 改动要点：

## 七、风险与回滚

| 风险 | 评估 | 处置 |
| --- | --- | --- |
| 品牌区加 `<a>` 后尺寸/换行变化 | 低：`.logo-area` 本就是 `display: flex` + `flex-shrink: 0`，`<a>` 只是换标签，盒模型不变 | 构建后核对 1280 / 768 / 480 三档顶栏高度仍是 64 / 64 / 60（上一轮定例） |
| 同页点品牌触发整页重渲染、滚动揭示重播 | 低：VitePress 路由同路径不压栈，只 `scrollTo(0,0)`；文档页一直是这个行为 | 实测滚到 4000px 后点品牌，落在 `/`、`scrollY=0`，可接受 |
| 实时值比构建期旧导致可见跳变 | 低：部署钉住 `PLUGIN_VERSION` 后两者相等；只有本地开发拿未发布号构建时才会被纠正一次 | 接受；这方向本来就是「纠正成公开版」 |
| Marketplace 返回的「最新」是已审批但未上架的版本 | 中低：API 列表包含 approved·hidden 条目，构建期脚本本来也用同一条规则（`updates?size=1`），行为与今天一致、不是新增偏差 | 若真出现，再在客户端按 `listed` 过滤——本轮不提前做，避免与构建期口径分叉 |
| CF Function 不可用 | 低：静默保留静态值，页面不报错 | 无 |
| 部署时忘记钉 `PLUGIN_VERSION` | 中：会取同级插件仓 `gradle.properties`，若那时是开发版号（例如 2026.11.5 未上架），首帧会先显示未发布版本再被实时值纠正 | 部署命令显式带 `PLUGIN_VERSION=2026.11.4` |
| VitePress 改了 `VPSwitchAppearance` 类名 | 低：拦截失效后开关照旧能用，只是退回无动画的瞬时切换 | 无功能风险；升级 VitePress 后顺手看一眼文档页开关有没有动画 |
| View Transitions 不支持（Firefox < 144 / Safari < 18） | 低：`toggle` 里有能力判断，直接落值 | 与今天的切换观感一致 |
| 过渡期间全局关 transition 误伤别的动画 | 低：只在切换的 0.55s 内生效，且是 `transition` 不是 `animation` | 若发现某处过渡被吃掉，把 `.theme-switching *` 收窄到具体选择器 |

**回滚**：T1 是模板一处 + 样式两条，T2 是新增一个文件 + 改一个 composable，T3 是新增一个 composable + CSS 一段 + 两处接线，T4/T5 是数据与发布动作。代码侧 `git revert` 单提交即可；数据侧重新部署上一次快照即可（`plugin-version.json` 回 2026.11.3 不影响实时补齐，它只是首帧兜底）。
