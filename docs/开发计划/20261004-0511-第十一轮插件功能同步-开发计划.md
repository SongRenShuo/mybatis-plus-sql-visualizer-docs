## 三、红线核对（每条新增表述的出处）

新增仅一处表述（roadmap 预览与诊断节一行），逐项出处：

1. **三态与文案**：`SqlPreviewPanel.kt:3844-3849` bindStateText() 优先级＝活控制台「已绑定：{0}」＞记忆回退「关联（上次使用）：{0}」＞「未绑定数据源（在控制台执行一次查询即可绑定）」；中文权威 `MpSqlVisualizerBundle_zh.properties:804-806`，英文 `MpSqlVisualizerBundle.properties:898-900`（Bound / Associated (last used) / No data source bound）。文案以 bundle 原文为准，不转述、不拔高。
2. **指示行位置与形态**：参数区「预设」行之下常驻灰字文本行（c143e9d 提交信息；SqlPreviewPanel.kt:3658/:3672），无参数分支同样常驻。
3. **绑定语义同源**：指示行反映当前预览会话执行控制台 ExecConsoleContext 绑定，与 R33 结构化 EXPLAIN 判定同源（020ce83 沙盒走查实证「绑定语义实证=当前预览会话执行控制台 ExecConsoleContext 与 R33 同源，app 控制台查询不触发绑定属设计内」）→ 表述写「与执行 SQL / 执行计划实际使用的数据源同源」，**不写**「与 EXPLAIN 直送通道严格同源」（O-96 S2 前提证伪定案：记忆态与直送非严格同源，故记忆态独立文案不冒称已绑定）。
4. **记忆持久化**：项目级 PropertiesComponent 持久、跨 IDE 重启存活（O-96 计划 §五前提 2 证实 + 510b3db「复测主判据场景反转通过（跨重启持久）」）；在籍校验 fail-closed（UUID 失效回落未绑定、同名歧义弃记忆），→ 表述写「最近使用数据源按项目记忆、跨重启有效」。
5. **即时刷新**：f699a24 之后执行挂载控制台即升级「已绑定」（修复前停留记忆态）→ 表述以修复后行为为准写「执行挂载数据源后即时刷新」。
6. O-93 修复后行为与 roadmap 既有 L34「方言智能推断（……回退 MySQL……）」描述一致（该行本就是目标语义），既有行不改。
