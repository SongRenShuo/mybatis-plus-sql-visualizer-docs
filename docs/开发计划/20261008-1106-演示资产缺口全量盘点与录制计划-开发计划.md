## 一、背景与判据

用户两点观察与一项新需求：

1. **控制台捕获相关内容偏多**，应减少篇幅、把用户往增强捕获引导（已随本轮实施，见 §五）。
2. **缺图不止一张**——按「正常每个功能都需要配图」的口径重新过一遍全站，把缺失的动图与截图**全部**登记到录制计划。
3. 新需求：**「跳转到源码」功能较重要**，本轮录制后要在**插件官网首页**（**https://sql-visualizer.jvtools.cn/**，即本仓部署的站点；用户已澄清不是 jvtools.cn 聚合站）新增一个**独立模块**展示它，形态对齐现有的「Wrapper → SQL 实时预览」「控制台日志一键还原」两个带图模块。

盘点判据（本轮口径）：**一个「可独立触发、有独立界面反馈」的功能点至少配一张图**；纯表格、纯列表、纯文本说明类小节（触发方式表 / 支持的注解形式 / 已知边界 / 快捷键表）不配图。以此判据逐节比对现有素材。

## 六、官网首页新增「跳转到源码」独立模块（本站 = sql-visualizer.jvtools.cn）

**用户澄清**：插件官网＝ **https://sql-visualizer.jvtools.cn/**，即本仓部署的站点（不是 jvtools.cn 聚合站）。所以新模块落**本仓**，形态对齐首页现有的「Wrapper → SQL 实时预览」「控制台日志一键还原」两个模块。

**落点**：`.vitepress/theme/components/home/FeatureAlternate.vue` 的 `features` 数组（目前 **7 个模块**，由 `CoolHome.vue` 渲染在「大幅提升您的 SQL 调试效率」区块）。每个模块字段：

```
{ badge, title, description,
  features: [ { title, description } × 3 ],
  imageSrc: '/demo/xxx.gif', poster: '/demo/xxx.png',
  gifReady, gifError, reverse? }
```

现有 7 个模块的 `badge` 依次为：Wrapper 预览 / 日志还原 / 反向转换 / 智能生成 / 多框架支持 / 跨生态 / AI Agent 集成；`reverse` 出现在第 2、4、6 个（左右交错）→ **新增的第 8 个应带 `reverse: true`** 以延续交错节奏（实施时按实际观感确认）。

**需要素材**：模块是**带图模块**，`imageSrc` + `poster` 必填。**直接复用批次 1 的 A1 成片**（`/demo/sql-log-jump-source.gif` + 同名 `.png`）——素材同属本仓 `public/demo/`，功能页与首页模块共用一份，不用另录。

**建议文案**（待用户定稿）：

- badge: `日志溯源`
- title: `SQL 溯源 · 日志直达源码`
- description: `执行日志一键回到发出 SQL 的那一行；预览面板的调用栈逐帧列出，点哪一帧跳哪一帧。`
- features（三条）：
  1. `精确落点` / `日志条目右键即跳到执行 SQL 的代码行，真实调用栈定位不做表名猜测`
  2. `调用栈逐帧` / `预览面板悬停展开完整调用链，帧数可配（12~64），基础设施帧自动跳过`
  3. `两种通道都能用` / `增强捕获免配置直达；控制台通道配拦截器后同样精确`

**英文侧同构**：英文首页（`en/index.md`）用的是另一套布局——`EnHomeFeatures`（数据来自 `.vitepress/theme/data/homeHighlights.js` 的 `enCards`，**纯文字卡**）+ `EnFeatureMatrix`（`enFeatureMatrix` 三组表格），**没有带图模块**。因此英文侧按现有形态补两处：`enCards` 增一条卡片、`enFeatureMatrix` 的对应组增一行，保持中英能力面一致（不新造英文侧不存在的模块形态）。
