# 搜索结果摘要核心能力化-开发计划

> 日期：2026-10-15
> 状态：已部署至 Cloudflare Pages 并完成正式域名验收；搜索引擎实际摘要及图标待索引刷新观察。用户追加约束：首页可见内容保持原样，并修复搜索结果的通用地球图标。
> 输入：用户提供的浏览器搜索「SQL Visualizer」结果截图；当前仓库首页、首页文案与 VitePress 配置。

## 一、问题与已知事实

截图中的灰色摘要以「加入超过 500 名开发者的行列，在 IntelliJ IDEA 中享受更高效的 SQL 调试体验。所有功能永久…」开头。它讲的是号召安装、人数和价格，却没有回答首次看到搜索结果的人最关心的两件事：这是什么插件，能解决哪些 SQL 问题。用户希望摘要优先介绍插件核心能力。

这段话来自首页底部 CTA：`.vitepress/theme/data/homeContent.js:273-280`，由 `.vitepress/theme/components/home/CtaSection.vue:21-23` 渲染为首页正文。中文首页的 `meta description` 则来自 `.vitepress/config.mts:142-147`，当前仅写「IntelliJ IDEA 插件：MyBatis-Plus / MyBatis-Plus-Join / JPA / Hibernate 的 SQL 调试利器」。同文件 `:29-30` 更详细的全站默认 description 被中文 locale 配置覆盖，不能把改全站默认值当作首页修复。首页 `index.md` 使用自定义 `CoolHome`，没有单页 description。

因此，截图**表明搜索引擎展示了与 CTA 正文一致的片段**，但无法仅凭截图证明它一定从哪个 HTML 节点抽取，也不能证明每个查询都会显示同一摘要。搜索引擎可能依据查询词重写摘要；修改 meta 或正文只能提高出现核心描述的机会，不能强制指定最终灰字，也不保证立即更新。

## 二、建议文案与备选方案

优先把「产品身份 + 主能力 + 使用收益」放在搜索结果前两行，避免把「500+」「永久免费」放在开头。候选文案如下，均为拟稿，实施前以已发行插件能力核对措辞。

| 方案 | 候选中文摘要 | 取舍 |
| --- | --- | --- |
| A 核心能力优先（推荐） | SQL Visualizer 是 IntelliJ IDEA 的 SQL 调试插件：无需启动项目，预览 MyBatis-Plus Wrapper、XML/注解及 HQL 的最终 SQL；运行后捕获真实参数与耗时，并从日志跳回源码。 | 覆盖静态预览与运行期排障两条主链，明确插件类型；信息较密，搜索端可能截断后半句。 |
| B 单场景短句 | SQL Visualizer 是 IntelliJ IDEA 的 SQL 调试插件。编写 MyBatis-Plus Wrapper、XML 或注解 SQL 时，无需启动项目即可预览 SQL；运行后也能还原参数、定位源码。 | 表述更短，易读；未体现 JPA/Hibernate、MPJ、EXPLAIN 等能力。 |
| C 跨框架覆盖 | SQL Visualizer 在 IntelliJ IDEA 中预览 MyBatis-Plus、MPJ、MyBatis XML 和 JPA/Hibernate 的 SQL，并捕获运行时参数与耗时，帮助定位慢查询和源代码。 | 适合框架覆盖导向的查询；首次接触产品的人对缩写的理解成本更高。 |

**推荐 A** 作为中文首页 meta description 的定稿方向；首页首屏已有「写代码时就看见最终 SQL」及具体能力描述，可适当压缩、对齐 A，但不必把整段长文复制进 meta。CTA 仍应承担安装转化，不必为了搜索结果把安装区改成产品说明书；只把开头的固定人数宣传换成与产品相关的一句自然承接，例如「在 IntelliJ IDEA 中预览最终 SQL，还原运行时参数与耗时；安装后从代码到日志都能更快定位问题。」人数若保留，应有可核验且会更新的数据源，否则不再作为主要宣传点。英文首页 CTA 同步调整英文措辞，避免中英文站出现两种不同定位。

## 三、实施范围与顺序

1. **先核对待验证前提。** 抓取生产中文首页的 HTML 与 HTTP 状态，分别确认 `<meta name="description">`、首屏正文、CTA 正文及 canonical；对照当前仓库构建产物，排除线上尚未部署到这版、旧索引或非首页 URL 的情况。记录搜索查询词、地区/语言、截图时间、实际落地 URL；能获取 Search Console 数据时再查看查询及索引状态，不能获取就标记「未验证」，不据此作保证。
2. **定稿并核实能力边界。** 以在售版本对应的发行源码/功能页核对「无需启动项目」「HQL 预览」「运行期捕获」「日志跳回源码」各自前提，避免暗示所有场景都无需运行，或把计划中能力写成已发行能力。保留文案适当长度，不以固定字符数宣称可以控制搜索引擎截断。
3. **统一首页主要摘要入口。** 调整 `.vitepress/config.mts` 的 `locales.root.description`；视取舍决定是否把全站默认 description 与 `locales.en.description` 对齐其各自受众。对 `WebSite` / `SoftwareApplication` JSON-LD 的 description 只做一致性复核，不假定修改结构化数据能控制普通搜索摘要。若希望首页独有措辞，也可在 `index.md` frontmatter 设置单页 description，但必须验证与 locale 配置的实际优先级及最终 HTML 只输出一个有效 meta description，避免另建多份互相冲突的权威文案。
4. **减少 CTA 被截取时的低信息密度。** 将 `.vitepress/theme/data/homeContent.js` 中 zh/en 的 `cta.subtitle` 改为产品能力导向的转化文案，保留安装按钮和价格信息；不要使用 `data-nosnippet` 把整段 CTA 从搜索结果中粗暴排除，也不要隐藏正文或针对爬虫单独投喂不同内容。
5. **构建与发布后验证。** 本地构建后查中文首页和英文首页生成 HTML：标题、单一有效 description、canonical、对应语言的首屏/CTA 文字均正确；检查其他页面没有因全局默认描述调整而意外改变。部署须另按站点发布流程执行；部署后直接取生产 HTML 复核。若有站点管理权限，可在 Search Console 请求重新抓取，随后分时记录搜索结果截图；未见变化时区分「HTML 未更新」「索引未刷新」「搜索引擎按查询重写」三种情况。

## 四、验收标准与不做的事

- 中文首页 HTML 中 description 首句即说明「SQL Visualizer / IntelliJ IDEA 插件 / SQL 调试」，随后至少明确两条核心能力；英文首页描述与页面语言匹配。
- 首屏及 CTA 的可见正文与 meta 不互相矛盾；任何被摘取的首页关键段落都不再以未经核验的「500+」作为产品首要介绍。
- 抽查移动端及桌面端 CTA：句子自然、按钮和布局不受影响；产品能力表述经发行事实核对。
- 搜索结果更新只作为**发布后的观察指标**，不把「Google 必须显示指定灰字」当作可由本站控制的验收门槛。
- 本计划不改搜索排名策略、不购买投放、不批量重写功能页，也不为影响摘要而遮蔽真实内容。

## 五、实施时的范围修订（用户补充）

用户明确要求：**搜索结果改，点进首页后可见内容不变**；并追加搜索结果图标目前显示通用地球，需尽量让它使用插件 logo。因此第三区所列「修改 CTA 正文」不再实施，改为以下更窄的落点：

- 仅在 `index.md` / `en/index.md` 增加单页 description，避免更改 locale 默认描述影响其他页面；保留所有首页可见文案及布局。
- 首页 CTA 字符串原封不动，仅将现有字幕文字包在不改变样式的 `<span data-nosnippet>` 中，使该 CTA 不被搜索引擎作为普通摘要的候选文字；其它首页正文仍可被搜索引擎摘取，无法强制显示 meta description。此标记也会被现有 Pagefind 构建配置排除，因此 CTA 字幕不再作为站内全文搜索命中。
- 现有 `public/favicon.svg` 是插件 logo，生产 `/favicon.svg` 返回 200，但 `/favicon.ico` 返回 404。基于同一 SVG 生成 PNG/ICO 兼容格式并从页面 head 指向它们；保持页面内现有 logo、颜色、文案和排布不变。发布后核对图标文件响应与 HTML 引用；搜索平台可能缓存通用图标，**不能承诺立即换图**。
- 能力取证以插件已发布标签 `2026.10.13` 为准。该版支持静态预览、运行期参数/耗时捕获、日志源码定位，但受表达式求值、捕获路径和来源信息限制，搜索摘要须采用「静态预览」「支持捕获/定位」而不是对所有场景承诺「最终 SQL、必有真实参数及源码」。

以上修订优先于前文有关 CTA 改写、全站默认描述以及搜索结果必须显示某句话的建议。
