# 文档页更新时间显示-开发计划

> 日期：2026-10-29 12:15（实施与回填：同日 12:40 前后）
> 状态：已实施并通过本地构建验证，未部署
> 范围：文档站所有使用默认文档布局（VPDoc）的页面；首页与 `layout: page` 页不在范围

## 一、需求与现状

用户希望每篇文档能显示自己的更新时间，位置在文档上方或下方都可以。

现状是"文案配了、开关没开"：

- `.vitepress/config.mts` 的 zh/en 两套 `themeConfig` 里都已经有 `lastUpdated: { text: '最后更新于' }` 与 `{ text: 'Last updated' }`（约 :211 / :283）。
- 但站点根配置**没有** `lastUpdated: true`。VitePress 只有在根级开启时才在构建期为每页取 git 时间。
- 产物印证：`.vitepress/dist/guide/getting-started.html` 里能 grep 到"最后更新于"，但那是序列化进页面的主题配置字符串，不是渲染节点，页面里没有 `<time>`、也没有 `.VPLastUpdated`；`sitemap.xml` 里同样没有 `<lastmod>`。

VitePress 1.6.4 源码事实（`node_modules/vitepress/dist/node/chunk-D3CUZ4fa.js`）：

- 只有 `includeLastUpdatedData && frontmatter.lastUpdated !== false` 成立时，才执行 `pageData.lastUpdated = getGitTimestamp(fileOrig)`；frontmatter 写 `lastUpdated: false` 可以单页关闭，写日期则直接用该日期。
- `getGitTimestamp` 的实现是 `git log -1 --pretty="%ai" <文件名>`，工作目录设为该文件所在目录，并按文件路径缓存。拿不到时返回 0 或 NaN，模板里按假值处理、不显示。
- 默认主题的 `VPDocFooter` 在 `page.lastUpdated` 为真时渲染 `VPDocFooterLastUpdated`，位置在 `.edit-info` 里，也就是**正文之下、上一篇/下一篇之上**。
- 该组件把可读文本放在 `onMounted` 里生成（SSR 只输出 `<time datetime="ISO 时间">`，文本为空），默认 `formatOptions` 是 `{ dateStyle: 'short', timeStyle: 'short' }`，支持 `forceLocale` 与任意 `Intl.DateTimeFormat` 选项（含 `timeZone`）。
- `generateSitemap` 在根级 `lastUpdated` 为真时**自动**给每个 URL 生成 `<lastmod>`，同样尊重 frontmatter 的关闭标记。

实测 git 时间可用：`guide/getting-started.md` 最后提交 2026-10-27 17:23:44 +0800，`features/wrapper-preview.md` 为 2026-10-27 07:28:48 +0800。

## 二、方案（采用 A）

### 方案 A：开启内置能力，显示在正文下方

改动只有配置，不加组件：

1. `.vitepress/config.mts` 根级加 `lastUpdated: true`。
2. zh/en 两处的 `lastUpdated` 补格式选项，**精确到秒**（用户要求带时分秒）：

```ts
// root（zh）
lastUpdated: {
  text: '最后更新于',
  formatOptions: {
    year: 'numeric',
    month: '2-digit',
    day: '2-digit',
    hour: '2-digit',
    minute: '2-digit',
    second: '2-digit',
    hour12: false,
    timeZone: 'Asia/Shanghai',
    forceLocale: true
  }
}
// en 同配置，text 为 'Last updated'
```

选择理由：

- 位置就是用户说的"下方"，且在所有文档页一致；有 sidebar、有 outline 的页面用的是同一个页脚。
- 时间固定按北京时间输出，避免海外访客看到跨日或错时。
- `forceLocale: true` 让中文页用中文格式（`2026/10/27 17:23:44`）、英文页用英文格式（`10/27/2026, 17:23:44`）。
- 顺带把 sitemap 的 `<lastmod>` 补上，对搜索引擎是纯收益。

已知观感问题：内置模板固定输出 `{{ text }}: <time>`，中文会呈现"最后更新于: 2026/10/27 17:23:44"，冒号是半角。要全角冒号得自建组件，本次不做。

### 内部文档不再公开（用户追加决策）

用户指出 `docs/` 下的开发计划一类文档对访客没有作用，不应公开。实施方式是把它们从构建源里整体排除，而不是只在更新时间上排除：

```ts
srcExclude: ['docs/**'],
```

效果：`docs/` 下 114 个 markdown 页不再产出 HTML，不进入 sitemap、不进 pagefind 索引、不进 llms.txt。仓库里文件照常保留、git 历史不受影响。

### 不做

- 不在每篇 md 里手写日期或 frontmatter `lastUpdated`。
- 不给首页（`layout: false`）和需求池 / Bug 悬赏（`layout: page`）加时间，它们没有文档页脚。
- 不引入"预计阅读时间"等其他元信息。

## 三、边界与例外

- **首页**：`index.md` / `en/index.md` 是 `layout: false` 的自定义首页，没有文档页脚，不会显示。
- **`layout: page` 页面**：`about/feedback.md`、`about/bounty.md`、`en/about/feedback.md`、`en/about/bounty.md` 走自定义页面布局，不会显示。
- **内部文档**：`docs/**` 已整体排除出构建，链接访问返回 404。
- **新文件**：尚未提交的 md 拿不到 git 时间，页面暂时不显示；首次提交后的下一次构建才出现。
- **时间语义**：取的是最后一次**提交**时间，不是工作区修改时间。
- **重命名**：`git log` 未加 `--follow`，改名后的文件时间会变成改名那次提交的时间。
- **自动生成页**：`about/changelog.md` 由 `scripts/update-changelog.mjs` 生成，时间等于生成脚本那次提交。
- **中英不同步**：中英文是两份独立文件，时间各自独立。

## 四、实施步骤

1. `.vitepress/config.mts`：根级加 `lastUpdated: true` 与 `srcExclude: ['docs/**']`；两处 `themeConfig.lastUpdated` 补 `formatOptions`（含 `second`、`hour12: false`、`timeZone`）。
2. `scripts/prepare-pagefind.mjs`：原本无条件遍历 `dist/docs` 给内部页打 `data-pagefind-ignore`，目录被排除后直接 `ENOENT` 中断构建，改为目录存在才遍历、否则跳过（保留兜底能力）。
3. `npm run build`。
4. 产物与浏览器逐项核对（读数见下）。
5. 提交配置与脚本改动；部署按任务流程另行确认。

## 五、验收边界

- 所有默认文档布局页面在正文下方、上一篇/下一篇之上显示"最后更新于 / Last updated + 日期时间"，日期时间与 `git log -1` 一致。
- 首页、需求池、Bug 悬赏、404 页面不出现该行。
- 中文页格式为 `2026/10/27 17:23:44`，英文页为 `10/27/2026, 17:23:44`，不随访客系统语言漂移。
- `docs/` 下任何路径返回 404，`sitemap.xml` 不含 `/docs/` 条目。
- 构建成功、无 hydration 报错；sitemap 每条 URL 带 `<lastmod>`。
- 不新增依赖，不引入客户端请求。

## 六、待验证前提

- **构建发生在本地**：当前部署链路是 `npm run deploy` = 本地 `vitepress build` + `wrangler pages deploy` 上传 dist，git 历史完整，时间可用。若改成 Cloudflare Pages 从 Git 仓库自动构建，浅克隆会让所有页面拿到同一个提交时间，必须补 `git fetch --unshallow`。
- **中文路径 git 可用**：已用 `docs/开发计划` 下的文件抽检（本次构建未报错，`lastmod` 计数等于 URL 计数）。
- **构建耗时**：本次构建 13.50 秒（pagefind 0.34 秒）；排除 114 个内部页后比上一轮含 docs 的构建更快。
- **页脚位置**：已在浏览器读取坐标确认（见实施记录）。
- **SSR 文本为空**：内置组件只在客户端填充可读日期，静态 HTML 里只有 `datetime` 属性。若要求 HTML 直接带可读日期，需自建组件（本次未做）。

实施中发现并修掉一个真实缺陷：排除 `docs/` 后首次构建在 `scripts/prepare-pagefind.mjs` 处报 `ENOENT: scandir ... .vitepress/dist/docs`，构建退出码 1。该脚本原假设内部页一定存在，改为目录缺失时跳过，构建恢复。这不是"清一下目录就好"的偶发问题——只要 `srcExclude` 生效，每次构建都会撞上。
