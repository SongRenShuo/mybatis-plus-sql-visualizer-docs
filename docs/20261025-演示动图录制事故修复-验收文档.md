## 一、验收判据

| 读数 | 阈值 | 怎么取 |
|---|---|---|
| 宽 | 1280 | `Image.open(gif).size[0]` |
| 时长 | 6~15s | `duration × n_frames` |
| 体积 | ≤2MB | 文件大小 |
| 四边无白边 | 四边各 4px 带均值 <120 | 裁一张 `shot(REGION)` 算边缘亮度 |
| 首尾同态 | 视觉一致 | 抽首帧与尾帧目视比对 |

## 三、本轮修掉的系统性根因

| # | 根因 | 影响的图 | 修法 |
|---|---|---|---|
| 1 | **IME 未切英文**：`typewrite` 在中文态被转成候选框，汉字进了演示数据 | code-completion / annotation-preview | `nav.force_en_us()`（`LoadKeyboardLayoutW('00000409')` + `PostMessage(WM_INPUTLANGCHANGEREQUEST)`）；只调 `ActivateKeyboardLayout` 无效 |
| 2 | **Ctrl+G 输入框留在画面里**：`goto` 的 Enter 被 IME/时序吞掉，当时的像素护栏判不准（弹窗本体是深灰，与编辑器只差 3~5 个灰度级，实测恒判 False） | batch-operation / jpa-write-path / jpa-embedded | `goto_col` 末尾**无条件按 Esc**——跳转已生效，Esc 只关输入框 |
| 3 | **预览弹窗渲染中间态**：等 1.2~2.6s 不够，弹窗要 ~3s 才画完，中途开录会录到半透明错位 | jpa-write-path / jpa-criteria | 预览等待统一提到 3.4~3.6s |
| 4 | **构图错位与白边**：窗口外框与 REGION 没对齐（顶部切 20px）；照外框录进了 8px 圆角阴影 | 全部 | 外框对齐 `(277,25,1370,984)` + 录制区内缩 8px → `(285,26,1354,974)` |
| 5 | **凝视段被当静止裁掉**：裸屏捕获不含光标，纯 `moveTo` 零像素变化，assemble 裁完只剩 3.1s | jpa-criteria | 改成真实交互（粘贴参数值让 SQL 实时变化），兼顾演示效果 |
| 6 | **开错同名文件**：demo 工程里 `UserMapper.xml` / `UserMapper.java` / `UserRepository.java` 都有重名 | 本轮踩了 3 次 | 新增 `record/mcpnav.py`，走 IDE 内置 MCP `open_file_in_editor` 按路径精确打开 |

### `dialect-gate` 相关：方言闸门三处缺陷已修并真机验证

用户定案：「方言不能影响最终的执行。哪怕方言是错的，用户手动选择了数据源，可以正常提示方言不一致，但是还是要能成功执行」。

按此修了三处（插件仓 `8619a3af` + `e7a27700`）：

| # | 缺陷 | 修法 |
|---|---|---|
| 1 | `MANUAL_CONFLICT` / `RERENDER_UNAVAILABLE` 直接阻断执行 | 改为「红字提示 + 放行」，UI 仍挂「切换数据源」入口；**边界**：有一边方言未知（`TARGET_UNKNOWN_BLOCK` / `RENDER_UNKNOWN_BLOCK`）仍拦，那是「无从判断」不是「判断出冲突」 |
| 2 | 报错文案报「方言（MySQL）」，而预览头部写的是 `方言: PostgreSQL（手动指定）` | 改为优先用 `dialectGateRequest.renderedDialectName` |
| 3 | 平台按 psiFile 方言筛 runner，数据源无 Dialects 映射时 `runners=0`，用户看到「没有匹配数据源」 | runner 为空时把 exec 文件**重映射到目标源方言**再枚举一次，命中即复用既有控制台/结果表/审计链路 |

**真机验证（2026-10-25，PG 方言 + MySQL 目标源冲突场景）**：

```
[M36] runners=0
[M36] runners empty → remapped exec file to target dialect, retry runners=0
（补凭据后）
[M36] runners=3
```

界面弹出「选择数据源」列出三条 PG 源；选中后**执行真的送到数据库**，返回 PG 自己的报错：

```
执行失败: [42P01] ERROR: relation "user" does not exist
位置: 163 [当前库=public, 数据源=pg_demo@114.66.55.245, 数据源默认库=dbx_test]
```

即：不再被插件拦在「没有匹配数据源」，而是交给数据库判定——这正是用户要的语义。

**环境侧踩坑（与插件无关，但影响复现）**：PG 数据源首次连报 `Driver files are not downloaded`，必须点 `Download Driver Files` 装 `postgresql-42.7.13`；随后弹「Please provide database credentials」需填 user/password（`dbx_test` / 见 dbx 开发环境表），填错字段会静默失败。填对后树里显示 `1 of 3`、`list_database_schemas` 返回 `dbx_test.public`（已 introspect）。

**`dialect-gate.gif` 现在的可录形态**：PG 方言 + MySQL 目标源 → 提示方言不一致但执行成功（数据库报 `relation "user" does not exist`）。与原计划「阻断态 + 两出口」不同，需产品确认演示哪种；若要「阻断态」，得构造「一边方言未知」的场景（那是保留阻断的分支）。
