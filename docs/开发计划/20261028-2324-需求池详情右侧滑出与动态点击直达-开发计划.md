> 日期：2026-10-28 23:24
> 任务号：T-FeedbackDrawer
> 状态：**已上线（2026-10-29 部署 + 生产只读复验）**
> 涉及仓库：`mybatis-plus-sql-visualizer-docs`（当前仓库，master）
> 来源：用户 2026-10-28「文档站需求反馈池和工具站需求反馈池功能优化，目前两个页面的点击进入需求详情是跳转 稍微不方便 可以改成点击后在右侧弹详情页，需求池动态需要支持点击跳转到具体需求，现在生成两份开发计划文件到对应项目下」

## 一、需求理解

### 1.1 原话拆解

1. 「点击进入需求详情是跳转」——现状：点列表/看板卡片后，`FeedbackPage` 用 `v-if` 把整个两栏布局（反馈池 + 动态栏）**整体替换**成 `FeedbackDetail`（`FeedbackPage.vue:4-23`），配合 `?postNo=` 查询串。用户感知就是「跳走了」，返回要再点一次「← 返回列表」，上下文丢失。
2. 「改成点击后在右侧弹详情页」——详情改为**右侧滑出抽屉**：列表与动态栏留在原位，抽屉从右侧滑入覆盖其上，关闭后回到原位。
3. 「需求池动态需要支持点击跳转到具体需求」——动态栏条目（新需求 / 状态变更）当前纯展示，点击无反应；改为点击即打开对应需求的详情（同款抽屉）。

### 1.2 硬约束

| 约束 | 落地口径 |
|------|----------|
| 深链不回归 | 邮件「查看详情」等外链 `?postNo=FR-xxxx` 直开**抽屉**（行为从直开详情页改为直开抽屉，URL 同步逻辑不变）；`?category=` 深链弹提交表单不受影响 |
| 不改后端 | `/feedback/activity` 的两类条目都已返回 `postNo`（`sql-visualizer-admin` `routes.ts:1031`、`:1049`），动态点击直达纯前端接线 |
| 中英文一致 | 抽屉文案走既有 `i18n.ts`（关闭按钮复用 `t('close')`），en 侧随 `useData().lang` 自动生效，不新增硬编码中文 |
| 移动端可用 | 窄屏抽屉全屏化，375px 无横向溢出；触屏可关闭（× / 点遮罩） |

### 1.3 本次不做

- 不做抽屉内的「上一篇 / 下一篇」需求切换；
- 不做列表内嵌展开（inline expand）形态——用户点名的是右侧弹详情；
- 不动 `FeedbackDetail` 的内容结构（详情卡片 / 附件 / 状态历史 / 评论全部原样复用）；
- 不做关闭时的退场动画（与现有提交弹窗一致，只有进场动画）；
- 不改工具站（另一份计划）。

## 三、方案设计

### 3.1 页面结构改造（FeedbackPage.vue）

```
改造前：
  selectedPost ? <FeedbackDetail/> : (两栏：FeedbackPool + FeedbackActivity)

改造后：
  两栏（FeedbackPool + FeedbackActivity）常驻渲染
  + <Teleport to="body"> 抽屉 <FeedbackDetailDrawer v-if="selectedPost" :post-no="selectedPost" .../>
  + 既有深链 ?category= 提交弹窗（不动）
```

- `selectedPost` 仍是唯一开关状态：列表卡片、看板卡片、动态条目三处入口都写它，抽屉 `v-if` 挂载。
- `watch(selectedPost)` 的 `?postNo=` 同步逻辑原样保留（`:110-115`）。
- 反馈池 / 动态栏从「v-else 卸载」改为常驻，`poolRef` / `activityRef` 在抽屉打开期间不再为 null，`onDeepLinkSubmitted` 里现有的 `poolRef.value?.` 可选链兜底继续成立。

### 3.2 新组件 FeedbackDetailDrawer.vue（抽屉壳）

只做壳，不复制详情逻辑——内容插槽放现有 `FeedbackDetail`：

```
┌─────────────────────────────────────────────┐
│  遮罩（fixed inset:0，rgba(0,0,0,.55)，点击关闭）│
│                          ┌────────────────┐ │
│                          │ ×        (固定) │ │
│   两栏背景被遮罩盖住       │  FeedbackDetail │ │
│                          │  （内部独立滚动） │ │
│                          │                │ │
│                          └────────────────┘ │
└─────────────────────────────────────────────┘
```

- **挂载方式**：`Teleport to="body"`，与现有提交弹窗一致——规避 VitePress 页面容器潜在 `transform/filter` 祖先把 `position:fixed` 的包含块改掉的风险（现有 modal 走 Teleport 已是既定做法）。
- **面板**：`position: fixed; top: 0; right: 0; height: 100dvh`（fallback `100vh`），宽 `min(640px, 92vw)`；`overflow-y: auto` 内部独立滚动；背景 `var(--vp-c-bg)`，左侧投影 `box-shadow` 与圆角（仅左上/左下）。
- **进场动画**：面板 `transform: translateX(100%) → 0` 的 CSS `@keyframes`（约 0.25s ease-out），遮罩同步淡入；关闭无退场动画（`v-if` 直接卸载，与现有弹窗口径一致）。
- **关闭三通道**：右上角 × 按钮（`:title`/`:aria-label` 走 `t('close', locale)`）、点遮罩（`@mousedown.self`，与现有弹窗一致）、Esc（见 3.5）。
- **内容复用**：`<FeedbackDetail :key="postNo" ...>` —— `:key` 强制重挂载，保证动态条目在抽屉开着时点另一条能切换内容并重新拉取（`FeedbackDetail` 只在 `onMounted` 拉数据，不 watch `postNo`）。
- `FeedbackDetail` 底部既有的「← 返回列表」链接保留，`@back` 事件同样走关闭抽屉，语义不变。

### 3.3 动态栏点击直达（FeedbackActivity.vue）

- 每个条目 `<li>` 加 `@click="$emit('select-post', item.postNo)"`，`cursor: pointer`，hover 时背景 `var(--vp-c-bg-mute)`（或 brand-soft）反馈；标题色 hover 变 `var(--vp-c-brand-1)`。
- 键盘可达：`tabindex="0"` + `@keydown.enter` 触发同一 emit；焦点态 `outline` 沿用浏览器默认。
- `FeedbackPage` 里 `<FeedbackActivity @select-post="selectedPost = $event" />`——与反馈池同一个入口状态，复用同一个抽屉。

### 3.4 背景数据同步（列表不再卸载带来的新职责）

抽屉内操作发生时，让常驻的反馈池跟上：

| 抽屉内操作 | 事件链 | 背景同步 |
| --- | --- | --- |
| 投票 | `FeedbackDetail.onVoteUpdate` 新增 `emit('vote', props.postNo, count, hasVoted)` | `FeedbackPage` 调 `poolRef.value?.applyVoteUpdate(postNo, count, hasVoted)`——`FeedbackPool` 把内部既有 `onVoteUpdate`（`:416-427`，已同步卡片票数与 `stats.totalVotes`）通过 `defineExpose` 暴露为 `applyVoteUpdate`。定向更新，不重拉、不闪烁 |
| 发评论 | `FeedbackDetail.submitComment` 成功分支新增 `emit('commented')` | `FeedbackPage` 调 `poolRef.value?.reload()`（刷新卡片评论数）。评论不进动态流（activity 只有「新需求 / 状态变更」），动态栏**不需要**刷 |

评论成功时抽屉内 `loadDetail()` 原样保留（自己的评论区即时更新）。

### 3.5 Esc 层级与互斥

- `FeedbackPage.onKeydown`（`:137-139`）扩展为分层关闭：有深链提交弹窗先关弹窗，否则抽屉开着就关抽屉——`if (deepLinkCategory) closeForm(); else if (selectedPost) selectedPost = null`。
- 两者实际互斥：`?category=` 深链处理时会连 `postNo` 一起清（`:99-106`），且抽屉打开时遮罩挡住工具栏、提交弹窗无法再被打开。分层 guard 只是兜底。
- `FeedbackPool` 内部的提交弹窗 Esc（子组件独立监听）与抽屉不并存，无需处理。

### 3.6 背景滚动锁

- 抽屉开着时背景仍可被滚轮带动（遮罩本身不可滚，滚轮会穿透滚到 body），加锁：`watch(selectedPost)` 里对 `document.body` 增删 `overflow: hidden`（内联 style 或挂类均可，卸载时必恢复）；组件 `onBeforeUnmount` 兜底移除，防深链刷新场景残留。
- 现有提交弹窗没做滚动锁、维持现状，不顺手改（控制改动面）。

### 3.7 断点与移动端

- `≥768px`：右侧抽屉 `min(640px, 92vw)`，与现有 `@media (max-width: 767px)` 断点体系一致。
- `<768px`：抽屉全屏（`width: 100vw`），遮罩实际不可见但保留点击关闭；× 按钮固定在面板顶部不随内容滚走（sticky）。
- 抽屉内部内容沿用 `FeedbackDetail` 现有窄屏样式（评论表单 `fd-form-row` 在 640px 已回落纵向），不额外改详情内部 CSS；**待验证前提**：640px 宽下 `.fd-title` 1.5rem 与附件缩略图 4rem 的观感，走查若拥挤再微调，不预先改。

### 3.8 层级表

| 层 | z-index | 说明 |
| --- | --- | --- |
| 提交弹窗（遮罩+对话框） | 1000 | 现状不动 |
| **抽屉遮罩 / 面板** | 1000 / 1001 | 与提交弹窗互斥，同层无冲突；面板略高保证同层时也在上 |
| 提交成功 toast | 1200 | 现状不动，深链提交成功时 toast 显示在抽屉之上（两者可并存：提交成功 → toast + 反馈池刷新，抽屉不受影响） |

## 六、风险与待验证前提

1. **待验证前提｜Teleport 必要性**：抽屉按 3.2 走 `Teleport to body`，规避 VitePress 容器祖先 `transform` 劫持 `fixed` 包含块的风险；实施时先按 Teleport 写，若走查发现双滚动条或定位异常再排查包含块。
2. **待验证前提｜640px 内容观感**：`FeedbackDetail` 原按 800px 居中设计（`.feedback-detail max-width:800px`），640px 抽屉内该 max-width 不再绑定，标题/附件/评论表单的实际观感以走查为准，拥挤再单独微调、不在本任务预先改。
3. **`?postNo=` 语义变化**：深链从「直开详情页」变为「直开抽屉」，URL 形态不变，旧链接全部兼容；无降级路径（详情页形态不再保留），若用户反悔改回只是还原 `FeedbackPage` 的 v-if 结构。
4. **滚动锁与主题冲突**：VitePress 主题自身管理 body 滚动（侧栏等）；抽屉锁只在 `selectedPost` 存在期间生效且卸载即恢复，与主题无持久写入，理论无冲突，走查确认关闭后页面滚动正常即可。
5. **动态条目指向已删/隐藏帖**：后端 activity 只聚合 `is_deleted=0 AND is_hidden=0` 的帖（`routes.ts:1012/1026`），正常不会指到不存在的需求；但状态变更有延迟窗口（管理端操作后用户未刷新页面），点了旧条目抽屉内走 `FeedbackDetail` 现有错误分支显示「加载失败」，可接受，不做额外容错。
6. **部署**：本计划只提交不部署；部署走既有 `npm run deploy`（Cloudflare Pages），另行确认后执行，部署后按惯例 curl 生产页确认。
