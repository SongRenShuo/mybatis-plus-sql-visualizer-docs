# 演示 GIF 录制指南

> 2026-09-12 修订九轮全量重录（7/8 张）验收通过后沉淀。本文是面向下一次录制/补拍的操作手册，管线原理与平台坑的完整分析在插件仓库 `docs/经验总结/20260910-0100-IntelliJ演示GIF录制-经验总结.md`（§十为本轮新增），两处不重复维护。
> 本方法论已固化为 ZCode skill **`ide-demo-gif`**（用户级 `~/.zcode/skills/ide-demo-gif/`，含通用化工具脚本与场景模板，自然语言「录一张演示 GIF」可触发）。本文保留作背景与规格依据；通用能力改动以 skill 内 scripts 为权威源。
> 录制脚本在插件仓库 `record/`（**已入库 master**，2026-09-15 起录制基线就是 master；
> 分支只用于隔离并行开发，如 2026-09-19 的 `t-gif-rec-mcp`），中间产物 `record/perf/` 不入库。

## 环境启动

1. 插件仓库 **master**（并行开发期用隔离 worktree，如 `mpsv-gif-rec`），确认 `grep -c gifRecord build.gradle.kts` 非 0。
   > **口径订正（2026-09-20）**：本节此前写「开关只在 dev、master 敲参数会被静默忽略、record/ 脚本仅 dev 分支」——
   > 该说法自 2026-09-15 起已过时：开关与 `record/` 脚本均已入库 master，照旧口径执行会白开一个 dev worktree。
2. `python C:\Users\USER\.zcode\cli\parallel_tasks.py check`，有并行任务先 register 独立沙盒名。
3. `./gradlew runIde -PgifRecord=true` 后台跑，一条命令带上 262 平台 + JCEF + toolchain24 + 独立沙盒 MPSV-GifFresh；不带参数即 243 常规态，录完无需还原。
4. 沙盒免费评估模式即可，全部 Ultimate 功能可用。

## 环境就位清单（每次开新沙盒都要）

- 主题 Islands Dark + 缩放 120%（新沙盒这两项要重设；Islands Dark 会随 colors.scheme.xml 保留，Zoom 缺省回 100%）
- 编辑器字体确认 13pt 默认——「120% + 18pt」正是被用户判退的中间态，别搞混
- 窗口定位 (277,25,1370,984)：用 Win32 `MoveWindow`（DPI 感知脚本），**等 IDE 完全空闲后再移**——刚启动/改完 Zoom 的窗口会被 AWT 最小高度钳制（1042→1100）弹回
- 关项目目录树（修订九硬性项）：Project 工具窗的「—」隐藏按钮，别点到「折叠全部」
- 系统输入法切英文态：微软拼音「中」态下 typewrite 走组合输入，候选框会录进画面且提交时机不稳
- 录制中系统空闲时优先，用户/其他会话动鼠标会打偏点击

## 管线流程

```
标定（shot.py 抓帧定坐标 → 改 scene 脚本常量）
→ scene_tN.py 重放（mss 15fps 无损 mp4 + curlog 光标日志）
→ assemble.py 转制（空白压缩 + 光标回绘 + palette GIF + poster）
→ ffmpeg 抽帧逐点验收（动作节点/定格/poster 三处）
```

固定套路：

- scene 脚本内**自包含就位**：open_file/goto_line/图标检测全在 `Recorder.start()` 之前，take 中途只做演示动作
- gutter 图标用 `find_gutter_icons` 像素检测动态取，不写死坐标；当前构图条带在 region 相对 x≈95~130
- 13pt 下视口行数比 150% 时代多一倍，「取最低簇」会误选下方方法的图标——用窄 y_range 直取或取最接近视口中心者
- 弹窗控件坐标（取消按钮、复选框、输入框）必须弹窗打开态现标；取消按钮当前在 (1485,827)
- 转制后核对 `decoded 帧数 == Recorder.frames`，防残留帧混入（见下）

## 录制期纪律（适用所有轮次，不折中）

**插件功能问题一律停录回修，不在录制现场处理**（用户 2026-09-19 定调）。

录制过程中一旦发现插件功能问题——界面异常、数据错误、崩溃、行为与文档描述不符、工具返回不符合预期——**立即停止录制**，不在现场改代码、不打临时补丁、不绕过问题继续录。带着问题往下录只会产出与真实行为不符的演示，事后还得重录。

处置流程：① 停录并记录现场证据（截图 / `idea.log` 片段 / 复现步骤）；② 回插件项目按正常流程定位根因 → 修复 → 补或跑测试 → 提交；③ 修复验证通过后**重新开始录制该张**（不是续录，停录时的现场状态已不可信）；④ 若问题同时影响文档描述，同步订正对应文档页。

**沙盒侧的操作限制不算「插件功能问题」**：例如「合成点击对某控件不生效」属于本机自动化环境限制，处理方式是换等价交互面并在脚本里注明，不进停录流程——但要在实施状态里如实记录，避免下一次重复踩。

## 本轮踩坑定论（按代价排序）

1. **assemble 残留帧**：decode_frames 原来不清 frames 目录，上次解码帧数多于本次时旧尾帧混入新 GIF（T4 实证 132=119 新+13 旧，旧构图布局直接穿帮）。已修复为解码前清目录；转制后核对帧数是最后防线。
2. **T5 捕捉顺序**：先点「捕捉」再启动应用，监听建立失败、列表恒空。正解是应用先跑起来（Services 选中 MybatisPlusDemoApplication 后点面板 ▶），再点捕捉，脚本内 urllib 轮询 `/user/list` 触发查询。
3. **IME**：整个录制期保持英文态，打字前看一眼任务栏指示器。中文态的候选框入镜只有抽帧才能发现。
4. **T3 类打字场景全键盘化**：goto_line 居中有 ±2 行漂移，点击行坐标不可靠；goto 本身把光标落在目标行行首，之后 End/Enter/键入全键盘完成，鼠标只做演示滑动。
5. **前台抢夺**：`AttachThreadInput + SetForegroundWindow` 只给焦点不改 Z 序，视觉上窗口还在浏览器后面，坐标点击会穿透。要配 TOPMOST→NOTOPMOST 舞步；点击坐标在窗口可视区内（DWM 阴影边约 13px 不算数，超了就点到后面的窗口上）。
6. **坐标系两套**：shot.py/region 截图是 region 相对坐标，点击要 +277/+25；全屏截图 raster 是 1280×720，物理坐标 ×1.5。混用是最大的时间坑，写坐标前先想清楚手里是哪张图。裁剪局部图量的坐标还要再加一层偏移——三套数字（屏幕 / region / 裁剪内）逐级换算，点错一格就是 neighboring 控件。
7. **运行时改 Zoom 的钳制**：见环境就位清单，预写 other.xml 或等空闲后再定位。
8. **PixPin 全局热键撞车**：PixPin 常驻时 `Ctrl+Shift+A`（截图）、`Ctrl+Alt+S`（取色）都会被它劫持——Find Action 和 Settings 快捷键全部失效还会弹出它的覆盖层。开 Settings 走 IDE 工具栏齿轮菜单；Find Action 期间先确认 PixPin 不在撞键范围。
9. **IDE 编辑器缓冲污染**：误打进编辑器的文字用 Ctrl+Z 可能撤不掉（撤销栈状态异常），关标签重开也可能复用内存脏 Document。可靠清理是右键 > Local History > Show History，选污染前的时间点 Revert——它按内容快照回滚，不依赖撤销栈。
10. **置顶覆盖层抢前台**：ZCode 自动化面板等常驻应用若处于置顶态，TOPMOST→NOTOPMOST 舞步会把 IDE 抬回非置顶带、照样被盖住，坐标点击会打进覆盖层（曾误触自动化面板）。点前先 EnumWindows 核对目标窗口标题与位置，必要时让 IDE 持续保持 TOPMOST 干完活再撤。
11. **活动态像素判定量错元素**：tab 活动高亮改成判定规则前，先沿判定带扫一条像素列看真实 RGB——修订九用的「亮蓝 b>120」阈值实际量到的是聚焦下拉边框，活动标签药丸本身是暗蓝 (35,53,88)，规则应为 b>60 且 b−r>30。活动/非活动两态都量一遍再定阈值。
13. **合成点击对部分控件根本不生效**（本轮代价最大）：插件设置页的逐项复选框，同一坐标点阵扫描 9 点 **0/9 命中**（长悬停 1.5s、间隔 3s 均无改善），而同一窗口内的按钮、左树行、输入框全部可靠；平台页同语义的 Enabled 复选框 4/4 可靠。gutter 图标的合成点击同样不稳（4 连击全空），键盘入口 `Alt+Shift+Q` 反而每次成。**分镜设计前先逐控件试一遍**，不可靠就换等价面（本轮把「逐工具门控」从插件页移到平台页）。
14. **总开关一关，整组控件置灰**：插件设置页的总开关关掉后，十一个工具复选框整体转禁用态，症状与「坐标点错」完全一样（点不动），白耗数轮。凡「点不动」先查有没有把上游开关关掉。
15. **悬停浮层会拦截后续点击**：鼠标停在编辑器 gutter 上约 1 秒会弹出「Ask AI」小浮层（约 235×42），此后取消/复制等按钮连续点空。移向 gutter 后要**立刻点**，别停留。
16. **误操作会污染后续整轮**：一次误点（总开关）或一次误打（Ctrl+A/Delete/paste 落在编辑器里把文档覆盖）都会让后面全错。录制前先做状态归一 + 像素自检；发现编辑器内容被改，磁盘文件用 `git checkout --` 还原、编辑器缓冲用 Ctrl+Z 或 Local History Revert。
17. **录制段从 prep 已就位的界面开始**：把开窗、寻路、搜索、滚动全部移进 prep，录制段只留动作——M1 实测 40s → 13.3s。代价是 prep 要自己做状态归一（开关、勾选、滚动位置）与像素自检，失败就中止而不是录进坏画面。
18. **接缝 diff 的来源往往不是光标**：M1 首版 6.22 是光标没归位（补一次 `move` 回起点后 0.02）；S1 的 1.79 是**状态差**——条目选中高亮在、焦点却在列表 vs 编辑器。首尾要停成同一态，**连焦点在哪都要一致**。另：列表按时间升序、新条目在下方，解析还没落库完就开录会让首尾列表内容不同，录制前给足落库时间（本轮 7s）。
19. **字节码增强会话的两条断线规律**（2026-09-20 实测，影响所有需要「调用点」的场景）：① 把面板「捕捉」关掉会**连带断掉 agent 会话**，再打开不会自动重连（日志 `pushCaptureActive: active=true → disabled=false（sessions=0）`），此后捕获的条目**没有调用点**、依赖调用点的菜单项全灰；② 会话会在挂载后约 **45~80 秒自行掉线**（`AgentSession - Socket closed`），而应用进程并未退出（端口仍在、pid 不变）。→ 需要调用点的场景必须「**重启应用 → 立刻开捕捉 → 立刻触发查询**」，把条目抢在窗口内录进列表；条目一旦入库就带调用点，后续操作不受掉线影响。另：demo 应用若含 DevTools，改源码触发的自动重启会让新 JVM 不带 agent，会话同样掉线。

20. **AI Assistant 的「对话面板」不是点主工具栏 AI 按钮**（2026-09-20 实测，曾据此误判「ACP 面板不可达」）：点主工具栏 AI 按钮打开的是 AI Assistant 的**落地页/推广页**（本沙盒无 Ultimate 许可时整页是订阅 FAQ + Trial 标签）；**对话面板是右侧工具窗**（图标在右侧栏），打开后顶部是 `Chat History` / `New Chat`，正文是 agent 名（如 `Codex`）与 `Configured authentication: Managed by agent`，底部是提示框与 agent/模型两个下拉。**判据**：面板左上能看到 agent 名与认证行才算面板。
21. **需要「现场打开某个文件」的桥段一律移进 prep**：M1-c 首版把「打开 idea.log」放在录制段里，Find Action + 原生文件对话框 + 4.5s 载入共 13s，成片直接 30s 超规格；改到 prep 里开好并定位，录制段只切标签后压到 11.9s。**判据**：录制段里任何「等待外部资源加载」的动作都该前置。
22. **搜索定位要选唯一子串**：在 idea.log 里搜 `[MCP-AUDIT]` 会先命中上一轮的旧审计行（工具名还是改名前的 `mpsv_`），画面上工具名对不上；应搜 `tool=sqlv_check_sql` 这类唯一子串。

12. **runIde 构建疑似卡死**：daemon 低 CPU、产物目录长时间无变化、日志停在同一行即判定卡死，杀 gradle client+daemon 重跑（第二次全 UP-TO-DATE 很快）。构建输出直写日志文件（`> abs/path.log 2>&1`），`-q` 加管道会缓冲到结束才可见。另注：沙盒 IDE 进程是 java.exe 而非 idea64.exe，找窗口按标题不按进程名。
