# 需求池日期修复与看板搜索 开发计划

- 日期：2026-09-06
- 范围：docs 仓库前端（`.vitepress/theme/components/feedback/`），后端 Worker 不动
- 需求来源：用户反馈「需求池中需求的日期、评论和状态变更的日期没有正常显示；看板页面需要加一个和列表一样的需求池搜索」

## 一、需求分析

### 1. 日期不显示（已线上复现）

用 puppeteer 打开生产详情抽屉，实际渲染出字面量 "Invalid Date"：

```
老张 · Invalid Date          ← 详情头部「提交人 · 日期」
小李 Invalid Date            ← 评论时间
page errors: []              ← 无异常，Vue 静默渲染
```

后端 D1 的 `CURRENT_TIMESTAMP` 存的是 UTC、格式 `YYYY-MM-DD HH:MM:SS`（无时区标识），
接口原样返回（如 `"createdAt":"2026-09-05 17:22:55"`）。前端三个组件的解析全都有问题：

| 位置 | 现状代码 | 后果 |
|---|---|---|
| `FeedbackDetail.vue` `formatDate`（详情头部 L18 / 状态时间线 L68 / 评论 L83 共用） | `new Date(dateStr + (includes('T') ? '' : 'T00:00:00'))` | 带时间的串变成 `2026-09-05 17:22:55T00:00:00`，**Invalid Date**，页面直接打出 "Invalid Date" 字面量 |
| `FeedbackPool.vue` `formatDate`（列表卡片日期） | `new Date(dateStr.replace(' ', 'T'))` | 能解析但按**本地时区**理解 UTC 时间，UTC+8 下偏 8 小时，「今天/昨天/几天前」可能错一天 |
| `FeedbackActivity.vue` `relativeTime`（动态面板时间） | 同上 | 同上，相对时间偏差 |

另外 `FeedbackDetail.formatDate` 硬编码 `'zh-CN'`，英文站也输出中文日期格式；
`FeedbackPool.formatDate` 的「今天/昨天/N 天前/N 周前」也是硬编码中文。

**方案**：新建共享工具 `feedback/dateTime.ts`，统一 `parseUtcDate(dateStr)`：
- 纯日期 `YYYY-MM-DD` → 补 `T00:00:00`；空格分隔 → 换 `T`；
- 结尾无 `Z`/`±HH:MM` 时补 `Z`（显式声明 UTC）；
- 解析失败返回 `null`，调用方回退显示原始字符串。

三个组件改用该工具；相对时间/绝对日期的文案改走 i18n（新增 `timeToday`/`timeYesterday`/`timeWeeksAgo` 键，中英文各一份），绝对日期按组件 `locale` 选 `zh-CN`/`en-US` 格式。

### 2. 看板搜索

列表搜索的实现是服务端关键字搜索：`.filters` 行的输入框 `v-model="searchKeyword"`，
回车触发 `applySearch() → loadData()`，`loadData` 给 `/feedback/posts` 拼 `?keyword=`。
看板与列表共用同一份 `posts`（`postsForBoard` 由其派生），所以看板搜索与列表搜索
「一样」的最 faithful 做法就是复用同一状态与同一条链路——输入框绑同一个
`searchKeyword`，回车同样走 `applySearch()`，看板列卡片随 `posts` 自动过滤，
列头计数（`getStatusPosts().length`）随之变化，空列显示既有「暂无」。

在 `FeedbackPool.vue` 看板视图分支顶部（状态统计条下方、看板上方）加一行搜索输入，
placeholder 复用既有 `t('search')` 键。切换列表/看板时关键字天然同步。

不改 `RoadmapBoard.vue`（保持纯展示组件），不改后端。

## 三、验收标准

1. 详情抽屉：头部「提交人 · 日期」、状态时间线、评论时间均显示正常日期（非 "Invalid Date"）。
2. 列表卡片与动态面板的相对时间按 UTC 存储正确换算，不再偏 8 小时。
3. 英文站日期/相对时间文案随语言切换。
4. 看板视图有搜索框，输入关键字回车后各列只剩命中卡片、列计数更新，清空回车恢复全量；与列表共用关键字。
5. 三处以上解析失败场景不出现 Invalid Date / NaN。

## 四、实施记录（2026-09-06）

T1–T5 全部按计划落地，未改 `RoadmapBoard.vue`（保持纯展示组件）与后端。

本地验证 13/13 PASS（puppeteer + 本地 preview，`/api/v1` 经请求改写到生产 Worker 取真数据）：

- parseUtcDate 单元核对：`2026-09-05 17:22:55` 与 `2026-09-05T17:22:55Z` 解析出同一时间戳；纯日期补 UTC 零点；带 `+08:00` 偏移不追加 Z；乱码/空 → null。
- 看板搜索：初始 3 卡 → 搜 "Wrapper" 仅 FR-0012、列计数和=1 → 无命中词 0 卡且 6 列全显「暂无」→ 清空恢复 3 卡。
- 详情抽屉：头部「匿名 · 2026-09-03」、状态时间线 3 条均带日期、评论 1 条带日期，全页无 "Invalid Date"/"NaN"，无 pageerror。
- 列表日期「2 天前/今天/今天」、动态面板「17 分钟前…」，与 UTC+8 换算一致。

踩坑两条：
- 测试脚本里 `el.value=''` 不触发 `input` 事件，Vue `v-model` 不感知，清空回车后搜索词仍是旧值——须用 `HTMLInputElement` 原生 value setter + `dispatchEvent(new Event('input'))`。
- `vitepress preview` 的参数是站点根目录不是 dist（传 `.vitepress/dist` 会二次拼接成 `dist/.vitepress/dist` 500 崩溃）；正确用法 `npx vitepress preview --port 4987`。
- preview（sirv）不执行 Pages functions，本地页面调 `/api/v1` 必 404——测试用 puppeteer `setRequestInterception` 把相对 API 请求改写到生产域名。

生产复核（commit 5047ffe，deployment 21922dfb）8/8 PASS：看板 3 卡 → 搜 "Wrapper" 仅 FR-0012 → 清空恢复；详情头部「匿名 · 2026-09-03」、时间线 3 条、评论 1 条均带日期；无 Invalid Date/NaN/pageerror。正式域名 `/assets/chunks/theme.*.js` 已含 `board-search`，确认新包生效。

复核踩坑：`about/feedback.html` 会 308 到 clean URL `/about/feedback`，`curl` 不带 `-L` 拿到的是空跳转体，据此做的产物 grep 会假阴性；Python urllib 默认不跟 308，须自挂 RedirectHandler。另外本地 preview 进程会锁住 `.vitepress/dist` 导致 `vitepress build` 清目录 rimraf 失败——部署前先杀 preview。
