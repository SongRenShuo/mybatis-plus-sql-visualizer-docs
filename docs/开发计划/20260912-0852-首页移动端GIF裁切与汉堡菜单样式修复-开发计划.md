# 首页移动端 GIF 裁切与汉堡菜单样式修复 - 开发计划

> 日期：2026-09-12
> 状态：已实施
> 范围：文档站（本仓库）首页自定义组件，不涉及插件仓库

## 一、问题结论（浏览器 390×844 手机视口实测）

### 问题 1：首页四大功能块 GIF 在手机端被裁成竖条（用户主诉"gif 宽度不太够"）

- 组件：`.vitepress/theme/components/home/FeatureAlternate.vue`（"大幅提升您的 SQL 调试效率"区块，4 组功能）
- 实测数据：375px 视口下 GIF 容器 279×300，素材原图 1440×1034（横版，比例 1.39）
- 根因：`.feature-video` 写死 `min-height: 300px` + `object-fit: cover`。手机端容器仅 279px 宽，300px 的最小高把盒子拉成竖比例（0.93），cover 模式下横向约 33% 的画面被裁掉，IDE 界面两侧内容丢失、文字更不可读
- 附带：768~1024px 平板区间双列布局下同样触发轻度裁切（自然高约 292px < 300px）

### 问题 2：首页汉堡展开菜单样式粗糙（用户主诉"点击按钮后的样式有问题"）

参照文档页 VitePress 原生 VPNavScreen（全屏导航层，视为正确基准），首页 `NavHeader.vue` 的 `.mobile-menu` 差异：

1. **菜单项文字完全贴住屏幕左边缘**：`.mobile-link` 仅 `padding: 0.75rem 0`，`.mobile-links` 无水平内边距，文字与分隔线均从 x=0 拉通，与顶栏 24px 边距完全不对齐
2. **非全屏、无浮层感**：菜单只是挂在 header 下的一条下拉面板，页面内容紧贴菜单底边露出；背景 `var(--bg-primary)` 与页面同色，几乎无法区分层级。文档页为全屏遮罩式，边界清晰
3. 打开菜单时背景页面仍可滚动；无展开过渡动画，闪现
4. 顺带对齐：三条杠颜色为 `--text-secondary`（#9ca3af 浅灰），文档页用 `--vp-c-text-1` 主文字色，视觉存在感不一致

### 巡检结论：其他页面无同类布局问题

- `GifPlayer.vue`（8 个 features 详情页在用）：poster `width:100%` 自然比例，无固定高裁切 ✓
- `DocsShowcase.vue`（首页文档入口三卡）：`aspect-ratio: 16/10` + cover，两端一致但上下裁掉约 13% 的 IDE 画面（工具栏/状态栏被切），按"素材原比例零裁切"口径一并修正
- en 首页、features、guide、about、feedback 页：390px 视口批量检测均无横向溢出 ✓
- `EnHomeFeatures` / `EnFeatureMatrix` / `Testimonials` / `PricingSection` / `CtaSection` / `WelfareCard`：响应式断点齐全，无固定像素列宽 ✓

## 二、修复方案

### 修复 1：FeatureAlternate GIF 恢复原比例（零裁切）

`.feature-video` 的 `min-height: 300px` 替换为 `aspect-ratio: 1440 / 1034`：

- poster 未加载时按比例撑起占位，无布局抖动；加载后 GIF 绝对定位叠层 `inset: 0` 完全覆盖，淡入机制（T9c 弱网体验）不变
- 手机端从 279×300 裁切竖条变为 279×200 完整画面；PC 端渲染结果不变（自然高度本就大于 300px，min-height 此前不生效）
- 平板 768~1024px 区间的轻度裁切一并消除

### 修复 2：DocsShowcase 卡片比例统一为素材原比例

`.docs-showcase-video-wrap` 的 `aspect-ratio: 16 / 10` 改为 `1440 / 1034`，IDE 画面完整显示，PC/手机一致，与修复 1 口径统一（全站 GIF 零裁切）。

### 修复 3：NavHeader 展开菜单全屏化（对齐文档页体验）

`.mobile-menu` 由 header 下的下拉面板改为固定定位全屏导航层，参照 VPNavScreen：

- `position: fixed; top: var(--nav-h); left: 0; right: 0; bottom: 0`（`--nav-h: 60px` 与现有顶栏高度一致），背景 `var(--bg-primary)`，`overflow-y: auto`
- `.mobile-links` 加 `padding: 1rem 1.5rem`，菜单项水平边距与顶栏 container 对齐；链接加大点击区（上下 1rem），字号 1.05rem
- 菜单展开时给 `.nav-bar` 加实体背景（复用 `.scrolled` 视觉），避免顶栏透明区与浮层粘连
- 展开时锁定 `document.documentElement` 滚动，收起时恢复；Escape 关闭；组件卸载时兜底恢复滚动
- 加入淡入下移过渡（0.2s），消除闪现感
- 三条杠颜色 `--text-secondary` → `--text-primary`，与文档页视觉分量一致（开合动画不变）

### 不做的事

- 不引入 rem/vw 方案、不改 768px 断点约定（延续 20260905 移动端适配守则）
- 不动 en 首页导航（用 VitePress 默认 layout，本就正确）
- 不改 GIF 素材本体与录制管线

## 五、二轮修复（20260912 同日，真机反馈）

### 5.1 手机端大标题两行重叠

- 实测：h2.section-title 字号 36px、line-height 被解析为固定 24px，两行行框各 44px、行距 24px，重叠 20px
- 根因：VitePress 全局 reset `h1,h2,h3,h4,h5,h6 { line-height: 24px }`。自定义首页（layout:false）标题不受 .vp-doc 排版保护，凡是换行的大字号标题必重叠；PC 端只因标题单行未暴露
- 修复：style.css 增加 `.cool-home h1~h6 { line-height: 1.25 }` 统一兜底（组件内已有显式行高的 scoped 规则优先级更高不受影响）

### 5.2 暗色模式 GIF 白边

- 实测：System.Drawing 逐像素扫描 8 张 poster + 4 个 GIF 首帧，素材四边带录制窗口浅灰窗框（左/右 7-8px、底部 2-8px、顶部 0-1px），亮色页面下不可见、暗色下呈白边；全站 GifPlayer（8 个功能详情页）同源同样存在
- 修复：三处媒体容器按百分比 clip-path 裁边 `inset(0.15% 0.6% 0.85% 0.6%)`（FeatureAlternate `.feature-video`、DocsShowcase `.docs-showcase-video`、style.css `.mp-gif-player img/video`），百分比随渲染尺寸等比缩放，手机/PC 均覆盖素材最大窗框厚度；poster 与 GIF 叠层同类共用；不改素材本体

### 5.3 复验结论

- 手机 390×844：标题行高 45px 零重叠；暗色模式 GIF 卡片四周白边消失；展开菜单不回归
- PC 1440×900：功能详情页 GifPlayer、首页 DocsShowcase/FeatureAlternate 边缘干净，行距正常，无回归
